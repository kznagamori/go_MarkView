# 01. 概要・コンセプト

> 索引: [README](README.md) | 次: [02. 機能要求](02-functional.md)

## 1.1 目的

MarkView は、**Markdown ドキュメントを受け取った側が、追加のセットアップなしに GitHub と同じ見た目で読める**ようにするためのビューアである。

ソフトウェア開発の現場では、設計書・手順書・API 仕様・README といった一次資料が Markdown で書かれ、リポジトリの外へ（ZIP や共有フォルダ、USB メモリ等で）配布される場面が頻繁にある。しかし受け取った側の環境には、Markdown を GitHub と同じ体裁で表示できる手段が必ずしも存在しない。

- テキストエディタで開くと、記法が生のまま表示され読みにくい。
- ブラウザは Markdown をレンダリングしない。
- VS Code や専用エディタのインストールを相手に強いるのは、配布物としては重い。

MarkView はこの隙間を埋める。**実行ファイル 1 つを Markdown と一緒に配布すれば、受け取った側はダブルクリックするだけで読める**という体験を提供することが本アプリケーションの存在理由である。

## 1.2 ターゲット利用者

主たる利用者は、**ソフトウェア開発者およびその周辺職種**（プロジェクトマネージャ、テスタ、テクニカルライタ、顧客側の技術担当者など）である。

| 利用者像 | 状況 | MarkView に期待すること |
| --- | --- | --- |
| ドキュメントを配る開発者 | 設計書一式を顧客・協力会社に渡す | 相手の環境を問わず、意図した体裁で読んでもらいたい |
| ドキュメントを受け取る人 | 開発ツールに詳しくない場合もある | インストール不要で、開けばすぐ読める |
| 執筆中の開発者 | エディタで Markdown を書いている | 保存するたびに最終的な見た目を確認したい |
| 閉域環境の作業者 | インターネットに接続できない | 外部通信なしで図表を含め完全に表示できる |

## 1.3 コンセプト

### 1.3.1 1 実行ファイルで完結する

配布物は実行ファイル 1 つとする。以下を**必要としない**ことを設計の絶対条件とする。

- インストール作業（レジストリ変更、システムディレクトリへの配置）
- ランタイムや外部ツールの別途導入（Node.js、Python、ブラウザ拡張など）
- 実行ファイルの隣に置く付随ファイル（CSS、JS、設定ファイル、DLL 等）
- インターネット接続

CSS・JavaScript・フォント・アイコンといった描画資産はすべて実行ファイル内部に埋め込む（[AR-020](05-architecture.md)）。

> [!NOTE]
> Linux 版のみ、OS の WebKitGTK 共有ライブラリに依存する（[AR-003](05-architecture.md)）。これはディストリビューション標準のパッケージであり、「アプリ固有の付随ファイル」ではないが、唯一の外部依存として [06. ビルド・配布](06-build-release.md) に明記し、未導入時の案内を実装する。

### 1.3.2 3 つの「軽い・小さい」

本アプリケーションは以下 3 点を、機能追加よりも優先する価値とする。判断に迷う場合はこの順で軽さを優先する。

| 観点 | 目標 | 検証方法 |
| --- | --- | --- |
| **ファイルサイズ** | 実行ファイル単体で 30 MB 以下、配布アーカイブで 12 MB 以下 | CI で常に計測し、目標超過を警告として可視化（[BR-060](06-build-release.md)） |
| **メモリ使用量** | 一般的な文書の表示中で 250 MB 以下（WebView プロセス含む合計） | 手動計測および [NFR-020](07-nonfunctional.md) の受け入れ基準 |
| **動作の軽快さ** | 起動 1.0 秒以内、100 KB 文書の表示 300 ms 以内 | [NFR-010](07-nonfunctional.md) の受け入れ基準 |

この価値観から導かれる具体的な帰結を以下に示す。

- 機能は「閲覧に必要か」で判断する。**アプリケーション内の編集は、文書のブロックの数と種類を変えない 4 種類——タスクリストのチェックボックス、表のセルの文字、コードブロックと図の中身、1 つのブロックの中で選んだ文字の取り消し線と文字色——に限り、利用者が明示的に切り替える「編集モード」の中でだけ行う**（[FR-140](02-functional.md)）。段落や見出しの文字の書き換え、ブロックの追加・削除・移動など、それ以外の編集は外部のエディタへ委譲する（[FR-090](02-functional.md)）。**MarkView 自身がファイルを書き換える経路は、編集モードの書き込みだけに限る**（[NFR-031](07-nonfunctional.md)）。
- 常駐プロセス、自動更新チェック、テレメトリ、クラッシュレポート送信は実装しない。
- 重い資産（Mermaid・KaTeX・PlantUML）は、それを使う文書を開いたときにのみ読み込む。
- ファイルツリーはディレクトリを開いたときに初めて読み込む（遅延展開）。

### 1.3.3 GitHub の見た目に準拠する

描画結果は、同じ Markdown ファイルを GitHub 上で表示したときの見た目に準拠させる。ここでいう「準拠」とは、ピクセル単位の一致ではなく、**読み手が GitHub と同じ構造・強調・配色として解釈できること**を指す。具体的な適用範囲は [04. Markdown 描画仕様](04-markdown.md) で定義する。

準拠の対象には次を含む。

- 見出し・本文・リスト・引用・表の書式と余白
- コードブロックのシンタックスハイライトの配色
- GitHub Flavored Markdown（GFM）の文法解釈
- GitHub Alerts（`> [!NOTE]` 等）の装飾
- Light / Dark 両テーマの配色

**例外として、次の 2 つは GitHub と見え方が違うことを受け入れる**（4.73.0。利用者の判断）。どちらも編集モードで付けた修飾（[FR-146](02-functional.md), [FR-147](02-functional.md)）に関わるものであり、読み手が文書の構造を取り違えることはない。

- **文字色**（FR-147）。GitHub はサニタイズで `style` 属性を取り除くため、色は付かず文字だけが残る。
- **`www.` で始まる裸の URL（[MD-070](04-markdown.md)）を取り消し線や文字色で囲んだもの。** MarkView ではリンクのままだが、GitHub ではリンクにならず文字になる（`https://` で始まるもの・`<https://…>`・`[文字](URL)` はリンクのまま）。

## 1.4 代表的なユースケース

### UC-01: 配布物として Markdown と一緒に渡す

1. 配布者は、`MarkView.exe` と `README.md`、`docs/` ディレクトリを同じ ZIP にまとめて渡す。
2. 受領者は ZIP を展開し、`MarkView.exe` をダブルクリックする。
3. MarkView は同じフォルダにある `README.md` を自動的に表示し、そのフォルダをツリールートとする（[FR-013](02-functional.md)）。
4. 受領者は README 内のリンクをたどって `docs/` 以下の文書を読み進める（[FR-050](02-functional.md)）。

### UC-02: 単一の Markdown ファイルを開く

1. 利用者は MarkView を起動し、ツールバーのファイルボタンから `.md` を選択する。あるいは、ウィンドウに `.md` ファイルをドラッグ＆ドロップする。
2. 文書が表示され、そのファイルが属するディレクトリがツリールートになる（[FR-030](02-functional.md)）。

### UC-03: 執筆中の文書をプレビューする

1. 利用者は外部エディタで Markdown を編集しながら、MarkView で同じファイルを開いておく。ツールバーの「エディタで開く」から、表示中のファイルをそのままエディタへ渡せる（[FR-090](02-functional.md)）。
2. エディタで保存すると、MarkView が変更を検知して自動的に再描画し、スクロール位置を維持する（[FR-014](02-functional.md)）。

### UC-04: 閉域環境で図表付きの文書を読む

1. インターネットに接続されていない環境で MarkView を起動する。
2. Mermaid 図・PlantUML 図・数式・コードハイライトを含む文書が、外部通信なしで完全に表示される（[AR-020](05-architecture.md)）。

### UC-05: リンクをたどって文書間を移動する

1. 利用者は目次となる `README.md` を開き、本文中の `[設計](./docs/design.md)` をクリックする。
2. **同じウィンドウ**でリンク先の文書が開く（[FR-050](02-functional.md)）。ファイルツリーの起点は変わらない。
3. 読み終えたら、ツールバーの戻るボタン、`Alt+←`、またはマウスの戻るボタンで直前の文書へ戻る。戻った位置は、リンクをクリックした時点のスクロール位置となる（[FR-051](02-functional.md)）。

### UC-06: チェックリストを消し込む

1. 利用者は、タスクリストを含む作業手順書を MarkView で開く。
2. ツールバーの編集モードボタン、または `Ctrl+Shift+M` で編集モードに入る（[FR-140](02-functional.md)）。
3. 終えた作業のチェックボックスをクリックすると、その場でファイルへ書き込まれる（[FR-141](02-functional.md)）。表の誤記は、セルをダブルクリックして直す（[FR-142](02-functional.md)）。
4. 間違えたら `Ctrl+Z` で戻す（[FR-144](02-functional.md)）。別の文書を開くと、編集モードは自動的に終わる。

### UC-07: 大きな図の細部を読む

1. 利用者は、本文幅へ縮小されて文字が読めない構成図（Mermaid / PlantUML）を含む文書を開く。
2. 図の右上のボタンで原寸表示に切り替え、図の中を横にスクロールして読む（[FR-121](02-functional.md)）。あるいは拡大画面を開き、全体を見てから必要な箇所を拡大する（[FR-122](02-functional.md)）。
3. `Esc` で拡大画面を閉じると、開く前の本文の位置に戻る。

### UC-08: 図をファイルで書きながら確かめる

1. 利用者は、PlantUML の図（`.puml`）や Mermaid の図（`.mmd`）を外部エディタで書きながら、同じファイルを MarkView で開いておく（[FR-025](02-functional.md), [FR-026](02-functional.md)）。ファイルツリーには図のファイルも並ぶ（[FR-037](02-functional.md)）。
2. エディタで保存するたびに、MarkView が図を描き直す（[FR-014](02-functional.md)）。PlantUML のファイルに図が複数あれば、図ごとに見出しを付けて並べ、アウトラインから移れる。
3. 細かな直しは、編集モードで図をダブルクリックし、その場の編集欄で直す（[FR-145](02-functional.md)）。

### UC-09: 手順書に手を入れる

1. 利用者は、作業手順書を MarkView で開き、編集モードに入る（[FR-140](02-functional.md)）。
2. 手順のコマンドの誤りは、コードブロックをダブルクリックして、その場の編集欄で直す（[FR-145](02-functional.md)）。
3. もう使わない手順は、文字を選んで取り消し線を引き（[FR-146](02-functional.md)）、注意してほしい箇所は文字色で示す（[FR-147](02-functional.md)）。どちらも、ツールバーの修飾のボタン・右クリックメニュー・ショートカット（取り消し線だけ）で行う。
4. 書き込まれたファイルは、GitHub でも取り消し線のまま読める（文字色は GitHub では付かない。1.3.3）。

## 1.5 スコープ

### 1.5.1 本バージョンに含めるもの

- Markdown ファイルの表示（GitHub 準拠、Mermaid、PlantUML、数式、画像、シンタックスハイライト）
- **PlantUML ファイル・Mermaid ファイル・画像ファイルの単体での表示**（図のファイルは編集モードで書き換えられる。画像ファイルは表示だけ）
- ファイルを開く操作（ダイアログ、ドラッグ＆ドロップ、コマンドライン引数）
- ファイル更新の自動検知と再描画
- アウトラインペイン（表示・非表示の切り替え、スクロール連動）
- ファイルツリーペイン（表示・非表示の切り替え、遅延展開、**表示する種類の絞り込み（フィルター）と、右クリックメニュー（エディタやファイルマネージャで開く・パスのコピー・ツリールートの変更）**）
- 文書内リンクによる文書間の移動（同一ウィンドウ）と、戻る・進む（ツールバーのボタン・`Alt+←` / `Alt+→`・マウスのサイドボタン）による履歴移動
- コードブロックのクリップボードコピー
- Light / Dark テーマの切り替え
- 表示中のファイルを外部エディタで開く操作（自由な編集はエディタで行う）
- **編集モードでの限定的な書き換え**（タスクリストのチェックボックス、表のセルの文字、**コードブロックと図の中身、選んだ文字の取り消し線と文字色**。取り消し・やり直しを含む）
- **表の表示上の並べ替え**（ファイルは書き換えない）
- **Mermaid 図・PlantUML 図・画像の原寸表示と拡大画面**
- **右クリックメニュー**（コピー・全選択・リンク先のコピー・入力欄の切り取りと貼り付け・編集モードの修飾・ファイルツリーの操作）
- 文書内検索、表示倍率の変更、キーボードショートカット
- アイコン中心のツールバー（群ごとの区切り付き）と、英日併記のツールチップ
- アプリケーション固有のアイコン（実行ファイル・ウィンドウ・情報ダイアログ）
- アプリケーション情報ウィンドウ（OSS ライセンス表示を含む）
- Windows / Linux 向けのバイナリ配布と、タグ起点の自動リリース

### 1.5.2 スコープ外

以下は本バージョンでは実装しない。将来の拡張候補として記録する。

| 項目 | 除外理由 |
| --- | --- |
| Markdown の自由な編集・保存（アプリ内） | ビューアとしての単純さと軽さを優先するため。**文書のブロックの数と種類を変えない 4 種類の書き換えだけを編集モードで持ち**（[FR-140](02-functional.md)）、**それ以外は利用者が選んだ外部エディタへ渡す**（[FR-090](02-functional.md)） |
| 太字・斜体の付け外し、GitHub Alerts で包む・外す操作、選択すると浮かぶ小さなツールバー、すべての修飾を外す操作（`Clear formatting`） | 選んだ文字の修飾は取り消し線と文字色の 2 つに絞った（[FR-146](02-functional.md), [FR-147](02-functional.md)。4.73.0。利用者の判断。「実現性が高く、文書の構造が壊れない」ことを優先した）。太字・斜体を記号で書くには記号の効き方の規則と記法の組み立て直しが要り、Alerts で包む操作は文書のブロックの構造を変える |
| コードブロックの言語指定の変更、字下げ形式のコードブロックと数式ブロックの書き換え | 書き換えるのは、フェンス付きのコードブロックと図の中身に限る（[FR-145](02-functional.md)） |
| 表の行・列の追加と削除、並べ替えた順序の保存 | 表の構造を変える編集であり、編集モードの範囲（[FR-140](02-functional.md)）を超えるため。並べ替えは表示だけとする（[FR-130](02-functional.md)） |
| PDF・HTML エクスポート、印刷 | 出力レイアウト調整の実装コストが「軽さ」の目標に見合わないため |
| タブによる複数文書の同時表示 | メモリ使用量が文書数に比例して増加するため。文書間の移動はリンクと履歴で代替する |
| 全文検索（ディレクトリ横断） | インデックス保持がメモリ目標と衝突するため。検索は表示中の文書内に限定する |
| プラグイン機構・ユーザ定義 CSS | 「1 実行ファイルで完結」と矛盾し、検証パターンが増大するため |
| 最近開いたファイルの履歴 | 閲覧したファイルパスを保存しない方針のため（[NFR-042](07-nonfunctional.md)） |
| macOS 対応 | 要求ターゲット外。技術構成上は将来対応可能（[AR-090](05-architecture.md)） |
| 自動更新機能 | 常駐・外部通信を行わない方針のため |
| UI の多言語化・ロケール切り替え | ツールバーをアイコン中心に構成し、ツールチップの英日併記で理解を担保するため。言語リソース機構は持たない（[UI-024](03-ui.md)） |
| 画像ビューアとしての機能（回転・編集・前後の画像への移動・スライドショー・画像の情報の表示等） | **画像ファイルは、文書と同じく 1 枚ずつ本文ペインに表示する**（[FR-027](02-functional.md)。4.73.0）が、**画像のための新しい操作は持たない**（ステータス領域の寸法と大きさの表示は除く）。 大きく見るのは、図と同じ原寸表示と拡大画面（[FR-121](02-functional.md), [FR-122](02-functional.md)）だけとする。どちらもメインウィンドウ内の描画であり、採用する Wails v2 が 2 つ目のウィンドウを持てない制約とも整合する。**4.72.0 までは、画像ファイルへのリンクを OS の既定ビューアに委ねていた**（[FR-053](02-functional.md)） |
| ファイルツリーに Markdown・図・画像以外のファイル（ソースコード・設定ファイル等）を並べること | ファイルツリーは MarkView で開けるものを選ぶための道具であり、開けないファイルを並べても選べないため（[FR-031](02-functional.md), [FR-037](02-functional.md)） |
| PlantUML の取り込み用の断片（`.iuml`）の表示 | 単体では図にならないため（[FR-025](02-functional.md)） |
| `.md` のファイル関連付け | インストーラを持たず、システムに痕跡を残さない方針のため（[BR-071](06-build-release.md)） |

## 1.7 用語定義

| 用語 | 定義 |
| --- | --- |
| **文書** | MarkView が現在表示している 1 つのファイル。Markdown ファイルのほか、図のファイルと画像ファイル（FR-025〜FR-027）を含む |
| **図のファイル** | PlantUML の図を書いたファイル（`.puml` / `.pu` / `.wsd` / `.plantuml`。FR-025）と、Mermaid の図を書いたファイル（`.mmd` / `.mermaid`。FR-026）の総称 |
| **画像ファイル** | 本文ペインに単体で表示する画像のファイル（FR-027）。拡張子は埋め込み画像と同じ 9 つ（FR-022） |
| **開けるファイル** | MarkView が文書として表示できるファイル。**Markdown ファイル（`.md` / `.markdown` / `.mdown` / `.mkd`）・図のファイル（`.puml` / `.pu` / `.wsd` / `.plantuml` / `.mmd` / `.mermaid`）・画像ファイル（`.png` / `.jpg` / `.jpeg` / `.gif` / `.svg` / `.webp` / `.avif` / `.bmp` / `.ico`）の 3 種類**をいう。**拡張子の一覧の正はここに置き**、他の節はこれと同じものを挙げる。ファイル選択ダイアログ・ドロップ・起動引数・リンク・表示履歴のどれで開いても同じに扱い、**ツリーのフィルター（FR-037）に関わらず開く**（ファイルツリーから開けるのは、ツリーに出しているものだけ。FR-036） |
| **文字のファイル** | 開けるファイルのうち、Markdown ファイルと図のファイル。外部エディタで開けて（FR-090）、編集モードを使える（FR-140）のは文字のファイルだけである |
| **ツリールート** | ファイルツリーペインが表示するディレクトリ階層の最上位ディレクトリ |
| **アウトライン** | 表示中の文書の見出し（`#`〜`######`。PlantUML ファイルでは図ごとの見出し。MD-086）から構成される階層目次 |
| **本文ペイン** | 描画済みの文書（Markdown・図のファイル・画像ファイル）を表示するウィンドウ中央〜右側の領域 |
| **サイドペイン** | ファイルツリーペインおよびアウトラインペインの総称 |
| **GFM** | GitHub Flavored Markdown。GitHub が定義する Markdown 方言 |
| **WebView** | OS が提供する HTML 描画コンポーネント（Windows: WebView2、Linux: WebKitGTK） |
| **描画資産** | 描画に用いる CSS・JavaScript・フォント等の静的ファイル群 |
| **編集モード** | 表示中の文字のファイル（Markdown・図のファイル）への限定的な書き込みを許す状態（FR-140）。起動時は常に編集モードでない |
| **原寸表示** | 図・画像を本文幅へ縮小せず、本来の大きさで本文中に描く表示（FR-121） |
| **拡大画面** | 図・画像 1 つだけを、ステータス領域を除くメインウィンドウいっぱいに表示し、拡大・縮小・移動できる画面（FR-122, UI-104）。独立した OS ウィンドウではない |
| **編集欄** | 編集モードで、表のセル（FR-142）やコードブロック・図（FR-145）を書き換えるために、その要素の位置に開く入力欄。`Save` と `Cancel` のボタンを持ち、同時に 1 つだけ開く |
| **ツリーのフィルター** | ファイルツリーに並べるファイルの種類（Markdown・図・画像）を選ぶ機能（FR-037）。Markdown は常に並べる |
| **ファイルマネージャ** | OS の既定のファイル管理のアプリケーション（Windows のエクスプローラーなど）。ファイルツリーの右クリックメニューから、ディレクトリを開く先である（FR-036） |
| **文書の切り替え** | **表示するファイルが別のファイルに変わること。** 開く操作（FR-010 / FR-011 / FR-033 / FR-036 の `Open`）・リンクによる遷移（FR-050。画像ファイルへのリンクの FR-053 を含む）・履歴の移動（FR-051）で起きる。**同じファイルを開き直すこと、同じ文書の中のアンカーへ移ること、同じ文書の再描画（FR-014 / FR-015）は含まない。** 編集モード（FR-140）・並べ替え（FR-130）・原寸表示（FR-121）・拡大画面（FR-122）は、この語で状態を解除する契機を定める |
| **同じファイル** | **シンボリックリンクを解決した実体のパスが、パスの比較規則（Windows では大文字小文字を区別しない。IMP-025）で一致すること。** 表記の違うパスやリンク経由のパスでも、実体が同じなら同じファイルとする |
| **同じ文書の再描画** | 同じファイルを読み直して描き直すこと。ファイル更新の自動検知（FR-014）・手動の再読み込み（FR-015）・**同じファイルの開き直し**（ファイル選択ダイアログ・ツリー・ドロップから同じファイルを開いた場合）を含む。**編集モードの書き込みの直後の読み直し（FR-143。FR-014 の再描画の処理を直接呼ぶ）も含む。** 状態の引き継ぎ（FR-121 / FR-122 / FR-130 / FR-140 / FR-144）と大きなファイルの同意（FR-016）では、これらを同じに扱う。**ただし FR-130 だけは、書き込みの直後の読み直しを区別する**（並べ直さない） |
