### DSP-113: アウトライン **MUST**

UI-040 を実装する。

```
┌────────────────────────┐
│ OUTLINE                │
├────────────────────────┤
│ MarkView               │ ← h1: 13px
│   Overview             │ ← h2: 13px, 12px インデント
│     Purpose            │ ← h3: 12px, 24px インデント
│     Scope              │
│   Usage                │ ← 現在位置: 強調
└────────────────────────┘
```

| 項目 | 値 |
| --- | --- |
| 行の高さ | 24px |
| インデント | 1 レベルあたり 12px（UI-040） |
| 文字サイズ | h1〜h3: 13px、h4 以降: 12px |
| 通常の文字 | `--fg-muted` |
| ホバー | 文字 `--fg-default`、背景 `--neutral-muted` |
| 現在位置（FR-042） | 文字 `--accent-fg`、左端に 2px の `--accent-fg`、背景 `--accent-subtle` |
| 長い見出し | 1 行で省略（`text-overflow: ellipsis`）。全文はツールチップ |
| 見出しなし | `No headings` を `--fg-subtle`、12px、中央寄せで表示 |

アウトラインは横スクロールさせず省略表示とする。ファイルツリー（横スクロール・省略なし）と扱いが逆なのは、ファイル名は完全一致で識別する必要があるのに対し、見出しは先頭部分で判別できるためである。

### DSP-121: 本文要素 **MUST**

MD-020〜MD-026 を実装する。値は `github-markdown-css` に従う（DSP-001）。代表値を以下に示す。

| 要素 | 主な指定 |
| --- | --- |
| 段落 | 下マージン 16px |

| 引用 | 左に 4px の `--border-default`、左パディング 16px、文字 `--fg-muted`。**本文と同じ左端から始める**（ブラウザ既定の左右マージン 40px を打ち消す） |
| 水平線 | 高さ 0.25em（倍率 100 % で 4px。`--border-default`）、上下マージン 24px。**脚注の区切りだけは 1px** |
| インラインコード | 背景 `--neutral-muted`、角丸 6px、パディング 0.2em 0.4em、サイズ 85 % |
| リンク | 色 `--accent-fg`、**常に下線**（`text-underline-offset: 0.2em`）。色だけで区別しない |
| 脚注 | 文書末尾に区切り線を挟んで一覧表示、12px。参照は `[1]` の形（括弧は CSS で付ける）、戻りリンクは `↩` |
| 生 HTML のインライン要素（MD-072） | `mark` は背景 `--attention-subtle`・文字 `--fg-default`（**ブラウザ既定の純黄色を使わない**）。`small` は 90 %。`abbr[title]` は点線の下線。`kbd` は等幅 11px 相当、地 `--canvas-subtle`、枠と内側の影 `--border-muted`、角丸 6px |

### DSP-122: 表 **MUST**

MD-024 を実装する。

| 項目 | 値 |
| --- | --- |
| 枠線 | セルごとに `1px solid var(--border-default)` |
| ヘッダ行 | 太字、背景 `--canvas-subtle` |
| 偶数行 | 背景 `--canvas-subtle` |
| セルのパディング | 6px 13px |
| 幅が溢れる場合 | **表の内部だけを横スクロール**させる（UI-050）。`table` 自身に `display: block` と `width: max-content` を与えて実現し、ラッパ要素を足さない。本文の DOM を変えないため、見出しアンカーの位置も検索の走査対象も変わらない |

### DSP-123: 画像 **MUST**

FR-022 を実装する。

| 項目 | 値 |
| --- | --- |
| 最大幅 | 100 %（本文幅）。縦横比を維持して縮小 |
| 背景 | `--canvas-default`（透過 PNG の視認性のため） |
| 読み込み失敗時 | 破線 1px の枠（`--border-default`）内に alt テキストを `--fg-muted` で表示。高さは内容に応じる |

読み込みに失敗した画像は、**`<img>` を `<span class="img-broken">` へ置き換えて描く**（IMP-226）。**代替テキストは自前で描く。**

| 項目 | 値 |
| --- | --- |
| フック | **`span.img-broken`** |
| 中身 | `alt` の文字列。**`textContent` で入れる**（IMP-220） |
| `display` | `inline-block`（枠を成立させるため） |
| 枠 | `1px dashed var(--border-default)` |
| 文字色 | `--fg-muted` |
| 余白 | `padding: 8px 12px` |
| 背景 | なし（`transparent`）。成功時の地は失敗時には意味がない |

> [!IMPORTANT]
> **代替テキストの描画をブラウザ既定に委ねてはならない**（NFR-061）。
>
> **既定の描画はエンジンごとに違う。** Blink（WebView2）は `alt` の文字列をインラインで流し込むが、
> **WebKitGTK は自前の壊れ画像アイコンを描き、`alt` を描かない**
> （[BUG-008](../bugs/2026-09-06-bug-008-broken-image-alt-webkitgtk.md)）。
> **`FR-022`（MUST）は「代替テキストと破損を示すプレースホルダを表示する」と定めており、枠だけでは満たさない。**
>
> **4.32.0 より前はフックが `img.is-broken` であった。** 枠は両エンジンで出ていたため、
> **「枠が出ているか」だけを見ると気づけない。** 見るのは**枠の中身**である。

> [!NOTE]
> **CSS だけでは実装できない。** 読み込みに失敗した `img` を選ぶセレクタが**どちらのエンジンにも存在しない**ため、置き換えに JavaScript が要る（IMP-226）。表示仕様がクラス名を名指ししているのはこのためで、`.img-broken` は 12 章と 21 章の接続点である。
>
> **`::after { content: attr(alt) }` で描く案は採らない。** `<img>` は置換要素であり、擬似要素が描かれるかどうかがエンジンと状態に依存する。**エンジン既定に委ねるのと同じ誤りを、別の場所で繰り返すことになる。**

### DSP-272: PlantUML 図 **MUST**

MD-083 を実装する。DSP-270（Mermaid 図）と同じ枠に収め、**値の違うところだけ**を定める。

| 項目 | 値 |
| --- | --- |
| 配置 | 本文幅の中央 |
| 最大幅 | 100 %。超える場合は縦横比を保って縮小 |
| 背景 | `--canvas-default` |
| 上下マージン | 16px |
| テーマ | Light: `{ dark: false }` / Dark: `{ dark: true }`（IMP-233） |
| 描画前 | 元のソースをコードブロックとして表示しておき、描画完了時に置き換える。空白領域を出さない |
| **構文エラー時** | **PlantUML が返したエラー図をそのまま図として表示する**（FR-024）。こちらでエラー文言を組み立てない |
| **描画しないとき** | コードブロック表示のまま、上部に理由を `--danger-fg`、12px で併記（DSP-270 と同じ）。理由は 3 種（下表） |
| コピーボタン | 描画後も表示し、対象は元の PlantUML ソース（FR-060, IMP-119） |

> [!IMPORTANT]
> **「エラー図をそのまま出す」と「理由を併記する」は別の状態である。** 前者は PlantUML 自身が行番号付きで描いた**図が出ている**状態、後者は MarkView が描画をやめて**図が出ていない**状態である。見た目を混ぜない。
>
> Mermaid（DSP-270）は構文エラーでも後者の形になる。**同じ「構文エラー」で見た目が違うのは、処理系の返し方が違うからである**（FR-024）。

理由は次の 3 種とする。文言は `strings.js`（IMP-290）に持つ。

| 理由 | 起きる場面 | 文言のキー |
| --- | --- | --- |
| 取り込み指令を含む | Go 側が `data-puml-error="include"` を付けた（IMP-119） | `pumlInclude` |
| 処理系が図を返さなかった | 4096 px 超え、未対応の図種別（`ditaa` 等。MD-083） | `pumlUnsupported` |
| 描画が完了しなかった | 資産の読み込み失敗、タイムアウト（IMP-233） | `pumlFailed` |

> [!IMPORTANT]
> **判定は「SVG が得られたか」だけで行う。** 図種別ごとの判定をフロントエンドに持たない（IMP-233）。
>
> このため、**処理系がエラー図（SVG）を返す種別は「図が出ている」側に入る。** `salt` のように版によってエラー図を返したり例外テキストを返したりするものは、どちらの見え方にもなりうる。**どちらであっても空白にならず、他の図の描画を止めない**ことが要件である。

### DSP-151: 一時メッセージ **MUST**

FR-090 / FR-110 を実装する。

| 種別 | 背景 | 文字 | 表示時間 |
| --- | --- | --- | --- |
| 情報 | `--accent-subtle` | `--accent-fg` | 5 秒 |
| 警告 | `--attention-subtle` | `--attention-fg` | 5 秒 |
| エラー | `--danger-subtle` | `--danger-fg` | 5 秒 |

- ステータス領域の全幅を一時的に占有し、5 秒後に元の表示へ戻る（UI-060）。
- 表示中に新しいメッセージが来た場合、置き換えてタイマをリセットする。積み上げない。
- 溢れる場合は末尾を省略し、全文はツールチップで示す。

## 21.8 検索バー（DSP-160 系）

### DSP-160: 外観 **MUST**

UI-080 を実装する。

```
                          ┌──────────────────────────────────┐
                          │ 🔍 goroutine        3 / 12  ∧ ∨ ✕│
                          └──────────────────────────────────┘
                            本文ペインの右上、上 16px / 右 16px
```

| 項目 | 値 |
| --- | --- |
| 位置 | 本文ペインの右上。本文を押し下げない（UI-080）。**本文のスクロールに追従せず、常に右上に留まる**（下記） |
| オフセット | 上 16px / 右 16px（スクロールバーの内側） |
| 背景 | `--canvas-overlay`、枠 `1px solid var(--border-default)`、角丸 6px、影 `--shadow-overlay` |
| 高さ / パディング | 32px / 0 8px |
| 入力欄 | 幅 200px、背景 `--canvas-inset`、枠なし、13px |
| プレースホルダ | `Find in document`、`--fg-subtle` |
| ヒット数 | 12px、`--fg-muted`。`3 / 12` 形式 |
| ヒットなし | `No results` を `--danger-fg` で表示 |
| ボタン | 前へ / 次へ / 閉じる。24 × 24px、アイコン 16px |
| 重なり順 | `z-index: 20`（DSP-015） |

> [!IMPORTANT]
> **本文をスクロールしても、検索バーは本文ペインの右上に留まる。** `Ctrl+F` から `Esc` までの間、
> 常に見えていなければならない。UI-080 の「オーバーレイ表示」「本文ペインの右上」はこれを含意する。
>
> **`position: absolute` で実現する場合、包含ブロックがスクロールする器であってはならない。**
> 絶対配置の要素は `fixed` や `sticky` と違い、**スクロールする内容の一部として一緒に流れる。**
> 本文ペイン（`overflow-y: auto`）の中に置くと、下へスクロールしたとき画面外へ出る。
> 配置の詳細は IMP-202 が定める。
>
> **これを外すと 2 つ壊れる。** 移動のたびにボタンが画面外へ出て押せなくなり、さらに
> 入力欄へフォーカスを戻す処理がスクロールを巻き戻して、**FR-080 の「移動時は該当箇所まで
> スクロールする」を打ち消す。** 実際に起きた（[調査報告](../bugs/2026-09-03-search-jump-buttons.md)）。

### DSP-161: ヒットの強調 **MUST**

| 対象 | 背景 | 文字 |
| --- | --- | --- |
| ヒット（通常） | `--search-hit` | `--fg-default` |
| ヒット（現在位置） | `--search-hit-current` | `--fg-default` |

現在位置のヒットには 1px の `--attention-fg` の枠を付け、色覚に依存せず判別できるようにする。
