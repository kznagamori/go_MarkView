# 04. Markdown 描画仕様

> 索引: [README](README.md) | 前: [03. 画面・操作仕様](03-ui.md) | 次: [05. アーキテクチャ](05-architecture.md)

本文書は、MarkView が解釈する Markdown の文法と、その描画結果に関する要求を定義する。

## 4.1 基準（MD-001）

### MD-001: 準拠する仕様 **MUST**

- 文法解釈は **GitHub Flavored Markdown (GFM) Spec** に準拠する。GFM が規定しない拡張については本文書で個別に定義する。
- 描画結果の見た目は、同一の Markdown を GitHub の README / ファイルビューで表示したときに準拠する。
- 「準拠」とは、フォント・余白・配色・装飾が GitHub と同じ意図で解釈できることを指し、ピクセル単位での一致は求めない。

### MD-002: 判定基準 **MUST**

準拠の確認は、リポジトリに用意する検証用 Markdown（すべての対応記法を網羅したもの）を GitHub 上の表示と MarkView の表示で比較して行う（BR-053）。

## 4.2 タイポグラフィと基本レイアウト（MD-010）

### MD-010: フォント **MUST**

本文の書体は GitHub と同等のシステムフォントスタックを使用する。フォントファイルを埋め込まず、OS のフォントを利用する（ファイルサイズ削減のため）。

| 用途 | フォントスタック |
| --- | --- |
| 本文 | `-apple-system, BlinkMacSystemFont, "Segoe UI", "Noto Sans", Helvetica, Arial, sans-serif` に加え、日本語向けに `"Yu Gothic UI", "Meiryo", "Noto Sans CJK JP", sans-serif` をフォールバックとして続ける |
| コード | `ui-monospace, SFMono-Regular, "SF Mono", Menlo, Consolas, "Liberation Mono", "Noto Sans Mono", monospace` |

- 絵文字の描画は OS のカラー絵文字フォント（Windows: Segoe UI Emoji、Linux: Noto Color Emoji）に委ねる。絵文字フォントは埋め込まない。
- Ubuntu 環境で日本語フォントが未導入の場合の豆腐表示は、OS 側の問題として扱い、アプリケーションでは対処しない。

### MD-011: 基本メトリクス **MUST**

| 項目 | 値 |
| --- | --- |
| 本文の文字サイズ | 16 px（表示倍率 100 % のとき） |
| 行の高さ | 1.6 |
| 段落間の余白 | 16 px |
| 本文の最大幅 | 980 px（UI-050） |

## 4.3 ブロック要素（MD-020）

### MD-020: 見出し **MUST**

- `#` から `######` の 6 段階を `<h1>`〜`<h6>` として描画する。
- `<h1>` と `<h2>` の下端に境界線を引く（GitHub と同じ）。
- 各見出しに一意な ID（アンカー）を付与する（MD-021）。
- 見出しにマウスを乗せたとき、見出し左側にアンカーリンクのアイコンを表示する（**SHOULD**）。クリックで当該見出しへのリンクとして機能する。
- Setext 形式（`===` / `---` による下線）の見出しも `<h1>` / `<h2>` として解釈する。

### MD-021: 見出しアンカーの生成規則 **MUST**

GitHub と互換のスラッグを生成する。手順は以下のとおり。

1. 見出しテキストからインライン記法を除去し、プレーンテキストにする。
2. 英大文字を小文字に変換する。
3. 空白文字をハイフン `-` に置換する。
4. 英数字、ハイフン、アンダースコア、および非 ASCII 文字（日本語等）以外の記号を除去する。
5. 同一文書内で重複した場合、2 つ目以降に `-1`, `-2` … を付加する。

この規則により、GitHub 上の README に書かれた `#見出し` 形式のリンクが MarkView でも同じように動作する。

### MD-022: リスト **MUST**

- 順序なしリスト（`-`, `*`, `+`）、順序付きリスト（`1.` 等）、およびそれらの入れ子を描画する。
- タスクリスト（`- [ ]` / `- [x]`）をチェックボックスとして描画する。チェックボックスは**読み取り専用**とし、クリックしても状態は変化しない（ビューアであり、ファイルを書き換えないため）。
- リストのマーカー、インデント幅、項目間の余白は GitHub に準拠する。

### MD-023: 引用 **MUST**

`>` による引用を、左側の縦線と淡色の文字で描画する。入れ子の引用にも対応する。GitHub Alerts の形式（MD-040）に該当する場合はそちらを優先する。

### MD-024: 表 **MUST**

- GFM のパイプ記法による表を描画する。
- 列の左寄せ・中央寄せ・右寄せ指定（`:---`, `:---:`, `---:`）に対応する。
- ヘッダ行の強調、行ごとの背景色の交互表示、セルの罫線を GitHub に準拠して描画する。
- 表が本文幅を超える場合、**表自身の内部で横スクロール**させる。ページ全体には横スクロールを発生させない。

### MD-025: 水平線・段落・改行 **MUST**

- `---`, `***`, `___` を水平線として描画する。
- 行末の半角スペース 2 個、およびバックスラッシュによる強制改行に対応する。
- 段落中の単純な改行は、GFM と同じく空白として扱う（改行しない）。

### MD-026: 折りたたみ **MUST**

`<details>` / `<summary>` による折りたたみを、GitHub と同様に開閉可能な形で描画する（MD-072 のサニタイズを通過する要素として許可する）。

## 4.4 コードブロックとシンタックスハイライト（MD-030）

### MD-030: シンタックスハイライト **MUST**

- フェンス付きコードブロック（``` および `~~~`）の言語指定に従って、シンタックスハイライトを適用する。
- 配色は GitHub の Light / Dark テーマに準拠し、アプリのテーマに追従する。
- ハイライトは**サーバ側（Go）で行い、HTML として出力する**。ブラウザ用のハイライトライブラリを埋め込まない（NFR-011）。
- 言語指定がない場合、ハイライトを適用せず等幅フォントで表示する。言語の自動判定は行わない（誤判定と処理時間を避けるため）。
- 未知の言語名が指定された場合もエラーとせず、ハイライトなしで表示する。

### MD-031: 対応言語 **MUST**

少なくとも以下の言語で正しくハイライトされること。

Go, C, C++, C#, Java, Kotlin, Swift, Rust, Python, Ruby, PHP, JavaScript, TypeScript, JSX/TSX, HTML, CSS, SCSS, SQL, Shell / Bash, PowerShell, Batch, Dockerfile, Makefile, YAML, TOML, JSON, XML, INI, Diff / Patch, Markdown, Lua, Perl, R, Scala, Haskell, Elixir, Zig, Terraform (HCL), Protobuf, GraphQL, Vim script, AWK

言語名のエイリアス（`sh` / `bash` / `zsh`、`py` / `python`、`yml` / `yaml`、`ps1` / `powershell` 等）も解決すること。

### MD-032: コードブロックの体裁 **MUST**

- 背景色付きの矩形領域として描画し、角丸と内側余白を GitHub に準拠させる。
- コードが幅を超える場合、**コードブロック内部で横スクロール**させる。折り返しは行わない。
- 行番号は表示しない（GitHub の README 表示と同じ）。
- 右上にコピーボタンを配置する（FR-060）。

### MD-033: インラインコード **MUST**

`` `code` `` を、淡い背景色の付いた等幅テキストとして描画する。

## 4.5 GitHub Alerts（MD-040）

### MD-040: 対応する種別 **MUST**

引用ブロックの先頭行が以下の形式の場合、GitHub Alerts として専用の装飾で描画する。

| 記法 | 表示 | 配色 |
| --- | --- | --- |
| `> [!NOTE]` | Note | 青 |
| `> [!TIP]` | Tip | 緑 |
| `> [!IMPORTANT]` | Important | 紫 |
| `> [!WARNING]` | Warning | 黄 |
| `> [!CAUTION]` | Caution | 赤 |

- 種別に対応するアイコンとラベルを先頭に表示し、左側に種別色の縦線を引く。
- ラベルは GitHub と同じ英語表記（Note / Tip / Important / Warning / Caution）とする。
- 大文字小文字は区別しない（`[!note]` も有効とする）。
- 記法が種別名として認識できない場合（`> [!FOO]` 等）は、通常の引用として描画する。
- アイコンはインライン SVG とし、テーマに応じた色で表示する。

## 4.6 脚注・絵文字（MD-050）

### MD-050: 脚注 **MUST**

- `[^1]` 形式の脚注参照と `[^1]: 説明` 形式の脚注定義に対応する。
- 脚注は文書末尾に一覧として描画し、参照箇所と相互にリンクする。
- 参照番号は出現順に振り直す（GitHub と同じ）。

### MD-051: 絵文字ショートコード **MUST**

- `:sparkles:` のような GitHub 絵文字ショートコードを対応する絵文字に変換する。
- 対応するショートコードの集合は GitHub の絵文字一覧に準拠する。
- 未知のショートコードはそのままテキストとして表示する。
- 絵文字はテキストとして出力し、画像には置換しない（サイズ削減とコピー可能性のため）。

## 4.7 数式（MD-060）

### MD-060: 数式の記法 **MUST**

GitHub と同じ記法に対応する。

| 記法 | 種別 |
| --- | --- |
| `$...$` | インライン数式 |
| `$$...$$` | ブロック数式（中央揃えで独立行に表示） |
| ```` ```math ```` コードブロック | ブロック数式 |

- 描画は KaTeX により行い、外部通信なしで完結させる。
- 通貨表記（`$100 と $200`）を数式と誤認しないよう、GitHub と同じ判定規則（`$` の直後・直前の空白の扱い）に従う。
- 構文エラーの場合、該当箇所に元のソースとエラー内容を表示する。文書全体の描画は継続する。
- コードブロック・インラインコード内の `$` は数式として解釈しない。

### MD-061: 数式の遅延読み込み **MUST**

数式記法を含まない文書では、KaTeX の JavaScript・CSS を読み込まない（NFR-013）。判定は変換後の HTML に数式要素が含まれるかで行う。

## 4.8 リンク・画像・生 HTML（MD-070）

### MD-070: リンク **MUST**

- インラインリンク、参照リンク、自動リンク（URL の裸書き）に対応する。
- リンクのクリック時の挙動は FR-050 に従う。
- 外部リンクであることを示すアイコンを付加してもよい（**MAY**）。
- リンクには常に下線を引く（DSP-121）。色だけで区別すると色覚に依存する。

### MD-071: 画像 **MUST**

- ローカル画像・リモート画像（`http://` / `https://`）の両方を表示する（FR-022）。
- リモート画像の読み込みは、その画像を含む文書を表示したときにのみ発生する。
- リモート画像の読み込みに失敗した場合、alt テキストとプレースホルダを表示する。読み込みのタイムアウトは 10 秒とし、それを超えた場合は失敗として扱う。
- 画像リンク（`[![alt](image.png)](target.md)` のように画像をリンクで囲む記法）に対応する。クリック時の動作はリンク先に対する FR-050 の規則に従う。
- 埋め込まれた画像そのものをクリックしても何も起こらない。画像を単独で開くのは、画像を**リンク先**として指定した場合のみであり、その場合は OS の既定画像ビューアに委ねる（FR-053）。

> [!NOTE]
> リモート画像を表示する仕様上、外部ホストへの画像リクエストが発生する。これは MarkView が行う唯一の外部通信であり、文書に `http(s)` 画像が含まれる場合に限られる。アプリケーション自身がバージョン確認やテレメトリ等の通信を行うことはない（NFR-032, NFR-040）。

### MD-072: 生 HTML の扱い **MUST**

Markdown 中に直接記述された HTML は、**サニタイズしたうえで描画する**。

許可する要素（GitHub の許可リストに準拠）:

`a`, `b`, `i`, `strong`, `em`, `u`, `s`, `del`, `ins`, `mark`, `small`, `sub`, `sup`, `br`, `hr`, `p`, `div`, `span`, `blockquote`, `pre`, `code`, `kbd`, `samp`, `var`, `h1`〜`h6`, `ul`, `ol`, `li`, `dl`, `dt`, `dd`, `table`, `thead`, `tbody`, `tfoot`, `tr`, `th`, `td`, `caption`, `colgroup`, `col`, `img`, `picture`, `source`, `details`, `summary`, `figure`, `figcaption`, `abbr`, `cite`, `q`, `time`, `ruby`, `rt`, `rp`

除去する対象:

- `script`, `style`, `iframe`, `object`, `embed`, `form`, `input`, `button`, `link`, `meta`, `base`, `svg`（インライン SVG）, `math`
- すべてのイベントハンドラ属性（`onclick`, `onerror`, `onload` 等、`on` で始まる属性）
- `javascript:`, `vbscript:`, `data:`（`data:image/gif` `jpeg` `png` `webp` を除く）で始まる URL。**`data:image/svg+xml` は除去する。** 上の一覧が `svg` 要素を除去対象としており、data URI 経由で SVG を持ち込めるのは同じ規定の抜け道になるため
- `style` 属性（**MAY**: 色・配置に限定して許可してもよいが、既定では除去する）

除去した要素・属性は黙って取り除き、エラーとしない。

> [!NOTE]
> 上の許可要素の一覧に `input` は含まれないが、**タスクリスト（MD-022）の描画には必要**である。実装では `type="checkbox"` と `checked` / `disabled` に限って許可する（IMP-116）。読み取り専用であり、スクリプトを伴わない。`type` を持たない `input` や `type="text"` は通さない。

> [!IMPORTANT]
> サニタイズは、任意の第三者から受け取った Markdown を開くという利用形態を前提とした必須の安全対策である（NFR-030）。許可リストは実装時にハードコードし、設定で緩められないようにする。

### MD-073: Front Matter **MUST**

- 文書先頭の `---` で囲まれた YAML ブロック、および `+++` で囲まれた TOML ブロックを Front Matter として認識し、**本文として描画しない**。
- Front Matter は文書の 1 行目から始まる場合のみ認識する。
- Front Matter の内容を表形式で表示する機能は提供しない（既定で非表示）。
- `title` キーが存在してもウィンドウタイトルには使用しない。タイトルは常にファイル名とする（UI-013）。

## 4.9 Mermaid（MD-080）

### MD-080: 描画対象 **MUST**

- 言語指定が `mermaid` のフェンス付きコードブロックを Mermaid 図として描画する。
- 対応する図種別は、埋め込んだ Mermaid のバージョンがサポートするすべてとする（フローチャート、シーケンス図、クラス図、状態遷移図、ER 図、ガント、円グラフ、Git グラフ等）。埋め込まれるバージョンはリリースごとに更新されうるため（BR-043）、特定バージョン固有の記法に依存した実装を行わない。実際に同梱された版はアプリケーション情報ウィンドウで確認できる（UI-100）。
- 図は本文幅に収まるよう縮小し、縦横比を維持する。
- 図の背景はテーマに追従させ、Light テーマでは明色、Dark テーマでは暗色の Mermaid テーマを適用する。

### MD-081: セキュリティ設定 **MUST**

Mermaid の `securityLevel` は `strict` 相当に設定し、図の定義から任意のスクリプトやクリックハンドラが実行されないようにする。`click` によるリンクジャンプは無効とする。

### MD-082: 遅延読み込み **MUST**

`mermaid` コードブロックを含まない文書では、Mermaid の JavaScript を読み込まない（NFR-013）。
