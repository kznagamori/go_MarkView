# 02. 機能要求

本文書は MarkView の機能要求を定義する。画面上の配置・見た目は [03. 画面・操作仕様](03-ui.md)、Markdown の解釈規則は [04. Markdown 描画仕様](04-markdown.md) を参照。

## 2.1 ファイルを開く（FR-010 系）

### FR-010: ファイル選択ダイアログからの表示 **MUST**

ツールバーのファイルボタン、またはショートカット `Ctrl+O` により、OS 標準のファイル選択ダイアログを開く。

- ダイアログのフィルタは次の 5 つとし、既定は `Supported files` とする（4.73.0。利用者の判断）。フィルタ名は英語とする（UI-024）。**拡張子の正は [1.7](01-overview.md) の「開けるファイル」の表とし、実装でも 1 か所の定義から組み立てる。**

| フィルタ | 対象 |
| --- | --- |
| `Supported files` | 開けるファイルの 3 種類すべて（下の 3 行の和） |
| `Markdown files` | `*.md`, `*.markdown`, `*.mdown`, `*.mkd` |
| `Diagrams` | `*.puml`, `*.pu`, `*.wsd`, `*.plantuml`, `*.mmd`, `*.mermaid`（FR-025, FR-026） |
| `Images` | `*.png`, `*.jpg`, `*.jpeg`, `*.gif`, `*.svg`, `*.webp`, `*.avif`, `*.bmp`, `*.ico`（FR-027） |
| `All files` | `*.*` |

- ファイルが選択されたら、その文書を本文ペインに表示する。開けるファイルでなければ（`All files` で選んだ場合）、表示もツリールートも変えずに、対応していない旨をステータス表示する（FR-110）。
- ファイルが選択されたら、そのファイルが存在するディレクトリを新しいツリールートとする（FR-030）。開けないファイルを選んだ場合は変えない。
- ダイアログの初期ディレクトリは、現在のツリールートとする。ツリールートが未確定の場合はカレントディレクトリとする。
- キャンセルされた場合、表示中の内容を変更しない。

### FR-011: ドラッグ＆ドロップによる表示 **MUST**

ウィンドウ上に OS からファイルまたはディレクトリがドロップされたとき、以下のとおり動作する。

| ドロップされた対象 | 動作 |
| --- | --- |
| 開けるファイル（[1.7](01-overview.md)。Markdown・図・画像）1 つ | その文書を表示し、親ディレクトリを新しいツリールートとする |
| ディレクトリ 1 つ | そのディレクトリを新しいツリールートとし、直下に README（FR-013 と同じ探し方）があれば表示する。**無ければ表示を変えず、通知もしない**（4.89.0。v1.0.0 から「開けないファイル」の旨を出していた） |
| 複数のファイル | 開けるファイルのうち 1 つのみを対象とし、他は無視する。OS から渡されたリストの先頭にある開けるファイルを採る |
| 開けないファイル | 何も変更せず、対応していない旨をステータス表示する（FR-110） |

- ドラッグ中はウィンドウ全体にドロップ可能であることを示す視覚的フィードバックを表示する（UI-070）。
- ドロップ対象領域はウィンドウ全体とし、本文ペイン・サイドペインのいずれにドロップしても同じ結果となる。

### FR-012: コマンドライン引数による起動 **MUST**

実行ファイルは第 1 引数にパスを受け取る。

```
MarkView [オプション] [パス]
```

| 引数 | 動作 |
| --- | --- |
| 開けるファイル（[1.7](01-overview.md)）のパス | その文書を表示し、親ディレクトリをツリールートとする |
| 開けないファイルのパス | 親ディレクトリをツリールートとし、対応していない旨を表示して起動する（起動自体は失敗させない） |
| ディレクトリのパス | そのディレクトリをツリールートとし、直下に README（FR-013 と同じ探し方）があれば表示する |
| 存在しないパス | エラーメッセージを表示して起動する（起動自体は失敗させない） |
| 引数なし | FR-013 に従う |

サポートするオプションは以下とする。

| オプション | 動作 |
| --- | --- |
| `--version` / `-v` | バージョン、コミットハッシュ、ビルド日時を標準出力に出力して終了（ウィンドウを開かない）。終了コード 0 |
| `--help` / `-h` | 使用方法を標準出力に出力して終了（ウィンドウを開かない）。終了コード 0 |
| 上記以外の `-` で始まる引数 | 使用方法を**標準エラー出力**へ出して終了する（ウィンドウを開かない）。終了コード 2 |

未知のオプションで起動を続行しない理由は、存在しないパスの場合（起動して案内を出す）と異なり、**オプションの指定誤りは利用者が気づくべき入力の誤り**だからである。黙って無視すると、意図した動作をしていないことに気づけない。

> [!NOTE]
> この経路は、Windows の「プログラムから開く」、Linux のファイルマネージャからの関連付け起動、およびシェルからの直接実行のすべてで共通に使われる。

### FR-013: 引数なし起動時の動作 **MUST**

引数なしで起動した場合、以下の順に探索し、最初に見つかったものを表示する。

| 順 | 探索対象 | 見つかった場合のツリールート |
| --- | --- | --- |
| 1 | **プロセスのカレントディレクトリ**の直下の README（下記） | カレントディレクトリ |
| 2 | **実行ファイルが存在するディレクトリ**の直下の README（下記） | 実行ファイルのディレクトリ |
| 3 | （いずれも該当なし） | カレントディレクトリ |

- **探すのは、拡張子を除いた名前が `README` の Markdown のファイル**（拡張子は [1.7](01-overview.md) の Markdown のもの。`README.md`・`readme.md`・`README.markdown` 等）とし、名前の大文字小文字を区別しない。**図や画像のファイルは探さない。** 複数が見つかった場合は、`README.md` を優先し、次いで名前の昇順で先頭のものを採る（4.81.0 で、v1.0.0 からの振る舞いと UT-802 に合わせて `README.md` 以外の拡張子も書いた。利用者の判断）。
- カレントディレクトリと実行ファイルのディレクトリが同一の場合、探索は 1 回で済ませる。
- 3 に至った場合、本文ペインに操作案内（ファイルを開く方法（`Ctrl+O`）、ドラッグ＆ドロップの案内、ファイルツリーで選ぶ案内）を表示する。**この案内は本文ペインの状態画面（UI-052 の「文書未表示」）として出し、文書としては描画しない**（4.81.0 で、v1.0.0 からの実装と下位の仕様に合わせた。4.80.0 までは「内蔵する Markdown として描画する」としていた。利用者の判断）。文言は英語とする（UI-024）。
- 実行ファイルのパスはシンボリックリンクを解決したうえで求める。

> [!TIP]
> 順 2 を設けているのは、「`MarkView` と `README.md` を同じフォルダに入れて配布し、受領者はダブルクリックするだけ」というユースケース（[UC-01](01-overview.md)）を、どの環境でも成立させるためである。Windows のエクスプローラからダブルクリックした場合はカレントディレクトリが実行ファイルの場所と一致するため順 1 で解決するが、Linux のファイルマネージャやデスクトップランチャから起動した場合はカレントディレクトリがホームディレクトリや `/` になることがあり、順 1 だけでは配布物の `README.md` に到達できない。
>
> 一方、順序を逆にして実行ファイルの場所を優先すると、`PATH` に置いた `MarkView` をシェルから使う場合に、意図しない場所の `README.md` が開いてしまう。カレントディレクトリを先に見ることで、両方の使い方を満たす。

### FR-014: ファイル更新の自動検知と再描画 **MUST**

表示中のファイル（Markdown・図・画像のファイル）が外部で更新された場合、自動的に再描画する。

- 監視対象は**表示中の 1 ファイルのみ**とする。ディレクトリ全体や、文書に埋め込まれた画像のファイルは監視しない。**画像ファイルを単体で表示している間（FR-027）は、そのファイルを監視する**（4.73.0）。埋め込み画像のファイルを書き換えたときは、手動の再読み込み（FR-015）か文書の更新による再描画で新しい画像になる（FR-022）。
- 保存操作が複数の書き込みイベントを発生させる場合に備え、最後のイベントから 150 ms 以内に追加のイベントがなければ再描画する（デバウンス）。
- 再描画後、**本文のスクロール位置を維持する**。文書が短くなり同じ位置が存在しない場合は、可能な限り近い位置に復元する。
- 再描画後、アウトラインを再構築する。展開済みのファイルツリーの状態は維持する。
- 表示中のファイルが削除された場合、直前の描画結果を保持したまま、ファイルが失われた旨をステータス表示する。
- 表示対象を切り替えたときは、以前のファイルの監視を解除する。**状態画面（UI-052。大きなファイルの確認・サイズ上限超過・描画中の想定外のエラー）へ移った場合も切り替えに当たる**——状態画面の表示中に、前に表示していた文書の更新で画面が置き換わってはならない（[BUG-012](../bugs/2026-09-14-bug-012-state-screen-previous-document.md)）。監視は常に 1 つ以下とする。
- エディタによっては保存が「一時ファイル作成 → リネーム」で行われ、監視ハンドルが切れることがある。この場合は同一パスに対する監視を張り直す。
- **編集モードで書き込んだ後は（FR-141〜FR-147）、監視のイベントを待たずに、ここで定める再描画の処理を直接呼ぶ。** 共有フォルダやネットワーク上のファイルでは、監視のイベントが届かないことがあるためである。**再描画の処理そのものは 1 つとし、書き込みのために別の処理を作らない。**
- **監視のイベントを受けて読み直した内容が、直前に描画した内容と同じなら、再描画しない。** 書き込みの後に届いたイベントで同じ描画を繰り返さないためである。**手動の再読み込み（FR-015）は、内容が同じでも再描画する。** 画像ファイル（FR-027）は中身を読まないため、ファイルの版（更新時刻と大きさ）が同じなら同じとみなす。
- **同じ文書の再描画（[1.7](01-overview.md)）では、次の状態を引き継ぐ。** 開いていた折りたたみ（`<details>`。MD-026）は、**文書の中で同じ順番にあるもの**を開いたまま保つ。本文中のチェックボックス（FR-141）にフォーカスがあった場合は、同じ順番のチェックボックスへフォーカスを戻す（UI-051 の例外）。**`Space` でチェックボックスを続けて切り替えられるようにするためであり、再描画のたびに折りたたみが閉じて読んでいた箇所を見失わないためでもある。**
- **編集欄（セル・コードブロック。FR-142, FR-145）が開いている間は、外部の更新による再描画と、MarkView 自身の書き込みの直後の再描画を、画面に当てずに保留する**（4.73.0。利用者の判断）。外部の更新のときは、その旨をステータス領域に出す（警告。UI-060）。保留の間にさらに再描画が起きたら、最新の内容だけを残す。**編集欄を閉じた時点で、保留していた内容で再描画する。** 長い入力を黙って捨てないためである。
  - **外部の更新を保留している間は、編集欄の確定を受け付けない**（4.74.0。利用者の判断）。編集欄を閉じず、確定の指示を Go 側へ送らず、警告を出し直す。入力は編集欄に残るので、利用者は写し取ってから `Cancel` で閉じられる
  - **表示中のファイルが削除された場合と、読み直した内容に不正なバイト列が含まれていた場合（FR-021）も、編集欄は入力ごと開いたまま残し、確定は書き込まずに拒む**（警告）。編集モードは、利用者が編集欄を閉じた時点で終える（FR-140。4.74.0。利用者の判断）

### FR-015: 手動での再読み込み **MUST**

ツールバーの再読み込みボタン、または `F5` / `Ctrl+R`（UI-090）により、表示中のファイルをディスクから読み直して再描画する。動作は FR-014 と同一（スクロール位置維持を含む）とする。表示中の文書がない場合（文書未表示。UI-052 の `welcome`）、この操作は無効とする。

- **状態画面（UI-052 の `confirm-large` / `too-large` / `render-error`）の表示中は、その画面が対象にしているファイルを読み直す。** 大きさを測り直して状態画面を出し直すか、条件を満たせば描画する（`render-error` を外部のエディタで直した後にやり直せる）。**前に表示していた文書を読み直さない**——ウィンドウタイトルとステータス領域が対象のファイルを指しているのに、押すと前の文書が表示されることになる（[BUG-012](../bugs/2026-09-14-bug-012-state-screen-previous-document.md)）。状態画面の間は監視しない（FR-016）ため、これが対象を読み直す唯一の手段でもある。
- **編集欄（FR-142, FR-145）が開いている間は、再読み込みを受け付けない**（警告を出し、フォーカスを編集欄へ戻す。FR-140 の表。4.74.0。利用者の判断）。

### FR-016: 大きなファイルの扱い **SHOULD**

ファイルの実バイト数に応じて次のとおり扱う。

| サイズ | 動作 |
| --- | --- |
| 10 MB 以下 | そのまま描画する |
| 10 MB 超 50 MB 以下 | 描画を保留し、本文ペインに確認画面を表示する |
| 50 MB 超 | 描画せず、ファイルが大きすぎる旨を本文ペインに表示する。開く手段は提供しない |

確認画面の扱いは以下とする。画面仕様は [UI-052](03-ui.md) を参照。

- **モーダルダイアログを使わない**（FR-110 の方針と整合させる）。本文ペインにファイル名・実サイズ・描画に時間を要する旨と、実行するためのボタンを表示する。
- 確認画面の表示中も、ツールバー・ファイルツリー・アウトラインは通常どおり操作できる。別のファイルを選択した場合、確認は破棄される。
- 実行が指示された時点で描画を開始する。描画中は処理中であることを示す（NFR-012）。**`Open anyway` を淡色にして押せなくし、文言を `Rendering...` に変える**（描き終えて本文が出るか、別の状態画面になるまで。二度押しも防ぐ。UI-052。4.81.0。利用者の判断）。
- 確認画面を表示した時点で、ウィンドウタイトル（UI-013）とステータス領域のパス表示を対象ファイルのものに更新する。**FR-051 の契機（ファイル選択ダイアログ・ドロップ・ツリー・リンク・起動）で表示した場合は、表示履歴（FR-051）に積む**（履歴の移動と読み直しでは積まない。4.81.0 で契機を限った）。`Alt+←` で直前の文書へ戻れること。
- ファイル更新の自動検知（FR-014）の対象とするのは、実際に描画を開始したファイルに限る。確認画面を表示しているだけの状態では監視しない。**それまで表示していた文書の監視も外す**（FR-014）。
- **確認のうえ描画した文書は、同じ文書の再描画（[1.7](01-overview.md)。更新の自動検知・再読み込み・同じファイルの開き直し・編集モードの書き込みの後の読み直し）では確認し直さない。** 描画を始めた後に確認画面へ戻すと、外部エディタで保存するたび・`F5` のたびに描画が止まり、編集モード（FR-140）では書き込むたびに編集モードが終わるためである。**同意は文書の切り替え（1.7）で消える**（別の文書へ移ってから戻った場合は、改めて確認する）。
  - 読み直した結果が 50 MB を超えていれば、同意の有無に関わらずサイズ上限超過の表示にする
  - 確認せずに描画していた文書が、読み直した結果 10 MB を超えていれば、確認画面を表示する（同意していないため）
- **画像ファイル（FR-027）にも同じ規則を当てる**（4.73.0。利用者の判断）。大きさはファイルの大きさで測り、中身を読まない。カメラの写真（5〜15 MB）でも確認画面が出ることがあるが、受け入れる。画素数は問わない（FR-027）。

## 2.2 Markdown 表示（FR-020 系）

### FR-020: Markdown の描画 **MUST**

読み込んだ Markdown を HTML に変換し、GitHub 準拠のスタイルで本文ペインに表示する。対応する文法・描画規則は [04. Markdown 描画仕様](04-markdown.md) で定義する。

### FR-021: 文字コードと改行コードの扱い **MUST**

- UTF-8（BOM 付き・BOM なしの両方）を正しく読み込む。BOM は本文として描画しない。
- 改行コード CRLF / LF / CR のいずれも正しく解釈する。
- UTF-8 として不正なバイト列を含む場合、その箇所を U+FFFD に置換して読み込みを継続し、警告をステータス表示する。読み込み自体は失敗させない。
- 本要求は文字のファイル（Markdown と図のファイル。[1.7](01-overview.md)）に当てはめる。**画像ファイル（FR-027）は文字として読まない。**

> [!NOTE]
> Shift_JIS 等のレガシーエンコーディングの自動判別は行わない。開発者向けの Markdown は UTF-8 が事実上の標準であり、判別ロジックの追加はサイズと誤判定リスクに見合わないため。

### FR-022: 画像の表示 **MUST**

- Markdown 内の相対パス・絶対パスで指定されたローカル画像を表示する。相対パスは**表示中の Markdown ファイルが存在するディレクトリ**を基準に解決する。
- 対応形式は PNG、JPEG、GIF（アニメーション含む）、SVG、WebP、AVIF、BMP、ICO とする。
- `http://` / `https://` で指定されたリモート画像も表示する（MD-071）。
- 画像が存在しない・読み込めない場合、代替テキスト（alt）と破損を示すプレースホルダを表示する。文書全体の描画は継続する。**画素数が大きすぎて WebView が解けない画像も同じとする**（上限は設けない。FR-027）。
- 画像の最大表示幅は本文幅とし、超える場合は縦横比を保って縮小する。**ただし原寸表示（FR-121）に切り替えた画像を除く。**
- **固有の大きさを持たない画像（`width` / `height` の無い SVG）は、本文の幅いっぱいに、縦横比を保って描く**（GitHub と同じ。MD-002。4.91.0）。**v1.1.0 は、原寸表示のボタンを置く器の中で幅 0 に縮み、見えなかった**（[BUG-029](../bugs/2026-11-09-bug-029-svg-no-size-collapsed.md)）。
- **ローカル画像のファイルを書き換えた後に再描画したとき（FR-014, FR-015）は、新しい内容の画像を表示する**（4.73.0。[BUG-026](../bugs/2026-11-08-bug-026-stale-embedded-image.md)）。**WebView は、1 つのページの中で一度読んだ画像を、同じ URL なら応答のキャッシュの指示に関わらず使い回す**（WebView2 / WebKitGTK とも実機で確かめた）。MarkView はページを遷移しない（AR-060）ため、使い回されるとウィンドウを閉じるまで古い画像が出続ける。**ファイルが変わっていない画像は取り直さない**（再描画のたびにちらつかせない）。
- 上の対応形式の拡張子は 9 つ（`.png` / `.jpg` / `.jpeg` / `.gif` / `.svg` / `.webp` / `.avif` / `.bmp` / `.ico`）であり、画像ファイルとして開ける拡張子（FR-027）と、ローカルの画像を配信する拡張子（AR-041）と同じとする（[1.7](01-overview.md) の「開けるファイル」の表）。**実装でも定義を 1 つにし、2 か所に書かない。**

### FR-023: Mermaid 図の表示 **MUST**

- 言語指定 `mermaid` のコードブロックを Mermaid 図として描画する。**生 HTML（MD-072）で図のブロックを装ったものは描画しない**（NFR-030）。
- 描画は外部通信なしで行う（AR-020）。
- Mermaid のテーマは、アプリの Light / Dark テーマに追従させる。
- 構文エラーで描画できない場合、エラー内容と元のコードをコードブロックとして表示する。文書全体の描画は継続する。
- Mermaid 記法を含まない文書では Mermaid の実行環境を読み込まない（NFR-013）。
- Mermaid ファイル（FR-026）の図も、本要求と同じ規則で描画する。

### FR-024: PlantUML 図の表示 **MUST**

- 言語指定 `plantuml` または `puml` のコードブロックを PlantUML 図として描画する。**生 HTML（MD-072）で図のブロックを装ったものは描画しない**——装ったブロックが、下の取り込み指令の検査（MD-084）を通らずに処理系へ渡るためである（NFR-030）。
- 描画は外部通信なしで行う（AR-020, NFR-032）。**同梱した処理系だけで描き、PlantUML のサーバへ送らない。**
- PlantUML の配色は、アプリの Light / Dark テーマに追従させる。
- 構文エラーで描画できない場合、**PlantUML が生成するエラー図をそのまま表示する**。文書全体の描画は継続する。Mermaid（FR-023）と扱いが違うのは、PlantUML が構文エラーを例外ではなく「エラーを描いた図」として返し、その図が行番号と該当行を含むためである。
- 次の 2 つは描画できない。いずれも本文中に理由を表示し、元のソースをコードブロックとして残す（FR-110）。
  - **取り込みのプリプロセッサ指令**（`!include` / `!includeurl` / `!includesub` / `!import` と、`from` を伴う `!theme`）を含むブロック。**Go 側で検査して描画対象から外す**（MD-084, NFR-032）。標準ライブラリ（`!include <C4/...>` 等）もこの形であり、**同梱した処理系は持っていない**
  - **幅か高さが 100,000 px を超える図**（4.96.0。v1.2.0-rc.1 までは 4096 px。[BUG-030](../bugs/2026-11-11-bug-030-plantuml-size-limit.md)）。処理系が描画を拒む（上限の値は MarkView が処理系へ明示して渡す。MD-083）。**理由は、処理系が図を返さなかったとき（未対応の図種別など）と同じ「描けなかった」旨とし、上限を超えたことを区別して出さない**——処理系の返す文言は版で変わり、文言で見分けない（DSP-272, IMP-233。4.81.0 で下位に合わせた。利用者の判断）。**文言には、理由の候補として「対応していない図か、上限より大きい図かもしれない」ことと上限の値を書く**（4.96.0。利用者の判断）
- PlantUML 記法を含まない文書では PlantUML の実行環境を読み込まない（NFR-013）。
- PlantUML ファイル（FR-025）の図も、本要求と同じ規則で描画する（図ごとに切り分けて渡す。MD-086）。

### FR-025: PlantUML ファイルの表示 **MUST**

拡張子が `.puml` / `.pu` / `.wsd` / `.plantuml` のファイル（**PlantUML ファイル**）を、Markdown ファイルと同じく文書として開き、本文ペインに図を表示する（4.73.0）。

- ファイルの中の図を `@start…` の行から `@end…` の行までで切り分け、**図ごとに見出しを付けて上から順に並べる**（切り分けと見出しの規則は MD-086）。見出しはアウトライン（FR-040）に出す。**処理系は 1 回の描画で先頭の図しか描かない**（同梱の処理系で実測）ため、切り分けずに渡すと 2 つ目以降の図が黙って消える。
- 図の描画は、Markdown の中の PlantUML のブロック（FR-024）と同じ規則に従う。テーマへの追従、構文エラーのエラー図、取り込み指令の拒否（**図ごとに検査し、拒んだ図だけ理由を出す**。MD-084）、上限（MD-083）を超える図、コピーボタン（FR-060）、原寸表示と拡大画面（FR-120〜FR-122）を含む。
- **図が 1 つも無いファイル**は、ソースを等幅のコードブロックとして表示し、図が見つからない旨（`No diagrams found.`）を添える。
- **取り込み用の断片（`.iuml`）は対象にしない。** 単体では図にならないためである。ツリーに出さず、リンク先なら OS の既定のアプリケーションで開く（FR-050）。
- 編集モードでは、図ごとにその場の編集欄で書き換えられる（FR-145）。図の外の行は変えない。
- 文字コードと改行コード（FR-021）、大きさの規則（FR-016）、監視（FR-014）、表示履歴（FR-051）、外部エディタ（FR-090）は、Markdown ファイルと同じに働く。外部エディタで書きながら MarkView で開いておけば、保存のたびに図が描き直される（UC-08）。

### FR-026: Mermaid ファイルの表示 **MUST**

拡張子が `.mmd` / `.mermaid` のファイル（**Mermaid ファイル**）を、文書として開き、本文ペインに図を表示する（4.73.0）。

- **ファイル全体を 1 つの図として描く**（1 ファイル 1 図。規則は MD-087）。見出しは付けず、アウトライン（FR-040）は見出しが無い表示になる。
- 図の描画は、Markdown の中の Mermaid のブロック（FR-023）と同じ規則に従う（テーマへの追従、構文エラーの表示、図の中のリンク（MD-081）、コピーボタン、原寸表示と拡大画面）。
- **中身が空白だけのファイル**は、図を出さず `No diagrams found.` を表示する（FR-025 と同じ文言）。
- `.mmd` は MultiMarkdown の文書の拡張子としても使われる。**拡張子で種類を決める規則を崩さない**——MultiMarkdown の文書を開くと、Mermaid の構文エラーとして表示される。Markdown として表示し直す手段は持たない。
- 編集モードでは、ファイル全体を 1 つの図として、その場の編集欄で書き換えられる（FR-145）。
- 文字コード・大きさ・監視・表示履歴・外部エディタは、FR-025 と同じに働く。

### FR-027: 画像ファイルの表示 **MUST**

画像のファイル（拡張子は埋め込み画像と同じ 9 つ。FR-022）を、文書として開き、本文ペインに単体で表示する（4.73.0）。**画像を編集する機能は持たない**（利用者の指示）。

- 本文の幅より大きい画像は、**本文の幅に合わせて縦横比を保って縮小する。** 小さい画像は拡大しない（埋め込み画像の FR-022 と同じ規則）。**固有の大きさを持たない SVG は、本文の幅いっぱいに描く**（FR-022 と同じ規則。4.91.0。[BUG-029](../bugs/2026-11-09-bug-029-svg-no-size-collapsed.md)）。画像は本文の幅の中で中央に置き、縦は上に詰める。
- **画像の透過した部分には市松模様を敷く**（画像の範囲だけ）。透過しているかどうかが分かるようにするためである。埋め込み画像には敷かない。
- 本文には画像だけを出す。**ステータス領域の右端に、画像の寸法とファイルの大きさを出す**（`1920 × 1080 px` と `245 KB`。UI-060）。固有の大きさを持たない SVG は、寸法を出さず大きさだけを出す。
- **原寸表示と拡大画面は、図と同じ仕組みをそのまま使う**（FR-120〜FR-122）。拡大画面のボタンは、読み込みに成功していれば**常に**出す（原寸表示のボタンは、埋め込み画像と同じく縮小表示中と原寸表示中だけ）。拡大画面でも画像の範囲に市松模様を敷く。**画像のための新しい操作（回転・前後の画像への移動・Exif などの画像の情報の表示など）は持たない**（ステータス領域の寸法と大きさは除く）（[1.5.2](01-overview.md)）。
- **読み込みに失敗した画像**（壊れたファイル、WebView が解けない形式、**画素数が大きすぎて WebView が解けない画像**）は、埋め込み画像と同じ壊れた画像の表示とし（DSP-123）、代替テキストはファイル名とする。原寸表示と拡大画面のボタンは出さず、ステータス領域の寸法も出さない。**画素数の上限は設けない**——W1 / L1 の実機で、16384 × 16384 px までは表示でき、30000 × 30000 px でも固まらず落ちずに壊れた画像の表示になることを確かめた（利用者の判断）。
- **大きさの規則は Markdown と同じ**とする（FR-016。10 MB を超えたら確認画面、50 MB を超えたら開かない）。
- **表示中の画像ファイルが外部で更新されたら、再描画して新しい画像を表示する**（FR-014, FR-022）。
- アウトラインは見出しが無い表示とする。文書内検索（FR-080）は開けるが、本文に文字が無いため一致しない（読み込みに失敗したときは、代替テキストのファイル名を探せる）。
- **編集モードと外部エディタは使えない**（FR-140, FR-090。ツールバーのボタンを淡色にする。UI-021）。
- ウィンドウタイトル（UI-013）・ステータス領域のパス（UI-060）・表示履歴（FR-051）・ツリーの強調（FR-031）は、Markdown の文書と同じに扱う。

## 2.3 ファイルツリー（FR-030 系）

### FR-030: ツリールートの決定 **MUST**

ツリールートは以下の契機でのみ変更される。

| 契機 | 新しいツリールート |
| --- | --- |
| ファイル選択ダイアログでファイルを選択（FR-010） | 選択されたファイルの親ディレクトリ |
| ファイルをドロップ（FR-011） | ドロップされたファイルの親ディレクトリ |
| ディレクトリをドロップ | ドロップされたディレクトリ |
| コマンドライン引数（FR-012） | 引数がファイルなら親ディレクトリ、ディレクトリならそれ自身 |
| 引数なし起動（FR-013） | カレントディレクトリ、または実行ファイルのディレクトリ（FR-013 の探索順による） |
| ファイルツリーの右クリックメニューの `Set as tree root`（FR-036） | そのディレクトリ |
| ファイルツリーの右クリックメニューの `Set parent as tree root`（FR-036） | いまのツリールートの親ディレクトリ |

**ファイルツリー内のファイルを選択してもツリールートは変更しない。** また、文書内リンクによる遷移（FR-050）でもツリールートは変更しない。これは、ドキュメント群を配布したときにツリーが利用者の操作で意図せず移動してしまうことを防ぐためである。**ツリーの右クリックメニューでツリールートを変える操作（4.73.0）は、利用者が明示的に選ぶものであり、この理由に反しない。** ツリールートを変えても、表示中の文書・表示履歴・編集モードは変えない（文書の切り替えではない）。ツリールートは保存しない（NFR-042）。

### FR-031: ツリーの表示内容 **MUST**

- ツリールート以下のディレクトリと、**ツリーのフィルター（FR-037）で表示している種類のファイル**を階層表示する。
- **表示対象のファイルは、Markdown（`*.md`, `*.markdown`, `*.mdown`, `*.mkd`）と、フィルターで選んだ図のファイル（FR-025, FR-026）・画像ファイル（FR-027）に限る**（4.73.0）。ソースコード・設定ファイル・その他の種類のファイルは、ツリーに表示しない。ファイルツリーは「MarkView で開けるものを選ぶ」ための道具であり、開けないファイルを並べても選択できないため。**Markdown は常に表示する。**
- **表示している種類のファイルを 1 つも含まないディレクトリ（下位階層を含めて）は表示しない。**
- 名前が `.` で始まるディレクトリ・ファイルは表示しない。
- `node_modules`、`vendor`、`.git`、`target`、`dist`、`build` は既定で表示しない。
- 並び順はディレクトリを先、ファイルを後とし、それぞれ名前の昇順（大文字小文字を区別しない）とする。ファイルの種類で分けて並べない。
- ファイルは、種類（Markdown・図・画像）を見分けられるアイコンで表示する（UI-030）。
- 現在表示中のファイルをツリー上で強調表示する。**表示中のファイルの種類をフィルターで隠しているときは、強調する行が無い状態とする**（FR-052 と同じ見え方。ただしツリールートの外ではないため、ステータス領域のパスは相対パスのままとする）。

### FR-032: ツリーの遅延展開 **MUST**

ディレクトリの内容は、そのディレクトリが展開された時点で初めて読み込む。起動時に階層全体を再帰的に走査してはならない。これは、巨大なディレクトリをツリールートにした場合の起動遅延とメモリ増加を防ぐためである。

- ツリールート直下のみ、起動時に読み込んで展開状態で表示する。
- 表示中のファイルに至る経路上のディレクトリは、自動的に展開する。
- 1 ディレクトリあたりのエントリ数が 1000 を超える場合、先頭 1000 件を表示し、省略された旨を末尾に表示する。**件数は、表示する種類で絞り込んだ後の数で数える**（FR-037。画像を隠しているのに画像の数で上限に掛からないように）。

> [!NOTE]
> 「表示している種類のファイルを含まないディレクトリを隠す」という規則（FR-031）と遅延展開は本来相反する。実装では、ディレクトリ判定のために 1 階層下までを先読みし、それでも判定できない深い階層は「展開してみるまで表示する」ことを許容する。判定のために全階層を走査してはならない。

### FR-033: ツリーからのファイル選択 **MUST**

ツリー上のファイル（Markdown・図・画像）をクリックすると、そのファイルを本文ペインに表示する。このとき、

- **ツリールートは変更しない**（FR-030）。
- 本文のスクロール位置は先頭に戻す。
- 表示履歴に追加する（FR-051）。
- ファイル監視の対象を新しいファイルに切り替える。
- **ツリーから受け取ったパスは、いまのツリーが見せているものであることを確かめてから開く**（FR-036 の検査と同じ。4.73.0）。

### FR-034: ツリーの表示・非表示切り替え **MUST**

ツールバーのファイルツリーボタン、またはショートカット（UI-090）により、ファイルツリーペインの表示・非表示をトグルする。非表示時はファイルツリーの内容をメモリ上に保持したままでよいが、再表示時にツリールートの内容を再読み込みして最新状態を反映する。

### FR-035: ツリーの手動更新 **SHOULD**

ファイルツリーはディレクトリの変更を自動監視しない（FR-014 の監視は表示中ファイルのみ）。ツリーの再読み込みは以下の契機で行う。

- ツリーペインを非表示から表示に切り替えたとき
- 再読み込み操作（FR-015）を行ったとき
- ディレクトリノードを折りたたんでから再度展開したとき
- ツリーの右クリックメニューでツリールートを変えたとき（FR-036）
- ツリーのフィルターを切り替えたとき（FR-037）

### FR-036: ファイルツリーの右クリックメニュー **MUST**

ファイルツリーの項目を右クリックしたとき、その項目についての操作を並べたメニューを出す（4.73.0。見た目と操作は UI-032）。

| 右クリックした所 | 項目 | 動作 |
| --- | --- | --- |
| ファイル | `Open` | クリックと同じく MarkView で開く（FR-033） |
| ファイル | `Open in editor...` | エディタ選択ウィンドウ（UI-103）を出し、選んだエディタで**そのファイル**を開く（FR-090, FR-091 と同じ流れ）。**画像ファイルでは使えない** |
| ファイル | `Open containing folder` | そのファイルの親ディレクトリを OS の既定のファイルマネージャで開く（ファイルを選んだ状態にはしない） |
| ファイル | `Copy path` | 絶対パスをクリップボードへ格納する |
| ディレクトリ | `Open in file manager` | そのディレクトリを OS の既定のファイルマネージャで開く |
| ディレクトリ | `Set as tree root` | そのディレクトリをツリールートにする（FR-030） |
| ディレクトリ | `Copy path` | 絶対パスをクリップボードへ格納する |
| ツリールートの名前の行（UI-030） | `Open in file manager` / `Set parent as tree root` / `Copy path` | ツリールートについての同じ操作と、**1 つ上のディレクトリをツリールートにする操作**。ドライブやファイルシステムの根では `Set parent as tree root` を使えない |

- **右クリックだけでは項目を選ばない（開かない）。** ツリーの中のフォーカスとツリーの強調も動かさない（メニューを閉じたら、フォーカスは開く前の位置へ戻る。UI-032）。
- 編集モード（FR-140）の間も使える（ファイルを書き換えない）。`Open` で文書が切り替われば、編集モードは終わる（編集欄が開いている間は切り替えない。FR-140）。
- **パスはフロントエンドから受け取るが、使う前に Go 側で次を確かめ、満たさなければ何もしない。** フロントエンドが渡す値は、形が正しくても信じない。**ツリーからファイルを開く（FR-033）・ディレクトリを展開する（FR-032）操作にも同じ検査を通す。** 検査は「ツリーに出しているものだけを受け付ける」ためのものであり、**ツリーに出ているものは、今までどおり開ける・展開できる**ようにする（4.74.0。利用者の判断）。
  - 絶対パスで、**ツリー上のパス（シンボリックリンクを解決する前のパス）がいまのツリールートの中**にある。ツリールートの名前の行の操作、`Open containing folder` の親ディレクトリ、展開では、ツリールートそのものでもよい。リンク先の実体がツリールートの外にあっても、ツリーに並んでいるものは受け付ける
  - **ツリールートからの相対パスの各部分が、ツリーに表示する規則に当てはまる**（FR-031。名前が `.` で始まるもの・既定で隠すディレクトリ・フィルターで隠した種類を含まない）——ツリーに出していないものは受け付けない。ツリールートそのものの名前と、ツリールートより上の部分には当てはめない
  - **種類はリンク先の実体で見る**: 開くのは開けるファイル、`Open in editor...` は**文字のファイル**（[1.7](01-overview.md)。画像を含めない）、展開・ファイルマネージャで開く・ツリールートにするのはディレクトリ
  - **ファイルが既に無い場合は、何もしないのではなく、FR-110 の「見つかりません」を出す**（ツリーは自動では更新されないため、消したファイルが並んでいることがある。FR-035）
- **`Set parent as tree root` はパスを受け取らない。** いまのツリールートの親を Go 側で求める。
- **ファイルマネージャで開くのはディレクトリだけとする。** ファイルを OS の既定のアプリケーションへ渡すと、実行ファイルなら実行される（NFR-035）。
- `Open in editor...` では、エディタ選択ウィンドウ（UI-103）に開くファイルの名前を出す。**エディタへ渡す引数は、確かめたファイルの絶対パス 1 つだけとする**（NFR-035）。エディタ選択ウィンドウを閉じたら、確かめたファイルの控えを捨てる（ツールバーから開いた場合も、開いた時点の対象を控える。FR-091）。
- ツリールートを変えたら、ツリーを読み直す。**表示中の文書・表示履歴・編集モードは変えない**（FR-030）。表示中の文書がツリールートの外になれば、FR-052 の表示になる。
- 起動やコピーに失敗した場合は、ステータス領域に通知する（FR-110）。

### FR-037: ファイルツリーのフィルター **MUST**

ファイルツリーに並べるファイルの種類を、利用者がチェックボックスで選べるようにする（4.73.0。利用者の指示。見た目と操作は UI-033）。

| 種類 | 拡張子 | 外せるか | 既定 |
| --- | --- | --- | --- |
| Markdown | `.md` / `.markdown` / `.mdown` / `.mkd` | **外せない**（常に表示） | 表示 |
| 図（Diagrams。FR-025, FR-026） | `.puml` / `.pu` / `.wsd` / `.plantuml` / `.mmd` / `.mermaid` | 外せる | **表示** |
| 画像（Images。FR-027） | `.png` / `.jpg` / `.jpeg` / `.gif` / `.svg` / `.webp` / `.avif` / `.bmp` / `.ico` | 外せる | **非表示** |

- **文言に拡張子をすべて書き**、ツリーに出ているファイルの拡張子を利用者に意識させる（利用者の指示）。拡張子の並びは、開けるファイルの定義（[1.7](01-overview.md)）から組み立て、2 か所に書かない。
- **切り替えたその場でツリーに反映する。** 展開していたディレクトリは展開したまま、表示中のファイルの強調とスクロール位置もできるだけ保って読み直す（FR-035 の 5 番目の契機。**ほかの契機の読み直しと違い、展開の状態を保つ**。IMP-271。4.81.0 で書き分けた）。
- 選択は設定に保存し、再起動しても引き継ぐ（UI-110）。設定が無い・壊れている・項目が無い（v1.1.0 までの設定ファイル）ときは、上の既定とする（UI-113）。
- **効くのはツリーの表示だけである。** ファイル選択ダイアログ・ドロップ・起動引数・リンク・表示履歴では、選択に関わらず開けるファイルの 3 種類を開く。
- 表示している種類を含まないディレクトリは出さない（FR-031）。ツリーからの操作の検査は、フィルターで隠した種類を受け付けない（FR-036）。
- **ソースコードや設定ファイルなど、開けない種類を選ぶ選択肢は作らない**（FR-031 の理由）。
- 多重起動（UI-115）では、他の設定と同じく後勝ちとする。あるウィンドウで切り替えても、開いている他のウィンドウには反映しない（テーマと同じ）。
- ファイルツリーペインが非表示の間も、選択は保存した値のまま保つ。

## 2.4 アウトライン（FR-040 系）

### FR-040: アウトラインの生成 **MUST**

表示中の文書の見出し（`#` から `######`）を抽出し、階層構造としてアウトラインペインに表示する。

- 見出しレベルの入れ子はソース上の階層をそのまま反映する。レベルが飛んでいる場合（`#` の次に `###` 等）でも、出現順を保ったまま相対的な深さで表示する。
- 見出しテキストに含まれるインライン記法（強調、コード、リンク等）は、プレーンテキストに変換して表示する。
- コードブロック内の `#` 始まりの行は見出しとして扱わない。
- 見出しが 1 つも存在しない場合、その旨をアウトラインペインに表示する。
- **PlantUML ファイル（FR-025）では、図ごとの見出し（MD-086）をアウトラインに出す。** Mermaid ファイル（FR-026）と画像ファイル（FR-027）は見出しを持たず、見出しが無い旨を表示する。

### FR-041: アウトラインからの移動 **MUST**

アウトラインの項目をクリックすると、本文ペインの該当見出しまでスクロールする。スクロールは即座に行い、対象の見出しがペイン上端付近に来る位置に合わせる。

**見出しが折りたたみ（`<details>`。[MD-026](04-markdown.md)）の中にある場合は、折りたたみを開いてから移動する**（FR-080 の IMPORTANT）。アウトラインは本文の見出しをすべて挙げるため、折りたたみの中の見出しも項目として現れる。

### FR-042: スクロール連動 **MUST**

本文ペインのスクロールに追従し、現在表示中の位置に対応するアウトライン項目を強調表示する。

- 判定は「本文ペインの上端より上にある最後の見出し」とする。
- 強調表示された項目がアウトラインペインの表示範囲外にある場合、アウトラインペインを自動スクロールして可視にする。
- 連動処理は本文の描画性能に影響を与えない方式で実装する（AR-051）。

### FR-043: アウトラインの表示・非表示切り替え **MUST**

ツールバーのアウトラインボタン、またはショートカット（UI-090）により、アウトラインペインの表示・非表示をトグルする。

## 2.5 文書内リンクと履歴（FR-050 系）

### FR-050: 文書内リンクの遷移 **MUST**

本文中のリンクは、リンク先の種類に応じて以下のとおり処理する。

| リンク先 | 動作 |
| --- | --- |
| Markdown ファイル・図のファイル（`./docs/design.md`、`./arch.puml`、絶対パスを含む） | **表示中のウィンドウで**当該ファイルを開く。ツリールートは変更しない |
| Markdown ファイル + アンカー（`./a.md#section` 等） | 当該ファイルを表示し、該当見出しまでスクロールする |
| 同一文書内のアンカー（`#section`） | 該当見出しまでスクロールする。`#user-content-section` と書かれていても同じ見出しへ移る（MD-021, AR-053）。**本文の外（画面の要素）へは移らない。** 本文に該当する要素が無ければ、リンク先が見つからない旨をステータス表示する |
| 画像ファイル | **表示中のウィンドウで MarkView の画像ファイルとして開く**（FR-027, FR-053。4.73.0） |
| その他のファイル（開けないファイル。PlantUML の取り込み用の断片 `.iuml` を含む） | OS の既定アプリケーションで開く |
| `http://` / `https://` | **OS の既定ブラウザで開く**。WebView 内では遷移させない |
| `mailto:` 等のその他スキーム | OS の既定ハンドラに委譲する |
| 存在しないパス | 遷移せず、リンク先が見つからない旨をステータス表示する |

**移動先の見出しが折りたたみ（`<details>`。[MD-026](04-markdown.md)）の中にある場合は、折りたたみを開いてから移動する**（FR-080 の IMPORTANT）。閉じたままの要素はレイアウトを持たず、スクロール先として指定しても何も起きない。

開けるファイル（[1.7](01-overview.md)）へのリンクを開く際の詳細は以下のとおり。

- **新しいウィンドウやタブを開かない。** 表示中のウィンドウの本文ペインを、リンク先の文書の内容で置き換える。
- 遷移前の文書は表示履歴に積み、`Alt+←` で元の文書へ戻れる（FR-051）。戻った際は遷移前のスクロール位置を復元する。
- 遷移後、本文のスクロール位置は先頭に戻す（アンカー付きリンクの場合は該当見出しの位置）。
- 遷移後、ウィンドウタイトル（UI-013）、ステータス領域のパス表示、アウトライン、ファイル監視の対象を、新しい文書のものに更新する。
- ファイルツリーの**ツリールートと展開状態は変更しない**。強調表示のみ新しい文書へ移す。
- 相対パスは表示中の文書（Markdown・図のファイル）のディレクトリを基準に解決する（AR-042）。
- ツリールート外への遷移も許可する（例: `../other/doc.md`）。この場合の表示は FR-052 に従う。
- WebView 内でのページ遷移は一切発生させない。すべての遷移はアプリケーションが制御する（AR-060）。
- **例外として、編集モード（FR-140）の間は、表のセルの中のリンクと、図の中のリンク（MD-081）をクリックしても遷移しない**（FR-142, FR-145）。セルと図のダブルクリック（編集の開始）の 1 回目で、文書が切り替わる・既定のブラウザが開くのを防ぐためである（図は 4.74.0）。
- **Mermaid の図の中のリンク**（`click` で URL を指定したノード、ラベルに書いた HTML のリンク。MD-081）も、本文中のリンクと同じく扱う。**拡大画面（FR-122）の中では、押しても何もしない**（UI-104。[BUG-015](../bugs/2026-09-17-bug-015-mermaid-click-link-navigation.md)）。
- **リンクを開くのは、マウスの左ボタンでのクリックとキーボードだけとする。** 中ボタンなど左ボタン以外で押しても何もしない（AR-060。[BUG-016](../bugs/2026-09-17-bug-016-link-middle-click.md)）。本文の中の図のリンクと、拡大画面の中のリンクも同じ。

> [!IMPORTANT]
> 上の表の「その他スキーム」で OS へ委譲するのは **`mailto:` に限る**。`javascript:` や `file:` を含む任意のスキームを OS へ渡すと、文書の作成者が利用者の環境で任意のハンドラを起動できてしまう。文書は任意の第三者から受け取りうるため、許可するスキームは `http` / `https` / `mailto` の 3 つに固定し、それ以外はリンク先を開けない旨をステータス表示する（IMP-170, NFR-030）。

### FR-051: 表示履歴の前後移動 **MUST**

表示した文書の履歴を保持し、**直前に表示していたファイルへ戻る操作と、戻る前の文書へ進む操作**を提供する。

| 手段 | 戻る | 進む |
| --- | --- | --- |
| ツールバーのボタン（UI-020。4.73.0） | 戻るボタン | 進むボタン |
| キーボード（UI-090） | `Alt+←` | `Alt+→` |
| マウスのサイドボタン（**SHOULD**。4.73.0） | 戻るボタン | 進むボタン |

- **戻れない・進めないときは、ツールバーのボタンを淡色にし、押せないようにする**（UI-021）。戻れるか・進めるかは Go 側の履歴から受け取る。**フロントエンドで履歴を数え直さない**——履歴の正は Go 側にあり、2 か所で数えるとずれる。
- マウスのサイドボタンは、ウィンドウのどこで押しても働く。**WebView 自身のページの履歴を戻らせない**（AR-060）。サイドボタンが届かない環境では、ボタンとキーボードで操作する。
- 戻る・進むを受け付けない場面は、`Alt+←` / `Alt+→` と同じとする（情報ウィンドウ・エディタ選択ウィンドウ・拡大画面の表示中。UI-090）。右クリックメニューと文字色の一覧（UI-085）の表示中は、キーとサイドボタンを受け付けない。**ツールバーの戻る・進むボタンを押した場合は、メニューの外の押下としてメニューを閉じ、そのまま戻る・進む**（UI-085）。**編集欄（FR-142, FR-145）が開いている間は、切り替えずに、開いている編集を確定するか取り消すよう促す**（FR-140）。
- 履歴に積む契機は、**起動時の表示（FR-012, FR-013）**、ファイル選択ダイアログ（FR-010）、ドラッグ＆ドロップ（FR-011）、ファイルツリーからの選択（FR-033, FR-036）、文書内リンクによる遷移（FR-050, FR-053）とする（起動時は 4.81.0 で書き足した。起動時の文書へ戻れることは v1.0.0 から変わらない）。ファイル更新の自動検知（FR-014）と手動の再読み込み（FR-015）では履歴に積まない。
- **上の契機で状態画面（UI-052 の `confirm-large` / `too-large` / `render-error`）を出した場合も、その対象を履歴に積む**（FR-016 の確認画面とそろえる。4.73.0。[BUG-024](../bugs/2026-11-08-bug-024-state-screen-not-in-history.md)）。積まないと、状態画面から戻ったときに直前の文書を飛ばし、開いていた文書が 1 つだけなら戻れない。
- **履歴の先の文書を開けなかった場合**（削除・名前の変更・権限が無い等。FR-110 の「直前の内容を維持」に当たる失敗）**は、その項目を履歴から取り除き、履歴の位置を移動の前へ戻す。開けなかった理由はステータス領域に出す**（4.73.0。利用者の判断。[BUG-023](../bugs/2026-11-08-bug-023-history-step-on-open-failure.md)）。位置だけを進めると、画面と履歴の位置が食い違い、その間に別の文書を開くと見ていた文書が履歴から消える。項目を残すと、戻るたびに同じ項目で止まる。**状態画面になった場合は「開けなかった」に入れない**（画面がその文書を対象にしている。UI-013）。**1 回の操作で 1 つ戻る**ことは変えない（開けない項目を飛ばして、その先の文書を開かない）。
- 履歴はブラウザと同様のスタック構造とする。戻った状態から新しい文書を開くと、前方履歴は破棄される。
- 履歴に記録する情報は、ファイルパス・スクロール位置・アンカーとする。
- 履歴で戻った場合、記録されたスクロール位置を復元する。
- 履歴の保持上限は 50 件とする。
- **履歴はメモリ上のみに保持し、終了時に破棄する**。ディスクには一切保存しない（NFR-042）。

### FR-052: ツリールート外の文書を開いた場合 **MUST**

リンク遷移（FR-050）や履歴移動（FR-051）により、ツリールートの外にあるファイルを表示することがある。**ツリーの右クリックメニューでツリールートを変えた結果（FR-036）、表示中の文書がツリールートの外になることもある。** この場合、

- **ツリールートを変更しない。** ファイルツリーの表示内容・展開状態・スクロール位置をいずれも変えない。
- ファイルツリー上で強調表示されるノードは存在しない状態とする（UI-030）。
- ステータス領域には相対パスではなく**絶対パス**を表示し、ツリー外の文書であることが分かる表示を付す（UI-060）。
- その文書からさらにリンクをたどる場合も、基準はその文書自身のディレクトリとする。
- `Alt+←` でツリールート内の文書へ戻った時点で、ファイルツリーの強調表示が復活する。
- **表示中のファイルの種類をフィルター（FR-037）で隠している場合も、強調表示されるノードは無い状態とする。** ただしツリールートの外ではないため、ステータス領域は相対パスのままとし、ツリー外の印を付けない（FR-031）。

> [!NOTE]
> ツリー外へ遷移してもツリールートを動かさないのは、FR-030 と同じ理由による。配布されたドキュメント群を読み進める最中に、リンク 1 つでツリーの起点が移動してしまうと、利用者が元の一覧へ戻る手掛かりを失うため。

### FR-053: 画像の表示先 **MUST**

画像ファイルへのリンク（`[構成図](./arch.png)` のように、画像を**リンク先**として指定した記法）をクリックした場合、**その画像ファイルを MarkView で開く**（FR-027。4.73.0。利用者の判断）。Markdown の文書へのリンクと同じく、表示中のウィンドウで開き、表示履歴に積み（FR-051）、`Alt+←` で元の文書へ戻れる。

- **4.72.0 までは OS の既定画像ビューアで開いていた。** 4.73.0 で画像ファイルを MarkView で表示できるようにしたため（FR-027）、図のファイルへのリンクと同じく MarkView で開く。
- 画像ファイルが存在しない場合は、リンク先が見つからない旨をステータス表示する（FR-110）。
- 本文に**埋め込まれた**画像（`![構成図](./arch.png)`）のクリックでは何も起こさない。ただし画像がリンクで囲まれている場合（`[![構成図](./arch.png)](./design.md)`）は、リンク先に対して FR-050 の規則を適用する。
- 開けないファイルへのリンクは、これまでどおり OS の既定のアプリケーションで開く（FR-050）。

> [!NOTE]
> **4.72.0 までは、画像の表示を OS に委ねていた。** 理由は 2 つあった。第一に、採用している Wails v2 はアプリケーションが 2 つ目のネイティブウィンドウを開くことをサポートしていない（AR-001）。第二に、自前の画像ビューアを実装すれば拡大・縮小・回転といった機能を順次求められることになり、「閲覧に特化した軽いアプリケーション」という位置づけから離れる。
>
> **4.73.0 の画像ファイルの表示（FR-027）は、どちらにも当たらない。** 画像は文書と同じく本文ペインに出し、画像を見るための別のウィンドウや専用の画面を作らない。大きく見るのは図と同じ原寸表示と拡大画面（FR-121, FR-122）だけであり、**画像のための新しい操作は 1 つも足さない**（[1.5.2](01-overview.md)）。拡大画面（4.39.0）は「本文の中で縮小されて読めない図・画像を、読むために大きく見る」ためのものであり、回転・編集・前後の画像への移動といった画像ビューアの機能は持たない。

## 2.6 コードブロックのコピー（FR-060 系）

### FR-060: コピーボタンの表示 **MUST**

本文中のすべてのコードブロック（フェンス付き・インデント形式の両方）の**右上**にコピーボタンを配置する。

- ボタンはコードブロック内にオーバーレイ表示し、コードの内容と重ならない位置とする。
- 既定では半透明で表示し、コードブロックにマウスカーソルが乗ったときに不透明にする。タッチ操作やキーボード操作の環境を考慮し、**常に操作可能な状態**とする（`display: none` としない）。
- Mermaid 図・PlantUML 図として描画されたブロックにもコピーボタンを表示し、コピー対象は元のソースとする。どちらも描画後に `<pre>` が SVG へ置き換わる（FR-023, FR-024）。
- 図の右上には、コピーボタンと並べて原寸表示・拡大画面のボタンも置く（FR-120, UI-053）。
- **編集モード（FR-140）の間は、フェンス付きのコードブロックと図の右上に、編集のボタン（鉛筆）も置く**（FR-145, UI-053）。

### FR-061: コピー動作 **MUST**

コピーボタンをクリックすると、当該コードブロックの内容をクリップボードに格納する。

- コピー対象はコードブロックの生のテキストとし、シンタックスハイライトのための HTML タグや行番号は含めない。
- **コピーされる内容は、画面に見えているコード（図では、その図として描画した原文）と一致させる。** 文書の書き手が、生 HTML でコードブロックや図の目印を装い、見えていない文字列をコピーさせる手段を与えない（NFR-030。FR-063 の `Copy link address` と同じ考え方）。
- 末尾の改行 1 つは除去する。それ以外の空白・インデントは保持する。
- コピー成功時、ボタンの表示を一時的に変化させ（アイコン変更等）、成功したことを 1.5 秒程度示す。
- コピーに失敗した場合、失敗した旨を表示する。

### FR-062: 選択範囲のコピー **SHOULD**

本文中のテキストはマウスで選択でき、`Ctrl+C` でクリップボードにコピーできる。右クリックメニューからもコピーできる（FR-063）。

### FR-063: 右クリックメニュー **MUST**

右クリックしたとき、**MarkView 自身が描くメニュー**を表示する。**WebView の標準の右クリックメニューは引き続き無効とする**（AR-060）。標準のメニューには「戻る」「再読み込み」「検証」といったページとしての操作が含まれ、ページ遷移を一切発生させない方針（AR-060）と相容れないためである。

メニューを出す場所と、そこに並べる項目は次のとおりとする。

| 場所 | 項目（上から順） |
| --- | --- |
| 本文ペイン | `Copy link address`（**リンクの上で開いたときだけ**）、`Strikethrough` と `Text color`（**編集モードの間だけ**。FR-146, FR-147）、`Copy`、`Select all` |
| 情報ウィンドウのライセンス欄（UI-101） | `Copy`、`Select all` |
| 入力欄（検索バーの入力欄 UI-080、セルの編集欄 FR-142、**コードブロックの編集欄 FR-145**） | `Cut`、`Copy`、`Paste`、`Select all` |
| **ファイルツリーの項目と、ツリールートの名前の行**（4.73.0） | FR-036 の表のとおり（見た目は UI-032） |

**上記以外の場所**（ツールバー・ファイルツリーの項目の外・アウトライン・ステータス領域・拡大画面 FR-122 など）では、メニューを出さず何も起こさない。**本文ペインの中にある入力欄**（セル・コードブロックの編集欄）で右クリックした場合は、入力欄の項目を出す。

各項目の動作は次のとおりとする。

| 項目 | 動作 | 使えない状態 |
| --- | --- | --- |
| `Copy` | 選択範囲をクリップボードに格納する。**格納する内容は `Ctrl+C`（FR-062）と同じ**とする（書式付きの内容とプレーンテキストの両方） | 選択範囲が無い |
| `Cut` | 入力欄の選択範囲をクリップボードに格納し、入力欄から取り除く | 選択範囲が無い |
| `Paste` | クリップボードのテキストを、入力欄のカーソル位置へ挿入する。**書式は持ち込まない。** セルの編集欄では改行を半角空白に置き換える（FR-142）。**コードブロックの編集欄では改行をそのまま入れる**（FR-145） | クリップボードにテキストが無い |
| `Select all` | その場所の全体を選択する。本文ペインでは**本文全体**、ライセンス欄では欄の全文、入力欄では入力欄の全文とする | — |
| `Copy link address` | リンク先を、**Markdown に書かれたとおりの形**でクリップボードに格納する（`[設計](./docs/design.md#api)` なら `./docs/design.md#api`、`[設計](./設計.md)` なら `./設計.md`）。参照リンクは定義に書かれた形とする。**解決した絶対パスにしない。百分率エンコードした形にもしない** | — |
| `Strikethrough` | 選んだ文字の取り消し線を付ける・外す（FR-146）。選択の全体が取り消し線なら、印を付けて示す | 選択が空、または修飾できる 1 つのブロックに収まっていない（FR-146） |
| `Text color` | 文字色の一覧（7 色と `Default`。FR-147）をサブメニューで出し、選んだ色を付ける・替える・外す。選択の全体が同じ色なら、その色に印を付ける | 同上 |

- 項目名は英語とする（UI-024）。見た目と操作は UI-085（ファイルツリーは UI-032）で定める。
- `Strikethrough` と `Text color` は、`Copy` の前に区切り線を挟んで並べる。**編集モードでないときは行ごと出さない**（`Copy link address` と同じ扱い）。編集モードの間は常に出し、使えないときは淡色にする（位置で覚えられるように）。
- **右クリックで選択範囲を変えない。** 文字列を選択したまま右クリックし、`Copy` を選べること。
- 使えない項目は消さずに淡色で表示し、選べないようにする。**位置で覚えられるようにするためである。** `Copy link address`（リンクの上でないとき）と、`Strikethrough` / `Text color`（編集モードでないとき）だけは、行ごと出さない。
- 項目を選んだとき、`Esc`、メニューの外のクリック（**マウスのサイドボタンを除く**。FR-051。4.81.0 で書き足した）、本文のスクロール、ウィンドウがフォーカスを失ったときに閉じる。
- 失敗した場合はステータス領域に通知する（FR-110）。
- **書かれたとおりのリンク先は、Go 側が変換時に求めて渡す。** 描画後の `href` は百分率エンコードされ、参照リンクは解決済みであり、書かれた形を失っている。フロントエンドは Markdown を解析しない（AR-031）ため、自力では求められない。**生 HTML で書かれた `<a>` は、`href` 属性の値をそのまま用いる。**
- **文書の書き手が、コピーされる文字列を偽装できてはならない**（NFR-030）。見えているリンクの遷移先と、コピーされる文字列を食い違わせる手段を与えない。

> [!NOTE]
> **`Copy` を `Ctrl+C` と同じ内容にする**のは、メニューとキーで結果が食い違うと、利用者がどちらを使ったかによって貼り付け先の見え方が変わるためである。コードブロックのコピーボタン（FR-061）がプレーンテキストだけを格納するのは、コードを貼り付ける先で書式が邪魔になるからであり、目的が違う。
>
> **リンク先を書かれたとおりにコピーする**のは、別の Markdown へ貼ればそのまま使え、かつ**利用者の環境のパス（ユーザー名を含むことがある）を漏らさない**ためである。

## 2.7 テーマ（FR-070 系）

### FR-070: テーマの切り替え **MUST**

ツールバーのテーマボタン、またはショートカット（UI-090）により、Light テーマと Dark テーマを切り替える。

- 切り替えは本文・サイドペイン・ツールバー・スクロールバーを含むアプリ全体に即座に適用される。
- コードブロックのシンタックスハイライト配色もテーマに追従する（MD-030）。
- Mermaid 図と PlantUML 図もテーマに追従して再描画する（FR-023, FR-024）。
- 文字色（FR-147）は、Dark テーマでは一覧の Dark の色で描く。
- 選択中のテーマは設定に保存する（UI-110）。

### FR-071: 初回起動時のテーマ **MUST**

設定が存在しない状態での初回起動時は、OS のテーマ設定（ダークモードの有効・無効）に追従する。判定できない場合は Light テーマとする。

## 2.8 検索・表示倍率（FR-080 系）

### FR-080: 文書内検索 **MUST**

`Ctrl+F` で検索バーを表示し、表示中の文書内をインクリメンタルに検索する。

- 大文字小文字を区別しない部分一致とする。
- 一致箇所をすべてハイライトし、現在の一致箇所を他と区別できる配色で表示する。
- `Enter` / `Shift+Enter` または検索バーのボタンで、次・前の一致箇所へ移動する。移動時は該当箇所までスクロールする。
- 「現在位置 / 総ヒット数」を表示する。ヒットしない場合はその旨を表示する。
- `Esc` で検索バーを閉じ、ハイライトを解除する。
- 検索対象は本文ペインに描画されたテキストとし、アウトライン・ファイルツリーは対象外とする。
- **折りたたみ（`<details>`。[MD-026](04-markdown.md)）の中も検索対象とし、その中の一致箇所へも移動する。** 移動の際に折りたたみを開き、**開いたものを閉じ直さない。**
- 検索対象文書の切り替え・再描画時と、表を並べ替えた後（FR-130）は検索状態をリセットする。並べ替えるとヒットの順序が本文の順序と食い違うためである。
- **図（FR-023, FR-024）と数式（MD-060）を描き終えたら、件数とハイライトを画面の実際の内容に合わせる**（4.69.0。[BUG-017](../bugs/2026-09-18-bug-017-search-hits-before-rendering.md)）。**描画は原文を図や数式へ置き換える**ため、描く前に検索していると、画面に無いものが件数に残る。
  - **描き終えて画面から消えた一致箇所は、件数から除く。** 図や数式の中は検索の対象外であり（IMP-241）、入力し直したときと同じ件数になる
  - **描けずに原文が戻った図**（取り込み指令を拒んだもの・処理系が描かなかったもの。FR-024）**は、戻った原文の中を探し直し、ハイライトを付け直す**
  - **このとき本文をスクロールしない。** 移動は利用者の操作（`Enter` / `Shift+Enter` / ボタン）でだけ行う。**現在位置が消えた場合は、文書の順でその後ろに残っている最初の一致箇所を現在位置とする**（末尾なら先頭へ回る。利用者の判断）
- **画像ファイル（FR-027）でも検索バーを開ける**（特別扱いしない）。本文に文字が無いため一致しない（読み込みに失敗したときは、代替テキストのファイル名を探せる）。PlantUML ファイル（FR-025）では図の見出しを探せる（図の中は、Markdown の中の図と同じく対象外）。

> [!IMPORTANT]
> **閉じた折りたたみの中身は、画面に無いのではなく「スクロール先として指定できない」。** 大きさも位置も持っており（実測）、**それでもスクロールは起きない。** ハイライトも件数も正しく作れるため、実装は「移動できている」と誤認しやすい。**スクロール先として指定しても何も起きず、エラーにもならない。** 折りたたみの中を数に入れる以上、そこへ行けなければならない（[調査報告](../bugs/2026-09-04-bug-004-search-collapsed-details.md)）。
>
> 同じことは**アンカーによる移動**（FR-050）と**アウトラインからの移動**（FR-041）にも当てはまる。折りたたみの中の見出しが対象になりうるためである。

### FR-081: 表示倍率の変更 **MUST**

- `Ctrl` + `+` / `-` で本文の表示倍率を拡大・縮小する。`Ctrl+0` で 100 % に戻す。
- 倍率の範囲は 50 %〜300 %、刻みは 10 % とする。
- `Ctrl` + マウスホイールでも同様に変更できる。
- 倍率は本文ペインにのみ適用し、ツールバーとサイドペインのフォントサイズは変更しない。
- **倍率は設定に保存しない**（UI-111, UI-115）。セッション内でのみ保持し、起動時は常に 100 % から始める。100 % 以外のときは倍率を画面上に表示する。

## 2.9 外部エディタ（FR-090 系）

### FR-090: 外部エディタで開く **MUST**

ツールバーの「エディタで開く」ボタン（[UI-020](03-ui.md)）、またはショートカット `Ctrl+E`（[UI-090](03-ui.md)）により、**画面が対象にしている文字のファイル（Markdown・図のファイル。[1.7](01-overview.md)）を、利用者が選んだエディタで開く。** ファイルツリーの右クリックメニューの `Open in editor...`（FR-036）からは、**ツリーで選んだ文字のファイル**を開く（4.73.0）。

- MarkView 自身は**文書を自由に編集する機能**を持たない。外部のエディタへ委譲する（[1.3.2](01-overview.md)）。**編集モードで書き換えられるのは、文書のブロックの数と種類を変えない 4 種類に限る**（FR-140）。
- 開いた後もファイルの監視（FR-014）は続く。**エディタで保存すると MarkView が自動的に再描画する。** この 2 つが組み合わさって UC-03（[1.4](01-overview.md)）が成立する。
- **対象は「画面がいま開こうとしているファイル」とする。** 本文を表示していればその文書、状態画面（[UI-052](03-ui.md)）を出していればその対象ファイルである。**ツールバーと `Ctrl+E` から開く場合は、ウィンドウタイトル（[UI-013](03-ui.md)）が示しているものと一致する。** エディタ選択ウィンドウを開いた時点の対象を控え、`Open` ではそのファイルを開く（開いている間に文書が切り替わっても変えない。FR-091）。
- **`confirm-large` / `too-large` / `render-error` の状態画面でも実行できる。** 大きすぎて開けないファイル、描画に失敗したファイルこそ、エディタで中身を確かめたい。
- **文書未表示（`welcome`）のときと、画面の対象が画像ファイル（FR-027）のとき（その確認画面などの状態画面を含む）は、ボタンを淡色にし、実行できない状態とする**（[UI-021](03-ui.md)）。前者は対象となるファイルが存在せず、後者は画像をエディタで開いても文字として読めないためである（4.73.0。利用者の判断）。
- 起動に成功した場合、ステータス領域に一時メッセージ（[DSP-151](21-display-components.md)）で「エディタ名」を出す。**エディタが背面のウィンドウで開くことがあり、何も出ないと「押しても無反応」に見える。**
- 起動に失敗した場合はステータス領域に通知し、表示中の内容は変えない（FR-110）。

**渡すのは、対象ファイルの絶対パス 1 つだけとする。** 行番号・オプション・利用者が編集できるコマンドテンプレートのいずれも持たない（[NFR-035](07-nonfunctional.md)）。

> [!IMPORTANT]
> **「表示中の文書」ではなく「画面の対象」である。** 状態画面を出している間、Go 側が保持する「表示中の文書」は**前に開いていた文書のまま**残る（[IMP-192](11-impl-backend.md)）。そちらを渡すと、利用者が `big.md — too large` の画面を見ながら押したのに、前の文書がエディタで開く。**エラーも出ないため気づけない。** 対象は [IMP-190](11-impl-backend.md) が別に保持する。

### FR-091: エディタの選択 **MUST**

ボタンを押すと、**毎回エディタ選択ウィンドウ（[UI-103](03-ui.md)）を表示する。** そこで選んだうえで `Open` を実行したときに開く。

- **開くファイルの名前を、エディタ選択ウィンドウに表示する**（4.73.0。利用者の判断）。ツールバーから開いたときもファイルツリーから開いたときも同じ形とする。ツリーから開くと、画面に出ている文書とは別のファイルを開くことがあるためである（UI-103）。**開くファイルは、ウィンドウを開いた時点で決めて控え、開いている間にドロップで文書が切り替わっても変えない**（表示している名前と開くファイルを食い違わせない。4.74.0。利用者の判断）。
- 一覧には、**インストール済みとして検出できたエディタ**（[IMP-172](11-impl-backend.md)）と、`Other...`（任意の実行ファイルを選ぶ）を並べる。
- 検出できなかったエディタも、その旨を添えて一覧に残す。消すと「なぜ自分のエディタが出ないのか」が分からない。
- `Other...` は OS 標準のファイル選択ダイアログで実行ファイルを選ぶ。**選ばれたパスはフロントエンドを経由しない**（[IMP-300](13-impl-interface.md)）。
- 選択は設定に保存し、次回の初期選択とする（[UI-116](03-ui.md)）。保存がない場合、初期選択は無い。
- `Esc`、`Cancel`、ウィンドウ外のクリックで閉じる。閉じた場合は**何も保存せず、何も起動しない。**

> [!NOTE]
> **毎回選択ウィンドウを表示する**のは、MarkView が設定画面を持たないためである（UI-116）。エディタの指定は、テーマの切り替えやペイン幅のドラッグと違って「操作した結果」が自然に定まらず、尋ねる場面がどこかに必要になる。それを**開く操作そのものと一体にする**ことで、設定項目を並べた画面を作らずに済み、変更手段が常に目の前にある状態を保てる。

ツールバー右端の「?」ボタンにより、アプリケーション情報を表示する。表示内容は以下とする。

| 項目 | 画面上のラベル | 内容 |

- テキストは選択・コピー可能とする。
- ライセンス情報は**ビルド時に生成して実行ファイルに埋め込む**（BR-040）。実行時に外部から取得してはならない。
- パッケージを追加・更新した場合にライセンス情報の更新漏れが起きないよう、CI で生成結果の差分を検査する（BR-041）。

## 2.11 エラー処理（FR-110 系）

### FR-110: エラー通知 **MUST**

以下の事象が発生した場合、利用者に分かる形で通知する。**モーダルダイアログは用いない。** 通知先は事象の性質に応じて次の 3 か所とする。

| 事象 | 通知内容 | 通知先 | 描画の継続 |
| --- | --- | --- | --- |
| ファイルが存在しない | パスと「見つかりません」 | ステータス領域（UI-060） | 直前の内容を維持 |
| ファイルの読み取り権限がない | パスと「アクセスできません」 | ステータス領域 | 直前の内容を維持 |
| 開けないファイル（開けるファイルの 3 種類に当たらない。[1.7](01-overview.md)） | パスと「対応していないファイルです」 | ステータス領域 | 直前の内容を維持 |
| 履歴の先の文書を開けない（FR-051） | パスと開けない理由（「見つかりません」など） | ステータス領域 | 直前の内容を維持し、**その項目を履歴から取り除く** |
| リンク先が見つからない（FR-050） | リンク先と「見つかりません」 | ステータス領域 | 直前の内容を維持 |
| リンク先を開けない（許可されていないスキーム、既定のアプリケーションを起動できない。FR-050） | リンク先と「開けません」 | ステータス領域 | **直前の内容を維持**（状態画面にしない） |
| 文字コードが不正 | 「一部の文字を置換しました」 | ステータス領域 | 継続する |
| 表示中ファイルが削除された | 「ファイルが削除されました」 | ステータス領域 | 直前の内容を維持 |
| コピーに失敗した | 「コピーできませんでした」 | ステータス領域 | — |
| エディタを起動できない（FR-090） | 「エディタを起動できませんでした」 | ステータス領域 | 直前の内容を維持 |
| ディレクトリをファイルマネージャで開けない（FR-036） | パスと「開けません」 | ステータス領域 | 直前の内容を維持 |
| エディタに MarkView 自身が指定された（NFR-035） | 「MarkView はエディタとして使えません」 | ステータス領域 | 直前の内容を維持 |
| 貼り付けに失敗した（FR-063） | 「貼り付けできませんでした」 | ステータス領域 | — |

| コードブロックを編集できない（前置きが行ごとに違う等。FR-145） | 編集できない理由 | ステータス領域（**警告**） | 編集欄を開かない |
| 編集欄が開いている間に、他の書き込み・文書の切り替え・編集モードの終了を操作した（FR-140, FR-145） | 「開いている編集を確定するか取り消してください」 | ステータス領域（**警告**） | 何も変えず、編集欄へフォーカスを戻す |
| 編集欄が開いている間に、ファイルが外部で変更された（FR-014） | 「外部で変更されました。編集欄を閉じると表示を更新します」 | ステータス領域（**警告**） | 再描画を保留する |

| 画像が読み込めない | 代替テキストとプレースホルダ | 本文中の該当箇所 | 継続する |
| Mermaid の構文エラー | エラー内容と元のコード | 本文中の該当箇所 | 継続する |
| PlantUML の構文エラー | **PlantUML が返すエラー図そのもの** | 本文中の該当箇所 | 継続する |

### FR-111: 異常終了の回避 **MUST**

上記いずれの事象でもアプリケーションは異常終了しない。Markdown の解析・描画処理で発生した想定外のエラーは捕捉し、エラー内容を本文ペインの状態画面（UI-052）に表示して動作を継続する。この状態からでも、ツールバー・ファイルツリー・アウトラインの操作により別の文書を開ける。

## 2.12 図と画像の拡大表示（FR-120 系）

### FR-120: 対象と操作の提供 **MUST**

Mermaid 図・PlantUML 図・本文に埋め込まれた画像・画像ファイル（FR-027）について、**本文幅に合わせて縮小した表示とは別に、原寸や拡大で見る手段**を提供する。図は大きくなりがちであり、本文幅（980 論理ピクセル。UI-050）へ縮小すると文字が読めなくなるためである。

手段は 2 つとし、対象ごとに次のときに提供する。

| 対象 | 原寸表示（FR-121） | 拡大画面（FR-122） |
| --- | --- | --- |
| Mermaid 図（描画に成功したもの） | 縮小表示中と原寸表示中 | **常に** |
| PlantUML 図（**エラー図を含む**。FR-024） | 縮小表示中と原寸表示中 | **常に** |
| 本文に埋め込まれた画像（読み込みに成功したもの） | 縮小表示中と原寸表示中 | **縮小表示中と原寸表示中だけ** |
| 画像ファイル（FR-027。読み込みに成功したもの。4.73.0） | 縮小表示中と原寸表示中 | **常に** |

- **「縮小表示中」とは、対象の本来の幅が、本文での表示幅を超えている状態をいう。** ウィンドウ幅やペイン幅の変更で変わりうるため、そのたびに判定し直す。
- 操作は、対象の右上にコピーボタン（FR-060）と並べて置くボタンで行う（UI-053）。**対象そのもののクリック・ダブルクリックには割り当てない。** 図の中の文字の選択や、画像をリンクで囲んだ記法（MD-071）とぶつかるためである。**原寸表示と拡大画面の操作は、編集モードの間もボタンだけで行う。** 編集モードの間の、コードブロックと図のダブルクリックによる編集欄の開き方は FR-145 で定める（閲覧中は今どおり、図の中の文字をダブルクリックで選べる。4.73.0）。
- **画像のボタンを縮小表示中に限る**のは、段落の中に並ぶアイコンやバッジ（shields.io 等）にまでボタンが付き、本文が繁雑になるのを避けるためである。原寸で出ている画像は、大きく見る理由が薄い。
- 次のものは対象にしない。描画に失敗した Mermaid 図（コードブロックのまま。FR-023）、描画しなかった PlantUML 図（取り込み指令・大きすぎる図。FR-024）、読み込みに失敗した画像（DSP-123）、描画を待っている図、数式（MD-060）。
- **表示済みの図・画像をそのまま使う。** 図の再描画、画像の再取得、Go 側での変換を行わない（NFR-013, NFR-032）。
- 文書・ファイルを変更しない。編集モード（FR-140）とは無関係に使える。
- 再描画（FR-014, FR-015）の前後で「**同じ対象**」とは、**文書の中で同じ種類のもの（Mermaid 図・PlantUML 図・画像）のうち、同じ順番にあるもの**をいう。FR-121 と FR-122 はこの意味で状態を引き継ぐ。
  - **順番は、描画に成功したかどうかに関わらず数える。** Mermaid 図と PlantUML 図は**文書に描画される順**（描画に失敗したもの・描画しなかったものを含む。**脚注の中のものは脚注の一覧の位置で数え、参照されていない脚注の定義の中のものは描画されないため数えない**。[BUG-027](../bugs/2026-11-08-bug-027-footnote-edit-ref-order.md)。4.81.0 で下位に合わせた）、画像は本文中の画像の順（読み込みに失敗したものを含む）とする。成否で数え方を変えると、1 つの図が壊れただけで後ろの図がすべて「別の対象」になる
  - **図は描画が非同期である。** 引き継げるかどうかの判断は、再描画後にその図の描画が終わってから（成功・失敗のどちらでも）行う。描画を待っている間に「見つからない」と判断しない

### FR-121: 本文中での原寸表示 **MUST**

- ボタンで、その対象だけを**縮小表示と原寸表示の間で切り替える。**
- 原寸表示では、対象を**本来の大きさ**で描く。本文幅を超える分は、**その対象の枠の内側で横スクロール**させる。ページ全体に横スクロールを発生させない（UI-050。表の MD-024 と同じ扱い）。
- 「本来の大きさ」は論理ピクセルで数え、**表示倍率（FR-081）の影響を受けない**。図と画像は倍率に追随しない（DSP-021）ためである。
- 状態は対象ごとに持つ。**テーマの切り替え（FR-070）では維持する**——図は再描画されるが、利用者から見れば同じ図である。
- **同じ文書の再描画（[1.7](01-overview.md)。編集モードでの書き込みによるものを含む）でも、同じ対象（FR-120）が再描画後にもあれば原寸表示を保つ。** 編集のたびに図が縮小表示へ戻ると、読んでいた箇所を見失うためである（FR-130 の並べ替えと同じ考え方）。
- **文書の切り替え**（[1.7](01-overview.md)）では縮小表示に戻す。
- 状態は設定に保存しない（UI-111）。

### FR-122: 拡大画面 **MUST**

- ボタンで、対象 1 つだけを表示する**拡大画面**を開く。**メインウィンドウ内に描画する画面であり、独立した OS ウィンドウではない**（AR-001, AR-060）。情報ウィンドウ（UI-100）と同じ位置づけであり、Wails v2 は 2 つ目のウィンドウを持てない。
- 拡大画面は、**ステータス領域を除く**メインウィンドウいっぱいを使う（UI-104）。**開いている間に出た通知（FR-110）を見落とさないためである。**
- **開いた時点では、対象の全体が画面に収まる倍率**で中央に表示する。小さな図は拡大され、大きな図は縮小される。まず全体を見てから、必要な箇所へ寄る使い方を想定する。その倍率が下の範囲を外れる場合は、範囲の端に丸める。
- 拡大画面では次の操作ができる。操作の割り当ては UI-104 で定める。
  - 拡大・縮小（ボタン、キー、マウスホイール）。**ホイールではカーソルの位置を中心に**拡大・縮小する
  - 「全体」（開いた時点と同じ、全体が収まる倍率）と「原寸」（100 %）への切り替え
  - ドラッグと方向キーによる表示位置の移動
- 倍率の範囲は **10 %〜1000 %** とし、現在の倍率を画面に表示する。
- **図は SVG のまま拡大し、拡大しても輪郭をぼやけさせない。** 画像はラスタのまま拡大してよい（ぼやけることを許容する）。
- **画像ファイル（FR-027）から開いたときは、画像の範囲に市松模様を敷く**（4.73.0）。埋め込み画像から開いたときは敷かない。
- `Esc` と閉じるボタンで閉じる。閉じたとき、**本文のスクロール位置を開く前のまま保ち、フォーカスを開いたボタンへ戻す。** 開いている間に再描画されて開いたボタンが無くなっていれば、同じ対象（FR-120）のボタンへ戻し、それも無ければ本文ペインへ戻す。
- 開いている間は、背後のメインウィンドウの操作を受け付けない（UI-100 と同じ。**ファイルのドロップを除く**。UI-090）。同時に開ける拡大画面は 1 つとし、**情報ウィンドウ・エディタ選択ウィンドウとも同時には開かない。** 開いたときは、ファイルツリーのフィルターの枚（UI-033）を閉じる。
- 開いている間に表示中の文書が再描画された場合（同じ文書の再描画。[1.7](01-overview.md)。外部の更新や、同じファイルのドロップ）、**同じ対象（FR-120）が再描画後にもあれば中身を差し替え、倍率と表示位置を保つ（SHOULD）。** 外部エディタで図を書き直しながら拡大画面で確かめる使い方（UC-03）のためである。見つからなければ閉じる。**文書の切り替え**（[1.7](01-overview.md)。開いている間にファイルがドロップされた場合など）では閉じる。
- 倍率と表示位置は設定に保存しない（UI-111）。

> [!NOTE]
> **本文中の原寸表示（FR-121）と拡大画面（FR-122）の両方を持つ**のは、見たいものが違うからである。原寸表示は**本文を読む流れのまま**図の細部を追うためのものであり、本文幅（980 論理ピクセル）より広くは見られない。拡大画面は**ステータス領域を除くウィンドウいっぱい**を使い、原寸を超えて拡大できる。

## 2.13 表の並べ替え（FR-130）

### FR-130: 表示上の並べ替え **SHOULD**

GFM の表（MD-024）を、列を選んで並べ替えて表示できる。**並べ替えるのは表示だけであり、ファイルは書き換えない。** 編集モード（FR-140）でなくても使える。

- 見出し行の各セルに並べ替えのボタンを置く（UI-054）。**見出しセル全体のクリックには割り当てない。** 編集モードでのセルの編集（FR-142）と操作がぶつかるためである。
- ボタンを押すたびに、その列で **昇順 → 降順 → 元の順** を巡回する。並べ替えの基準にする列は 1 つの表につき 1 列とし、別の列のボタンを押すと、その列の昇順から始める。
- 対象は、見出し行を除く行が 2 行以上ある表とする。
- 比較は、セルに**表示されている文字列**で行う。
  - 両方が数値として解釈できる場合は、数値として比べる。前後の空白を除き、桁区切りの `,` と末尾の `%` を無視したうえで 10 進数として解釈できるものを数値とする（`-1.5`、`1,234`、`10%`）
  - それ以外は文字列として比べる。大文字と小文字を区別せず、文字列の中の数字の並びは数値の大小で比べる（`item2` は `item10` より前）
  - 数値と文字列が混ざる場合は、昇順では数値を先に、降順では文字列を先に置く（降順は昇順の逆順とする）
  - **ただし空のセルは、昇順・降順のどちらでも末尾に置く**（逆順の例外）
  - 比較して等しい行は、元の順序を保つ
- どの列を、どちら向きに並べ替えているかを見出しセルに表示する。
- **文書の切り替え**（[1.7](01-overview.md)）で解除する。**同じ文書の再描画（[1.7](01-overview.md)）では、再描画後も同じ順番の表（文書の中で何番目の GFM の表か）の列数が変わっていなければ状態を保つ。** 編集のたびに行の並びが元へ戻ると、いま直した行を見失うためである。状態の保ち方は再描画の契機で分ける。
  - **編集モードでの書き込み（FR-141〜FR-147）による再描画では、並べ直さない。** 直前の行の並びをそのまま保つ。**並べ替えの基準にしている列のセルを直しても、その行は動かない**（並べ替えの順から外れうる）。見出しセルの表示は並べ替え中のままとし、次にボタンを押したときに巡回の次の段へ進んで並べ直す
  - **それ以外の再描画**（外部の更新・再読み込み・同じファイルの開き直し）では、保った列と向きで並べ直す
  - 再描画後に、見出し行を除く行が 2 行未満になった場合、または列数が変わった場合は解除する
- 並べ替えたら、検索の状態をリセットする（FR-080）。
- 状態は設定に保存しない（UI-111）。
- **生 HTML で書かれた表（`<table>`。MD-072）は対象にしない。** 見出し行と本体の行の区別や、セルの結合の有無が保証されないためである。**文書の書き手が、生 HTML で並べ替えの対象を装えてはならない**（NFR-030）。

## 2.14 編集モード（FR-140 系）

> [!IMPORTANT]
> **MarkView は閲覧に特化したアプリケーションであり、文書を自由に編集する機能は持たない**（[1.3.2](01-overview.md)）。本節の編集は、**次の 4 種類に限る。いずれも文書のブロックの数と種類を変えない。**
>
> 1. タスクリストのチェックボックス（FR-141）
> 2. 表のセルの文字（FR-142）
> 3. **コードブロックと図の中身**（FR-145）。言語指定と囲いの種類は変えない（囲いの長さだけは中身に合わせて延ばす）。PlantUML ファイルの図と Mermaid ファイルも含む
> 4. **1 つのブロックの中で選んだ文字の取り消し線と文字色**（FR-146, FR-147）。書くのは `<del>` と決めた色の `<span>` を差し込む・取り除くことだけで、文字そのものは変えない
>
> **段落や見出しの文字の書き換え、ブロックの追加・削除・移動、リストや表の構造、リンク先、画像は、これまでどおり外部エディタへ委ねる**（FR-090）。2〜4 は、書き込む内容を解き直して、構造が変わらないことを確かめてから書き込む（FR-143。2 は 4.43.0 から表の形を確かめている）。**「構造を変えない」を、規則だけでなく確かめで保証する。**
>
> **対象を増やすときは、本節の改訂から始める。** 「ついでにここも直せるように」と足していくと、境界が消えてエディタになる。**4.39.0 では 1・2 の 2 種類だったが、4.73.0 で 3・4 を加えて 4 種類にした**（利用者の判断。v1.2.0）。

### FR-140: 編集モード **MUST**

**表示中のファイルへの書き込みは、編集モードの間だけ行う。** 編集モードでない間の振る舞いは、本節を加える前と変わらない（チェックボックスは読み取り専用で、セル・コードブロック・図は編集できず、修飾の操作は使えない）。

- ツールバーの編集モードボタン（UI-020）、またはショートカット `Ctrl+Shift+M`（UI-090）で、編集モードの開始と終了を切り替える。
- **起動時は常に編集モードでない。** 状態を設定に保存しない（UI-111）。受け取った文書を読むだけのつもりで開いたときに、書き換えられる状態で始まってはならない。多重起動（UI-115）で後勝ちになる値にしないためでもある。
- 編集モードを開始できるのは、**文書を描画している状態**に限る。次の状態では開始できない（ボタンを淡色にする。UI-021）。

| 状態 | 開始できない理由 |
| --- | --- |
| 文書未表示と状態画面（`welcome` / `confirm-large` / `too-large` / `render-error`。UI-052） | 書き換える対象が描画されていない |
| 読み込みの際に不正なバイト列を置き換えた文書（FR-021） | **表示している内容と、ファイルの内容が一致していない** |
| 表示中のファイルが削除された（FR-014） | 書き込み先が無い |
| **画像ファイル**（FR-027。4.73.0） | 書き換える対象を持たない（画像は編集しない。利用者の指示） |

- 次のときは、**自動的に編集モードを終える。**
  - **文書の切り替え**（[1.7](01-overview.md)）が起きたとき。**利用者が「この文書を直す」と決めた文書だけを書き換えるためである。** リンクで移った先の文書が、書き換えられる状態で開いてはならない。切り替え先が状態画面（UI-052）であっても終える
  - 上の表の「開始できない状態」になったとき（読み直した結果、不正なバイト列を含んでいた場合や、ファイルが削除された場合）。**編集欄が開いていれば、利用者が編集欄を閉じた時点で終える**（下記）
- **次のときは終えない。**
  - 同じ文書の再描画（FR-014, FR-015）。編集モードでの書き込みも FR-014 の経路で再描画されるためである
  - 同じファイルを開き直したとき、同じ文書の中のアンカーへ移ったとき（文書の切り替えに当たらない。[1.7](01-overview.md)）
  - **保存に伴う一時的な削除。** 「一時ファイルへ書いてからリネームする」保存（FR-014）では、途中でファイルが一瞬存在しなくなる。**MarkView 自身の書き込み（FR-143）も同じ形になりうる。** 「削除された」と判断するのは、FR-014 の待ち（デバウンス）を経てもファイルが存在しないときに限る
- **編集欄（FR-142, FR-145）が開いている間の操作は、次の表のとおり扱う**（4.73.0 / 4.74.0。利用者の判断）。「拒む」ときは、何もせずに、開いている編集を確定するか取り消すよう促し（警告。FR-110）、フォーカスを編集欄へ戻す。**ただし情報ウィンドウ・エディタ選択ウィンドウ・拡大画面の表示中（ドロップを受けた場合）は、フォーカスを動かさない。**

| 扱い | 操作 |
| --- | --- |
| **拒む** | 文書を切り替える操作（ファイルツリー・リンク（**同じ文書の中のアンカーを除き、外部の URL・開けないファイルへのリンクも拒む**——画面の側ではリンク先の種類を判定しないため。4.76.0。利用者の判断）・戻る / 進む（ボタン・サイドボタン・`Alt+←` / `Alt+→`）・ドロップ・ファイル選択ダイアログ・ツリーの右クリックメニューの `Open`）、**同じファイルの開き直し**（同じ経路で同じファイルを開く）、**再読み込み**（FR-015）、他の書き込み（チェックボックス・別の編集欄・修飾・編集欄の外からのファイルの取り消しとやり直し）、編集モードの終了（ボタンと `Ctrl+Shift+M`）、**表の並べ替え**（FR-130） |
| **保留する**（編集欄を閉じた時点で当てる） | 外部の更新による再描画（FR-014）、MarkView 自身の書き込みの直後の再描画 |
| **編集欄を保ったまま行う** | テーマの切り替え（FR-070）、文書内検索（FR-080）、ツリーの展開とフィルター（FR-032, FR-037）、拡大画面を開くこと（FR-122）など、表示中の文書を差し替えない操作 |

- **自動で編集モードを終える状態（ファイルの削除・不正なバイト列）になっても、編集欄が開いていれば、編集欄は入力ごと残す**（FR-014。4.74.0。利用者の判断）。確定は書き込まずに拒み（入力は写し取れる）、**利用者が編集欄を閉じた時点で編集モードを終える。**
- **これで、開いている編集欄の入力を MarkView が黙って捨てる場面は無くなる**（アプリケーションの終了を除く。モーダルダイアログで保存を尋ねない。FR-110）。上の「自動的に編集モードを終える」は、切り替えが起きる前に止める形で保つ。
- 編集モードの間は、そのことを画面上で常に明示する（ツールバーのボタンの ON 表示と、本文ペインの表示。UI-021, UI-055）。
- 編集モードを終えたら、取り消しの履歴（FR-144）を破棄する。

### FR-141: タスクリストのチェックボックスの切り替え **MUST**

- 編集モードの間、タスクリスト（MD-022）のチェックボックスをクリックする（またはフォーカスして `Space` を押す）と、状態を反転してファイルへ書き込む。
- **チェックボックスの見た目は、書き込みの完了を待たずに即座に反転する**（NFR-012）。ファイルから読み直した再描画は、その後に FR-014 の経路で行う。書き込みに失敗したら見た目を戻す（FR-143）。
- 書き換えるのは、その項目の **`[ ]` / `[x]` の括弧の中の 1 文字だけ**とする。オンにするときは `x`（小文字）を、オフにするときは半角空白を書く。`[X]`（大文字）はオンとして扱い、オフにすると半角空白になる。
- **対象は GFM のタスクリストの項目に限る。** 生 HTML で書かれた `<input type="checkbox">`（MD-072）は、編集モードの間も読み取り専用のままとする。
- **文書の書き手が、書き換えの対象を偽装できてはならない**（NFR-030）。どれがタスクリストの項目かを、描画後の HTML の**属性の有無や形だけで**判断しない（変換ごとの鍵と照合する。IMP-120）。
- **編集欄（FR-142, FR-145）が開いている間は、切り替えを受け付けない**（FR-145。見た目も変えない）。
- 書き込みは FR-143 の規則に従う。

### FR-142: 表のセルの書き換え **MUST**

- 編集モードの間、GFM の表（MD-024）のセル（**見出し行のセルを含む**）を**ダブルクリック**すると、そのセルの編集欄を開く。
- **セルの中にあるボタン**（並べ替えのボタン UI-054、画像の原寸表示・拡大画面のボタン UI-053）**の上でのダブルクリックでは、編集を始めない。** ボタンを素早く 2 回押す操作と区別がつかないためである。
- **編集モードの間は、表のセルの中のリンクをクリックしても遷移しない**（FR-050 の例外）。ダブルクリックの 1 回目でリンク先へ移ると、編集を始める前に文書が切り替わり、編集モードが終わるためである。リンクをたどるときは編集モードを終える。
- 編集欄には、そのセルの **Markdown のソース**（`**太字**` のような記法を含み、前後の空白を除いたもの）を入れた状態で開く。描画後の文字列ではない。
- 編集欄は 1 行とし、下に `Save` と `Cancel` のボタンを置く（4.73.0。利用者の判断）。**`Enter` か `Save` で確定してファイルへ書き込み、`Esc`（編集欄にフォーカスがあるとき）か `Cancel` で取り消す。**
  - **編集欄からフォーカスが外れても、編集欄は開いたままとし、書き込みも取り消しもしない**（4.73.0。利用者の判断。コードブロックの編集欄（FR-145）と同じ動作にそろえた）。**4.72.0 までは、フォーカスが外れたら取り消していた。** 確定は利用者の明示的な操作でだけ起きるため、意図しない確定を起こさないことは変わらない
  - 編集欄で開いた右クリックメニュー（FR-063）を、項目の実行・`Esc`・本文のスクロールで閉じたとき、ウィンドウへ戻ったとき（ウィンドウがフォーカスを失ってメニューが閉じた場合を含む）は、編集欄へフォーカスを戻す（`Paste` の後に続けて入力できるように）。メニューの外をクリックして閉じた場合は、フォーカスはクリックした先へ移り、編集欄は開いたまま残る（UI-085）
  - **編集欄にフォーカスがある間の `Enter` は確定だけに使い、検索の移動（FR-080）には使わない。** 検索バーを開いたままセルを編集しても、`Enter` で検索のヒットへ移らない
  - **IME の変換中の `Enter` と `Esc` は変換の操作であり、確定にも取り消しにも使わない。** 日本語の変換を確定した `Enter` で書き込みが起きてはならない
- 確定したら、**セルの見た目は書き込みの完了を待たずに新しい内容へ変える**（NFR-012）。表示するのは、確定した文字列をそのまま文字として出したものでよく、記法の描画はファイルから読み直した再描画（FR-014 の経路）で行う。書き込みに失敗したとき・表の形の確かめで拒まれたとき（FR-143）は、**入力を捨てず、編集欄を入力ごと開き直して理由を出す**（4.74.0。利用者の判断）。
- 書き換えるのは**そのセルのソースの範囲だけ**とする。区切りの `|`、セルの前後の空白、他のセル、区切り行（`---`）、表の外は変えない。**桁を揃えるための空白を詰め直さない。**
- 入力された文字列は次のとおり扱う。
  - エスケープされていない `|` は、表の区切りにならないよう `\|` として書き込む
  - 改行は入力できない。貼り付け（FR-063）で持ち込まれた改行は、半角空白に置き換える
  - 内容が変わっていなければ書き込まない
  - 空にしてよい（空のセルになる）
- 次のセルは編集できない。
  - **ソース上に存在しないセル。** 行のセルの数が見出し行より少ないとき、GFM の規則で補われる空のセルがこれに当たる。書き込むには区切りの `|` を足すことになり、表の形を変えるためである
  - 生 HTML で書かれた表（`<table>`）のセル
- 表を並べ替えている間（FR-130）も、**表示上の位置ではなくソース上の位置で**、正しいセルを書き換える。
- **セルの編集欄が開いている間の操作は、FR-140 の表に従う**（4.73.0）。外部の更新を保留している間の確定は受け付けず（FR-014）、**入力は編集欄に残る。** ファイルの削除などで編集モードを終える状態になっても、編集欄は入力ごと残す（FR-140）。
- 書き込みは FR-143 の規則に従う。

### FR-143: 書き込みの規則 **MUST**

FR-141 / FR-142 / FR-144 / FR-145 / FR-146 / FR-147 のすべての書き込みは、次の規則に従う。

- **書き込む前に、ファイルの現在の内容が、MarkView が把握している内容と一致することを確かめる。** 「把握している内容」とは、**最後に読み込んだ内容、またはその後に MarkView 自身が書き込んだ内容**のうち新しいほうをいう。一致しない場合（外部のエディタや別の MarkView が先に保存した場合）は**書き込まず**、その旨を通知し（FR-110）、ファイルを読み直して再描画する（編集欄の確定では、編集欄を入力ごと開き直す。再描画は、編集欄を閉じるまで保留する。FR-014）。**他者の変更を黙って上書きしない。**
- **再描画を待たずに続けて操作した場合も、各操作は直前の書き込みを反映した内容に対して行う。** 書き換える位置は操作のたびに求め直し、前の書き込みで位置がずれたセルやチェックボックスを取り違えない。続けてクリックしただけで「ファイルが変更されていた」と誤って拒まない。
- **MarkView 自身による表示中ファイルの読み直し（FR-014, FR-015, 同じファイルの開き直し）と書き込みは、1 つずつ順に行う。** 読み直しの途中に書き込みが割り込まないようにし、「把握している内容」との比較は読み込みを終えた時点の値で行う。**割り込ませると、自分の書き込みを「外部の変更」と取り違え、取り消しの履歴を誤って捨てる**（FR-144）。
- **書き込みの指示は、それが作られた描画に対してだけ有効とする。** 次の指示は Go 側で拒み、何も書き込まない。編集モードでないときに届いた指示、状態画面（UI-052）の表示中に届いた指示、**その指示を作った描画の後に、文書の切り替えか、MarkView 自身の書き込み以外を契機とする再描画（外部の更新・再読み込み・開き直し）が起きていた場合の指示**である。**MarkView 自身の書き込みの直後の再描画では、それより前の描画で作った指示を有効なまま保つ**——構造を変えない編集では何番目の要素かは変わらず（2.14 の IMPORTANT。4 種類の書き換えはどれも文書のブロックの数と種類を変えず、タスク・表・セル・コードブロック・図・修飾できるブロックを増減しない。FR-145〜FR-147 は下の確かめでそれを保証する）、位置は書き込みのたびに求め直すためである（上記）。保たないと、続けてクリックしただけで 2 つ目が拒まれる。見た目を先に変えるため（FR-141, FR-142）、指示は描画より遅れて届くことがあり、**その間に表示が別の文書へ切り替わっていれば、画面に無い文書を書き換えることになる。** 拒んだことは通知しない（見た目は最新の描画に従う）。
- **書き込みは、書き込み先と同じディレクトリに作った一時ファイルへ内容の全体を書き出し、リネームで置き換える。** 途中で失敗しても元のファイルが残るためである。
  - **元のファイルが書き込み可能でなければ、置き換えない**（読み取り専用の扱い）。ディレクトリに書き込めれば置き換え自体はできてしまうが、利用者が書き込みを禁じたファイルを書き換えてはならない
  - ディレクトリに書き込めない場合は、書き込めないものとして通知する（FR-110）
  - 置き換えた後のファイルの権限ビットは、元のファイルに合わせる（**SHOULD**。下の「ファイルの権限を変えない」）
  - **ハードリンクは切れ、Windows でファイル個別に設定したアクセス制御は引き継がれない。** これは許容する。一部だけが書かれたファイルを残さないことを優先する
- **書き換える箇所以外のバイト列を 1 バイトも変えない。** BOM の有無、改行コード（CRLF / LF / CR）、末尾の改行、Front Matter（MD-073）、ソース上の空白をそのまま残す。**読み込み時の正規化（FR-021）を書き戻さない。**
- シンボリックリンクを開いている場合は、**リンク先の実体**を書き換える。リンクそのものを通常のファイルで置き換えない。
- 書き込みに失敗した場合（読み取り専用、権限が無い、他のプログラムが開いている等）は、通知し（FR-110）、表示を書き込み前の状態に戻す。**書きかけの状態（一部だけが書かれたファイル）を残さない。**
- ファイルの権限を変えない（**SHOULD**）。
- 書き込みに使う一時ファイル（上記）は、**成功しても失敗しても、書き込みが終わった後に残さない。** バックアップファイルを作らない。
- **セルの書き換え（FR-142）、コードブロック・図の書き換え（FR-145）、修飾（FR-146, FR-147）は、書き込む内容を作ったら、それを解き直して次を確かめ、満たさなければ書き込まない**（FR-110 で通知する。4.73.0）。文書の中のブロックの数と種類、表・タスク・コードブロック・図の数が変わらないこと（セルでは表の形が変わらないこと）。書き換えた要素以外の中身が変わらないこと。**修飾ではさらに**、そのブロックの見えている文字が 1 文字も変わらないこと、インラインの要素（太字・斜体・リンク・コード・画像など）の並びとハード改行の数が変わらないこと、選んでいない文字の取り消し線と色が変わらないこと（**手書きの取り消し線を全体で外したとき（FR-146）は、外れた範囲を選んだ文字とみなし、その取り消し線をインラインの要素の並びの比べから除く**。4.78.0）。**規則で「壊れない」と言えても、パーサの実装に依存する部分を規則だけで保証しない**（4.43.0 で、セルのエスケープの規則がパーサと食い違っていた）。
- 書き込んだ後は、**監視のイベントを待たずに** FR-014 の再描画の処理を呼び、スクロール位置を維持する（FR-014）。
- **内容が変わらない書き込みはしない**（同じ内容のセルの確定、同じ色を選ぶ、色の無い文字に `Default` を選ぶなど。4.74.0）。読んだだけのファイルに変化を残さない（NFR-042）。
- **書き込み先は、Go 側が保持する表示中のファイルだけとする。フロントエンドから書き込み先のパスを受け取らない。** フロントエンドが伝えるのは「どの要素か（チェックボックス・セル・コードブロック・図・修飾するブロックと選んだ位置）」と、新しい文字列や操作の種類と、修飾では照合のためのブロックの見えている文字の全体（FR-146）だけである（AR-031, IMP-300 と同じ考え方）。**書き込み先が画面の対象（FR-090 の IMPORTANT）と一致することは、上の「指示を作った描画に対してだけ有効」によって保証する。**

### FR-144: 元に戻す・やり直す **MUST**

- 編集モードの間、`Ctrl+Z` で直前の書き込みを取り消し、`Ctrl+Y` または `Ctrl+Shift+Z` で、取り消した書き込みをやり直す。**取り消しとやり直しも、それ自体がファイルへの書き込みであり、FR-143 に従う。**
- 対象は FR-141 / FR-142 / FR-145 / FR-146 / FR-147 の書き込みとする。1 回の操作（チェックボックス 1 つ・セル 1 つの確定・コードブロック 1 つの確定・修飾 1 回）を 1 回で取り消す。
- **入力欄（セル・コードブロックの編集欄・検索バーの入力欄）にフォーカスがある間は、入力欄の中の取り消しとして働き**、ファイルの取り消しは行わない。**編集欄が開いている間は、編集欄の外にフォーカスがあっても、ファイルの取り消しとやり直しを受け付けない**（FR-145）。
- 履歴は**メモリ上だけ**に持ち、ディスクに書かない（NFR-042）。保持する上限は 100 操作とし、超えたら古いものから捨てる。
- **履歴は書き換えた箇所の差分（位置と、前後の文字列）で持ち、文書全体の写しを持たない。** FR-143 の「把握している内容」との一致も、内容の要約値（ハッシュ）で確かめ、内容の写しを保持しない。**最大 50 MB の文書（FR-016）でも、編集のためにメモリ使用量が文書の大きさに比例して増えないようにする**（NFR-020）。
  - **例外として、コードブロックと図の書き換え（FR-145）では、1 回の記録がそのブロックの大きさになる**（PlantUML ファイルの図ではその図、**Mermaid ファイルではファイル全体**）。**大きさの上限は設けない**（4.73.0。利用者の判断。NFR-020）。巨大なコードブロックや図を書き換えるほど、取り消しの履歴は大きくなる。同梱の Mermaid は既定で 50,000 文字を超える図を描かないため、Mermaid ファイルで書き換えるのはほとんどが数十 KB までの図である。理論上の最悪（50 MB のファイルを 100 回書き換える）は受け入れる
- 取り消した後に新しく書き込んだら、やり直しの履歴を捨てる。
- 次のときは履歴を破棄する。
  - 編集モードを終えたとき（FR-140）
  - **ファイルが MarkView の書き込み以外で変更されたと分かったとき**（同じ文書の再描画（[1.7](01-overview.md)）で読み直した結果が「把握している内容」（FR-143）と一致しない場合と、FR-143 の書き込み前の確認で一致しなかった場合）。**他者の変更の上から、古い状態を書き戻さないためである**
- 取り消すもの・やり直すものが無いときは、何もしない（通知しない）。
- 編集モードでないときの `Ctrl+Z` / `Ctrl+Y` / `Ctrl+Shift+Z` は、何もしない。

### FR-145: コードブロックと図の書き換え **MUST**

編集モードの間、フェンス付きのコードブロック（MD-030）と図（Mermaid・PlantUML のブロック。FR-023, FR-024）の**中身**を、その場の編集欄で書き換えられるようにする（4.73.0）。PlantUML ファイル（FR-025）の図と Mermaid ファイル（FR-026）も含む。

| 対象 | 書き換える範囲 |
| --- | --- |
| フェンス付きのコードブロック（` ``` ` / `~~~`） | 開きと閉じの囲いの間の行（中身） |
| Markdown の中の Mermaid / PlantUML のブロック | 同上 |
| PlantUML ファイルの図（MD-086） | **`@start…` の行から `@end…` の行まで**（図の名前を直せるように、この 2 行も含める）。`@end…` の行が無い図は、ファイルの終わりまで（MD-086 の 4）。図の外の行は変えない |
| Mermaid ファイル（MD-087） | **ファイル全体**（先頭の BOM は除き、末尾の改行を含む。改行コードはファイルのものにそろえる。FR-143） |

- **対象にしないもの**: 字下げ形式のコードブロック、` ```math ` の数式ブロック、生 HTML の `<pre>`（MD-072）。**言語指定（開きの囲いの後ろの文字列）と囲いの種類は書き換えない**（利用者の判断）。
- **開き方**: 対象を**ダブルクリック**するか、右上の**編集のボタン**（鉛筆。UI-053）を押す。図をダブルクリックで開くのは編集モードの間だけであり、閲覧中は今どおり図の中の文字をダブルクリックで選べる（FR-120）。**右上のボタン（コピー・原寸表示・拡大画面・編集）の上でのダブルクリックでは編集を始めない**（FR-142 と同じ）。**編集モードの間は、図の中のリンクをクリックしても遷移しない**（FR-050。ダブルクリックの 1 回目で文書が切り替わらないように）。
- **編集欄**は対象の位置にその場で重ね、ハイライトの無い等幅の複数行の入力欄とし、下に `Save` と `Cancel` のボタンを置く（UI-055）。編集欄には、書き換える範囲のソースを、ハイライトを付けずにそのまま入れる。**ただし引用やリストの前置きは除き、改行は LF にそろえ、Markdown の中のブロックでは最後の行の改行を含めない**（書き戻すときに付け直す。値と書き戻し方は IMP-122 の表。4.78.0 で明記した）。
  - **`Ctrl+Enter` か `Save` で確定し、`Esc`（編集欄にフォーカスがあるとき）か `Cancel` で取り消す。** `Enter` は改行である。`Tab` は字下げに使うため、キーボードで編集欄を開いたまま外へ出る手段は持たない（確定か取り消しで閉じる）
  - **フォーカスが外れても開いたまま**とし、書き込みも取り消しもしない（FR-142 と同じ）
  - `Tab` / `Shift+Tab` で字下げを入れる / 外す（タブ文字。複数行を選んでいれば各行）
  - IME の変換中のキーには何も割り当てない（FR-142 と同じ）。貼り付けた改行はそのまま入れる（FR-063）
- **囲いとの衝突**: 中身の行の頭（字下げは半角空白 3 つまで。タブを含む字下げも数える）に、囲いと同じ文字の、囲い以上の長さの並び（` ``` ` の囲いの中の ` ``` ` など）を書いた場合は、**開きと閉じの囲いを、中身の最も長い並びより 1 つ長くする**（利用者の判断）。閉じの囲いが無いブロック（文書や引用の終わりで閉じたもの）は、開きの囲いだけを延ばす。**行の途中の並びと、半角空白 4 つ以上の字下げの後ろの並びは囲いを閉じないため、延ばさない**（IMP-122 の 5。4.81.0 で書き足した）。
- **引用やリストの中のブロック**では、書き込む各行の前に、そのブロックの行頭の前置き（引用の `> ` やリストの字下げ）を付ける。**前置きが行ごとに違うブロック、タブの一部だけが字下げに使われているブロック、前置きを決められないブロック（リストの中で、中身の行も閉じの囲いも無いもの。4.81.0 で書き足した）は、編集できないものとする**（編集のボタンを淡色にし、ダブルクリックでは編集できない理由をステータス領域に出す。利用者の判断）。書き換えの規則を手で作ると、パーサと食い違いうるためである。
- 入力の改行は、そのブロックの改行コードにそろえる（FR-143 の「書き換える箇所以外を変えない」を、書き換える箇所の中でも崩さない）。内容が変わっていなければ書き込まない。
- 確定したら、**書き込みの完了を待たずに、入力した文字列を素の等幅の文字として表示する**（NFR-012）。ハイライトと図の描画は、ファイルから読み直した再描画（FR-014 の経路）で戻る。**書き込みに失敗したとき・書き込む内容の確かめで拒まれたとき（FR-143）は、入力を捨てず、編集欄を入力ごと開き直して理由を出す**（4.74.0。利用者の判断）。
- **PlantUML ファイルの図**は、書き込む内容の図の数が変わらないことを確かめる（`@enduml` を消して 2 つの図がつながる、などを拒む）。**Mermaid ファイル**は、書き込む内容が空白だけにならないこと（図が無くならないこと。MD-087 の 3）を確かめる（Go 側は Mermaid の構文を解かない。AR-031）。
- **編集欄は同時に 1 つだけ**とする（セルの編集欄を含む）。**編集欄が開いている間の操作は、FR-140 の表に従う**（他の書き込み・文書の切り替え・同じファイルの開き直し・再読み込み・編集モードの終了・表の並べ替えを拒み、外部の更新と自分の書き込みの直後の再描画を保留する。利用者の判断）。
- **外部の更新による再描画は保留し**（FR-014）、**保留の間の確定は受け付けない**（編集欄を閉じず、警告を出し直す。入力は編集欄に残る）。利用者は入力を写し取ってから `Cancel` で閉じ、閉じた時点で保留していた内容で再描画する。ファイルが削除された場合も、編集欄は入力ごと残す（FR-140）。
- 編集欄を開いたまま、拡大画面を開いてよい（FR-140 の表）。拡大画面の表示中は背後の操作を受け付けないため、閉じてから編集を続ける。
- 書き込みは FR-143 の規則に従い、書き込む内容を解き直して確かめる。
- **文書の書き手が、書き換えの対象を偽装できてはならない**（NFR-030）。生 HTML でコードブロックや図を装ったものは対象にしない（変換ごとの鍵と照合する。IMP-120）。

### FR-146: 選んだ文字の取り消し線 **MUST**

編集モードの間、本文で選んだ文字に取り消し線を付ける・外す（4.73.0）。

- **書き込むのは HTML の `<del>` タグだけとし、記号（`~~`）は書かない**（利用者の判断）。`<del>` はどこに置いても効き、行頭に置いても文書の構造を変えない。記号は日本語の括弧や句読点の隣で効かないことがあり、行頭の `~~~` はコードブロックを始めうる。GitHub も `<del>` を取り消し線として表示する。
- **トグルとする。** 選択の中の文字（空白を除く）がすべて取り消し線なら外し、そうでなければ付ける。
  - **付ける**: 取り消し線でない部分の両端に `<del>` と `</del>` を差し込む
  - **外す**: MarkView の形（`<del>…</del>`）なら、選んだ部分だけを外せる（`<del>あいう</del>` の「い」だけを外すと `<del>あ</del>い<del>う</del>`）。空のタグは作らない。**手書きの取り消し線**（`~~…~~`・`~…~`、`<s>`、`<strike>`）は記法を書き換えず、**その全体を外す**。選んだ範囲より広く外れるため、その旨をステータス領域に出す（警告。FR-110）
- 次の規則は、文字色（FR-147）にも当てはまる。
  - **選択は 1 つのブロックの中に限る**（利用者の判断）。対象は、段落・見出し・リストの項目の文字・表の 1 つのセル・引用と Alerts の中の段落・脚注の本文・リンクの文字である。**対象外**: コードブロックとインラインコードの中、数式の中、図、Front Matter、Alerts の見出し（MarkView が出している文字）、生 HTML のブロック、**図のファイルと画像ファイル**
  - **選択の両端の空白は除く。** インラインコード・数式・画像・脚注の参照・絵文字・自動リンクの一部だけにかかっていたら、その全体まで広げる（利用者の判断）。**脚注の戻りリンク（`↩`。変換器が書く文字で、ソースに無い）にかかっていたら、選択から外す**（4.78.0。利用者の判断）
  - **既存の記法は動かさない。** 太字・斜体・リンク・既存のタグの境界をまたぐ選択は、境界ごとに分けて差し込む（`**重要**な点` の「要な」→ `**重<del>要</del>**<del>な</del>点`）。**太字・斜体・取り消し線・リンクなどの中身をちょうど丸ごと選んだときは、その要素の外側に差し込む**（`日本語<del>**重要**</del>です`。利用者の判断）。日本語に接した区切り記号の内側にタグを置くと、太字などが効かなくなるためである（GitHub でも同じ）。**取り消し線と文字色の入れ子は、操作の順に関わらず「色が外、取り消し線が内」にそろえる**——取り消し線（`~~` と MarkView の形の `<del>`）の中身の全体に色を付けたら色の `span` をその外側に差し込み、色の `span` の中身の全体に取り消し線を付けたら `<del>` をその内側に差し込む（`<span style="color: …"><del>…</del></span>`。色の `span` はこの「要素」に含めない。4.80.0。利用者の判断。IMP-124 の 4。4.81.0 で要求に書き写した）
  - **分けられない、または付けると構造が変わる場合は、書き込まずに理由を出す**（FR-110。利用者の判断）。例: `<del>あ**いう**え</del>` の「う」だけを外す、日本語に接した太字の一部だけを選ぶ
  - **書き込む内容を解き直して確かめる**（FR-143）。見えている文字は 1 文字も変わらない
  - **画面の選択をソースの位置に対応付けるのは Go 側である**（AR-031）。フロントエンドは、ブロックの目印・選択の始まりと終わりの位置・そのブロックの見えている文字の全体を送る。**Go 側が組み立てた見えている文字と 1 文字でも違えば、書き込まない**（古い指示として扱う。FR-143）。食い違いうるブロック（サニタイズで中身ごと消える生 HTML を含むもの等）は、修飾できないだけで済む
  - 書き込みを待たずに、選んだ文字に修飾を当てて見せ（NFR-012）、失敗したら戻す。**ただし取り消し線を外す操作は、仮の見た目を出さず、書き込みの後の再描画で外れて見える**（祖先の `<del>` が引いた線は、子孫の要素から消せない。4.81.0。利用者の判断）。**再描画の後も選択を残し**、取り消し線の直後に続けて色を付けられるようにする
  - 1 回の操作は 1 回の書き込みとし（FR-143）、`Ctrl+Z` 1 回で戻る（FR-144）
  - **文書の書き手が、修飾の対象を偽装できてはならない**（NFR-030）。修飾できるブロックは、変換ごとの鍵と照合する（IMP-120）
- **操作の手段は 3 つ**とする: ショートカット `Ctrl+Shift+X`（UI-090）、右クリックメニューの `Strikethrough`（FR-063）、ツールバーの取り消し線のボタン（UI-020）。使えないとき（選択が空、修飾できる 1 つのブロックに収まっていない）は、ボタンとメニューの項目を淡色にし、ショートカットは何もしない。**入力欄（編集欄・検索バー）の中では働かない**（利用者の判断）。
- 選んだ文字を修飾する操作は、**選択すると浮かぶ小さなツールバー**と**すべての修飾を外す操作**を持たない（[1.5.2](01-overview.md)。利用者の判断）。

### FR-147: 選んだ文字の文字色 **MUST**

編集モードの間、本文で選んだ文字に、決めた一覧の色を付ける・替える・外す（4.73.0）。

| 名前 | ファイルに書く値（Light で描く色） | Dark で描く色 |
| --- | --- | --- |
| `Red` | `#d1242f` | `#f85149` |
| `Orange` | `#bc4c00` | `#db6d28` |
| `Yellow` | `#9a6700` | `#d29922` |
| `Green` | `#1a7f37` | `#3fb950` |
| `Blue` | `#0969da` | `#4493f8` |
| `Purple` | `#8250df` | `#ab7df8` |
| `Gray` | `#59636e` | `#9198a1` |

- **書き込むのは `<span style="color: #xxxxxx">` タグだけ**とし、形を 1 つに固定する（コロンの後に半角空白 1 つ、小文字の 16 進）。**色は上の一覧から選ぶ**（任意の色は選ばせない。利用者の判断）。一覧の後に `Default` を置き、選ぶと色を外す。値は GitHub の配色（Primer）から採った。
- **ファイルには Light の値を書き、Dark テーマでは対応する Dark の色で描く**（利用者の判断）。1 つの色で、白地と Dark の地の両方の読みやすさ（コントラスト比 4.5）を満たす色は無いためである。
- **GitHub では色が付かず、文字だけが残る**（GitHub はサニタイズで `style` を取り除く）。[1.3.3](01-overview.md) の例外として受け入れる（利用者の判断）。
- **付ける**: 色の無い部分の両端に差し込む（取り消し線の中身の全体に付けるときは、その外側。FR-146 の入れ子の規則）。**替える・外す**: MarkView の形の `span` の中なら、選んだ部分だけを替えたり外したりできる。**MarkView の形とは、`span` の `style` が `color` だけで、値が一覧にあるもの**とし、サニタイズが通す揺れ（値の大文字と小文字、コロンの後の空白の有無、末尾の `;`。MD-072）を含む。手で書いたものも同じに扱い、**替えるときは決めた形（上）で書き直す。** 選んだ部分と、替えたい `span` の間に別の要素があって分けられないときは、**替えるときは新しい `span` で囲む入れ子で替え**（内側の色が勝つ）、**外すときは書き込まずに理由を出す**（利用者の判断）。
- 選択の全体が同じ色なら、一覧のその色に印を付ける。
- 選択の範囲・既存の記法の扱い・確かめ・対応付け・見た目・取り消し・偽装の防止は、FR-146 の規則に従う。
- **操作の手段は 2 つ**とする: 右クリックメニューの `Text color`（サブメニューに一覧と `Default`。FR-063, UI-085）と、ツールバーの文字色のボタン（押すと、右クリックメニューのサブメニューと同じ一覧をボタンの下に出す。UI-020, UI-085）。**ショートカットは持たない。**
