# 02. 機能要求

> 索引: [README](README.md) | 前: [01. 概要](01-overview.md) | 次: [03. 画面・操作仕様](03-ui.md)

本文書は MarkView の機能要求を定義する。画面上の配置・見た目は [03. 画面・操作仕様](03-ui.md)、Markdown の解釈規則は [04. Markdown 描画仕様](04-markdown.md) を参照。

## 2.1 ファイルを開く（FR-010 系）

### FR-010: ファイル選択ダイアログからの表示 **MUST**

ツールバーのファイルボタン、またはショートカット `Ctrl+O` により、OS 標準のファイル選択ダイアログを開く。

- ダイアログのフィルタは既定で `Markdown files (*.md, *.markdown, *.mdown, *.mkd)` とし、`All files (*.*)` も選択できる。フィルタ名は英語とする（UI-024）。
- ファイルが選択されたら、その文書を本文ペインに表示する。
- ファイルが選択されたら、そのファイルが存在するディレクトリを新しいツリールートとする（FR-030）。
- ダイアログの初期ディレクトリは、現在のツリールートとする。ツリールートが未確定の場合はカレントディレクトリとする。
- キャンセルされた場合、表示中の内容を変更しない。

### FR-011: ドラッグ＆ドロップによる表示 **MUST**

ウィンドウ上に OS からファイルまたはディレクトリがドロップされたとき、以下のとおり動作する。

| ドロップされた対象 | 動作 |
| --- | --- |
| Markdown ファイル 1 つ | その文書を表示し、親ディレクトリを新しいツリールートとする |
| ディレクトリ 1 つ | そのディレクトリを新しいツリールートとし、直下に `README.md` があれば表示する |
| 複数のファイル | Markdown ファイルのうち 1 つのみを対象とし、他は無視する。OS から渡されたリストの先頭にある Markdown ファイルを採る |
| Markdown 以外のファイル | 何も変更せず、対応していない旨をステータス表示する（FR-110） |

- ドラッグ中はウィンドウ全体にドロップ可能であることを示す視覚的フィードバックを表示する（UI-070）。
- ドロップ対象領域はウィンドウ全体とし、本文ペイン・サイドペインのいずれにドロップしても同じ結果となる。

### FR-012: コマンドライン引数による起動 **MUST**

実行ファイルは第 1 引数にパスを受け取る。

```
MarkView [オプション] [パス]
```

| 引数 | 動作 |
| --- | --- |
| Markdown ファイルのパス | その文書を表示し、親ディレクトリをツリールートとする |
| ディレクトリのパス | そのディレクトリをツリールートとし、直下に `README.md` があれば表示する |
| 存在しないパス | エラーメッセージを表示して起動する（起動自体は失敗させない） |
| 引数なし | FR-013 に従う |

サポートするオプションは以下とする。

| オプション | 動作 |
| --- | --- |
| `--version` / `-v` | バージョン、コミットハッシュ、ビルド日時を標準出力に出力して終了（ウィンドウを開かない）。終了コード 0 |
| `--help` / `-h` | 使用方法を標準出力に出力して終了（ウィンドウを開かない）。終了コード 0 |
| 上記以外の `-` で始まる引数 | 使用方法を**標準エラー出力**へ出して終了する（ウィンドウを開かない）。終了コード 2 |

未知のオプションで起動を続行しない理由は、存在しないパスの場合（起動して案内を出す）と異なり、**オプションの指定誤りは利用者が気づくべき入力の誤り**だからである。黙って無視すると、意図した動作をしていないことに気づけない。

> [!NOTE]
> この経路は、Windows の「プログラムから開く」、Linux のファイルマネージャからの関連付け起動、およびシェルからの直接実行のすべてで共通に使われる。

### FR-013: 引数なし起動時の動作 **MUST**

引数なしで起動した場合、以下の順に探索し、最初に見つかったものを表示する。

| 順 | 探索対象 | 見つかった場合のツリールート |
| --- | --- | --- |
| 1 | **プロセスのカレントディレクトリ**の直下の `README.md` | カレントディレクトリ |
| 2 | **実行ファイルが存在するディレクトリ**の直下の `README.md` | 実行ファイルのディレクトリ |
| 3 | （いずれも該当なし） | カレントディレクトリ |

- `README.md` の探索では大文字小文字を区別しない（`readme.md`、`Readme.md` 等も対象とする）。同名で大小違いの複数が存在する場合は、`README.md` を優先し、次いで名前の昇順で先頭のものを採る。
- カレントディレクトリと実行ファイルのディレクトリが同一の場合、探索は 1 回で済ませる。
- 3 に至った場合、本文ペインに操作案内（ファイルを開く方法、ドラッグ＆ドロップの案内、主要なショートカット）を表示する。この案内は MarkView 自身が内蔵する Markdown として描画する。文言は英語とする（UI-024, UI-052）。
- 実行ファイルのパスはシンボリックリンクを解決したうえで求める。

> [!TIP]
> 順 2 を設けているのは、「`MarkView` と `README.md` を同じフォルダに入れて配布し、受領者はダブルクリックするだけ」というユースケース（[UC-01](01-overview.md)）を、どの環境でも成立させるためである。Windows のエクスプローラからダブルクリックした場合はカレントディレクトリが実行ファイルの場所と一致するため順 1 で解決するが、Linux のファイルマネージャやデスクトップランチャから起動した場合はカレントディレクトリがホームディレクトリや `/` になることがあり、順 1 だけでは配布物の `README.md` に到達できない。
>
> 一方、順序を逆にして実行ファイルの場所を優先すると、`PATH` に置いた `MarkView` をシェルから使う場合に、意図しない場所の `README.md` が開いてしまう。カレントディレクトリを先に見ることで、両方の使い方を満たす。

### FR-014: ファイル更新の自動検知と再描画 **MUST**

表示中の Markdown ファイルが外部で更新された場合、自動的に再描画する。

- 監視対象は**表示中の 1 ファイルのみ**とする。ディレクトリ全体や画像ファイルは監視しない。
- 保存操作が複数の書き込みイベントを発生させる場合に備え、最後のイベントから 150 ms 以内に追加のイベントがなければ再描画する（デバウンス）。
- 再描画後、**本文のスクロール位置を維持する**。文書が短くなり同じ位置が存在しない場合は、可能な限り近い位置に復元する。
- 再描画後、アウトラインを再構築する。展開済みのファイルツリーの状態は維持する。
- 表示中のファイルが削除された場合、直前の描画結果を保持したまま、ファイルが失われた旨をステータス表示する。
- 表示対象を切り替えたときは、以前のファイルの監視を解除する。**状態画面（UI-052。大きなファイルの確認・サイズ上限超過・描画中の想定外のエラー）へ移った場合も切り替えに当たる**——状態画面の表示中に、前に表示していた文書の更新で画面が置き換わってはならない（[BUG-012](../bugs/2026-09-14-bug-012-state-screen-previous-document.md)）。監視は常に 1 つ以下とする。
- エディタによっては保存が「一時ファイル作成 → リネーム」で行われ、監視ハンドルが切れることがある。この場合は同一パスに対する監視を張り直す。
- **編集モードで書き込んだ後は（FR-141〜FR-144）、監視のイベントを待たずに、ここで定める再描画の処理を直接呼ぶ。** 共有フォルダやネットワーク上のファイルでは、監視のイベントが届かないことがあるためである。**再描画の処理そのものは 1 つとし、書き込みのために別の処理を作らない。**
- **監視のイベントを受けて読み直した内容が、直前に描画した内容と同じなら、再描画しない。** 書き込みの後に届いたイベントで同じ描画を繰り返さないためである。**手動の再読み込み（FR-015）は、内容が同じでも再描画する。**
- **同じ文書の再描画（[1.7](01-overview.md)）では、次の状態を引き継ぐ。** 開いていた折りたたみ（`<details>`。MD-026）は、**文書の中で同じ順番にあるもの**を開いたまま保つ。本文中のチェックボックス（FR-141）にフォーカスがあった場合は、同じ順番のチェックボックスへフォーカスを戻す（UI-051 の例外）。**`Space` でチェックボックスを続けて切り替えられるようにするためであり、再描画のたびに折りたたみが閉じて読んでいた箇所を見失わないためでもある。**

### FR-015: 手動での再読み込み **MUST**

ツールバーの再読み込みボタン、または `F5` / `Ctrl+R`（UI-090）により、表示中のファイルをディスクから読み直して再描画する。動作は FR-014 と同一（スクロール位置維持を含む）とする。表示中の文書がない場合（文書未表示。UI-052 の `welcome`）、この操作は無効とする。

- **状態画面（UI-052 の `confirm-large` / `too-large` / `render-error`）の表示中は、その画面が対象にしているファイルを読み直す。** 大きさを測り直して状態画面を出し直すか、条件を満たせば描画する（`render-error` を外部のエディタで直した後にやり直せる）。**前に表示していた文書を読み直さない**——ウィンドウタイトルとステータス領域が対象のファイルを指しているのに、押すと前の文書が表示されることになる（[BUG-012](../bugs/2026-09-14-bug-012-state-screen-previous-document.md)）。状態画面の間は監視しない（FR-016）ため、これが対象を読み直す唯一の手段でもある。

### FR-016: 大きなファイルの扱い **SHOULD**

ファイルの実バイト数に応じて次のとおり扱う。

| サイズ | 動作 |
| --- | --- |
| 10 MB 以下 | そのまま描画する |
| 10 MB 超 50 MB 以下 | 描画を保留し、本文ペインに確認画面を表示する |
| 50 MB 超 | 描画せず、ファイルが大きすぎる旨を本文ペインに表示する。開く手段は提供しない |

確認画面の扱いは以下とする。画面仕様は [UI-052](03-ui.md) を参照。

- **モーダルダイアログを使わない**（FR-110 の方針と整合させる）。本文ペインにファイル名・実サイズ・描画に時間を要する旨と、実行するためのボタンを表示する。
- 確認画面の表示中も、ツールバー・ファイルツリー・アウトラインは通常どおり操作できる。別のファイルを選択した場合、確認は破棄される。
- 実行が指示された時点で描画を開始する。描画中は処理中であることを示す（NFR-012）。
- 確認画面を表示した時点で、ウィンドウタイトル（UI-013）とステータス領域のパス表示を対象ファイルのものに更新し、表示履歴（FR-051）に積む。`Alt+←` で直前の文書へ戻れること。
- ファイル更新の自動検知（FR-014）の対象とするのは、実際に描画を開始したファイルに限る。確認画面を表示しているだけの状態では監視しない。**それまで表示していた文書の監視も外す**（FR-014）。
- **確認のうえ描画した文書は、同じ文書の再描画（[1.7](01-overview.md)。更新の自動検知・再読み込み・同じファイルの開き直し・編集モードの書き込みの後の読み直し）では確認し直さない。** 描画を始めた後に確認画面へ戻すと、外部エディタで保存するたび・`F5` のたびに描画が止まり、編集モード（FR-140）では書き込むたびに編集モードが終わるためである。**同意は文書の切り替え（1.7）で消える**（別の文書へ移ってから戻った場合は、改めて確認する）。
  - 読み直した結果が 50 MB を超えていれば、同意の有無に関わらずサイズ上限超過の表示にする
  - 確認せずに描画していた文書が、読み直した結果 10 MB を超えていれば、確認画面を表示する（同意していないため）

## 2.2 Markdown 表示（FR-020 系）

### FR-020: Markdown の描画 **MUST**

読み込んだ Markdown を HTML に変換し、GitHub 準拠のスタイルで本文ペインに表示する。対応する文法・描画規則は [04. Markdown 描画仕様](04-markdown.md) で定義する。

### FR-021: 文字コードと改行コードの扱い **MUST**

- UTF-8（BOM 付き・BOM なしの両方）を正しく読み込む。BOM は本文として描画しない。
- 改行コード CRLF / LF / CR のいずれも正しく解釈する。
- UTF-8 として不正なバイト列を含む場合、その箇所を U+FFFD に置換して読み込みを継続し、警告をステータス表示する。読み込み自体は失敗させない。

> [!NOTE]
> Shift_JIS 等のレガシーエンコーディングの自動判別は行わない。開発者向けの Markdown は UTF-8 が事実上の標準であり、判別ロジックの追加はサイズと誤判定リスクに見合わないため。

### FR-022: 画像の表示 **MUST**

- Markdown 内の相対パス・絶対パスで指定されたローカル画像を表示する。相対パスは**表示中の Markdown ファイルが存在するディレクトリ**を基準に解決する。
- 対応形式は PNG、JPEG、GIF（アニメーション含む）、SVG、WebP、AVIF、BMP、ICO とする。
- `http://` / `https://` で指定されたリモート画像も表示する（MD-071）。
- 画像が存在しない・読み込めない場合、代替テキスト（alt）と破損を示すプレースホルダを表示する。文書全体の描画は継続する。
- 画像の最大表示幅は本文幅とし、超える場合は縦横比を保って縮小する。**ただし原寸表示（FR-121）に切り替えた画像を除く。**

### FR-023: Mermaid 図の表示 **MUST**

- 言語指定 `mermaid` のコードブロックを Mermaid 図として描画する。**生 HTML（MD-072）で図のブロックを装ったものは描画しない**（NFR-030）。
- 描画は外部通信なしで行う（AR-020）。
- Mermaid のテーマは、アプリの Light / Dark テーマに追従させる。
- 構文エラーで描画できない場合、エラー内容と元のコードをコードブロックとして表示する。文書全体の描画は継続する。
- Mermaid 記法を含まない文書では Mermaid の実行環境を読み込まない（NFR-013）。

### FR-024: PlantUML 図の表示 **MUST**

- 言語指定 `plantuml` または `puml` のコードブロックを PlantUML 図として描画する。**生 HTML（MD-072）で図のブロックを装ったものは描画しない**——装ったブロックが、下の取り込み指令の検査（MD-084）を通らずに処理系へ渡るためである（NFR-030）。
- 描画は外部通信なしで行う（AR-020, NFR-032）。**同梱した処理系だけで描き、PlantUML のサーバへ送らない。**
- PlantUML の配色は、アプリの Light / Dark テーマに追従させる。
- 構文エラーで描画できない場合、**PlantUML が生成するエラー図をそのまま表示する**。文書全体の描画は継続する。Mermaid（FR-023）と扱いが違うのは、PlantUML が構文エラーを例外ではなく「エラーを描いた図」として返し、その図が行番号と該当行を含むためである。
- 次の 2 つは描画できない。いずれも本文中に理由を表示し、元のソースをコードブロックとして残す（FR-110）。
  - **取り込みのプリプロセッサ指令**（`!include` / `!includeurl` / `!includesub` / `!import` と、`from` を伴う `!theme`）を含むブロック。**Go 側で検査して描画対象から外す**（MD-084, NFR-032）。標準ライブラリ（`!include <C4/...>` 等）もこの形であり、**同梱した処理系は持っていない**
  - **4096 px を超える大きさになる図**。処理系が描画を拒む
- PlantUML 記法を含まない文書では PlantUML の実行環境を読み込まない（NFR-013）。

## 2.3 ファイルツリー（FR-030 系）

### FR-030: ツリールートの決定 **MUST**

ツリールートは以下の契機でのみ変更される。

| 契機 | 新しいツリールート |
| --- | --- |
| ファイル選択ダイアログでファイルを選択（FR-010） | 選択されたファイルの親ディレクトリ |
| ファイルをドロップ（FR-011） | ドロップされたファイルの親ディレクトリ |
| ディレクトリをドロップ | ドロップされたディレクトリ |
| コマンドライン引数（FR-012） | 引数がファイルなら親ディレクトリ、ディレクトリならそれ自身 |
| 引数なし起動（FR-013） | カレントディレクトリ、または実行ファイルのディレクトリ（FR-013 の探索順による） |

**ファイルツリー内のファイルを選択してもツリールートは変更しない。** また、文書内リンクによる遷移（FR-050）でもツリールートは変更しない。これは、ドキュメント群を配布したときにツリーが利用者の操作で意図せず移動してしまうことを防ぐためである。

### FR-031: ツリーの表示内容 **MUST**

- ツリールート以下のディレクトリと Markdown ファイルを階層表示する。
- **表示対象のファイルは Markdown（`*.md`, `*.markdown`, `*.mdown`, `*.mkd`）のみとする。** 画像・ソースコード・その他の種類のファイルは、ツリーに表示しない。ファイルツリーは「読める文書を選ぶ」ための道具であり、開けないファイルを並べても選択できないため。
- Markdown ファイルを 1 つも含まないディレクトリ（下位階層を含めて）は表示しない。
- 名前が `.` で始まるディレクトリ・ファイルは表示しない。
- `node_modules`、`vendor`、`.git`、`target`、`dist`、`build` は既定で表示しない。
- 並び順はディレクトリを先、ファイルを後とし、それぞれ名前の昇順（大文字小文字を区別しない）とする。
- 現在表示中のファイルをツリー上で強調表示する。

### FR-032: ツリーの遅延展開 **MUST**

ディレクトリの内容は、そのディレクトリが展開された時点で初めて読み込む。起動時に階層全体を再帰的に走査してはならない。これは、巨大なディレクトリをツリールートにした場合の起動遅延とメモリ増加を防ぐためである。

- ツリールート直下のみ、起動時に読み込んで展開状態で表示する。
- 表示中のファイルに至る経路上のディレクトリは、自動的に展開する。
- 1 ディレクトリあたりのエントリ数が 1000 を超える場合、先頭 1000 件を表示し、省略された旨を末尾に表示する。

> [!NOTE]
> 「Markdown を含まないディレクトリを隠す」という規則（FR-031）と遅延展開は本来相反する。実装では、ディレクトリ判定のために 1 階層下までを先読みし、それでも判定できない深い階層は「展開してみるまで表示する」ことを許容する。判定のために全階層を走査してはならない。

### FR-033: ツリーからのファイル選択 **MUST**

ツリー上の Markdown ファイルをクリックすると、そのファイルを本文ペインに表示する。このとき、

- **ツリールートは変更しない**（FR-030）。
- 本文のスクロール位置は先頭に戻す。
- 表示履歴に追加する（FR-051）。
- ファイル監視の対象を新しいファイルに切り替える。

### FR-034: ツリーの表示・非表示切り替え **MUST**

ツールバーのファイルツリーボタン、またはショートカット（UI-090）により、ファイルツリーペインの表示・非表示をトグルする。非表示時はファイルツリーの内容をメモリ上に保持したままでよいが、再表示時にツリールートの内容を再読み込みして最新状態を反映する。

### FR-035: ツリーの手動更新 **SHOULD**

ファイルツリーはディレクトリの変更を自動監視しない（FR-014 の監視は表示中ファイルのみ）。ツリーの再読み込みは以下の契機で行う。

- ツリーペインを非表示から表示に切り替えたとき
- 再読み込み操作（FR-015）を行ったとき
- ディレクトリノードを折りたたんでから再度展開したとき

## 2.4 アウトライン（FR-040 系）

### FR-040: アウトラインの生成 **MUST**

表示中の文書の見出し（`#` から `######`）を抽出し、階層構造としてアウトラインペインに表示する。

- 見出しレベルの入れ子はソース上の階層をそのまま反映する。レベルが飛んでいる場合（`#` の次に `###` 等）でも、出現順を保ったまま相対的な深さで表示する。
- 見出しテキストに含まれるインライン記法（強調、コード、リンク等）は、プレーンテキストに変換して表示する。
- コードブロック内の `#` 始まりの行は見出しとして扱わない。
- 見出しが 1 つも存在しない場合、その旨をアウトラインペインに表示する。

### FR-041: アウトラインからの移動 **MUST**

アウトラインの項目をクリックすると、本文ペインの該当見出しまでスクロールする。スクロールは即座に行い、対象の見出しがペイン上端付近に来る位置に合わせる。

**見出しが折りたたみ（`<details>`。[MD-026](04-markdown.md)）の中にある場合は、折りたたみを開いてから移動する**（FR-080 の IMPORTANT）。アウトラインは本文の見出しをすべて挙げるため、折りたたみの中の見出しも項目として現れる。

### FR-042: スクロール連動 **MUST**

本文ペインのスクロールに追従し、現在表示中の位置に対応するアウトライン項目を強調表示する。

- 判定は「本文ペインの上端より上にある最後の見出し」とする。
- 強調表示された項目がアウトラインペインの表示範囲外にある場合、アウトラインペインを自動スクロールして可視にする。
- 連動処理は本文の描画性能に影響を与えない方式で実装する（AR-051）。

### FR-043: アウトラインの表示・非表示切り替え **MUST**

ツールバーのアウトラインボタン、またはショートカット（UI-090）により、アウトラインペインの表示・非表示をトグルする。

## 2.5 文書内リンクと履歴（FR-050 系）

### FR-050: 文書内リンクの遷移 **MUST**

本文中のリンクは、リンク先の種類に応じて以下のとおり処理する。

| リンク先 | 動作 |
| --- | --- |
| Markdown ファイル（`./docs/design.md`、絶対パスを含む） | **表示中のウィンドウで**当該ファイルを開く。ツリールートは変更しない |
| Markdown ファイル + アンカー（`./a.md#section` 等） | 当該ファイルを表示し、該当見出しまでスクロールする |
| 同一文書内のアンカー（`#section`） | 該当見出しまでスクロールする。`#user-content-section` と書かれていても同じ見出しへ移る（MD-021, AR-053）。**本文の外（画面の要素）へは移らない。** 本文に該当する要素が無ければ、リンク先が見つからない旨をステータス表示する |
| 画像ファイル | **OS の既定画像ビューアで開く**（FR-053） |
| その他のファイル | OS の既定アプリケーションで開く |
| `http://` / `https://` | **OS の既定ブラウザで開く**。WebView 内では遷移させない |
| `mailto:` 等のその他スキーム | OS の既定ハンドラに委譲する |
| 存在しないパス | 遷移せず、リンク先が見つからない旨をステータス表示する |

**移動先の見出しが折りたたみ（`<details>`。[MD-026](04-markdown.md)）の中にある場合は、折りたたみを開いてから移動する**（FR-080 の IMPORTANT）。閉じたままの要素はレイアウトを持たず、スクロール先として指定しても何も起きない。

Markdown ファイルへのリンクを開く際の詳細は以下のとおり。

- **新しいウィンドウやタブを開かない。** 表示中のウィンドウの本文ペインを、リンク先の文書の内容で置き換える。
- 遷移前の文書は表示履歴に積み、`Alt+←` で元の文書へ戻れる（FR-051）。戻った際は遷移前のスクロール位置を復元する。
- 遷移後、本文のスクロール位置は先頭に戻す（アンカー付きリンクの場合は該当見出しの位置）。
- 遷移後、ウィンドウタイトル（UI-013）、ステータス領域のパス表示、アウトライン、ファイル監視の対象を、新しい文書のものに更新する。
- ファイルツリーの**ツリールートと展開状態は変更しない**。強調表示のみ新しい文書へ移す。
- 相対パスは表示中の Markdown ファイルのディレクトリを基準に解決する（AR-042）。
- ツリールート外への遷移も許可する（例: `../other/doc.md`）。この場合の表示は FR-052 に従う。
- WebView 内でのページ遷移は一切発生させない。すべての遷移はアプリケーションが制御する（AR-060）。
- **例外として、編集モード（FR-140）の間は、表のセルの中のリンクをクリックしても遷移しない**（FR-142）。セルのダブルクリック（編集の開始）の 1 回目で文書が切り替わるのを防ぐためである。

> [!IMPORTANT]
> 上の表の「その他スキーム」で OS へ委譲するのは **`mailto:` に限る**。`javascript:` や `file:` を含む任意のスキームを OS へ渡すと、文書の作成者が利用者の環境で任意のハンドラを起動できてしまう。文書は任意の第三者から受け取りうるため、許可するスキームは `http` / `https` / `mailto` の 3 つに固定し、それ以外はリンク先を開けない旨をステータス表示する（IMP-170, NFR-030）。

### FR-051: 表示履歴の前後移動 **MUST**

表示した文書の履歴を保持し、**`Alt+←` で直前に表示していたファイルへ戻る**。`Alt+→` で戻る前の文書へ進む。

- 履歴に積む契機は、ファイル選択ダイアログ（FR-010）、ドラッグ＆ドロップ（FR-011）、ファイルツリーからの選択（FR-033）、文書内リンクによる遷移（FR-050）とする。ファイル更新の自動検知（FR-014）と手動の再読み込み（FR-015）では履歴に積まない。
- 履歴はブラウザと同様のスタック構造とする。戻った状態から新しい文書を開くと、前方履歴は破棄される。
- 履歴に記録する情報は、ファイルパス・スクロール位置・アンカーとする。
- 履歴で戻った場合、記録されたスクロール位置を復元する。
- 履歴の保持上限は 50 件とする。
- **履歴はメモリ上のみに保持し、終了時に破棄する**。ディスクには一切保存しない（NFR-042）。

### FR-052: ツリールート外の文書を開いた場合 **MUST**

リンク遷移（FR-050）や履歴移動（FR-051）により、ツリールートの外にある Markdown ファイルを表示することがある。この場合、

- **ツリールートを変更しない。** ファイルツリーの表示内容・展開状態・スクロール位置をいずれも変えない。
- ファイルツリー上で強調表示されるノードは存在しない状態とする（UI-030）。
- ステータス領域には相対パスではなく**絶対パス**を表示し、ツリー外の文書であることが分かる表示を付す（UI-060）。
- その文書からさらにリンクをたどる場合も、基準はその文書自身のディレクトリとする。
- `Alt+←` でツリールート内の文書へ戻った時点で、ファイルツリーの強調表示が復活する。

> [!NOTE]
> ツリー外へ遷移してもツリールートを動かさないのは、FR-030 と同じ理由による。配布されたドキュメント群を読み進める最中に、リンク 1 つでツリーの起点が移動してしまうと、利用者が元の一覧へ戻る手掛かりを失うため。

### FR-053: 画像の表示先 **MUST**

画像ファイルへのリンク（`[構成図](./arch.png)` のように、画像を**リンク先**として指定した記法）をクリックした場合、**OS の既定画像ビューアで開く**。別ウィンドウでの表示は OS 側のアプリケーションが担う。

- MarkView は、**画像ファイルへのリンクを開く**ための独立したウィンドウ・画面・オーバーレイをいずれも持たない。**本文に埋め込まれた画像を大きく見る拡大画面（FR-122）は、これとは別の機能である。**
- 画像を開いても、MarkView のウィンドウの表示内容・ウィンドウタイトル（UI-013）・アウトライン・表示履歴（FR-051）・ファイル監視の対象は、いずれも変化しない。
- 既定のアプリケーションが関連付けられていない、またはファイルが存在しない場合、その旨をステータス表示する（FR-110）。
- 本文に**埋め込まれた**画像（`![構成図](./arch.png)`）のクリックでは何も起こさない。ただし画像がリンクで囲まれている場合（`[![構成図](./arch.png)](./design.md)`）は、リンク先に対して FR-050 の規則を適用する。

> [!NOTE]
> 画像表示を OS に委ねるのは、2 つの理由による。第一に、採用している Wails v2 はアプリケーションが 2 つ目のネイティブウィンドウを開くことをサポートしていない（AR-001）。第二に、自前の画像ビューアを実装すれば拡大・縮小・回転といった機能を順次求められることになり、「閲覧に特化した軽いアプリケーション」という位置づけから離れる。OS の画像ビューアはこれらをすでに備えている。
>
> **4.39.0 で拡大画面（FR-122）を加えたが、リンク先の画像を開く先は変えていない。** 拡大画面は「**本文の中で縮小されて読めない**図・画像を、読むために大きく見る」ためのものであり、回転・編集・前後の画像への移動といった画像ビューアの機能は持たない（[1.5.2](01-overview.md)）。**図はメモリ上で生成され、OS のビューアへ渡せるファイルを持たない**ため、アプリ内で見せる以外に手段が無い。

## 2.6 コードブロックのコピー（FR-060 系）

### FR-060: コピーボタンの表示 **MUST**

本文中のすべてのコードブロック（フェンス付き・インデント形式の両方）の**右上**にコピーボタンを配置する。

- ボタンはコードブロック内にオーバーレイ表示し、コードの内容と重ならない位置とする。
- 既定では半透明で表示し、コードブロックにマウスカーソルが乗ったときに不透明にする。タッチ操作やキーボード操作の環境を考慮し、**常に操作可能な状態**とする（`display: none` としない）。
- Mermaid 図・PlantUML 図として描画されたブロックにもコピーボタンを表示し、コピー対象は元のソースとする。どちらも描画後に `<pre>` が SVG へ置き換わる（FR-023, FR-024）。
- 図の右上には、コピーボタンと並べて原寸表示・拡大画面のボタンも置く（FR-120, UI-053）。

### FR-061: コピー動作 **MUST**

コピーボタンをクリックすると、当該コードブロックの内容をクリップボードに格納する。

- コピー対象はコードブロックの生のテキストとし、シンタックスハイライトのための HTML タグや行番号は含めない。
- **コピーされる内容は、画面に見えているコード（図では、その図として描画した原文）と一致させる。** 文書の書き手が、生 HTML でコードブロックや図の目印を装い、見えていない文字列をコピーさせる手段を与えない（NFR-030。FR-063 の `Copy link address` と同じ考え方）。
- 末尾の改行 1 つは除去する。それ以外の空白・インデントは保持する。
- コピー成功時、ボタンの表示を一時的に変化させ（アイコン変更等）、成功したことを 1.5 秒程度示す。
- コピーに失敗した場合、失敗した旨を表示する。

### FR-062: 選択範囲のコピー **SHOULD**

本文中のテキストはマウスで選択でき、`Ctrl+C` でクリップボードにコピーできる。右クリックメニューからもコピーできる（FR-063）。

### FR-063: 右クリックメニュー **MUST**

右クリックしたとき、**MarkView 自身が描くメニュー**を表示する。**WebView の標準の右クリックメニューは引き続き無効とする**（AR-060）。標準のメニューには「戻る」「再読み込み」「検証」といったページとしての操作が含まれ、ページ遷移を一切発生させない方針（AR-060）と相容れないためである。

メニューを出す場所と、そこに並べる項目は次のとおりとする。

| 場所 | 項目（上から順） |
| --- | --- |
| 本文ペイン | `Copy link address`（**リンクの上で開いたときだけ**）、`Copy`、`Select all` |
| 情報ウィンドウのライセンス欄（UI-101） | `Copy`、`Select all` |
| 入力欄（検索バーの入力欄 UI-080、セルの編集欄 FR-142） | `Cut`、`Copy`、`Paste`、`Select all` |

**上記以外の場所**（ツールバー・ファイルツリー・アウトライン・ステータス領域・拡大画面 FR-122 など）では、メニューを出さず何も起こさない。**本文ペインの中にある入力欄**（セルの編集欄）で右クリックした場合は、入力欄の項目を出す。

各項目の動作は次のとおりとする。

| 項目 | 動作 | 使えない状態 |
| --- | --- | --- |
| `Copy` | 選択範囲をクリップボードに格納する。**格納する内容は `Ctrl+C`（FR-062）と同じ**とする（書式付きの内容とプレーンテキストの両方） | 選択範囲が無い |
| `Cut` | 入力欄の選択範囲をクリップボードに格納し、入力欄から取り除く | 選択範囲が無い |
| `Paste` | クリップボードのテキストを、入力欄のカーソル位置へ挿入する。**書式は持ち込まない。** セルの編集欄では改行を半角空白に置き換える（FR-142） | クリップボードにテキストが無い |
| `Select all` | その場所の全体を選択する。本文ペインでは**本文全体**、ライセンス欄では欄の全文、入力欄では入力欄の全文とする | — |
| `Copy link address` | リンク先を、**Markdown に書かれたとおりの形**でクリップボードに格納する（`[設計](./docs/design.md#api)` なら `./docs/design.md#api`、`[設計](./設計.md)` なら `./設計.md`）。参照リンクは定義に書かれた形とする。**解決した絶対パスにしない。百分率エンコードした形にもしない** | — |

- 項目名は英語とする（UI-024）。見た目と操作は UI-085 で定める。
- **右クリックで選択範囲を変えない。** 文字列を選択したまま右クリックし、`Copy` を選べること。
- 使えない項目は消さずに淡色で表示し、選べないようにする。**位置で覚えられるようにするためである。** `Copy link address` だけは、リンクの上でなければ行ごと出さない。
- 項目を選んだとき、`Esc`、メニューの外のクリック、本文のスクロール、ウィンドウがフォーカスを失ったときに閉じる。
- 失敗した場合はステータス領域に通知する（FR-110）。
- **書かれたとおりのリンク先は、Go 側が変換時に求めて渡す。** 描画後の `href` は百分率エンコードされ、参照リンクは解決済みであり、書かれた形を失っている。フロントエンドは Markdown を解析しない（AR-031）ため、自力では求められない。**生 HTML で書かれた `<a>` は、`href` 属性の値をそのまま用いる。**
- **文書の書き手が、コピーされる文字列を偽装できてはならない**（NFR-030）。見えているリンクの遷移先と、コピーされる文字列を食い違わせる手段を与えない。

> [!NOTE]
> **`Copy` を `Ctrl+C` と同じ内容にする**のは、メニューとキーで結果が食い違うと、利用者がどちらを使ったかによって貼り付け先の見え方が変わるためである。コードブロックのコピーボタン（FR-061）がプレーンテキストだけを格納するのは、コードを貼り付ける先で書式が邪魔になるからであり、目的が違う。
>
> **リンク先を書かれたとおりにコピーする**のは、別の Markdown へ貼ればそのまま使え、かつ**利用者の環境のパス（ユーザー名を含むことがある）を漏らさない**ためである。

## 2.7 テーマ（FR-070 系）

### FR-070: テーマの切り替え **MUST**

ツールバーのテーマボタン、またはショートカット（UI-090）により、Light テーマと Dark テーマを切り替える。

- 切り替えは本文・サイドペイン・ツールバー・スクロールバーを含むアプリ全体に即座に適用される。
- コードブロックのシンタックスハイライト配色もテーマに追従する（MD-030）。
- Mermaid 図と PlantUML 図もテーマに追従して再描画する（FR-023, FR-024）。
- 選択中のテーマは設定に保存する（UI-110）。

### FR-071: 初回起動時のテーマ **MUST**

設定が存在しない状態での初回起動時は、OS のテーマ設定（ダークモードの有効・無効）に追従する。判定できない場合は Light テーマとする。

## 2.8 検索・表示倍率（FR-080 系）

### FR-080: 文書内検索 **MUST**

`Ctrl+F` で検索バーを表示し、表示中の文書内をインクリメンタルに検索する。

- 大文字小文字を区別しない部分一致とする。
- 一致箇所をすべてハイライトし、現在の一致箇所を他と区別できる配色で表示する。
- `Enter` / `Shift+Enter` または検索バーのボタンで、次・前の一致箇所へ移動する。移動時は該当箇所までスクロールする。
- 「現在位置 / 総ヒット数」を表示する。ヒットしない場合はその旨を表示する。
- `Esc` で検索バーを閉じ、ハイライトを解除する。
- 検索対象は本文ペインに描画されたテキストとし、アウトライン・ファイルツリーは対象外とする。
- **折りたたみ（`<details>`。[MD-026](04-markdown.md)）の中も検索対象とし、その中の一致箇所へも移動する。** 移動の際に折りたたみを開き、**開いたものを閉じ直さない。**
- 検索対象文書の切り替え・再描画時と、表を並べ替えた後（FR-130）は検索状態をリセットする。並べ替えるとヒットの順序が本文の順序と食い違うためである。

> [!IMPORTANT]
> **閉じた折りたたみの中身は、画面に無いのではなく「スクロール先として指定できない」。** 大きさも位置も持っており（実測）、**それでもスクロールは起きない。** ハイライトも件数も正しく作れるため、実装は「移動できている」と誤認しやすい。**スクロール先として指定しても何も起きず、エラーにもならない。** 折りたたみの中を数に入れる以上、そこへ行けなければならない（[調査報告](../bugs/2026-09-04-bug-004-search-collapsed-details.md)）。
>
> 同じことは**アンカーによる移動**（FR-050）と**アウトラインからの移動**（FR-041）にも当てはまる。折りたたみの中の見出しが対象になりうるためである。

### FR-081: 表示倍率の変更 **MUST**

- `Ctrl` + `+` / `-` で本文の表示倍率を拡大・縮小する。`Ctrl+0` で 100 % に戻す。
- 倍率の範囲は 50 %〜300 %、刻みは 10 % とする。
- `Ctrl` + マウスホイールでも同様に変更できる。
- 倍率は本文ペインにのみ適用し、ツールバーとサイドペインのフォントサイズは変更しない。
- **倍率は設定に保存しない**（UI-111, UI-115）。セッション内でのみ保持し、起動時は常に 100 % から始める。100 % 以外のときは倍率を画面上に表示する。

## 2.9 外部エディタ（FR-090 系）

### FR-090: 外部エディタで開く **MUST**

ツールバーの「エディタで開く」ボタン（[UI-020](03-ui.md)）、またはショートカット `Ctrl+E`（[UI-090](03-ui.md)）により、**表示中の Markdown ファイルを利用者が選んだエディタで開く。**

- MarkView 自身は**文書を自由に編集する機能**を持たない。外部のエディタへ委譲する（[1.3.2](01-overview.md)）。画像を OS の既定ビューアへ委譲する FR-053 と同じ位置づけである。**編集モードで書き換えられるのは、構造を変えない 2 種類に限る**（FR-140）。
- 開いた後もファイルの監視（FR-014）は続く。**エディタで保存すると MarkView が自動的に再描画する。** この 2 つが組み合わさって UC-03（[1.4](01-overview.md)）が成立する。
- **対象は「画面がいま開こうとしているファイル」とする。** 本文を表示していればその文書、状態画面（[UI-052](03-ui.md)）を出していればその対象ファイルである。**ウィンドウタイトル（[UI-013](03-ui.md)）が示しているものと常に一致する。**
- **`confirm-large` / `too-large` / `render-error` の状態画面でも実行できる。** 大きすぎて開けないファイル、描画に失敗したファイルこそ、エディタで中身を確かめたい。
- **文書未表示（`welcome`）のときだけボタンを淡色にし、実行できない状態とする**（[UI-021](03-ui.md)）。対象となるファイルが存在しないためである。
- 起動に成功した場合、ステータス領域に一時メッセージ（[DSP-151](21-display-components.md)）で「エディタ名」を出す。**エディタが背面のウィンドウで開くことがあり、何も出ないと「押しても無反応」に見える。**
- 起動に失敗した場合はステータス領域に通知し、表示中の内容は変えない（FR-110）。

**渡すのは、対象ファイルの絶対パス 1 つだけとする。** 行番号・オプション・利用者が編集できるコマンドテンプレートのいずれも持たない（[NFR-035](07-nonfunctional.md)）。

> [!IMPORTANT]
> **「表示中の文書」ではなく「画面の対象」である。** 状態画面を出している間、Go 側が保持する「表示中の文書」は**前に開いていた文書のまま**残る（[IMP-192](11-impl-backend.md)）。そちらを渡すと、利用者が `big.md — too large` の画面を見ながら押したのに、前の文書がエディタで開く。**エラーも出ないため気づけない。** 対象は [IMP-190](11-impl-backend.md) が別に保持する。

### FR-091: エディタの選択 **MUST**

ボタンを押すと、**毎回エディタ選択ウィンドウ（[UI-103](03-ui.md)）を表示する。** そこで選んだうえで `Open` を実行したときに開く。

- 一覧には、**インストール済みとして検出できたエディタ**（[IMP-172](11-impl-backend.md)）と、`Other...`（任意の実行ファイルを選ぶ）を並べる。
- 検出できなかったエディタも、その旨を添えて一覧に残す。消すと「なぜ自分のエディタが出ないのか」が分からない。
- `Other...` は OS 標準のファイル選択ダイアログで実行ファイルを選ぶ。**選ばれたパスはフロントエンドを経由しない**（[IMP-300](13-impl-interface.md)）。
- 選択は設定に保存し、次回の初期選択とする（[UI-116](03-ui.md)）。保存がない場合、初期選択は無い。
- `Esc`、`Cancel`、ウィンドウ外のクリックで閉じる。閉じた場合は**何も保存せず、何も起動しない。**

> [!NOTE]
> **毎回選択ウィンドウを表示する**のは、MarkView が設定画面を持たないためである（UI-116）。エディタの指定は、テーマの切り替えやペイン幅のドラッグと違って「操作した結果」が自然に定まらず、尋ねる場面がどこかに必要になる。それを**開く操作そのものと一体にする**ことで、設定項目を並べた画面を作らずに済み、変更手段が常に目の前にある状態を保てる。

## 2.11 エラー処理（FR-110 系）

### FR-110: エラー通知 **MUST**

以下の事象が発生した場合、利用者に分かる形で通知する。**モーダルダイアログは用いない。** 通知先は事象の性質に応じて次の 3 か所とする。

| 事象 | 通知内容 | 通知先 | 描画の継続 |
| --- | --- | --- | --- |
| ファイルが存在しない | パスと「見つかりません」 | ステータス領域（UI-060） | 直前の内容を維持 |
| ファイルの読み取り権限がない | パスと「アクセスできません」 | ステータス領域 | 直前の内容を維持 |
| 対応していない拡張子 | 「Markdown ファイルではありません」 | ステータス領域 | 直前の内容を維持 |
| リンク先が見つからない（FR-050） | リンク先と「見つかりません」 | ステータス領域 | 直前の内容を維持 |
| リンク先を開けない（許可されていないスキーム、既定のアプリケーションを起動できない。FR-050, FR-053） | リンク先と「開けません」 | ステータス領域 | **直前の内容を維持**（状態画面にしない） |
| 文字コードが不正 | 「一部の文字を置換しました」 | ステータス領域 | 継続する |
| 表示中ファイルが削除された | 「ファイルが削除されました」 | ステータス領域 | 直前の内容を維持 |
| コピーに失敗した | 「コピーできませんでした」 | ステータス領域 | — |
| エディタを起動できない（FR-090） | 「エディタを起動できませんでした」 | ステータス領域 | 直前の内容を維持 |
| エディタに MarkView 自身が指定された（NFR-035） | 「MarkView はエディタとして使えません」 | ステータス領域 | 直前の内容を維持 |
| 貼り付けに失敗した（FR-063） | 「貼り付けできませんでした」 | ステータス領域 | — |
| 書き込む前にファイルが変更されていた（FR-143） | 「ファイルが変更されていたため保存しませんでした」 | ステータス領域 | **書き込まず**、読み直して再描画する |
| ファイルに書き込めない（FR-143） | パスと「保存できませんでした」 | ステータス領域 | 書き込み前の表示に戻す |
| 画像が読み込めない | 代替テキストとプレースホルダ | 本文中の該当箇所 | 継続する |
| Mermaid の構文エラー | エラー内容と元のコード | 本文中の該当箇所 | 継続する |
| PlantUML の構文エラー | **PlantUML が返すエラー図そのもの** | 本文中の該当箇所 | 継続する |
| PlantUML の図が大きすぎる（FR-024） | 上限を超えた旨と元のコード | 本文中の該当箇所 | 継続する |
| PlantUML の取り込み指令（FR-024） | 対応しない旨と元のコード | 本文中の該当箇所 | 継続する |
| 数式の構文エラー | エラー内容と元のソース | 本文中の該当箇所 | 継続する |
| ファイルが大きすぎる（FR-016） | サイズと上限値 | 本文ペインの状態画面（UI-052） | 描画しない |
| 描画中の想定外のエラー（FR-111） | エラー内容 | 本文ペインの状態画面（UI-052） | 描画しない |

通知の文言は英語で表示する（UI-024）。上表の「通知内容」列は意味を示したものであり、画面に出る文言そのものではない。

### FR-111: 異常終了の回避 **MUST**

上記いずれの事象でもアプリケーションは異常終了しない。Markdown の解析・描画処理で発生した想定外のエラーは捕捉し、エラー内容を本文ペインの状態画面（UI-052）に表示して動作を継続する。この状態からでも、ツールバー・ファイルツリー・アウトラインの操作により別の文書を開ける。

## 2.12 図と画像の拡大表示（FR-120 系）

### FR-120: 対象と操作の提供 **MUST**

Mermaid 図・PlantUML 図・本文に埋め込まれた画像について、**本文幅に合わせて縮小した表示とは別に、原寸や拡大で見る手段**を提供する。図は大きくなりがちであり、本文幅（980 論理ピクセル。UI-050）へ縮小すると文字が読めなくなるためである。

手段は 2 つとし、対象ごとに次のときに提供する。

| 対象 | 原寸表示（FR-121） | 拡大画面（FR-122） |
| --- | --- | --- |
| Mermaid 図（描画に成功したもの） | 縮小表示中と原寸表示中 | **常に** |
| PlantUML 図（**エラー図を含む**。FR-024） | 縮小表示中と原寸表示中 | **常に** |
| 本文に埋め込まれた画像（読み込みに成功したもの） | 縮小表示中と原寸表示中 | **縮小表示中と原寸表示中だけ** |

- **「縮小表示中」とは、対象の本来の幅が、本文での表示幅を超えている状態をいう。** ウィンドウ幅やペイン幅の変更で変わりうるため、そのたびに判定し直す。
- 操作は、対象の右上にコピーボタン（FR-060）と並べて置くボタンで行う（UI-053）。**対象そのもののクリック・ダブルクリックには割り当てない。** 図の中の文字の選択や、画像をリンクで囲んだ記法（MD-071）とぶつかるためである。
- **画像のボタンを縮小表示中に限る**のは、段落の中に並ぶアイコンやバッジ（shields.io 等）にまでボタンが付き、本文が繁雑になるのを避けるためである。原寸で出ている画像は、大きく見る理由が薄い。
- 次のものは対象にしない。描画に失敗した Mermaid 図（コードブロックのまま。FR-023）、描画しなかった PlantUML 図（取り込み指令・大きすぎる図。FR-024）、読み込みに失敗した画像（DSP-123）、描画を待っている図、数式（MD-060）。
- **表示済みの図・画像をそのまま使う。** 図の再描画、画像の再取得、Go 側での変換を行わない（NFR-013, NFR-032）。
- 文書・ファイルを変更しない。編集モード（FR-140）とは無関係に使える。
- 再描画（FR-014, FR-015）の前後で「**同じ対象**」とは、**文書の中で同じ種類のもの（Mermaid 図・PlantUML 図・画像）のうち、同じ順番にあるもの**をいう。FR-121 と FR-122 はこの意味で状態を引き継ぐ。
  - **順番は、描画に成功したかどうかに関わらず数える。** Mermaid 図と PlantUML 図はソース上のブロックの順（描画に失敗したもの・描画しなかったものを含む）、画像は本文中の画像の順（読み込みに失敗したものを含む）とする。成否で数え方を変えると、1 つの図が壊れただけで後ろの図がすべて「別の対象」になる
  - **図は描画が非同期である。** 引き継げるかどうかの判断は、再描画後にその図の描画が終わってから（成功・失敗のどちらでも）行う。描画を待っている間に「見つからない」と判断しない

### FR-121: 本文中での原寸表示 **MUST**

- ボタンで、その対象だけを**縮小表示と原寸表示の間で切り替える。**
- 原寸表示では、対象を**本来の大きさ**で描く。本文幅を超える分は、**その対象の枠の内側で横スクロール**させる。ページ全体に横スクロールを発生させない（UI-050。表の MD-024 と同じ扱い）。
- 「本来の大きさ」は論理ピクセルで数え、**表示倍率（FR-081）の影響を受けない**。図と画像は倍率に追随しない（DSP-021）ためである。
- 状態は対象ごとに持つ。**テーマの切り替え（FR-070）では維持する**——図は再描画されるが、利用者から見れば同じ図である。
- **同じ文書の再描画（[1.7](01-overview.md)。編集モードでの書き込みによるものを含む）でも、同じ対象（FR-120）が再描画後にもあれば原寸表示を保つ。** 編集のたびに図が縮小表示へ戻ると、読んでいた箇所を見失うためである（FR-130 の並べ替えと同じ考え方）。
- **文書の切り替え**（[1.7](01-overview.md)）では縮小表示に戻す。
- 状態は設定に保存しない（UI-111）。

### FR-122: 拡大画面 **MUST**

- ボタンで、対象 1 つだけを表示する**拡大画面**を開く。**メインウィンドウ内に描画する画面であり、独立した OS ウィンドウではない**（AR-001, AR-060）。情報ウィンドウ（UI-100）と同じ位置づけであり、Wails v2 は 2 つ目のウィンドウを持てない。
- 拡大画面は、**ステータス領域を除く**メインウィンドウいっぱいを使う（UI-104）。**開いている間に出た通知（FR-110）を見落とさないためである。**
- **開いた時点では、対象の全体が画面に収まる倍率**で中央に表示する。小さな図は拡大され、大きな図は縮小される。まず全体を見てから、必要な箇所へ寄る使い方を想定する。その倍率が下の範囲を外れる場合は、範囲の端に丸める。
- 拡大画面では次の操作ができる。操作の割り当ては UI-104 で定める。
  - 拡大・縮小（ボタン、キー、マウスホイール）。**ホイールではカーソルの位置を中心に**拡大・縮小する
  - 「全体」（開いた時点と同じ、全体が収まる倍率）と「原寸」（100 %）への切り替え
  - ドラッグと方向キーによる表示位置の移動
- 倍率の範囲は **10 %〜1000 %** とし、現在の倍率を画面に表示する。
- **図は SVG のまま拡大し、拡大しても輪郭をぼやけさせない。** 画像はラスタのまま拡大してよい（ぼやけることを許容する）。
- `Esc` と閉じるボタンで閉じる。閉じたとき、**本文のスクロール位置を開く前のまま保ち、フォーカスを開いたボタンへ戻す。** 開いている間に再描画されて開いたボタンが無くなっていれば、同じ対象（FR-120）のボタンへ戻し、それも無ければ本文ペインへ戻す。
- 開いている間は、背後のメインウィンドウの操作を受け付けない（UI-100 と同じ。**ファイルのドロップを除く**。UI-090）。同時に開ける拡大画面は 1 つとし、**情報ウィンドウ・エディタ選択ウィンドウとも同時には開かない。**
- 開いている間に表示中の文書が再描画された場合（同じ文書の再描画。[1.7](01-overview.md)。外部の更新や、同じファイルのドロップ）、**同じ対象（FR-120）が再描画後にもあれば中身を差し替え、倍率と表示位置を保つ（SHOULD）。** 外部エディタで図を書き直しながら拡大画面で確かめる使い方（UC-03）のためである。見つからなければ閉じる。**文書の切り替え**（[1.7](01-overview.md)。開いている間にファイルがドロップされた場合など）では閉じる。
- 倍率と表示位置は設定に保存しない（UI-111）。

> [!NOTE]
> **本文中の原寸表示（FR-121）と拡大画面（FR-122）の両方を持つ**のは、見たいものが違うからである。原寸表示は**本文を読む流れのまま**図の細部を追うためのものであり、本文幅（980 論理ピクセル）より広くは見られない。拡大画面は**ステータス領域を除くウィンドウいっぱい**を使い、原寸を超えて拡大できる。

## 2.13 表の並べ替え（FR-130）

### FR-130: 表示上の並べ替え **SHOULD**

GFM の表（MD-024）を、列を選んで並べ替えて表示できる。**並べ替えるのは表示だけであり、ファイルは書き換えない。** 編集モード（FR-140）でなくても使える。

- 見出し行の各セルに並べ替えのボタンを置く（UI-054）。**見出しセル全体のクリックには割り当てない。** 編集モードでのセルの編集（FR-142）と操作がぶつかるためである。
- ボタンを押すたびに、その列で **昇順 → 降順 → 元の順** を巡回する。並べ替えの基準にする列は 1 つの表につき 1 列とし、別の列のボタンを押すと、その列の昇順から始める。
- 対象は、見出し行を除く行が 2 行以上ある表とする。
- 比較は、セルに**表示されている文字列**で行う。
  - 両方が数値として解釈できる場合は、数値として比べる。前後の空白を除き、桁区切りの `,` と末尾の `%` を無視したうえで 10 進数として解釈できるものを数値とする（`-1.5`、`1,234`、`10%`）
  - それ以外は文字列として比べる。大文字と小文字を区別せず、文字列の中の数字の並びは数値の大小で比べる（`item2` は `item10` より前）
  - 数値と文字列が混ざる場合は、昇順では数値を先に、降順では文字列を先に置く（降順は昇順の逆順とする）
  - **ただし空のセルは、昇順・降順のどちらでも末尾に置く**（逆順の例外）
  - 比較して等しい行は、元の順序を保つ
- どの列を、どちら向きに並べ替えているかを見出しセルに表示する。
- **文書の切り替え**（[1.7](01-overview.md)）で解除する。**同じ文書の再描画（[1.7](01-overview.md)）では、再描画後も同じ順番の表（文書の中で何番目の GFM の表か）の列数が変わっていなければ状態を保つ。** 編集のたびに行の並びが元へ戻ると、いま直した行を見失うためである。状態の保ち方は再描画の契機で分ける。
  - **編集モードでの書き込み（FR-141〜FR-144）による再描画では、並べ直さない。** 直前の行の並びをそのまま保つ。**並べ替えの基準にしている列のセルを直しても、その行は動かない**（並べ替えの順から外れうる）。見出しセルの表示は並べ替え中のままとし、次にボタンを押したときに巡回の次の段へ進んで並べ直す
  - **それ以外の再描画**（外部の更新・再読み込み・同じファイルの開き直し）では、保った列と向きで並べ直す
  - 再描画後に、見出し行を除く行が 2 行未満になった場合、または列数が変わった場合は解除する
- 並べ替えたら、検索の状態をリセットする（FR-080）。
- 状態は設定に保存しない（UI-111）。
- **生 HTML で書かれた表（`<table>`。MD-072）は対象にしない。** 見出し行と本体の行の区別や、セルの結合の有無が保証されないためである。**文書の書き手が、生 HTML で並べ替えの対象を装えてはならない**（NFR-030）。

## 2.14 編集モード（FR-140 系）

> [!IMPORTANT]
> **MarkView は閲覧に特化したアプリケーションであり、文書を自由に編集する機能は持たない**（[1.3.2](01-overview.md)）。本節の編集は、**文書の構造を変えない 2 種類の書き換え——タスクリストのチェックボックスと、表のセルの文字——に限る。** それ以外の編集は、これまでどおり外部エディタへ委ねる（FR-090）。
>
> **対象を増やすときは、本節の改訂から始める。** 「ついでにここも直せるように」と足していくと、境界が消えてエディタになる。

### FR-140: 編集モード **MUST**

**表示中の Markdown ファイルへの書き込みは、編集モードの間だけ行う。** 編集モードでない間の振る舞いは、本節を加える前と変わらない（チェックボックスは読み取り専用で、セルは編集できない）。

- ツールバーの編集モードボタン（UI-020）、またはショートカット `Ctrl+Shift+M`（UI-090）で、編集モードの開始と終了を切り替える。
- **起動時は常に編集モードでない。** 状態を設定に保存しない（UI-111）。受け取った文書を読むだけのつもりで開いたときに、書き換えられる状態で始まってはならない。多重起動（UI-115）で後勝ちになる値にしないためでもある。
- 編集モードを開始できるのは、**文書を描画している状態**に限る。次の状態では開始できない（ボタンを淡色にする。UI-021）。

| 状態 | 開始できない理由 |
| --- | --- |
| 文書未表示と状態画面（`welcome` / `confirm-large` / `too-large` / `render-error`。UI-052） | 書き換える対象が描画されていない |
| 読み込みの際に不正なバイト列を置き換えた文書（FR-021） | **表示している内容と、ファイルの内容が一致していない** |
| 表示中のファイルが削除された（FR-014） | 書き込み先が無い |

- 次のときは、**自動的に編集モードを終える。**
  - **文書の切り替え**（[1.7](01-overview.md)）が起きたとき。**利用者が「この文書を直す」と決めた文書だけを書き換えるためである。** リンクで移った先の文書が、書き換えられる状態で開いてはならない。切り替え先が状態画面（UI-052）であっても終える
  - 上の表の「開始できない状態」になったとき（読み直した結果、不正なバイト列を含んでいた場合や、ファイルが削除された場合）
- **次のときは終えない。**
  - 同じ文書の再描画（FR-014, FR-015）。編集モードでの書き込みも FR-014 の経路で再描画されるためである
  - 同じファイルを開き直したとき、同じ文書の中のアンカーへ移ったとき（文書の切り替えに当たらない。[1.7](01-overview.md)）
  - **保存に伴う一時的な削除。** 「一時ファイルへ書いてからリネームする」保存（FR-014）では、途中でファイルが一瞬存在しなくなる。**MarkView 自身の書き込み（FR-143）も同じ形になりうる。** 「削除された」と判断するのは、FR-014 の待ち（デバウンス）を経てもファイルが存在しないときに限る
- 編集モードの間は、そのことを画面上で常に明示する（ツールバーのボタンの ON 表示と、本文ペインの表示。UI-021, UI-055）。
- 編集モードを終えたら、取り消しの履歴（FR-144）を破棄する。

### FR-141: タスクリストのチェックボックスの切り替え **MUST**

- 編集モードの間、タスクリスト（MD-022）のチェックボックスをクリックする（またはフォーカスして `Space` を押す）と、状態を反転してファイルへ書き込む。
- **チェックボックスの見た目は、書き込みの完了を待たずに即座に反転する**（NFR-012）。ファイルから読み直した再描画は、その後に FR-014 の経路で行う。書き込みに失敗したら見た目を戻す（FR-143）。
- 書き換えるのは、その項目の **`[ ]` / `[x]` の括弧の中の 1 文字だけ**とする。オンにするときは `x`（小文字）を、オフにするときは半角空白を書く。`[X]`（大文字）はオンとして扱い、オフにすると半角空白になる。
- **対象は GFM のタスクリストの項目に限る。** 生 HTML で書かれた `<input type="checkbox">`（MD-072）は、編集モードの間も読み取り専用のままとする。
- **文書の書き手が、書き換えの対象を偽装できてはならない**（NFR-030）。どれがタスクリストの項目かを、描画後の HTML の**属性の有無や形だけで**判断しない（変換ごとの鍵と照合する。IMP-120）。
- 書き込みは FR-143 の規則に従う。

### FR-142: 表のセルの書き換え **MUST**

- 編集モードの間、GFM の表（MD-024）のセル（**見出し行のセルを含む**）を**ダブルクリック**すると、そのセルの編集欄を開く。
- **セルの中にあるボタン**（並べ替えのボタン UI-054、画像の原寸表示・拡大画面のボタン UI-053）**の上でのダブルクリックでは、編集を始めない。** ボタンを素早く 2 回押す操作と区別がつかないためである。
- **編集モードの間は、表のセルの中のリンクをクリックしても遷移しない**（FR-050 の例外）。ダブルクリックの 1 回目でリンク先へ移ると、編集を始める前に文書が切り替わり、編集モードが終わるためである。リンクをたどるときは編集モードを終える。
- 編集欄には、そのセルの **Markdown のソース**（`**太字**` のような記法を含み、前後の空白を除いたもの）を入れた状態で開く。描画後の文字列ではない。
- 編集欄は 1 行とする。**`Enter` で確定してファイルへ書き込み、`Esc` で取り消す。編集欄からフォーカスが外れた場合も取り消す**（何も書き込まない）。**操作ごとに即座に書き込むため、意図しない確定を起こさない側へ倒す。**
  - **次の 2 つは「フォーカスが外れた」に数えない。** 編集欄で右クリックメニュー（FR-063）を開いている間と、ウィンドウ自体がフォーカスを失っている間（他のアプリケーションへ文字をコピーしに行く場合など）である。メニューを項目の実行・`Esc`・本文のスクロールで閉じたとき、ウィンドウへ戻ったとき（ウィンドウがフォーカスを失ってメニューが閉じた場合を含む）は、編集欄へフォーカスを戻す。**数えると、`Paste` を選ぶ前に編集欄が消える**
  - **ただし、メニューの外をクリックしてメニューを閉じた場合は「フォーカスが外れた」に数え、編集を取り消す。** フォーカスはクリックした先へ移る（UI-085）。メニューを開いていないときに編集欄の外をクリックした場合と同じ結果にするためである
  - **編集欄にフォーカスがある間の `Enter` は確定だけに使い、検索の移動（FR-080）には使わない。** 検索バーを開いたままセルを編集しても、`Enter` で検索のヒットへ移らない
  - **IME の変換中の `Enter` と `Esc` は変換の操作であり、確定にも取り消しにも使わない。** 日本語の変換を確定した `Enter` で書き込みが起きてはならない
- 確定したら、**セルの見た目は書き込みの完了を待たずに新しい内容へ変える**（NFR-012）。表示するのは、確定した文字列をそのまま文字として出したものでよく、記法の描画はファイルから読み直した再描画（FR-014 の経路）で行う。書き込みに失敗したら見た目を戻す（FR-143）。
- 書き換えるのは**そのセルのソースの範囲だけ**とする。区切りの `|`、セルの前後の空白、他のセル、区切り行（`---`）、表の外は変えない。**桁を揃えるための空白を詰め直さない。**
- 入力された文字列は次のとおり扱う。
  - エスケープされていない `|` は、表の区切りにならないよう `\|` として書き込む
  - 改行は入力できない。貼り付け（FR-063）で持ち込まれた改行は、半角空白に置き換える
  - 内容が変わっていなければ書き込まない
  - 空にしてよい（空のセルになる）
- 次のセルは編集できない。
  - **ソース上に存在しないセル。** 行のセルの数が見出し行より少ないとき、GFM の規則で補われる空のセルがこれに当たる。書き込むには区切りの `|` を足すことになり、表の形を変えるためである
  - 生 HTML で書かれた表（`<table>`）のセル
- 表を並べ替えている間（FR-130）も、**表示上の位置ではなくソース上の位置で**、正しいセルを書き換える。
- セルを編集している間に文書が再描画された場合（FR-014）と、編集モードが終わった場合（FR-140）は、編集を取り消す。
- 書き込みは FR-143 の規則に従う。

### FR-143: 書き込みの規則 **MUST**

FR-141 / FR-142 / FR-144 のすべての書き込みは、次の規則に従う。

- **書き込む前に、ファイルの現在の内容が、MarkView が把握している内容と一致することを確かめる。** 「把握している内容」とは、**最後に読み込んだ内容、またはその後に MarkView 自身が書き込んだ内容**のうち新しいほうをいう。一致しない場合（外部のエディタや別の MarkView が先に保存した場合）は**書き込まず**、その旨を通知し（FR-110）、ファイルを読み直して再描画する。**他者の変更を黙って上書きしない。**
- **再描画を待たずに続けて操作した場合も、各操作は直前の書き込みを反映した内容に対して行う。** 書き換える位置は操作のたびに求め直し、前の書き込みで位置がずれたセルやチェックボックスを取り違えない。続けてクリックしただけで「ファイルが変更されていた」と誤って拒まない。
- **MarkView 自身による表示中ファイルの読み直し（FR-014, FR-015, 同じファイルの開き直し）と書き込みは、1 つずつ順に行う。** 読み直しの途中に書き込みが割り込まないようにし、「把握している内容」との比較は読み込みを終えた時点の値で行う。**割り込ませると、自分の書き込みを「外部の変更」と取り違え、取り消しの履歴を誤って捨てる**（FR-144）。
- **書き込みの指示は、それが作られた描画に対してだけ有効とする。** 次の指示は Go 側で拒み、何も書き込まない。編集モードでないときに届いた指示、状態画面（UI-052）の表示中に届いた指示、**その指示を作った描画の後に、文書の切り替えか、MarkView 自身の書き込み以外を契機とする再描画（外部の更新・再読み込み・開き直し）が起きていた場合の指示**である。**MarkView 自身の書き込みの直後の再描画では、それより前の描画で作った指示を有効なまま保つ**——構造を変えない編集では何番目の要素かは変わらず（2.14 の IMPORTANT。書き換えはチェックボックスの 1 文字とセルの中身だけであり、タスク・表・セルを増減しない）、位置は書き込みのたびに求め直すためである（上記）。保たないと、続けてクリックしただけで 2 つ目が拒まれる。見た目を先に変えるため（FR-141, FR-142）、指示は描画より遅れて届くことがあり、**その間に表示が別の文書へ切り替わっていれば、画面に無い文書を書き換えることになる。** 拒んだことは通知しない（見た目は最新の描画に従う）。
- **書き込みは、書き込み先と同じディレクトリに作った一時ファイルへ内容の全体を書き出し、リネームで置き換える。** 途中で失敗しても元のファイルが残るためである。
  - **元のファイルが書き込み可能でなければ、置き換えない**（読み取り専用の扱い）。ディレクトリに書き込めれば置き換え自体はできてしまうが、利用者が書き込みを禁じたファイルを書き換えてはならない
  - ディレクトリに書き込めない場合は、書き込めないものとして通知する（FR-110）
  - 置き換えた後のファイルの権限ビットは、元のファイルに合わせる（**SHOULD**。下の「ファイルの権限を変えない」）
  - **ハードリンクは切れ、Windows でファイル個別に設定したアクセス制御は引き継がれない。** これは許容する。一部だけが書かれたファイルを残さないことを優先する
- **書き換える箇所以外のバイト列を 1 バイトも変えない。** BOM の有無、改行コード（CRLF / LF / CR）、末尾の改行、Front Matter（MD-073）、ソース上の空白をそのまま残す。**読み込み時の正規化（FR-021）を書き戻さない。**
- シンボリックリンクを開いている場合は、**リンク先の実体**を書き換える。リンクそのものを通常のファイルで置き換えない。
- 書き込みに失敗した場合（読み取り専用、権限が無い、他のプログラムが開いている等）は、通知し（FR-110）、表示を書き込み前の状態に戻す。**書きかけの状態（一部だけが書かれたファイル）を残さない。**
- ファイルの権限を変えない（**SHOULD**）。
- 書き込みに使う一時ファイル（上記）は、**成功しても失敗しても、書き込みが終わった後に残さない。** バックアップファイルを作らない。
- 書き込んだ後は、**監視のイベントを待たずに** FR-014 の再描画の処理を呼び、スクロール位置を維持する（FR-014）。
- **書き込み先は、Go 側が保持する表示中のファイルだけとする。フロントエンドから書き込み先のパスを受け取らない。** フロントエンドが伝えるのは「どのチェックボックスか・どのセルか」と新しい文字列だけである（AR-031, IMP-300 と同じ考え方）。**書き込み先が画面の対象（FR-090 の IMPORTANT）と一致することは、上の「指示を作った描画に対してだけ有効」によって保証する。**

### FR-144: 元に戻す・やり直す **MUST**

- 編集モードの間、`Ctrl+Z` で直前の書き込みを取り消し、`Ctrl+Y` または `Ctrl+Shift+Z` で、取り消した書き込みをやり直す。**取り消しとやり直しも、それ自体がファイルへの書き込みであり、FR-143 に従う。**
- 対象は FR-141 と FR-142 の書き込みとする。
- **入力欄（セルの編集欄・検索バーの入力欄）にフォーカスがある間は、入力欄の中の取り消しとして働き**、ファイルの取り消しは行わない。
- 履歴は**メモリ上だけ**に持ち、ディスクに書かない（NFR-042）。保持する上限は 100 操作とし、超えたら古いものから捨てる。
- **履歴は書き換えた箇所の差分（位置と、前後の文字列）で持ち、文書全体の写しを持たない。** FR-143 の「把握している内容」との一致も、内容の要約値（ハッシュ）で確かめ、内容の写しを保持しない。**最大 50 MB の文書（FR-016）でも、編集のためにメモリ使用量が文書の大きさに比例して増えないようにする**（NFR-020）。
- 取り消した後に新しく書き込んだら、やり直しの履歴を捨てる。
- 次のときは履歴を破棄する。
  - 編集モードを終えたとき（FR-140）
  - **ファイルが MarkView の書き込み以外で変更されたと分かったとき**（同じ文書の再描画（[1.7](01-overview.md)）で読み直した結果が「把握している内容」（FR-143）と一致しない場合と、FR-143 の書き込み前の確認で一致しなかった場合）。**他者の変更の上から、古い状態を書き戻さないためである**
- 取り消すもの・やり直すものが無いときは、何もしない（通知しない）。
- 編集モードでないときの `Ctrl+Z` / `Ctrl+Y` / `Ctrl+Shift+Z` は、何もしない。
