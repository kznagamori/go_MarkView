# 31. 単体テスト仕様: テストケース

> 索引: [README](README.md) | 単体テスト: [30](30-test-policy.md) / **31**

本文書は、パッケージごとの単体テストケースを定める。書き方の規範と禁止事項は [30. 方針と禁止事項](30-test-policy.md) にある。

## 31.1 読み方

### UT-090: 表の形式 **MUST**

各ケースは以下の形式で記す。

```
### UT-nnn: <観点>
対象: <パッケージ>.<関数>   根拠: <要求 ID> / <実装 ID>

| # | 入力 | 期待 |
```

- 「根拠」に挙げた仕様が変わったら、そのケースも見直す（UT-010）。
- 表の各行は、テーブル駆動テスト（UT-014）の 1 ケースに対応する。行の説明文をそのままサブテスト名にしてよい。
- ここに挙げたものは**最低限**であり、これで十分という意味ではない。実装中に気づいた境界値は追加してよい。逆に、ここにないケースを削る場合は理由を残す。

## 31.2 document パッケージ（UT-1xx）

### UT-101: BOM と改行コードの正規化
対象: `document.Normalize`　根拠: FR-021 / IMP-103

| # | 入力（バイト列） | 期待 |
| --- | --- | --- |
| 1 | `EF BB BF` + `"# A"` | `"# A"`（BOM 除去）、`replaced=false` |
| 2 | `"# A"`（BOM なし） | `"# A"` そのまま |
| 3 | `"a\r\nb"` | `"a\nb"` |
| 4 | `"a\rb"` | `"a\nb"` |
| 5 | `"a\nb"` | `"a\nb"`（変化なし） |
| 6 | `"a\r\n\r\nb"` | `"a\n\nb"` |
| 7 | `EF BB BF` のみ | `""` |
| 8 | 中間に現れる `EF BB BF` | 除去しない（先頭のみが BOM） |
| 9 | 空のバイト列 | `""`、`replaced=false` |

### UT-102: 不正な UTF-8 の置換
対象: `document.Normalize`　根拠: FR-021 / IMP-103

| # | 入力 | 期待 |
| --- | --- | --- |
| 1 | `"a"` + `0xFF` + `"b"` | `0xFF` が U+FFFD に置換、`replaced=true` |
| 2 | 正常な UTF-8 の日本語 | 変化なし、`replaced=false` |
| 3 | UTF-16 の BOM（`FF FE`）で始まる | 変換せず、不正バイトを置換して返す。**エラーにしない** |
| 4 | 途中で切れたマルチバイト列 | U+FFFD に置換、`replaced=true` |

### UT-103: 行数の算出
対象: `document`（`LineCount`）　根拠: FR-021 / IMP-104

| # | 入力 | 期待 |
| --- | --- | --- |
| 1 | `"a\nb\nc"` | 3 |
| 2 | `"a\nb\nc\n"` | 3（末尾の改行で加算しない） |
| 3 | `"a"` | 1 |
| 4 | `""` | 1 |
| 5 | `"\n"` | 1 |
| 6 | `"a\r\nb"`（正規化後に判定） | 2 |

### UT-104: サイズ閾値の判定
対象: `document.Load`　根拠: FR-016 / IMP-101, IMP-102

| # | ファイルサイズ | `Confirmed` | 期待 |
| --- | --- | --- | --- |
| 1 | 1 KB | false | 正常に読み込む |
| 2 | ちょうど 10 MiB | false | 正常に読み込む（**閾値ちょうどは超過ではない**） |
| 3 | 10 MiB + 1 バイト | false | `ErrNeedsConfirm`。`*SizeError` に実サイズと閾値が入る |
| 4 | 10 MiB + 1 バイト | **true** | 正常に読み込む |
| 5 | ちょうど 50 MiB | true | 正常に読み込む |
| 6 | 50 MiB + 1 バイト | true | `ErrTooLarge`（`Confirmed` でも読み込まない） |
| 7 | 0 バイト | false | 正常に読み込む。空の HTML を返す |

> [!NOTE]
> ケース 2 と 5（閾値ちょうど）、ケース 6（`Confirmed` でも拒否）が、この機能で最も間違えやすい箇所である（UT-013）。

### UT-105: 拡張子の判定
対象: `document.IsMarkdown`　根拠: FR-010, FR-031 / IMP-105

| # | 入力 | 期待 |
| --- | --- | --- |
| 1 | `README.md` | true |
| 2 | `README.MD` | true（大文字小文字を区別しない） |
| 3 | `a.markdown` / `a.mdown` / `a.mkd` | いずれも true |
| 4 | `a.txt` / `a.png` / `a.go` | false |
| 5 | `md`（拡張子なし、名前が md） | false |
| 6 | `.md`（名前が拡張子のみ） | false |
| 7 | `a.md.txt` | false |
| 8 | `` （空文字） | false |

### UT-106: 読み込みエラーの種別
対象: `document.Load`　根拠: FR-110 / IMP-021, IMP-102

| # | 状況 | 期待 |
| --- | --- | --- |
| 1 | 存在しないパス | `errors.Is(err, ErrNotFound)` が true |
| 2 | 読み取り権限のないファイル | `errors.Is(err, ErrPermission)` が true |
| 3 | 拡張子が Markdown でない | `errors.Is(err, ErrNotMarkdown)` が true |
| 4 | ディレクトリのパス | エラーを返す（`ErrNotMarkdown` または `ErrNotFound`） |

- エラーメッセージの文字列を比較しない。種別のみを `errors.Is` で判定する（UT-042）。
- ケース 2 は Windows では再現が難しい。`runtime.GOOS` で分岐し、Linux でのみ実行してよい。

## 31.5 watcher パッケージ（UT-4xx）

すべて `t.TempDir()` の実ファイルで検証する。待機はチャネルとタイムアウトで行う（UT-019, UT-037）。

### UT-401: 変更の検知
対象: `watcher`　根拠: FR-014 / IMP-140, IMP-141

| # | 操作 | 期待 |
| --- | --- | --- |
| 1 | 監視中のファイルへ追記 | `Modified` イベントが 1 件届く |
| 2 | 同じディレクトリの**別**ファイルを変更 | イベントが届かない（IMP-141） |
| 3 | 監視していないディレクトリのファイルを変更 | イベントが届かない |

### UT-402: デバウンス
対象: `watcher`　根拠: FR-014 / IMP-142

| # | 操作 | 期待 |
| --- | --- | --- |
| 1 | 20 ms 間隔で 5 回書き込む | イベントは **1 件**にまとまる |
| 2 | 500 ms 間隔で 2 回書き込む | イベントは 2 件 |

タイムアウトは 2 秒程度を確保する。CI の負荷でぎりぎりにならないようにする（UT-019）。
