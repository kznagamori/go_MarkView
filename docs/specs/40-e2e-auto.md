# 40. E2E テスト仕様: 方針と自動テスト

> 索引: [README](README.md) | E2E テスト: **40** / [41](41-e2e-manual.md)

本文書は、MarkView の E2E テスト（`E2E-nnn`）の方針と、**CI で自動実行するテスト**を定める。人が操作して確認する手動テストは [41. 手動テスト](41-e2e-manual.md) にある。

## 40.1 位置づけ

### E2E-001: 目的 **MUST**

E2E テストの目的は、**利用者が実際に受け取る配布物が、想定した環境で想定どおりに動くことを確かめること**である。

単体テスト（[30](30-test-policy.md) / [31](31-test-cases.md)）が「部品が正しいか」を見るのに対し、E2E テストは「組み上がったものが動くか」を見る。両者は代替関係にない。

| 観点 | 単体テスト | E2E テスト |
| --- | --- | --- |
| 対象 | `internal/` のパッケージ | ビルドされた実行ファイル |
| 実行 | `go test` | 配布物の起動、および人の操作 |
| 検出できるもの | ロジックの誤り | 組み合わせの誤り、環境依存、配布物の欠落 |
| 検出できないもの | 結合・配置・環境の問題 | 内部の境界値の誤り |

### E2E-002: 自動と手動の分担 **MUST**

| 区分 | 対象 | 実行 | 文書 |
| --- | --- | --- | --- |
| **自動テスト** | 配布物の構成、起動と終了、CLI の出力、依存ライブラリ、描画スモーク | リリース CI（BR-050）のビルド後 | 本文書 40.4 節 |
| **手動テスト** | UI の操作を伴うすべての振る舞い | プレリリースの成果物に対して人が実施（E2E-205） | [41 章](41-e2e-manual.md) |

いずれも**ビルドされた成果物を必要とする**ため、PR 単位の検証（BR-052）では実行しない。例外は描画スモークテスト（E2E-109）で、これは `frontend/vendor/` を変更する PR でも実行する。

分担の基準は「**CI で安定して繰り返せるか**」である。

- 自動テストは、**WebView の UI を操作しない**範囲に限る。ウィンドウ内の要素をクリックする、描画完了を待つ、といった操作は環境によって成否が変わり、失敗しても「また揺れたのだろう」と無視されるようになる（UT-037 と同じ理由）。
- 起動そのもの（プロセスが立ち上がり、異常終了しないこと）は自動テストの対象とする。これは配布物の検証として価値が高く、判定も明確である。
- UI の操作は手動テストに委ねる。回数は減るが、判断の伴う確認は人のほうが確実である。

> [!NOTE]
> `IMP-042` と `UT-038` は「WebView を起動する自動テストを行わない」と定めている。本文書の自動テストは、**起動と終了までを確認し、ウィンドウ内の操作を行わない**。この線引きにより既存方針と矛盾しない。線を越える変更を行う場合は、両方の文書を同時に改訂する。

## 40.2 検証環境（E2E-010 系）

### E2E-010: 対象環境 **MUST**

| コード | 環境 | 自動 | 手動 |
| --- | --- | --- | --- |
| **W1** | Windows 11 / amd64 | ○ | **全項目**（主環境） |
| **L1** | Ubuntu 24.04 / amd64 | ○ | OS 差の出る項目 |
| **WA** | Windows 11 / arm64 | ○（ビルドのみ） | 起動確認（入手できた場合） |
| **LA** | Ubuntu 24.04 / arm64 | ○ | 起動確認（入手できた場合） |

- 主環境を W1 とするのは、開発ホストが Windows 11 であり（01 章 1.6）、最も頻繁に動かされる環境だからである。
- L1 で確認する「OS 差の出る項目」は、41 章の各ケースに環境コードで示す。
- arm64（WA / LA）は実機の入手性に依存するため、**起動確認のみを必須とし、それ以外は任意**とする。CI ではビルドと自動テストが通ることをもって最低限の担保とする。

### E2E-011: 検証に用いる配布物 **MUST**

E2E テストは、**開発ビルドではなくリリースと同じ手順で作られた成果物**に対して行う（BR-010, BR-020）。

- 自動テストは、リリース CI がビルドした成果物（zip / tar.gz）を展開して実行する。
- 手動テストは、**プレリリースタグから CI が作った成果物**を用いる。手順は E2E-205 に定める。
- `wails dev` で起動したものや、手元でビルドしたものを検証の対象にしない。開発ビルドは開発者ツールが有効（BR-012）であり、またローカルビルドには埋め込み資産の自動更新（BR-043）が反映されないため、配布物と内容が食い違いうる。

### E2E-012: 検証用データ **MUST**

E2E テストで用いる Markdown 一式を `testdata/e2e/` に用意する。

```
testdata/
├── showcase.md              全対応記法（BR-053 が定める。UT-214 と E2E で共用）
├── showcase.golden.html     ゴールデン（UT-214）
└── e2e/                     E2E の検証用データ
    ├── README.md
    ├── docs/design.md
    ├── docs/img/sample.png
    ├── outside/external.md
    └── broken/invalid-utf8.md
```

| ファイル | 用途 |
| --- | --- |
| `e2e/README.md` | 起動時に自動表示される文書（FR-013）。他の文書へのリンクを含む |
| `e2e/docs/design.md` | 相対リンクの遷移先 |
| `e2e/docs/img/sample.png` | ローカル画像 |
| `e2e/outside/external.md` | ツリールート外への遷移先（FR-052） |
| `e2e/broken/invalid-utf8.md` | 不正な UTF-8 を含む（FR-021） |
| `showcase.md` | 全対応記法。**BR-053 が定める `testdata/showcase.md` をそのまま使う** |
| （生成） | 10 MB 超・50 MB 超のファイル（FR-016 の確認用） |

- **`showcase.md` を E2E 用に複製しない。** BR-053・UT-214・E2E で同じ 1 つのファイルを使う。複製すると、記法を追加したときに片方だけが更新される。
- 巨大ファイルはリポジトリに含めない。検証のたびに生成する。
- この一式は自動テストと手動テストの両方で使う。用途ごとに別のデータを用意しない。

## 40.3 自動テストで行わないこと（E2E-020 系）

### E2E-020: 禁止事項 **MUST**

| 禁止 | 理由 |
| --- | --- |
| ウィンドウ内の要素をクリック・入力する | 描画完了の判定が環境依存であり、flaky になる（E2E-002） |
| スクリーンショットを撮って画像比較する | フォント・DPI・OS のテーマで差が出て、意味のない失敗が続く |
| 固定時間の `sleep` で描画完了を待つ | 環境で揺れる（UT-037 と同じ） |
| ネットワークにアクセスする | リモート画像の確認は手動で行う（IMP-042） |
| 実際のリリースを作成して確認する | 検証のために公開してはならない |

### E2E-021: 失敗したときの扱い **MUST**

- 自動テストが失敗した場合、**リリースを中止する**（E2E-100 の表に従う）。失敗を承知でリリースしない。
- 失敗が環境の一時的な問題と判断される場合も、原因を特定してから再実行する。理由を確かめずに再実行を繰り返さない。繰り返しで通ったテストは、次に本物の不具合が出たときにも同じ扱いをされる。

## 40.4 自動テストのケース（E2E-1xx）

### E2E-100: 実行の位置づけ **MUST**

自動テストは、プレリリースタグと本タグのどちらでも同じ内容を実行する。プレリリースで通ったものが本リリースでも通ることを確かめる意味を持つ。

| ケース | 実行タイミング | 失敗時 |
| --- | --- | --- |
| E2E-101〜E2E-103 | リリース CI（BR-050）のビルド後 | リリースを中止 |
| E2E-104〜E2E-106 | 同上 | リリースを中止 |
| E2E-107 | 同上 | 記録のみ（BR-060） |
| E2E-108 | 同上 | リリースを中止 |
| E2E-109 | リリース CI および `frontend/vendor/` を変更する PR（BR-054） | リリースを中止 |

### E2E-101: 配布アーカイブの構成
根拠: BR-020, BR-021

| # | 確認 | 期待 |
| --- | --- | --- |
| 1 | zip / tar.gz を展開する | 成功する |
| 2 | 展開後のファイル一覧 | `MarkView`（または `MarkView.exe`）、`LICENSE`、`README.md` の 3 点のみ |
| 3 | ディレクトリ階層 | 作られない（BR-021） |
| 4 | 実行ファイルの権限（Linux） | 実行可能ビットが立っている |
| 5 | 設定ファイル・ランタイムの同梱 | **含まれない**（BR-021） |

### E2E-102: `--version` の出力
根拠: FR-012, BR-030

| # | 実行 | 期待 |
| --- | --- | --- |
| 1 | `MarkView --version` | 終了コード 0。**ウィンドウを開かない** |
| 2 | 出力内容 | バージョン（タグ名）、コミットハッシュ、ビルド日時を含む |
| 3 | バージョン文字列 | リリースしようとしているタグ名と一致する |
| 4 | `MarkView -v` | `--version` と同じ出力 |

ケース 3 は、`ldflags` の埋め込み漏れ（BR-030）を検出する。この確認がないと、`dev` のまま配布される事故が起きうる。

### E2E-103: `--help` の出力
根拠: FR-012

| # | 実行 | 期待 |
| --- | --- | --- |
| 1 | `MarkView --help` | 終了コード 0。ウィンドウを開かない |
| 2 | 出力内容 | 使用方法と、`--version` / `--help` の説明を含む |
| 3 | 出力の言語 | 英語（UI-024） |
| 4 | `MarkView -h` | 同じ出力 |

### E2E-104: 起動と終了
根拠: FR-012, FR-013, NFR-050

**ウィンドウ内の操作は行わない。** 起動して一定時間後に終了させ、異常終了していないことを確認する。

| # | 実行 | 期待 |
| --- | --- | --- |
| 1 | 検証用データのディレクトリで引数なし起動 | プロセスが起動し、5 秒後も生存している |
| 2 | 上記を終了させる | 異常終了しない。終了コードが 0、または OS のシグナルによる正常な終了 |
| 3 | `MarkView README.md` | 同上 |
| 4 | `MarkView docs/` | 同上 |
| 5 | 起動時の標準エラー出力 | MarkView 自身のログ出力がない（NFR-041。`MARKVIEW_DEBUG` は未設定）。GTK・WebKitGTK など OS 側のライブラリが出す警告は対象外とする |

実行方法:

| OS | 方法 |
| --- | --- |
| Linux | `xvfb-run` で仮想ディスプレイ上に起動し、`SIGTERM` で終了させる |
| Windows | ランナーのデスクトップセッションで起動し、一定時間後に終了させる |

> [!IMPORTANT]
> このケースが**リリース前に唯一「実行ファイルが動く」ことを機械的に確かめる手段**である。WebView2 / WebKitGTK の初期化に失敗すればここで落ちる。手動テストの前段として、壊れた成果物を早期に弾く役割を持つ。

### E2E-105: 不正な引数での起動
根拠: FR-012, FR-111

| # | 実行 | 期待 |
| --- | --- | --- |
| 1 | 存在しないパスを引数に指定 | **異常終了しない**。起動して生存する |
| 2 | ディレクトリでもファイルでもないもの（デバイスファイル等） | 異常終了しない |
| 3 | 読み取り権限のないファイル（Linux） | 異常終了しない |
| 4 | 引数を 2 つ以上指定 | 異常終了しない（2 つ目以降は無視） |
| 5 | 未知のオプション（`--nosuch`） | 使用方法を標準エラーへ出力し、終了コード 2 で終了する。ウィンドウを開かない（FR-012） |

「異常終了しない」の判定は、起動から 5 秒後にプロセスが生存しているか、または終了コードが 0 であることとする。

### E2E-106: Linux の依存ライブラリ
根拠: AR-003, BR-051

| # | 確認 | 期待 |
| --- | --- | --- |
| 1 | `ldd MarkView` の出力 | `libwebkit2gtk-4.1` に依存している（4.0 ではない） |
| 2 | 同上 | `not found` が 1 件もない（実行環境に依存が揃っている） |
| 3 | 依存の一覧 | 想定外のライブラリ（開発用パッケージ、テスト用ライブラリ）を含まない |
| 4 | glibc の要求バージョン | Ubuntu 24.04 で満たせる範囲である |

ケース 1 は、`-tags webkit2_41` の指定漏れ（BR-010）を検出する。指定を忘れると 4.0 系にリンクされ、Ubuntu 24.04 で起動できない配布物ができる。

### E2E-107: バイナリサイズ
根拠: NFR-021, BR-060

| # | 確認 | 期待 |
| --- | --- | --- |
| 1 | 実行ファイルのサイズを計測 | 記録する。25 MB 超なら警告（**失敗させない**） |
| 2 | アーカイブのサイズを計測 | 記録する。12 MB 超なら警告 |

### E2E-108: チェックサム
根拠: BR-020, NFR-052

| # | 確認 | 期待 |
| --- | --- | --- |
| 1 | `checksums.txt` の存在 | 全成果物の SHA-256 が記載されている |
| 2 | 記載値と実ファイル | 一致する |
| 3 | 成果物の数 | 4 種（Windows amd64/arm64、Linux amd64/arm64）すべてが揃っている |

### E2E-109: 描画スモークテスト
根拠: BR-054

BR-054 で定めた検証を E2E の一部として位置づける。内容は BR-054 に従い、本文書では重複して定義しない。

| # | 対象 | 期待 |
| --- | --- | --- |
| 1 | Mermaid の 7 種の図 | SVG が生成される |
| 2 | 数式（インライン・ブロック） | 数式要素が生成される |
| 3 | 実行中のコンソール | JavaScript のエラーが発生しない |
