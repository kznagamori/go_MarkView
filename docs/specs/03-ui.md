# 03. 画面・操作仕様

> 索引: [README](README.md) | 前: [02. 機能要求](02-functional.md) | 次: [04. Markdown 描画仕様](04-markdown.md)

本文書は MarkView の画面構成、操作方法、および設定の永続化仕様を定義する。

> [!NOTE]
> 本文書の節は画面の構成順（ウィンドウ → ツールバー → ペイン → 補助 UI → 設定）に並べており、ID の番号順とは一致しない。右クリックメニュー（UI-085）は 3.9 節、情報ウィンドウ（UI-100 系）は 3.10 節、エディタ選択ウィンドウ（UI-103）は 3.11 節、拡大画面（UI-104）は 3.12 節、キーボードショートカット（UI-090）は 3.13 節にある。

## 3.1 ウィンドウ構成（UI-010）

### UI-010: 全体レイアウト **MUST**

ウィンドウは上から順に「ツールバー」「コンテンツ領域」「ステータス領域」で構成する。コンテンツ領域は左から「ファイルツリーペイン」「アウトラインペイン」「本文ペイン」を横に並べる。

```
┌──────────────────────────────────────────────────────────────────────┐
│ [📁] [⟳] [◐] [☰] [🗂] [✎] [☑]                                 [?]   │ ← ツールバー (UI-020)
├────────────┬────────────┬────────────────────────────────────────────┤
│ Files      │ Outline    │                                            │
│            │            │   # MarkView                               │
│  docs/     │  MarkView  │                                            │
│   01.md    │   Overview │   Markdown ビューア                        │
│   02.md    │   Usage    │                                            │
│  README.md │    Launch  │   ## 概要                                  │
│            │    Config  │                                            │
│            │   FAQ      │   本文本文本文本文本文本文本文本文...      │
│            │            │                                            │
│  (UI-030)  │  (UI-040)  │             本文ペイン (UI-050)            │
├────────────┴────────────┴────────────────────────────────────────────┤
│ README.md                                    UTF-8  120 lines        │ ← ステータス領域 (UI-060)
└──────────────────────────────────────────────────────────────────────┘
        ↑            ↑
    ドラッグで幅を変更できる境界
```

> [!NOTE]
> 図中の `Files` / `Outline` は画面上に表示される実際の文言である。UI テキストの言語方針は UI-024 を参照。

- ファイルツリーペインとアウトラインペインは**独立したペイン**であり、片方だけの表示、両方の表示、両方の非表示のすべての組み合わせを取り得る。
- 両方とも非表示のときは、本文ペインがコンテンツ領域の全幅を占める。
- ツールバーとステータス領域は常に表示する。

### UI-011: ウィンドウの初期サイズ **MUST**

- 初回起動時のウィンドウサイズは 1280 × 860 論理ピクセルとする。
- 画面の作業領域がこれより小さい場合、作業領域の 90 % に収まるサイズへ縮小する。
- ウィンドウの初期位置は**プライマリモニタの作業領域の中央**とする。位置は保存も復元もしない（UI-111）。複数モニタ構成であっても、常にプライマリモニタに表示することで、ウィンドウが見えない位置に出る事態を防ぐ。
- 最小ウィンドウサイズは 640 × 480 とする。

### UI-012: 高 DPI 対応 **MUST**

Windows・Linux いずれの高 DPI 環境でも、ツールバーのアイコン・文字・ペイン境界がぼやけずに表示されること。ディスプレイのスケーリング設定に追従する。

### UI-013: ウィンドウタイトル **MUST**

ウィンドウタイトルは `<ファイル名> - MarkView` とする。

| 状態 | タイトル |
| --- | --- |
| 文書を表示中 | `README.md - MarkView` |
| 文書を表示していない（操作案内の表示中） | `MarkView` |

- ファイル名は拡張子を含む**ベース名のみ**とし、ディレクトリパスは含めない。パスはステータス領域に表示する（UI-060）。
- 表示対象が切り替わるたびにタイトルを更新する。ファイル選択ダイアログ、ドラッグ＆ドロップ、ファイルツリーからの選択、リンク遷移、履歴移動のいずれの経路でも更新する。
- 表示中のファイルが削除された場合も、タイトルは直前の表示内容を維持する（FR-110 で本文を維持することと整合させる）。
- Front Matter の `title` をタイトルに使用しない（MD-073 と整合させる）。ファイル名のほうが、利用者がタスクバー上で対象を識別する手掛かりとして確実であるため。
- 大きなファイルの確認画面（UI-052）やサイズ上限超過の表示中も、対象ファイル名をタイトルに反映する。描画したかどうかではなく、「いま何を開こうとしているか」を示す。

## 3.2 ツールバー（UI-020）

### UI-020: ボタン配置 **MUST**

ツールバーの左端から右へ、以下の順にアイコンボタンを配置する。「?」ボタンのみ右端に配置する。

| 位置 | ボタン | アイコン | 動作 | 種別 |
| --- | --- | --- | --- | --- |
| 左 1 | ファイルを開く | フォルダ | ファイル選択ダイアログを開く（FR-010） | 実行 |
| 左 2 | 再読み込み | 循環矢印 | 表示中のファイル（状態画面ではその対象）を再読み込み（FR-015） | 実行 |
| 左 3 | テーマ切り替え | 半月（Light 時）/ 太陽（Dark 時） | Light / Dark を切り替え（FR-070） | 実行 |
| 左 4 | アウトライン | 箇条書き | アウトラインペインの表示・非表示（FR-043） | **トグル** |
| 左 5 | ファイルツリー | ディレクトリツリー | ファイルツリーペインの表示・非表示（FR-034） | **トグル** |
| 左 6 | エディタで開く | 鉛筆 | **画面が対象にしているファイル**を外部エディタで開く（FR-090） | 実行 |
| 左 7 | 編集モード | チェック付きの四角 | 編集モードの開始・終了（FR-140） | **トグル** |
| 右端 | アプリケーション情報 | クエスチョンマーク | 情報ウィンドウを表示（FR-100） | 実行 |

> [!NOTE]
> **「エディタで開く」（左 6）と「編集モード」（左 7）は別の機能である。** 前者は外部のプログラムを起動し、後者は MarkView 自身が限定的に書き込む状態へ切り替える。アイコンもツールチップ（UI-024）も、互いに紛れない形にする。**鉛筆のアイコンは左 6 に残す**——v1.0.0 から「エディタで開く」を表してきたためである。

### UI-021: ボタンの状態表現 **MUST**

- トグル種別のボタンは、ON のとき背景色または枠線で押下状態であることを明示する。OFF のときは通常表示とする。
- 実行できない状態のボタン（文書未表示（`welcome`）のときの再読み込み等）は淡色表示にし、クリックを受け付けない。**状態画面（UI-052）の表示中の再読み込みは実行できる**（その対象を読み直す。FR-015）。
- **「エディタで開く」ボタンは、状態画面（UI-052）のうち `confirm-large` / `too-large` / `render-error` を表示している間も実行できる状態に保つ**（FR-090）。大きすぎて開けないファイル、描画に失敗したファイルこそ、エディタで中身を確かめたい。**文書未表示（`welcome`）のときだけ淡色にする。** 対象となるファイルが存在しないためである。
- **「編集モード」ボタンは、編集モードを開始できない状態（FR-140 の表）では淡色にする。** 編集モードの間は ON の表示とする。編集モードが自動的に終わったとき（FR-140）は、同時に OFF の表示へ戻す。
- すべてのボタンにマウスホバー時のツールチップを表示する。文言と言語は UI-024 に従う。
- キーボードの `Tab` でボタン間を移動でき、`Enter` / `Space` で実行できる。フォーカス位置は視覚的に明示する。

### UI-022: アイコンの仕様 **MUST**

- アイコンは**インライン SVG** とし、単色でテーマの前景色を継承する。テーマ切り替え時に別ファイルを読み込む必要がない形式とする。
- ラスタ画像（PNG 等）のアイコンは使用しない。DPI 依存とファイルサイズ増加を避けるため。
- 使用するアイコンセットは MIT または同等の再配布可能なライセンスのものとし、ライセンス表示（FR-101）の対象に含める。
- アイコンサイズは 16 × 16 論理ピクセル、ボタンのクリック領域は 28 × 28 以上とする。

### UI-023: ツールバーの高さと余白 **SHOULD**

ツールバーの高さは 40 論理ピクセルとし、本文の表示領域を不要に圧迫しないこと。

### UI-024: ツールチップの文言と UI テキストの言語 **MUST**

MarkView は、**ツールバーをアイコンのみで構成することで表示言語への依存を避け、機能の説明はツールチップで補う**方式を採る。言語の扱いは以下のとおりとする。

| 対象 | 言語 |
| --- | --- |
| **ツールバーボタンのツールチップ** | **英語と日本語を併記する**（`Open / 開く` の形式） |
| 上記以外のすべての UI テキスト | **英語のみ** |

「上記以外」には次を含む。ペイン見出し、ステータス領域のパス表記・エラーメッセージ・警告、検索バーのラベルとヒット数表示、ドラッグ＆ドロップのオーバーレイ文言、アプリケーション情報ウィンドウの項目名、文書未表示時の操作案内（FR-013）、ファイル選択ダイアログのフィルタ名、`--help` / `--version` の標準出力、**右クリックメニューの項目名（UI-085）、拡大画面の操作バーとそのツールチップ（UI-104）、本文中の図・画像・表のボタンのツールチップ（UI-053, UI-054）**。

ツールチップの文言は以下に固定する。

| ボタン | ツールチップ |
| --- | --- |
| ファイルを開く | `Open / 開く (Ctrl+O)` |
| 再読み込み | `Reload / 再読み込み (F5)` |
| テーマ切り替え（Light 表示中） | `Dark theme / ダークテーマ (Ctrl+Shift+T)` |
| テーマ切り替え（Dark 表示中） | `Light theme / ライトテーマ (Ctrl+Shift+T)` |
| アウトライン | `Outline / アウトライン (Ctrl+Shift+O)` |
| ファイルツリー | `File tree / ファイルツリー (Ctrl+Shift+E)` |
| エディタで開く | `Open in editor / エディタで開く (Ctrl+E)` |
| 編集モード | `Edit mode / 編集モード (Ctrl+Shift+M)` |
| アプリケーション情報 | `About / アプリケーション情報 (F1)` |

- 書式は `<英語> / <日本語> (<ショートカット>)` とする。ショートカットを持たないボタンでは括弧部分を省略する。
- 区切りは半角スラッシュの前後に半角空白を置く。
- **テーマ切り替えボタンのみ、現在の状態に応じてツールチップを変える。** 表示するのは現在のテーマ名ではなく、押したときに切り替わる先である。
- アウトライン・ファイルツリー・編集モードのトグルボタンは、ON / OFF のいずれでも同一の文言とする。現在の状態はボタンの見た目（UI-021）で示すため、ツールチップでは機能名のみを示す。
- OS のロケール判定や言語切り替え機構は実装しない。すべての環境で同一の文言を表示する。

> [!NOTE]
> **4.39.0 で「エディタで開く」の文言を `Edit / 編集` から `Open in editor / エディタで開く` へ改めた。** 編集モード（FR-140）を加えたことで、`Edit / 編集` と `Edit mode / 編集モード` が並び、**どちらが外部のプログラムを起動するのかが文言から読み取れなくなる**ためである。

> [!NOTE]
> ツールチップのみ併記とするのは、ここが「アイコンの意味が分からない利用者が最初に頼る場所」であり、日本語話者・英語話者のどちらにも通じる必要があるためである。一方、それ以外のテキストは英語に統一することで、文言の二重管理と表示幅の膨張を避ける。この方針により、言語リソース機構やロケール判定は不要となる（NFR-062）。

### UI-025: アプリケーションアイコン **MUST**

アプリケーションを表すアイコンを用意し、以下の 3 箇所で使用する。

| 用途 | 使用するファイル | 効果 |
| --- | --- | --- |
| 実行ファイル | `assets/icon.ico` | エクスプローラ・デスクトップ・タスクバーで、MarkView 固有のアイコンとして表示される |
| ウィンドウ・タスクバー | Windows: `assets/icon.ico` / Linux: `assets/icon.png` | ウィンドウ左上、タスクバー、`Alt+Tab` の切り替え画面 |
| アプリケーション情報ダイアログ | `assets/icon.png` | 見出しの横に表示する（UI-100） |

- 原本はリポジトリの `assets/` に置き、**ここを唯一の正とする**。ビルド時に必要な場所へ配置する手順は BR-013 で定める。
- `assets/icon.icns` は macOS 用の形式であり、macOS は本バージョンの対象外（NFR-060）のため使用しない。将来 macOS へ対応する際の予備資産として保持する（AR-090）。
- **ツールバー内のアイコン（UI-022）とは別物である。** ツールバーのアイコンは単色の SVG シンボルであり、アプリケーションアイコンはラスタ形式の固有画像である。両者を混同しない。
- 文書未表示時の案内画面（UI-052）にはアプリケーションアイコンを使用しない。そこでは「ファイルを開く」という行動を示唆するアイコンを用いる（DSP-181）。
- **Linux では、上の表の 1 行目と 2 行目を満たせない**（4.70.0。`v1.1.0-rc.1` の E2E-332 で確かめた）。**実行ファイル単体でアイコンを出す手段が無い。**
  - **ファイルマネージャのアイコン**: ELF にアイコンを埋め込む仕組みが無く、汎用の実行ファイルのアイコンになる
  - **ウィンドウ・タスクバーのアイコン**: `assets/icon.png` を Wails の `linux.Options{Icon:}` に渡しており、これは `gtk_window_set_icon` を呼ぶ。**Wayland では無視される**——GNOME は `.desktop` ファイルと `StartupWMClass` でアイコンを解決する
  - **`.desktop` ファイルを配布物に同梱しない**（BR-020）。「展開して実行するだけ」という配布の形を崩し、**置いても実行ファイル自体のアイコンは変わらない。** 置き方は利用者向け文書（`troubleshooting.md`）に載せる
  - **したがって、この要求は Windows でのみ検証する**（E2E-332）。Linux のウィンドウのアイコンは、X11 のセッションでは出ることがあるが**環境に依存する**ため、満たすことを求めない

### UI-026: 狭いウィンドウでのペインの一時的な非表示 **MUST**

ウィンドウ幅が不足し、本文ペインが読める幅を確保できなくなった場合、サイドペインを一時的に隠す。

| 条件 | 動作 |
| --- | --- |
| 本文ペインの幅が 240 論理ピクセルを下回る | **アウトラインペインを一時的に隠す** |
| 幅が回復し、本文が 240 論理ピクセル以上を確保できる | 隠したペインを自動的に戻す |

- 一時的に隠している間も、**ツールバーのトグルボタンは ON のまま**とし（UI-021）、設定値（UI-110）も変更しない。
- 利用者が明示的に OFF にした状態と、幅の不足による一時的な非表示を区別する。前者は設定に保存され、後者は保存されない。ウィンドウを広げれば、利用者が何もしなくても元の状態に戻る。
- ファイルツリーペインは自動的に隠さない。ファイルを選ぶ手段を失わせないため、最小ウィンドウ幅（640）でもファイルツリーと本文は両立させる。

> [!NOTE]
> 幅の上限規定（UI-030, UI-040）だけでは、最小ウィンドウ幅で両ペインを**上限まで広げた**状態から縮めたときに本文が 150 論理ピクセル程度まで潰れ、実質的に読めなくなる。本要求はその状態を避けるためのものであり、利用者の設定を書き換えるものではない。

> [!IMPORTANT]
> **本要求が発火するかどうかは、利用者が決めたペイン幅で決まる。両ペインが下限（160）にあるときは、最小ウィンドウ幅でも発火しない。**
>
> ```
> 到達しうる本文の最小幅 = 640（UI-011） - 160（UI-030） - 160（UI-040） = 320  >  240
> ```
>
> このとき本文は 320 論理ピクセルあり、**隠す理由が無い。** 隠さないことが本要求に忠実な振る舞いである。閾値 240 を上げて発火させることは行わない（読める幅で隠すことになる）。
>
> **この性質は検証手順に効く。** 幅を固定せずに「ウィンドウを狭める」だけの手順では、直前に何をしたかで結果が変わる（[E2E-246](41-e2e-manual.md)、[調査報告](../bugs/2026-09-04-bug-003-outline-auto-hide.md)）。発火する条件は [DSP-380](22-display-states.md) の表で確かめる。

## 3.3 ファイルツリーペイン（UI-030）

### UI-030: 表示仕様 **MUST**

- ペインの既定幅は 260 論理ピクセル。最小 160、最大はウィンドウ幅の 40 %。
- 右端の境界をドラッグして幅を変更できる。変更した幅は設定に保存する（UI-110）。
- ペイン上部に見出し `Files` を表示し、その下にツリールートのディレクトリ名を表示する。ディレクトリ名にマウスを乗せると、絶対パスをツールチップで表示する。
- 各ノードはディレクトリ／ファイルを区別できるアイコンと名前で表示する。表示対象は**ディレクトリと Markdown ファイルのみ**とし、画像やその他のファイルは表示しない（FR-031）。
- ディレクトリノードのクリックで展開・折りたたみを切り替える。
- 内容がペイン幅を超える場合は横スクロールを許可する。ファイル名は省略表示しない。
- 現在表示中のファイルは背景色で強調する。
- 表示中のファイルがツリールートの外にある場合（FR-052）、強調表示されるノードは存在しない。ツリーの表示内容と展開状態は変化させない。

### UI-031: キーボード操作 **SHOULD**

ペインにフォーカスがあるとき、`↑` `↓` でノード間を移動、`→` で展開、`←` で折りたたみ、`Enter` でファイルを開く操作ができる。

## 3.4 アウトラインペイン（UI-040）

### UI-040: 表示仕様 **MUST**

- ペインの既定幅は 240 論理ピクセル。最小 160、最大はウィンドウ幅の 40 %。
- 右端の境界をドラッグして幅を変更できる。変更した幅は設定に保存する（UI-110）。
- ペイン上部に見出し `Outline` を表示する。
- 見出しレベルに応じてインデントする。インデント幅は 1 レベルあたり 12 論理ピクセルとする。
- 見出しレベルに応じて文字サイズをわずかに変えてもよいが、レベル 4 以降は同一サイズとする。
- 長い見出しは 1 行で省略表示（`...`）し、ツールチップで全文を表示する。
- 現在位置の項目は背景色と文字色で強調する（FR-042）。

### UI-041: ペインの並び順 **MUST**

ファイルツリーペインとアウトラインペインを同時に表示する場合、**左からファイルツリー、アウトライン、本文** の順に固定する。並び順を変更する機能は提供しない。

## 3.5 本文ペイン（UI-050）

### UI-050: 表示仕様 **MUST**

- 本文はコンテンツ領域の残り全幅を占める。
- 本文の最大表示幅は 980 論理ピクセルとし、それより広い場合は水平方向中央に配置する。左右の余白は 32 論理ピクセルとし、本文ペインが狭いときは 16 論理ピクセルまで詰める（DSP-030。v1.0.0 から `clamp(16px, 4vw, 32px)` で実装している。最小のウィンドウ幅でサイドペインを出すと、32 のままでは本文が狭くなりすぎる）。
- 縦スクロールバーを表示する。横スクロールは発生させない（表・コードブロック・**原寸表示中の図と画像**（FR-121）等の広い要素は、その要素の内部で横スクロールする）。
- 本文の書体は、GitHub と同等のシステムフォントスタックを使用する（MD-010）。

### UI-051: スクロール **MUST**

- マウスホイール、スクロールバー、`PageUp` / `PageDown` / `Home` / `End` / 方向キーでスクロールできる。
- **キーボードでのスクロールは、本文ペインがフォーカスを持つことを前提とする。文書を表示した時点で、フォーカスを本文ペインへ移す**（IMP-220）。**例外として、同じ文書の再描画で本文中のチェックボックスにフォーカスがあった場合は、同じ順番のチェックボックスへ戻す**（FR-014）。
- スクロール位置は、FR-014・FR-015・FR-051 の各仕様に従って維持・復元される。

> [!IMPORTANT]
> **キーボードでのスクロールは「ブラウザの既定動作に任せれば済む」ものではない。**
>
> ブラウザは**フォーカスされている要素を含むスクロール器**を動かす。MarkView では
> `html, body` を `overflow: hidden` とし（UI-050 の「横スクロールを発生させない」と
> ツールバー・ステータス領域の固定のため）、**実際にスクロールするのは本文ペインだけ**である。
> したがって**本文ペインの外にフォーカスがあると、キーは届いていても動かせる器が無い。**
>
> 実際に、文書を開いた直後はフォーカスが `body` やツールバーのボタンに残り、
> **`PageUp` / `PageDown` が一切効かなかった**（[調査報告](../bugs/2026-09-05-bug-007-viewer-focus-on-open.md)）。
> 本文をクリックすれば効くため、**「効くときと効かないときがある」という形で現れる。**
>
> **キーを自前で処理して代替しない。** `Home` / `End` / 方向キーまで既定動作を作り直すことになり、
> フォーカスが本文に無いという本来の問題（DSP-016, IMP-295）も残る。

### UI-052: 本文ペインに表示する状態画面 **MUST**

文書を描画できない、または描画を保留している状態では、本文ペインに状態画面を表示する。モーダルダイアログは用いない（FR-110）。

| 状態 | 表示内容 | 対応要求 |
| --- | --- | --- |
| 文書未表示 | 操作案内（ファイルを開く方法、ドラッグ＆ドロップ、主要なショートカット） | FR-013 |
| 大きなファイルの確認 | ファイル名、実サイズ、時間を要する旨、`Open anyway` ボタン | FR-016 |
| サイズ上限超過 | ファイル名、実サイズ、上限値。実行ボタンは表示しない | FR-016 |
| 描画中の想定外のエラー | ファイル名とエラー内容。実行ボタンは表示しない | FR-111 |

大きなファイルの確認画面の構成は以下とする。

```
┌──────────────┬─────────────────────────────┐
│ Files        │                             │
│  docs/       │    big-report.md            │
│   big-report │    12.4 MB                  │
│   a.md       │                             │
│              │  This file is large.        │
│              │  Rendering may take a while.│
│              │                             │
│              │      [ Open anyway ]        │
└──────────────┴─────────────────────────────┘
```

- 文言はすべて英語とする（UI-024）。
- 状態画面は本文ペインの中央に配置し、周囲のペイン・ツールバー・ステータス領域は通常どおり表示・操作できる状態を保つ。
- `Open anyway` ボタンはキーボードでフォーカスでき、`Enter` / `Space` で実行できる。
- 状態画面の表示中も、表示倍率（FR-081）とテーマ（FR-070）は適用される。
- 状態画面の表示中、アウトラインペインには見出しがない旨を表示する（FR-040）。ファイルツリーの強調表示は対象ファイルに合わせる。
- ウィンドウタイトルは対象ファイル名とする（UI-013）。文書未表示の状態画面では `MarkView` とする。
- **ステータス領域の左には、対象ファイルのパスを出す**（UI-060。ツリー外なら絶対パスと `(outside tree)`）。**前に表示していた文書のパスを残さない**——タイトルとパスが別のファイルを指すと、利用者はどちらの状態画面か判断できない（[BUG-012](../bugs/2026-09-14-bug-012-state-screen-previous-document.md)）。文書未表示の状態画面では空とする。右の文字コードと行数は出さない。
- 状態画面（文書未表示を除く）の表示中は、前に表示していた文書を監視しない（FR-014, FR-016）。
- 状態画面の表示中は、編集モードを開始できない（FR-140）。

### UI-053: 図と画像のボタン **MUST**

FR-120 の対象（Mermaid 図・PlantUML 図・縮小表示中の画像）の右上に、次のボタンを置く。

```
Mermaid / PlantUML の図                        縮小表示中の画像

┌───────────────────────────────────┐          ┌────────────────────────────┐
│                     [1:1] [<>] [C]│          │                  [1:1] [<>]│
│                                   │          │                            │
│      +-------+     +-------+      │          │                            │
│      |   A   | --> |   B   |      │          │         (image)            │
│      +-------+     +-------+      │          │                            │
│                                   │          │                            │
└───────────────────────────────────┘          └────────────────────────────┘

  [1:1] = 原寸表示の切り替え (FR-121)   [<>] = 拡大画面 (FR-122)   [C] = コピー (FR-060)
```

- 並びは右から「コピー」「拡大画面」「原寸表示」とする。画像にはコピーボタンが無いため、右から「拡大画面」「原寸表示」となる。
- どのボタンをいつ出すかは FR-120 の表に従う。**原寸表示のボタンは、原寸表示中も出し続ける**（戻すためである）。
- 原寸表示のボタンはトグルとし、原寸表示中は押下状態を示す（UI-021 と同じ表し方）。
- コピーボタン（FR-060）と同じく**常に操作できる状態**とし、`Tab` で移動、`Enter` / `Space` で実行できる。フォーカス位置は視覚的に明示する。
- **マウスを乗せたときに、英語のツールチップを出す。** 文言は下表に固定し、支援技術に対する名前も同じ文字列とする。**英日併記はツールバーのボタンに限る**（UI-024）ため、ここは英語だけとする。`1:1` や矢印のアイコンだけでは意味が伝わりにくいためである。

| ボタン | ツールチップ |
| --- | --- |
| 原寸表示 | `Actual size` |
| 拡大画面 | `Expand` |

- 原寸表示のボタンのツールチップは、原寸表示中も同じ文言とする。状態は押下状態の見た目で示す（UI-024 のトグルボタンと同じ考え方）。
- **既存のコピーボタン（FR-060）には、これまでどおりツールチップを出さない。**
- **画像をリンクで囲んだ記法（MD-071）でも、ボタンの操作ではリンク先へ遷移しない。**
- 原寸表示中の対象は、その枠の内側で横スクロールできることが分かる見た目とする（表の横スクロールと同じ。MD-024）。

### UI-054: 表の並べ替えボタン **SHOULD**

FR-130 を操作するボタンを、並べ替えの対象になる表（見出し行を除く行が 2 行以上）の**見出し行の各セルの右端**に置く。

- 並べ替えていない列のボタンは淡色で表示し、並べ替えている列のボタンは**昇順と降順を区別できるアイコン**で表示する。
- マウスを乗せたときに、英語のツールチップ `Sort` を出す（UI-053 と同じ扱い）。並べ替えの状態によって文言を変えない。
- `Tab` で移動、`Enter` / `Space` で実行できる。
- ボタンは見出しの文字と重ならない位置に置く。見出しの文字が長い場合も、ボタンを隠さない。
- 支援技術に対して、並べ替えの状態（昇順・降順・なし）を伝える。

### UI-055: 編集モード中の本文ペイン **MUST**

- 編集モード（FR-140）の間、**本文ペインにも編集モードであることを示す表示を出す。** ツールバーのボタンの ON 表示（UI-021）だけに頼らない——ツールバーから目を離して本文を読んでいても、書き換えられる状態であることが分かるようにする。表示の具体は表示仕様で定める。
- **書き換えられる要素**（タスクリストのチェックボックス、編集できるセル）を、書き換えられない要素（生 HTML の `input`、ソース上に存在しないセル。FR-141, FR-142）と見分けられるようにする。
- セルの編集欄は、**そのセルの位置にその場で重ねて**表示する。表のレイアウトを大きく崩さない。編集欄を開いたら、フォーカスを編集欄へ移す。**`Enter` で確定した後と `Esc` で取り消した後は、フォーカスを本文ペインへ戻す**（UI-051）。**フォーカスが外れたことによる取り消し（FR-142）では、フォーカスを動かさない**——利用者が移した先（ツールバーのボタンや検索バー）から奪わないためである。
- 編集モードでない間、チェックボックスとセルの見た目は 4.38.0 までと変えない。

## 3.6 ステータス領域（UI-060）

### UI-060: 表示仕様 **MUST**

ウィンドウ最下部に高さ 24 論理ピクセル程度のステータス領域を設ける。表示内容は以下とする。

| 位置 | 内容 |
| --- | --- |
| 左 | 表示中ファイルのパス（ツリールートからの相対パス）。ホバーで絶対パスを表示。**状態画面（UI-052）の表示中は、その対象ファイルのパス** |
| 右 | 文字コード、総行数、表示倍率（100 % 以外のとき）。例: `UTF-8  120 lines  140%` |
| 全幅（一時） | 情報・警告・エラーのメッセージ（FR-090, FR-110）。5 秒後に自動的に元の表示へ戻る |

- 表示中のファイルがツリールートの外にある場合（FR-052）、左側には**絶対パス**を表示し、末尾に `(outside tree)` を付す。ツリー内の文書との区別が付くようにする。
- メッセージは種別（情報 / 警告 / エラー）に応じた背景色で表示する（DSP-151）。**情報を出すのは、エディタの起動に成功したときだけである**（FR-090）。
- メッセージが領域幅に収まらない場合は末尾を省略し、ホバーで全文を表示する。
- 表示するすべての文言は英語とする（UI-024）。例: `File not found: docs/missing.md`

## 3.7 ドラッグ＆ドロップの視覚的フィードバック（UI-070）

### UI-070: ドロップ領域の表示 **MUST**

- ウィンドウ上にファイルがドラッグされている間、ウィンドウ全体に半透明のオーバーレイと枠線を表示し、`Drop a Markdown file to open` という案内を表示する（UI-024）。

- 対応していない種類のファイルがドラッグされている場合も、オーバーレイの表示自体は行う（ドロップ時に FR-011 に従って処理する）。

## 3.8 検索バー（UI-080）

### UI-080: 表示仕様 **MUST**

- `Ctrl+F` により、本文ペインの右上に検索バーをオーバーレイ表示する。本文のレイアウトを押し下げない。
- 検索バーは「入力欄」「ヒット数表示（`3 / 12`）」「前へ」「次へ」「閉じる」で構成する。前へ・次へ・閉じるはアイコンボタンとする。
- **ヒット数は、折りたたみ（`<details>`。[MD-026](04-markdown.md)）の中の一致箇所も含めて数える**（[FR-080](02-functional.md)）。見えている範囲だけを数えない。**数に入れる以上、そこへ移動できなければならない**（FR-080 の IMPORTANT）。
- 入力欄のプレースホルダは `Find in document` とする。ヒットしない場合は `No results` を表示する（UI-024）。
- 表示と同時に入力欄へフォーカスを移す。本文中にテキストが選択されていた場合は、それを初期値とする。
- `Esc` または「閉じる」で消去し、フォーカスを本文へ戻す。

## 3.9 右クリックメニュー（UI-085）

### UI-085: 表示仕様 **MUST**

FR-063 のメニューの見た目と操作を定める。

```
本文ペイン（リンクの上）        本文ペイン                  入力欄

┌────────────────────┐        ┌────────────────────┐      ┌────────────────────┐
│ Copy link address  │        │ Copy               │      │ Cut                │
├────────────────────┤        │ Select all         │      │ Copy               │
│ Copy               │        └────────────────────┘      │ Paste              │
│ Select all         │                                    │ Select all         │
└────────────────────┘                                    └────────────────────┘
```

- **メインウィンドウ内に描画する。** 独立した OS ウィンドウではない（AR-060）。
- 右クリックした位置に出す。ウィンドウからはみ出す場合は、内側へずらして全体を見せる。
- 項目名はすべて英語とする（UI-024）。`Copy link address` とその他の項目の間には区切り線を置く。
- 使えない項目（FR-063 の表）は淡色で表示し、選べないようにする。
- 開いたらフォーカスをメニューへ移す。`↑` / `↓` で項目を移動し、`Enter` で実行、`Esc` で閉じる。**項目を実行したとき・`Esc` で閉じたときは、フォーカスを開く前の位置へ戻す。** 選択範囲は、項目（`Cut` / `Paste` / `Select all`）が変える場合を除いて保つ。
- キーボードの `Shift+F10` とアプリケーションキーでも開ける（**SHOULD**）。そのときは、選択範囲またはフォーカスのある要素の近くに出す。
- 閉じる契機は FR-063 に従う（項目の実行、`Esc`、メニューの外のクリック、本文のスクロール、ウィンドウがフォーカスを失ったとき）。**`↑` / `↓` / `Enter` はメニューの中の操作であり、閉じる契機ではない。** メニューの外をクリックして閉じた場合、フォーカスはクリックした先に移ってよい。**セルの編集欄から開いていた場合は、フォーカスが外れたものとして編集を取り消す**（FR-142）。**セルの編集欄から開いていた場合に限り、本文のスクロールとウィンドウのフォーカス喪失で閉じたときも、編集欄へフォーカスを戻す**（ウィンドウの場合は戻ったとき。FR-142）。
- 背後の操作をブロックする画面ではない。

```

- 項目名を含むすべての文言は英語とする（UI-024）。**エディタ名は固有名詞であり、そのまま表示する。**
- 一覧の順序は [IMP-172](11-impl-backend.md) のプリセット表の順に固定する。**検出できたものを先へ並べ替えない。** 並びが環境や起動のたびに変わると、位置で覚えられなくなる。
- 検出できなかったエディタは `(not installed)` を付して淡色で表示し、選択できないようにする。**一覧から消さない。** 消すと「なぜ自分のエディタが出ないのか」が分からない。
- `Other...` は常に一覧の末尾に置き、常に選択できる。`Browse` で OS 標準のファイル選択ダイアログを開く。選択後は**実行ファイル名**（パスではない）を `Other...` の下に表示する。
- 初期選択は、設定に保存されたエディタ（UI-116）とする。保存がない、または保存されたエディタが見つからない場合は**初期選択を持たず、`Open` を押せない状態とする。**
- **ウィンドウを開いた時点で、初期選択があれば `Open` にフォーカスを置く。** 同じエディタを使い続ける利用者が、ボタンと `Enter` の 2 操作で開けるようにするためである。初期選択がなければ一覧の先頭にフォーカスを置く。
- `Open` を実行すると、選択を設定へ保存したうえでエディタを起動し、ウィンドウを閉じる（FR-090）。**「保存」と「起動」を分けない。**
- すべての項目とボタンは `Tab` で移動でき、`Enter` / `Space` で実行できる。フォーカス位置は視覚的に明示する。

> [!IMPORTANT]
> **このウィンドウに項目を追加してはならない。** 決められるのは「どのエディタか」の 1 つだけとする。起動引数・オプション・拡張子の関連付けなどを足した時点で、これは**設定画面**になる。MarkView は設定画面を持たない（UI-116）。

## 3.12 拡大画面（UI-104）

### UI-104: 表示仕様 **MUST**

FR-122 の拡大画面の見た目と操作を定める。

```
┌──────────────────────────────────────────────────────────────────────┐
│  [ Fit ]  [ 1:1 ]   [ - ]  125%  [ + ]                         [x]   │ <- 操作バー
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│                                                                      │
│              +-----------+              +-----------+                │
│              |     A     | -----------> |     B     |                │
│              +-----------+              +-----------+                │
│                                                                      │
│                                                                      │
├──────────────────────────────────────────────────────────────────────┤
│ README.md                                          UTF-8  120 lines  │ <- ステータス領域（覆わない）
└──────────────────────────────────────────────────────────────────────┘
```

- **ツールバーとコンテンツ領域を覆い、ステータス領域は覆わない。** 開いている間に出た通知（FR-110。ファイルの削除など）を見落とさないためである（FR-122）。ステータス領域は表示を更新し続けるが、クリックなどの操作は受け付けない。実体はメインウィンドウ内に描画するオーバーレイであり、独立した OS ウィンドウではない（UI-100 と同じ機構。AR-060）。
- 上端に操作バーを置く。左から `Fit`（全体が収まる倍率）、`1:1`（原寸。100 %）、`-`（縮小）、現在の倍率、`+`（拡大）、右端に閉じるボタンを並べる。文言は英語とする（UI-024）。
- 操作バーのボタンには、英語のツールチップを出す（UI-053 と同じ扱い）。文言は `Fit (F)` / `Actual size (0)` / `Zoom out (-)` / `Zoom in (+)` / `Close (Esc)` とする。
- 拡大・縮小の 1 段階は **1.25 倍**とする。範囲の端（10 % / 1000 %。FR-122）に達したら、それ以上は変えない。
- 操作の割り当ては次のとおりとする。

| 操作 | 動作 |
| --- | --- |
| マウスホイール（`Ctrl` の有無を問わない） | カーソルの位置を中心に拡大・縮小する（1 目盛りで 1 段階） |
| ドラッグ | 表示位置を移動する |
| `+` / `Ctrl` + `+` | 拡大（画面の中心を基準） |
| `-` / `Ctrl` + `-` | 縮小（画面の中心を基準） |
| `0` / `Ctrl+0` | 原寸（100 %） |
| `F` | 全体が収まる倍率 |
| 方向キー | 表示位置を移動する |
| `Tab` / `Shift+Tab` | 操作バーのボタンの間を移動する |
| `Enter` / `Space` | フォーカスしている操作バーのボタンを実行する |
| `Esc` | 閉じる |

- **開いている間、`Ctrl` + `+` / `-` / `0` と `Ctrl` + ホイールは本文の表示倍率（FR-081）を変えず、拡大画面の倍率を変える。**
- 開いたらフォーカスを拡大画面へ移す。`Tab` は拡大画面の中の操作だけを巡る。閉じたらフォーカスを、開いたボタン（UI-053）へ戻す。
- **ドラッグは移動に使い、図の中の文字を選択しない。** 右クリックメニュー（FR-063）も出さない。**図の中のリンク（MD-081）を押しても何も起きない**（遷移もせず、既定のブラウザも開かない。リンクをたどるときは拡大画面を閉じて本文で押す。[BUG-015](../bugs/2026-09-17-bug-015-mermaid-click-link-navigation.md)）。
- ドラッグ中は、移動中であることが分かるカーソルにする。
- 表示位置は、対象が画面の外へ完全に出てしまわない範囲に留める。
- ウィンドウの大きさが変わったら、`Fit` の状態であれば全体が収まる倍率に合わせ直し、そうでなければ画面の中心に見えている箇所を保つ。
- 地の色はテーマに従う（UI-105）。図の配色も本文と同じテーマのまま表示する。

## 3.15 設定の永続化（UI-110 系）

### UI-110: 保存する項目 **MUST**

以下の項目を設定として保存し、次回起動時に復元する。

| 項目 | 既定値 | 備考 |
| --- | --- | --- |
| テーマ | OS 設定に追従（FR-071） | `light` / `dark` |
| アウトラインペインの表示状態 | 表示 | |
| ファイルツリーペインの表示状態 | 非表示 | |
| アウトラインペインの幅 | 240 | 論理ピクセル |
| ファイルツリーペインの幅 | 260 | 論理ピクセル |
| ウィンドウの幅・高さ | 1280 × 860 | 論理ピクセル |
| エディタ | 無し | 実行ファイルの絶対パス（UI-116） |

### UI-111: 保存しない項目 **MUST**

以下は**保存してはならない**。

| 項目 | 保存しない理由 |
| --- | --- |
| **ウィンドウの位置（X, Y 座標）** | モニタ構成の変更（外部ディスプレイの取り外し、解像度変更、ドッキング解除）により、次回起動時にウィンドウが画面外に配置され、利用者が操作できなくなる事故を確実に防ぐため。**起動時は常にプライマリモニタの作業領域の中央に配置する**（UI-011）。 |
| **表示倍率** | 文書ごと・ウィンドウごとに変えて使う値であるため。保存すると、あるウィンドウで変更した倍率が、以後に起動するすべてのウィンドウを支配する（UI-115）。**起動時は常に 100 % とする**（FR-081）。 |
| **ウィンドウの最大化状態** | 同上。1 つのウィンドウを最大化したまま終了すると、以後のすべてのウィンドウが画面いっぱいで開き、並べて使えなくなる（UI-115）。**起動時は常に通常状態とする。** |
| 表示していたファイルのパス | 閲覧履歴を残さないため（NFR-042） |
| ツリールートのパス | 同上 |
| 表示履歴 | 同上（FR-051） |
| スクロール位置 | セッション内でのみ意味を持つ情報のため |
| 検索文字列 | 同上 |
| **編集モードの状態** | 受け取った文書を読むつもりで開いたときに、書き換えられる状態で始まらないようにするため。**起動時は常に編集モードでない**（FR-140） |
| **編集の取り消し履歴** | 文書の断片を含むため。メモリ上だけに持つ（FR-144, NFR-042） |
| 表の並べ替えの状態 | セッション内でのみ意味を持つ情報のため（FR-130） |
| 図・画像の原寸表示の状態、拡大画面の倍率と表示位置 | 同上（FR-121, FR-122） |

倍率と最大化状態は、**セッション内では通常どおり機能する**。保存しないだけであり、操作を禁じるものではない（FR-081）。

### UI-112: 設定の保存先 **MUST**

設定は **OS / ユーザのテンポラリディレクトリ** に保存する。

| OS | パス |
| --- | --- |
| Windows | `%TEMP%\MarkView\config.json`（`os.TempDir()` の解決結果に従う。通常は `C:\Users\<user>\AppData\Local\Temp`） |
| Linux | `$TMPDIR/MarkView-<uid>/config.json`。`$TMPDIR` 未設定時は `/tmp/MarkView-<uid>/config.json` |

- Linux の `/tmp` は全ユーザ共有であるため、ディレクトリ名にユーザ ID を含め、ディレクトリのパーミッションを `0700`、ファイルのパーミッションを `0600` とする。他ユーザの設定を読み書きしてはならない。
- **このパーミッションは、閲覧内容の秘匿だけでなく任意コード実行の防止にも効いている**（UI-116, [NFR-035](07-nonfunctional.md)）。設定ファイルにはエディタの実行ファイルパスが含まれ、書き換えられればそのプログラムが起動する。**緩めてはならない。**
- 形式は JSON とし、人が読める整形で出力する。
- 書き込みは「一時ファイルへ書き出してからリネーム」で行い、書き込み中の異常終了で設定が破損しないようにする。
- **Windows では、同じ `MarkView` ディレクトリの下に WebView2 のユーザデータ領域も置く**（`%TEMP%\MarkView\webview2`。AR-004）。利用者に案内する「消す手順」を 1 か所に保つためである。設定ファイルとは別物であり、`config` パッケージは関与しない。

### UI-113: 設定が存在しない・破損している場合 **MUST**

テンポラリディレクトリは OS のクリーンアップ処理や再起動（特に Linux の `/tmp`）によって削除されうる。したがって、

- 設定ファイルが存在しない場合は、UI-110 の既定値で起動する。**エラーとして扱わない。**
- 設定ファイルが JSON として解析できない場合、破損したファイルを無視して既定値で起動し、次回の保存時に上書きする。エラー表示は行わない。
- 設定ファイルの一部の項目のみが存在する場合、欠けている項目は既定値を用いる。
- 保存された値が許容範囲外（ペイン幅が負、ウィンドウ幅が下限未満等）の場合、既定値に丸める。
- 設定ディレクトリを作成できない、または書き込めない場合、設定なしで動作を継続する。エラー表示は行わず、その回の設定変更は次回に引き継がれないだけとする。

> [!NOTE]
> テンポラリディレクトリを保存先とする以上、設定は「消えても差し支えのない、快適性のための情報」に限定される。この前提から、UI-111 の「保存しない項目」に業務上の意味を持つ情報（開いていたファイル等）は含めない設計としている。

### UI-114: 保存の契機 **SHOULD**

- 設定はアプリケーション終了時に保存する。
- 加えて、設定値が変更されてから 1 秒間変更がなかった時点でも保存する（異常終了時の消失を抑えるため）。
- ペイン幅のドラッグ操作中は保存せず、ドラッグ終了後に保存する。

### UI-115: 多重起動 **MUST**

**同一利用者が MarkView を複数同時に起動して使えること。** 単一インスタンス化（2 つ目の起動を最初のプロセスへ転送する、あるいは拒否する）を行わない。文書を並べて読む用途は、閲覧に特化したアプリケーションの基本的な使い方である。

インスタンス間で共有され、**MarkView が調停する**資源は、**設定ファイル（UI-112）と、編集モード（FR-140）で書き込む Markdown ファイル**の 2 つである。**WebView のユーザデータ領域**（Windows では `%TEMP%\MarkView\webview2`。UI-112, AR-004）も全インスタンスで共有されるが、調停は WebView のランタイムが行い、MarkView は関与しない。

**Markdown ファイル**は、複数のインスタンスが同じファイルを編集モードで開いている場合に共有される。**調停は FR-143 が担う**——書き込む前にファイルの内容を確かめ、他のインスタンスが先に書いていれば書き込まずに読み直す。**後勝ちで黙って上書きしない**点が、設定ファイルと違う。

**設定ファイル**については、以下を満たす。

- 設定の読み込みは起動時の 1 回のみ、書き込みは UI-114 の契機で構造体全体を置き換える。**同時に書いても壊れない**（一時ファイル＋リネーム。UI-112）が、**後から保存したインスタンスの内容が残る。**
- したがって、保存する項目（UI-110）は「後勝ちで上書きされても不都合が小さいもの」に限る。**ウィンドウごとに変えて使うことが前提の値を保存対象にしてはならない**（UI-111）。
- 他のインスタンスの設定変更を検知して追従することはしない。実行中の再読み込みを行わない。

> [!NOTE]
> 表示倍率と最大化状態を UI-110 から外したのは、この要求による。どちらも「1 つのウィンドウでの一時的な調整」として使われるのに、保存すると最後に終了したインスタンスの状態が以後すべてのウィンドウの初期値になる。**後勝ちが利用者の意図と食い違う**唯一の 2 項目であった。
>
> 残る項目のうち、テーマは全ウィンドウで揃っているのが自然であり、ペインの表示状態・幅とウィンドウの大きさは「好みの初期値」としての性格が強く、後勝ちでも不都合は小さい。エディタ（UI-116）も同じ性格である。

### UI-116: エディタ指定の保存 **MUST**

FR-091 で選ばれたエディタを設定として保存し、次回の**初期選択**とする。

- 保存する値は**実行ファイルの絶対パス**とする。プリセットの ID ではない。`Other...` で選ばれたものも同じ形で保存でき、保存の形式が 1 つで済む。
- **絶対パス以外は保存せず、読み込み時にも破棄する**（[IMP-153](11-impl-backend.md)）。相対パスやコマンド名を許すと、`$PATH` の内容によって起動されるプログラムが変わる（[NFR-035](07-nonfunctional.md)）。
- 保存されたエディタが見つからない場合（アンインストール、更新によるパスの変更）は、**エラーとせず「初期選択が無い」状態として扱う。** 選び直しを促すほうが、エラーを出して終わるより親切である（UI-113 と同じ考え方）。
- 多重起動では他の設定と同様に後勝ちとなる（UI-115）。**ウィンドウごとに違うエディタを使う動機がないため、後勝ちで不都合が生じない。**

> [!IMPORTANT]
> **MarkView は設定画面を持たない。** ここで保存されるのは「最後に開いたときのエディタ」であって、利用者が設定画面で登録した値ではない。この区別は UI-103 の設計（押すたびに選択ウィンドウを出す）と対になっており、**片方だけを変えてはならない。** 選択ウィンドウを省いて保存値で直接起動するようにすると、変更手段が画面から消え、設定画面を作る以外に手がなくなる。
