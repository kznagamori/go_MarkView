## 起動しない

### Linux — ウィンドウが開かず、共有ライブラリのエラーが出る

WebKitGTK 4.1 が入っていません。MarkView の**唯一の外部依存**です。

```sh
sudo apt install libwebkit2gtk-4.1-0
```

入っているか確かめるには次を実行します。`not found` が出なければ揃っています。

```sh
ldd ./MarkView | grep -i webkit
```

> [!NOTE]
> Ubuntu 24.04 は WebKitGTK 4.0 系を提供しません。MarkView は 4.1 系にリンクしています。
> 4.0 用のパッケージを入れても解決しません。

### Linux — `Permission denied` と出る

実行ビットが落ちています。tar.gz から展開した場合は付いているはずですが、
ファイルマネージャや別の経路でコピーすると落ちることがあります。

```sh
chmod +x ./MarkView
./MarkView
```

### Linux — SSH 越しやサーバ上で起動しない

MarkView は GUI アプリケーションです。ディスプレイのない環境では起動できません。

### Windows — 何も起きない

ウイルス対策ソフトが実行を止めている可能性があります。
[Windows の警告が出る](#windows-の警告が出る) を参照してください。

### 起動はするが「操作を案内する画面」が出る

引数なしで起動し、`README.md` が見つからなかった状態です。異常ではありません。
ツールバーの Open か、ファイルをウィンドウへドロップしてください。

探索の順序は [使い方](./usage.md#起動する) を参照してください。

## Windows の警告が出る

### 「Windows によって PC が保護されました」（SmartScreen）

MarkView は**コード署名を行っていません**。個人開発の OSS として、証明書の取得・維持費が
運用に見合わないためです。署名のない実行ファイルは、ダウンロード数が少ないうちは
この警告の対象になります。

実行する場合は、警告画面の **「詳細情報」** をクリックし、**「実行」** を選びます。

### ファイルのプロパティに「ブロックの解除」が出る

インターネットからダウンロードした ZIP を展開すると、中のファイルに「別のコンピューターから
取得した」という印（Zone.Identifier）が残ることがあります。

1. `MarkView.exe` を右クリックして「プロパティ」を開きます
2. 全般タブの下部にある **「セキュリティ: このファイルは他のコンピューターから取得したものです」**
3. **「ブロックの解除」** にチェックを入れて「OK」

**ZIP を展開する前に**、ZIP 自体のプロパティで解除しておくと、中のファイルすべてに適用されます。

### ウイルス対策ソフトが検知する

未署名で、かつ配布数の少ない実行ファイルは、ヒューリスティック検知の対象になりやすいものです。
配布物には実行ファイル圧縮（UPX 等）を使っていません（誤検知をさらに招くためです）が、
それでも検知されることがあります。

**まずチェックサムを照合してください。** リリースに添付している `checksums.txt` と一致すれば、
配布物が改変されていないことは確かめられます。

```powershell
Get-FileHash MarkView-<version>-windows-amd64.zip -Algorithm SHA256
```

```sh
sha256sum -c checksums.txt
```

一致していれば、ウイルス対策ソフト側で除外設定を行うか、ベンダに誤検知として報告してください。

## 表示がおかしい

### Mermaid の図が出ない、エラーが表示される

- 図の定義に誤りがあると、そのブロックだけエラー内容を表示し、**元のソースがコードブロックの
  まま残ります**。表示されているエラー文は Mermaid が返したものです。定義を見直してください。
- 他の図や本文の描画は止まりません。
- 同梱している Mermaid のバージョンは `F1`（アプリケーション情報）で確認できます。
  新しい記法を使っている場合、同梱版が対応していないことがあります。

### 数式が赤い文字のまま表示される

KaTeX が解釈できないコマンドです。**赤くなるのは解釈できなかった箇所だけ**で、
残りは描画されています。綴りやコマンド名を確認してください。

### 画像が出ない

- **相対パスは、表示中の Markdown ファイルがあるディレクトリを基準**に解決します。
  ツリーの起点ではありません。
- 対応形式は PNG、JPEG、GIF、SVG、WebP、AVIF、BMP、ICO です。
- リモート画像（`https://`）はネットワークに繋がっているときだけ表示されます。
  オフラインでは代替テキストとプレースホルダになります。
- 画像が見つからない場合も、文書全体の描画は止まりません。

### 文字化けする

MarkView が読むのは **UTF-8 だけ**です。Shift_JIS などの自動判別は行いません。

不正なバイト列は `�`（U+FFFD）に置き換えて読み進め、ステータス領域に警告を出します。
文字化けしている場合は、ファイルを UTF-8 に変換してください。

```powershell
Get-Content -Encoding Default file.md | Set-Content -Encoding utf8 file-utf8.md
```

```sh
iconv -f CP932 -t UTF-8 file.md > file-utf8.md
```

### `<script>` や `<iframe>` が消える

仕様どおりです。生の HTML はサニタイズしてから描画します。
何が通り、何が取り除かれるかは
[対応する Markdown 記法](./markdown.md#生-html) を参照してください。

### アウトラインが勝手に消える

**本文ペインの幅が 240 論理ピクセルを下回ると、アウトラインが一時的に隠れます。**
ツールバーのボタンは ON のままで、幅を広げると自動的に戻ります。利用者が消したわけでは
ないため、設定にも記録しません。

ファイルツリーはこの対象外で、自動的に隠れることはありません。

### コピーボタンが見当たらない

コードブロックの右上に**常に置かれています**が、既定は半透明です。
コードブロックにマウスを重ねると不透明になります。`Tab` キーでフォーカスを当てることも
できます。

## ファイルを開けない

### 「大きすぎる」と表示される

| サイズ | 動作 |
| --- | --- |
| 10 MB 超 50 MB 以下 | 確認画面が出る。`Open anyway` で表示できる |
| 50 MB 超 | 表示できない。開く手段は出ない |

50 MB（52,428,800 バイト）を超えるファイルは、分割するか別の手段で開いてください。

### 拡張子が違う

扱うのは `.md` `.markdown` `.mdown` `.mkd` です。それ以外の拡張子のファイルは、
ツリーにも出ませんし、リンクからも開きません。

### 読み取り権限がない

ステータス領域にその旨が出ます。表示中の内容は変わりません。

### 描画に時間がかかる

数千行の表や、極端に深い入れ子のリストを含む文書では時間がかかります。
**異常終了はしません。** 待つか、別の文書へ切り替えてください。

## 動きがおかしい

### 保存しても表示が更新されない

- 監視しているのは**表示中の 1 ファイルだけ**です。インクルード元や画像は監視しません。
- 保存から反映まで 150 ms ほどの猶予があります（連続する書き込みをまとめるため）。
- それでも反映されない場合は `F5` または `Ctrl+R` で読み直してください。

### エディタで開いても何も起きない

まず、**選んだのが GUI のエディタか**を確かめてください。

- `vim` / `nano` / `emacs -nw` のような**端末で動くエディタには対応していません**。端末を
  持たない状態で起動するため、何も起きないまま終わります（[使い方](./usage.md#エディタで開く)）。
- エディタが**背面のウィンドウで開いている**ことがあります。開いた直後にステータス領域へ
  `Opened in ...` と出ていれば、起動には成功しています。タスクバーを確かめてください。
- ステータス領域に `Failed to start the editor.` と出た場合は、実行ファイルが壊れているか、
  実行権限がありません。

### 一覧に自分のエディタが出てこない

一覧に名前があって `(not installed)` が付いている場合は、**MarkView が探した場所に
無かった**ということです。ポータブル版や独自の場所に入れている場合に起こります。

名前そのものが無い場合も含め、`Other...` → `Browse` で実行ファイルを直接選んでください。
選んだものは次回の初期選択として記憶されます。

### エディタの選択が消える

設定と同じテンポラリディレクトリに記録しているためです（下記）。
消えても、次に押したときに選び直すだけで、エラーにはなりません。

選んだエディタをアンインストールした場合や、更新でインストール先が変わった場合も同じです。

### MarkView 自身をエディタに指定してしまった

指定できません。`MarkView cannot be used as an editor.` と表示され、何も起動しません。
押すたびにウィンドウが増える事故を防ぐためです。

### 設定が毎回リセットされる

設定は**テンポラリディレクトリ**に保存しています。OS のクリーンアップや再起動で
消えることがあります。仕様上の動作で、消えても既定値で起動します。

保存先とその理由は [設定と保存されるもの](./settings.md#保存先) を参照してください。

### ウィンドウが毎回画面の中央に開く

**位置は保存も復元もしません。** 復元するのは大きさだけです。
モニタ構成が変わったときに画面外へ開く事故を避けるためです。

### 最大化して終了したのに、次回は最大化されていない

仕様どおりです。**最大化状態は保存しません。** 大きさは最大化する前の値で復元します。

複数同時に起動して並べて使えるようにするためです。保存すると、最後に閉じたウィンドウが
最大化だった場合に、以後のすべてのウィンドウが画面いっぱいで開くことになります
（[設定と保存されるもの](./settings.md#複数同時に起動したとき)）。

### 表示倍率が毎回 100 % に戻る

こちらも仕様どおりです。**倍率は保存しません。** 理由は最大化状態と同じで、
ウィンドウごとに変えて使える値だからです。

### 2 つ目を起動したら、設定が片方の状態に揃ってしまった

設定ファイルは全ウィンドウで共有していて、**最後に終了したウィンドウの内容が残ります**。
テーマ・ペインの表示状態と幅・ウィンドウの大きさが対象です。

保存する項目は「後から上書きされても困らないもの」に絞ってあります。
ウィンドウごとに変えて使う倍率と最大化状態は、そもそも保存していません。

### 「最近開いたファイル」が無い

機能として持っていません。開いたファイルのパスをどこにも記録しないためです。
[設定と保存されるもの](./settings.md#保存されないもの) を参照してください。

### テーマが OS 設定に追従しなくなった

一度でも自分で切り替えると、以後はその選択を記憶します。追従に戻すには設定ファイルを
削除してください（[消したいとき](./settings.md#消したいとき)）。

## それでも直らないとき

### 診断情報を出す

環境変数 `MARKVIEW_DEBUG=1` を設定して起動すると、**Markdown の変換中に想定外の失敗が
起きたときだけ**、その内容とスタックトレースを標準エラー出力へ出します。

**既定では何も出力しません。ログファイルも作りません**（通常動作でログを残さないためです）。
操作の記録や通信ログのような詳細なトレースは出ないので、期待しないでください。

```powershell
$env:MARKVIEW_DEBUG = "1"; .\MarkView.exe
```

```sh
MARKVIEW_DEBUG=1 ./MarkView
```

### 動作環境を確認する

`F1`（アプリケーション情報）で、バージョン・コミット・ビルド日時・OS とアーキテクチャ・
同梱している Mermaid / KaTeX のバージョンを確認できます。

```sh
MarkView --version
```

### 報告する

再現手順と、上の情報を添えて報告してください。

- [Issues](https://github.com/kznagamori/go_MarkView/issues)

再現に使った Markdown があると助かります。差し支えのある内容は、同じ現象が出る
最小限のファイルに置き換えてください。
