## 起動しない

### Linux — ウィンドウが開かず、共有ライブラリのエラーが出る

WebKitGTK 4.1 が入っていません。MarkView の**唯一の外部依存**です。

```sh
sudo apt install libwebkit2gtk-4.1-0
```

入っているか確かめるには次を実行します。`not found` が出なければ揃っています。

```sh
ldd ./MarkView | grep -i webkit
```

> [!NOTE]
> Ubuntu 24.04 は WebKitGTK 4.0 系を提供しません。MarkView は 4.1 系にリンクしています。
> 4.0 用のパッケージを入れても解決しません。

### Linux — `Permission denied` と出る

実行ビットが落ちています。tar.gz から展開した場合は付いているはずですが、
ファイルマネージャや別の経路でコピーすると落ちることがあります。

```sh
chmod +x ./MarkView
./MarkView
```

### Linux — SSH 越しやサーバ上で起動しない

MarkView は GUI アプリケーションです。ディスプレイのない環境では起動できません。

### Linux — アイコンが歯車などの汎用アイコンになる

Linux では、**実行ファイル単体で固有のアイコンを出せません**。
ファイルマネージャは実行ファイルの中身からアイコンを読まず、
ウィンドウやタスクバーのアイコンは、Wayland では**デスクトップエントリ**（`.desktop` ファイル）から解決されます。

ランチャーに登録したい場合は、次のように置いてください。

アイコンの画像は配布物に含まれていません。リポジトリの `assets/icon.png` か、任意の PNG を使ってください。

```sh
mkdir -p ~/.local/share/applications ~/.local/share/icons/hicolor/256x256/apps
cp /path/to/icon.png ~/.local/share/icons/hicolor/256x256/apps/markview.png

cat > ~/.local/share/applications/markview.desktop <<'EOF'
[Desktop Entry]
Type=Application
Name=MarkView
Exec=/path/to/MarkView %f
Icon=markview
MimeType=text/markdown;
Categories=Utility;TextEditor;
StartupWMClass=MarkView
EOF

update-desktop-database ~/.local/share/applications   # 関連付け（MIME）の更新
gtk-update-icon-cache ~/.local/share/icons/hicolor    # アイコンの更新
```

`Exec` は実際に置いた場所に合わせてください。
`Icon=markview` は**アイコンテーマから名前で引かれる**ため、上のようにテーマの階層（`hicolor/<サイズ>/apps/`）へ置きます。

なお、**情報ダイアログ（`?` ボタン）のアイコンは Linux でも表示されます**。

### Windows — 何も起きない

ウイルス対策ソフトが実行を止めている可能性があります。
[Windows の警告が出る](#windows-の警告が出る) を参照してください。

### 起動はするが「操作を案内する画面」が出る

引数なしで起動し、`README.md` が見つからなかった状態です。異常ではありません。
ツールバーの Open か、ファイルをウィンドウへドロップしてください。

探索の順序は [使い方](./usage.md#起動する) を参照してください。

## Windows の警告が出る

### 「Windows によって PC が保護されました」（SmartScreen）

MarkView は**コード署名を行っていません**。個人開発の OSS として、証明書の取得・維持費が
運用に見合わないためです。署名のない実行ファイルは、ダウンロード数が少ないうちは
この警告の対象になります。

実行する場合は、警告画面の **「詳細情報」** をクリックし、**「実行」** を選びます。

### ファイルのプロパティに「ブロックの解除」が出る

インターネットからダウンロードした ZIP を展開すると、中のファイルに「別のコンピューターから
取得した」という印（Zone.Identifier）が残ることがあります。

1. `MarkView.exe` を右クリックして「プロパティ」を開きます
2. 全般タブの下部にある **「セキュリティ: このファイルは他のコンピューターから取得したものです」**
3. **「ブロックの解除」** にチェックを入れて「OK」

**ZIP を展開する前に**、ZIP 自体のプロパティで解除しておくと、中のファイルすべてに適用されます。

### ウイルス対策ソフトが検知する

未署名で、かつ配布数の少ない実行ファイルは、ヒューリスティック検知の対象になりやすいものです。
配布物には実行ファイル圧縮（UPX 等）を使っていません（誤検知をさらに招くためです）が、
それでも検知されることがあります。

**まずチェックサムを照合してください。** リリースに添付している `checksums.txt` と一致すれば、
配布物が改変されていないことは確かめられます。

```powershell
Get-FileHash MarkView-<version>-windows-amd64.zip -Algorithm SHA256
```

```sh
sha256sum -c checksums.txt
```

一致していれば、ウイルス対策ソフト側で除外設定を行うか、ベンダに誤検知として報告してください。

## 表示がおかしい

### Mermaid の図が出ない、エラーが表示される

- 図の定義に誤りがあると、そのブロックだけエラー内容を表示し、**元のソースがコードブロックの
  まま残ります**。表示されているエラー文は Mermaid が返したものです。定義を見直してください。
- 他の図や本文の描画は止まりません。
- 同梱している Mermaid のバージョンは `F1`（アプリケーション情報）で確認できます。
  新しい記法を使っている場合、同梱版が対応していないことがあります。

### PlantUML の図が出ない

**理由が 3 通りあり、図の上に英語で書かれます。**

| 表示 | 意味 | どうするか |
| --- | --- | --- |
| `Include directives are not supported.` | `!include` 系の取り込み指令が入っています | 指令を外して、図の定義を 1 つのブロックに書いてください。標準ライブラリ（C4 など）は使えません |
| `PlantUML could not render this diagram. It may be unsupported or larger than 100,000 px.` | 処理系が図を返しませんでした | `salt` `ditaa` か、幅か高さが 100,000 px を超える大きな図です。大きな図は分割してみてください |
| `PlantUML rendering did not complete.` | 描画が終わりませんでした | 図が非常に複雑な場合に起こります。簡単な図で出るなら不具合として報告してください |

- **構文の誤りはこの 3 つに入りません。** PlantUML が描いた**エラー図がそのまま図として出ます**。
  行番号と該当行が図の中に書かれているので、そこを直してください。
- 他の図や本文の描画は止まりません。
- 描けなかったブロックも、**元のソースはコードブロックのまま残ります。**
  コピーボタンからソースを取り出せます。
- **`@enduml` などの終わりの行が無い図**は、終わりまでをそのまま処理系へ渡します。シーケンス図では図にならず、
  `PlantUML could not render this diagram. It may be unsupported or larger than 100,000 px.` と出ます。終わりの行を書き足してください。

### PlantUML の図が 1 ページ目しか出ない

`newpage` で区切った図は、**1 ページ目だけ**が描かれます。同梱している処理系の制約です。
ページごとに `@startuml` 〜 `@enduml` を分けて書いてください（PlantUML のファイルなら、図ごとに見出しが付いて並びます）。

### 図のファイルで `No diagrams found.` と出る

- PlantUML のファイル: `@startuml` のような図の始まりの行がありません。図の外の行は無視するため、
  図が 1 つも無いと、ソースをそのまま出してこの文言を添えます。
- Mermaid のファイル: 中身が空白だけです。

### `.mmd` のファイルが Mermaid の構文エラーになる

`.mmd` は MultiMarkdown の文書にも使われる拡張子ですが、MarkView は**拡張子で種類を決め**、`.mmd` を
Mermaid のファイルとして開きます。MultiMarkdown の文書なら、拡張子を `.md` に変えてください。

Mermaid のファイルに図を 2 つ書いた場合も構文エラーになります。1 ファイルに 1 つの図にしてください。

### リストや引用の中の `> [!NOTE]` が Alert にならない

仕様どおりです。**Alert になるのは文書の一番外側の引用だけ**で、GitHub と同じです
（[対応する Markdown 記法](./markdown.md#github-alerts)）。v1.1.0 までは入れ子でも Alert として描いていました。

### GitHub で文字色が付かない

仕様どおりです。編集モードで付けた文字色（`<span style="color: …">`）は、**GitHub では付かず、文字だけが残ります。**
GitHub が `style` を取り除くためです。取り消し線（`<del>`）は GitHub でも付きます。

### 数式が赤い文字のまま表示される

KaTeX が解釈できないコマンドです。**赤くなるのは解釈できなかった箇所だけ**で、
残りは描画されています。綴りやコマンド名を確認してください。

### 画像が出ない

- **相対パスは、表示中の Markdown ファイルがあるディレクトリを基準**に解決します。
  ツリーの起点ではありません。
- 対応形式は PNG、JPEG、GIF、SVG、WebP、AVIF、BMP、ICO です。
- リモート画像（`https://`）はネットワークに繋がっているときだけ表示されます。
  オフラインでは代替テキストとプレースホルダになります。
- 画像が見つからない場合も、文書全体の描画は止まりません。
- 画素数が大きすぎる画像は、WebView が表示できず、壊れた画像の表示になります（MarkView は画素数の上限を設けていません）。

### 画像を書き換えたのに古いまま

埋め込んだ画像のファイルは監視していません。`F5` で読み直すと新しい画像になります。
文書そのものが保存されて描き直されたときも、書き換えた画像は新しくなります。

### 文字化けする

MarkView が読むのは **UTF-8 だけ**です。Shift_JIS などの自動判別は行いません。

不正なバイト列は `�`（U+FFFD）に置き換えて読み進め、ステータス領域に警告を出します。
文字化けしている場合は、ファイルを UTF-8 に変換してください。

```powershell
Get-Content -Encoding Default file.md | Set-Content -Encoding utf8 file-utf8.md
```

```sh
iconv -f CP932 -t UTF-8 file.md > file-utf8.md
```

### `<script>` や `<iframe>` が消える

仕様どおりです。生の HTML はサニタイズしてから描画します。
何が通り、何が取り除かれるかは
[対応する Markdown 記法](./markdown.md#生-html) を参照してください。

### アウトラインが勝手に消える

**本文ペインの幅が 240 論理ピクセルを下回ると、アウトラインが一時的に隠れます。**
ツールバーのボタンは ON のままで、幅を広げると自動的に戻ります。利用者が消したわけでは
ないため、設定にも記録しません。

ファイルツリーはこの対象外で、自動的に隠れることはありません。

### コピーボタンが見当たらない

コードブロックの右上に**常に置かれています**が、既定は半透明です。
コードブロックにマウスを重ねると不透明になります。`Tab` キーでフォーカスを当てることも
できます。

### 図や画像に、原寸表示や拡大画面のボタンが出ない

- **埋め込んだ画像のボタンは、本文の幅に合わせて縮小されているときだけ**出ます。原寸のまま収まっている画像には出ません。
  画像のファイルとして開いたときは、拡大画面のボタンが常に出ます。
- 描けなかった Mermaid 図、`!include` などで図にならなかった PlantUML のブロック、読み込めなかった画像、
  描画を待っている図、数式には出ません。
- PlantUML の**エラー図には出ます**。

詳しくは [使い方](./usage.md#図と画像を大きく見る) を参照してください。

### 表に並べ替えのボタンが出ない

- 見出し行を除いて **2 行以上**ある表だけが対象です。
- 生 HTML で書いた表（`<table>`）には出ません。

### 表の行の並びが、書いた順と違う

並べ替えのボタンを押した状態です。**並べ替えは表示だけで、ファイルは書き換えていません。**
見出しの右端のボタンを押すたびに、昇順 → 降順 → 元の順と切り替わります。

## ファイルを開けない

### 「大きすぎる」と表示される

| サイズ | 動作 |
| --- | --- |
| 10 MB 超 50 MB 以下 | 確認画面が出る。`Open anyway` で表示できる |
| 50 MB 超 | 表示できない。開く手段は出ない |

50 MB（52,428,800 バイト）を超えるファイルは、分割するか別の手段で開いてください。
画像のファイルも同じ大きさの規則です。

### 拡張子が違う

開けるのは、Markdown（`.md` `.markdown` `.mdown` `.mkd`）、図のファイル（`.puml` `.pu` `.wsd` `.plantuml`
`.mmd` `.mermaid`）、画像のファイル（`.png` `.jpg` `.jpeg` `.gif` `.svg` `.webp` `.avif` `.bmp` `.ico`）の 3 種類です
（[使い方](./usage.md#文書を開く)）。それ以外の拡張子のファイルは、ツリーに出ず、開こうとすると
`Not a supported file:` と出ます。リンク先にあれば、OS の既定のアプリで開きます。

PlantUML の取り込み用の断片（`.iuml`）も開けません。単体では図にならないためです。

### ファイルツリーに画像（や図）のファイルが出ない

ツリーに並べる種類は、見出しの行の右端の漏斗のボタンで選びます。**既定では画像のファイルを並べません。**
`Images` にチェックを入れてください（[使い方](./usage.md#並べる種類を選ぶ)）。図のファイルも外せます。

フィルターが効くのはツリーの表示だけです。ファイル選択ダイアログ・ドロップ・リンクからは、選択に関わらず開けます。

### 読み取り権限がない

ステータス領域にその旨が出ます。表示中の内容は変わりません。

### 描画に時間がかかる

数千行の表や、極端に深い入れ子のリストを含む文書では時間がかかります。
**異常終了はしません。** 待つか、別の文書へ切り替えてください。

### 大きな PlantUML の図を開くと、しばらく画面が止まる

**PlantUML の図を 1 枚描く間は、スクロールもボタンも効きません。** 同梱した処理系が、図の配置を計算する間
画面を止めるためです。図が 1 枚描き終わるたびに効くようになり、描いている間も元のソースは出たままです。

- 止まる時間は図の種類と大きさで決まります。**JSON・YAML と、縦に長いアクティビティ図は重く**、
  JSON・YAML は高さ 2 万 px ほど、アクティビティ図は 5 万 px ほどで数秒かかります。シーケンス図は軽く、
  高さ 10 万 px 近くでも 1 秒ほどです（目安。PC の速さで変わります）。
- 長く止まるときは、図をいくつかのブロックに分けてください。分けた図は 1 枚ずつ描かれ、その合間は操作できます。
- 幅か高さが 100,000 px を超える図は、計算を終えたあとで描かれずに理由が出ます（[PlantUML の図が出ない](#plantuml-の図が出ない)）。

## 動きがおかしい

### 保存しても表示が更新されない

- 監視しているのは**表示中の 1 ファイルだけ**です。インクルード元や、文書に埋め込んだ画像は監視しません。
- 編集モードで編集欄を開いている間は、描き直しを待たせています。編集欄を閉じると描き直します。
- 保存から反映まで 150 ms ほどの猶予があります（連続する書き込みをまとめるため）。
- それでも反映されない場合は `F5` または `Ctrl+R` で読み直してください。

### リンクを押すと `Cannot open:` と出る

リンク先を、既定のブラウザや OS の既定のアプリへ渡せなかった状態です。表示中の文書はそのままです。

- 開こうとしたファイルに、既定のアプリが関連付けられていない。
- リンク先のファイルが存在しない。
- **Linux で `xdg-open` が見つからない。** MarkView は `xdg-open` を使って既定のアプリを起動します。
- `http://` / `https://` / `mailto:` 以外のスキームのリンクである。文書の書き手が、利用者の環境で
  任意のプログラムを起動できないようにするため、これ以外は開きません。

### 戻るボタンが押せない（淡色）

戻れる文書がありません。起動して最初に開いた文書や、履歴の先頭にいるときです。進むボタンも、
進める文書が無いときは淡色です。

### 戻ったら、途中の文書が履歴から消えていた

その文書を開けなかった（削除した・名前を変えた・権限が無いなど）ためです。**開けなかった項目は履歴から取り除き、
履歴の位置は元のまま**にします。開けなかった理由はステータス領域に出ます。もう一度戻ると、その手前の文書へ戻ります。

### マウスのサイドボタンで戻れない

環境によっては、サイドボタンが MarkView に届きません。ツールバーの戻る・進むボタンか、`Alt+←` / `Alt+→` を使ってください。
右クリックメニューや拡大画面を開いている間も、サイドボタンは働きません。

### リンクをマウスの中ボタンで押しても何も起きない

仕様どおりです。**リンクを開くのは左ボタンでのクリックとキーボードだけ**です。中ボタンで
新しいウィンドウを開いたり、ウィンドウの中が別のページに移ったりしないようにしています。

### 拡大画面で図のリンクを押しても何も起きない

仕様どおりです。拡大画面ではドラッグで表示位置を動かすため、図の中のリンクは開きません。
拡大画面を閉じて、本文の図のリンクを押してください。

### 右クリックしてもブラウザのメニューが出ない

仕様どおりです。「戻る」「再読み込み」「検証」といったページとしての操作を持ち込まないよう、
**MarkView 自身のメニュー**（`Copy`・`Select all` など）を出しています。
ツールバー・ファイルツリーの項目の外（余白や見出しの行）・アウトライン・ステータス領域・拡大画面では、メニューは何も出ません
（[使い方](./usage.md#右クリックメニュー)）。ファイルツリーの項目では、ファイルやディレクトリについてのメニューが出ます
（[ツリーの右クリックメニュー](./usage.md#ツリーの右クリックメニュー)）。

### `Open in file manager` で何も起きない・`Cannot open:` と出る

- OS の既定のファイルマネージャを起動できませんでした。**Linux では `xdg-open` を使います。** 入っているか確かめてください。
- そのディレクトリが既に無い場合は、`File not found:` と出ます。ツリーは自動では更新されないため、
  ペインを閉じて開き直すか `F5` で読み直してください。
- `Open containing folder` はフォルダを開くだけで、ファイルを選んだ状態にはしません。

### `Failed to paste.` と出る

右クリックメニューの `Paste` で、クリップボードの内容を読めなかった状態です。
`Ctrl+V` で貼り付けてみてください。

### エディタで開いても何も起きない

まず、**選んだのが GUI のエディタか**を確かめてください。

- `vim` / `nano` / `emacs -nw` のような**端末で動くエディタには対応していません**。端末を
  持たない状態で起動するため、何も起きないまま終わります（[使い方](./usage.md#エディタで開く)）。
- エディタが**背面のウィンドウで開いている**ことがあります。開いた直後にステータス領域へ
  `Opened in ...` と出ていれば、起動には成功しています。タスクバーを確かめてください。
- ステータス領域に `Failed to start the editor.` と出た場合は、実行ファイルが壊れているか、
  実行権限がありません。

### エディタで開くボタンが押せない（淡色）

**画像のファイルを表示しているとき**と、文書を表示していないときは使えません。画像をエディタで開いても、
文字として読めないためです。ツリーの右クリックメニューの `Open in editor...` も、画像のファイルでは淡色です。

### 一覧に自分のエディタが出てこない

一覧に名前があって `(not installed)` が付いている場合は、**MarkView が探した場所に
無かった**ということです。ポータブル版や独自の場所に入れている場合に起こります。

名前そのものが無い場合も含め、`Other...` → `Browse` で実行ファイルを直接選んでください。
選んだものは次回の初期選択として記憶されます。

### エディタの選択が消える

設定と同じテンポラリディレクトリに記録しているためです（下記）。
消えても、次に押したときに選び直すだけで、エラーにはなりません。

選んだエディタをアンインストールした場合や、更新でインストール先が変わった場合も同じです。

### MarkView 自身をエディタに指定してしまった

指定できません。`MarkView cannot be used as an editor.` と表示され、何も起動しません。
押すたびにウィンドウが増える事故を防ぐためです。

### 設定が毎回リセットされる

設定は**テンポラリディレクトリ**に保存しています。OS のクリーンアップや再起動で
消えることがあります。仕様上の動作で、消えても既定値で起動します。

保存先とその理由は [設定と保存されるもの](./settings.md#保存先) を参照してください。

### ウィンドウが毎回画面の中央に開く

**位置は保存も復元もしません。** 復元するのは大きさだけです。
モニタ構成が変わったときに画面外へ開く事故を避けるためです。

### 最大化して終了したのに、次回は最大化されていない

仕様どおりです。**最大化状態は保存しません。** 大きさは最大化する前の値で復元します。

複数同時に起動して並べて使えるようにするためです。保存すると、最後に閉じたウィンドウが
最大化だった場合に、以後のすべてのウィンドウが画面いっぱいで開くことになります
（[設定と保存されるもの](./settings.md#複数同時に起動したとき)）。

### 表示倍率が毎回 100 % に戻る

こちらも仕様どおりです。**倍率は保存しません。** 理由は最大化状態と同じで、
ウィンドウごとに変えて使える値だからです。

### 2 つ目を起動したら、設定が片方の状態に揃ってしまった

設定ファイルは全ウィンドウで共有していて、**各ウィンドウは自分で変えた項目だけを保存します**。
テーマ・ペインの表示状態と幅・ウィンドウの大きさ・エディタ・ファイルツリーに並べる種類が対象です。
同じ項目を 2 つのウィンドウで別々に変えたときは、**後から保存したほう**が残ります。
あるウィンドウでテーマやフィルターを切り替えても、開いているほかのウィンドウには反映しません
（次に開くウィンドウから反映します）。

保存する項目は「後から上書きされても困らないもの」に絞ってあります。
ウィンドウごとに変えて使う倍率と最大化状態は、そもそも保存していません。

### 選んだテーマが、新しく開いたウィンドウで元に戻る

v1.2.0-rc.1 までの不具合です（v1.0.0 から）。テーマを選んだ後に、ペインの開閉やツリーのフィルターを
変えたり、テーマを選ぶ前から開いていたウィンドウを閉じたりすると、次に開くウィンドウのテーマが
OS の設定に戻ることがありました。v1.2.0 で直しました。

### 「最近開いたファイル」が無い

機能として持っていません。開いたファイルのパスをどこにも記録しないためです。
[設定と保存されるもの](./settings.md#保存されないもの) を参照してください。

### テーマが OS 設定に追従しなくなった

一度でも自分で切り替えると、以後はその選択を記憶します。追従に戻すには設定ファイルを
削除してください（[消したいとき](./settings.md#消したいとき)）。

### 読んだ文書の手掛かりを残したくない

MarkView は、開いたファイルのパス・表示履歴・検索語を書きません。ただし、文書が `http://` / `https://` の
画像を参照していると、**WebView がその画像をキャッシュに残すことがあります。** 気になる場合は、
MarkView をすべて終了してから消してください
（[WebView のキャッシュに残るもの](./settings.md#webview-のキャッシュに残るもの)）。

## 編集モードで直せない

### 編集モードのボタンが押せない（淡色）

次のときは編集モードを始められません。

- 文書を表示していない、または大きなファイルの確認画面・エラーの画面を出している
- 読み込みのときに不正なバイト列を `�` に置き換えた文書である（表示とファイルの中身が一致しないため）。
  ファイルを UTF-8 に直してから開き直してください（[文字化けする](#文字化けする)）
- 表示中のファイルが削除された
- 画像のファイルを表示している（画像は編集しません）

### 編集モードが勝手に終わった

次のときは自動で終わります。

- **別の文書へ切り替えた**（ファイルツリー・リンク・戻る / 進む・ドロップ・`Ctrl+O`）。リンクで移った先の
  文書が、書き換えられる状態で開かないようにするためです。
- 読み直したら、不正なバイト列を含んでいた
- 表示中のファイルが削除された

編集欄を開いていたときは、編集欄を閉じた時点で終わります。

### `Save or cancel the open edit first.` と出る

セルかコードブロックの編集欄を開いたまま、別の文書へ移る・再読み込み・ほかの書き込み・編集モードの終了・
表の並べ替えをしようとした状態です。入力を黙って捨てないよう、受け付けていません。
編集欄で `Save`（`Enter` / `Ctrl+Enter`）か `Cancel`（`Esc`）を押してから操作してください
（[使い方](./usage.md#編集欄を開いている間)）。

### `The file changed on disk. Cancel the edit to see the changes.` と出る

編集欄を開いている間に、ファイルが外部で保存されました。**その間は確定できません**（ほかの人の変更を上書きしないため）。
入力を写し取ってから `Cancel` で閉じると、新しい内容で描き直します。その上で、もう一度直してください。

### チェックボックスを押しても切り替わらない

- 編集モードになっているかを確かめてください。本文ペインの右下に `Edit mode` と出ていれば編集モードです。
- **生 HTML で書いた `<input type="checkbox">` は切り替えられません。** 編集モードの間も淡色のままです。

### セルをダブルクリックしても編集欄が開かない

- 編集モードになっているかを確かめてください。直せるセルには破線の枠が付きます。
- 破線の枠が付かないセルは直せません。行のセルの数が見出し行より少ないときに補われた空のセルと、
  生 HTML で書いた表のセルです。
- 並べ替えのボタンや画像のボタンの上をダブルクリックしても、編集は始まりません。

### セルの中のリンクを押しても移動しない

編集モードの間は、表のセルの中のリンクでは移動しません。ダブルクリックの 1 回目で別の文書へ
切り替わらないようにするためです。編集モードを終えてから押してください。

### コードブロックや図をダブルクリックしても編集欄が開かない

- 編集モードになっているかを確かめてください。直せるコードブロックと図には、右上に編集のボタン（鉛筆）が出ます。
- 字下げで書いたコードブロック、` ```math ` の数式、生 HTML の `<pre>` は直せません（編集のボタンが出ません）。
- 編集のボタンが淡色のブロックは、行ごとに前置き（`> ` や字下げ）が違うなど、正しく書き戻せない形です。
  ダブルクリックすると `This code block cannot be edited in MarkView.` と出ます。エディタで直してください。
- 右上のボタンの上をダブルクリックしても、編集は始まりません。

### 確定したのに書き込まれない

- セルの確定は `Enter` か `Save`、コードブロックの確定は `Ctrl+Enter` か `Save` です。
  **`Esc` と `Cancel` は取り消し**で、何も書き込みません。編集欄の外をクリックしても、編集欄は開いたまま残ります。
- 内容が変わっていなければ書き込みません。

### `This change would alter the document structure and was not saved.` と出る

書き込む内容を読み直したら、文書の構造（表の形、図の数など）が変わることが分かったため、書き込みませんでした。
編集欄は入力ごと開き直しています。たとえば、PlantUML のファイルで `@enduml` を消して 2 つの図をつなげた場合です。
構造を変えたいときは、エディタで直してください。

### 取り消し線や文字色のボタンが押せない（淡色）

- 文字を選んでいるかを確かめてください。
- 選択が **1 つのブロック**（段落・見出し・リストの項目・表の 1 つのセルなど）に収まっている必要があります。
  2 つの段落にまたがる選択には付けられません。
- コードの中、数式の中、図、生 HTML のブロック、図や画像のファイルには付けられません。

### `This formatting cannot be applied here.` と出る

選んだ範囲に取り消し線や文字色を付けると、既存の記法を分けられない、または太字などが効かなくなるため、
書き込みませんでした。たとえば `<del>あ**いう**え</del>` の「う」だけを外す場合や、日本語に接した太字の一部だけを
選んだ場合です。選ぶ範囲を、記法の中身の全体か外側にしてみてください。

### `The whole strikethrough was removed.` と出る

`~~…~~` や `<s>` のように**手で書いた取り消し線**の一部を選んで外すと、その取り消し線の全体を外します。
記法を書き換えずに一部だけを外す方法が無いためです。戻すときは `Ctrl+Z` を押してください。

### `The file changed on disk and was not saved.` と出る

**外部のエディタや別の MarkView が、先にファイルを保存していた**ため、書き込みませんでした。
ほかの人の変更を上書きしないためです。MarkView はファイルを読み直して描き直しているので、
内容を確かめてから、もう一度直してください。

このとき、取り消しの履歴は消えます（古い内容を書き戻さないため）。

### `Failed to save:` と出る

ファイルに書き込めませんでした。表示は直す前に戻っています。

- ファイルが**読み取り専用**になっている。MarkView は、利用者が書き込みを禁じたファイルを書き換えません。
- ファイルやフォルダへの書き込み権限が無い。MarkView は同じフォルダに一時ファイルを作ってから置き換えるため、
  **フォルダにも書き込めなければなりません。**
- ほかのプログラムがファイルを開いたままにしている（Windows）。

### `Ctrl+Z` で元に戻らない

- 編集モードを終えると、取り消しの履歴は消えます。
- ファイルが MarkView 以外で変更されると、履歴は消えます。
- 編集欄や検索バーの入力欄にフォーカスがあるときは、その入力欄の中の取り消しになります。
- 戻れるのは 100 操作までです。

### 書き込んだら、ハードリンクが切れた・アクセス権が変わった

仕様どおりです。書き込みは、一時ファイルに書いてから置き換える方式で行います。途中で失敗しても
元のファイルを壊さないためです。この方式では、**ハードリンクは切れ、Windows でファイルに個別に
設定したアクセス権は引き継がれません。** 気になるファイルは、編集モードではなくエディタで直してください。

### 並べ替えている表のセルを直したら、行が並べ替えの順から外れた

仕様どおりです。直した行が動いて見失わないよう、書き込んだ後も行の並びをそのまま保ちます。
見出しのボタンを押すと、次の段階で並べ直します。

## それでも直らないとき

### 診断情報を出す

環境変数 `MARKVIEW_DEBUG=1` を設定して起動すると、**Markdown の変換中に想定外の失敗が
起きたときだけ**、その内容とスタックトレースを標準エラー出力へ出します。

**既定では何も出力しません。ログファイルも作りません**（通常動作でログを残さないためです）。
操作の記録や通信ログのような詳細なトレースは出ないので、期待しないでください。

```powershell
$env:MARKVIEW_DEBUG = "1"; .\MarkView.exe
```

```sh
MARKVIEW_DEBUG=1 ./MarkView
```

### 動作環境を確認する

`F1`（アプリケーション情報）で、バージョン・コミット・ビルド日時・OS とアーキテクチャ・
同梱している Mermaid / PlantUML / KaTeX のバージョンを確認できます。

```sh
MarkView --version
```

### 報告する

再現手順と、上の情報を添えて報告してください。

- [Issues](https://github.com/kznagamori/go_MarkView/issues)

再現に使った Markdown があると助かります。差し支えのある内容は、同じ現象が出る
最小限のファイルに置き換えてください。
