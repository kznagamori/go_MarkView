## 1. 症状

利用者の報告（2 か所で同じ形）:

> **E2E-223**: L1 でアウトライン、ファイルツリーにドラッグアンドドロップでき、テキストが表示され元に戻せなくなる
>
> **E2E-381 の手順 10**: L1: 手順 10 でドラッグアンドドロップすると Markdown がそのまま表示され、元に戻せない

**MarkView の画面がドロップしたファイルの中身（生の Markdown）に置き換わり、戻る手段が無い。**
[BUG-015](2026-09-17-bug-015-mermaid-click-link-navigation.md) / [BUG-016](2026-09-17-bug-016-link-middle-click.md) と同じ「WebView がページ遷移する」症状である（AR-060）。

## 2. なぜ v1.0.0 で出ていなかったか

**L1 でドロップを一度も試していない。**

| rc | E2E-223 の実施 | 備考 |
| --- | --- | --- |
| `v1.0.0-rc.3` | **W1 のみ** | — |
| `v1.0.0-rc.4` | **W1 のみ** | 「L1 は WSL 上の Ubuntu 24.04 であり、**ホストからのドラッグ＆ドロップを行えない**ため L1 では実施できなかった」 |
| `v1.1.0-rc.1` | **W1 / L1** | **L1 が実機の Ubuntu に変わり、初めて実施できた** |

**環境が変わって初めて見えた**という点で、[BUG-008](2026-09-06-bug-008-broken-image-alt-webkitgtk.md) / [BUG-009](2026-09-06-bug-009-task-checkbox-size-webkitgtk.md)（rc.3 で初めて Linux を実施して現れた）と同じである。

## 3. 確かめたこと（利用者。L1。2026-09-21）

| 見たもの | 結果 | 分かること |
| --- | --- | --- |
| **ドラッグ中にオーバーレイの案内が出るか** | **出ない** | **`hasFiles()` が偽である**——`dataTransfer.types` に `"Files"` が入っていない（GTK が渡すのは `text/uri-list`）。**だから `preventDefault()` にも届かない** |

**これで 2 つの NG が 1 つの原因に揃う。**

- **E2E-223 の確認内容 1**（ドラッグ中にオーバーレイと案内が出る。UI-070）が **L1 で満たされていない**。記録は OK だが、**この観察と食い違う**
- **確認内容 4**（本文ペイン以外にドロップしても同じ結果になる）と **E2E-381 の確認内容 10** は、`preventDefault()` が呼ばれないために WebView が遷移する

> [!NOTE]
> **E2E-223 の IMPORTANT は「1 だけが OK で 2 以降が NG になる」を警告していた**（[BUG-001](2026-09-04-bug-001-file-drop-windows.md)）。**今回はその裏返しである**——
> **1 が NG なのに 2・3 は OK** になった。Wails の GTK 側の経路が Go へパスを届けるため、**案内が出なくても文書は開く。**
> 「開けたから配線できている」とも言えない。**確認内容は 1 つずつ見る**（E2E-204）。

## 4. 経路（コードで確かめたこと）

### 4.1 こちら側

`frontend/js/dnd.js` は、**ファイルのドラッグと判定したときだけ**既定の動作を止める。

```js
function onOver(event) {
  if (!hasFiles(event)) return;   // ← L1 ではここで抜ける
  event.preventDefault();
}

function hasFiles(event) {
  return Boolean(event.dataTransfer) && [...event.dataTransfer.types].includes("Files");
}
```

`hasFiles` は**オーバーレイを出すかどうかの判定**（ウィンドウ内で完結するドラッグでは出さない）であり、**遷移を止めるかどうかの判定に流用されている。**

### 4.2 Wails の Linux 実装（v2.15.0）

`internal/frontend/desktop/linux/window.c` の `onDragDrop` は **`FALSE`（処理していない）を返す**ため、GTK は既定の処理を続け、`WebKitWebView` 自身がドロップされた URI へ遷移する。
**`DisableWebViewDrop`（`options.DragAndDrop`）は使えない**——`gtk_drag_dest_unset(webview)` を呼ぶだけで `gtk_drag_dest_set` をどこでも呼ばないため、真にすると**ドロップ自体が届かなくなる**（FR-011 が壊れる）。

## 5. 直し方

| 手順 | 何を |
| --- | --- |
| 1 | **`dragover` と `drop` の既定の動作を、条件を付けずに止める**（AR-060）。判定に掛けない——**判定はオーバーレイのためのものであり、遷移を止める条件ではない** |
| 2 | **ファイルのドラッグの見分けを広げる**。`types` に `"Files"` **または** `"text/uri-list"` があればファイルとみなす（WebKitGTK は後者しか渡さない） |
| 3 | **ウィンドウ内で始まったドラッグを除く。** `dragstart` で旗を立て、`dragend` で下ろす。**本文のリンクをドラッグすると `text/uri-list` が付く**ため、2 だけでは案内が出てしまう |

**W1 の振る舞いは変わらない**（`"Files"` があり、既に止めている）。**変わるのは L1 だけである。**

**`preventDefault()` を条件なしにするのは、[BUG-016](2026-09-17-bug-016-link-middle-click.md) で `auxclick` を足したときと同じ考え方である**——
**遷移が起きてしまうと戻す手段が無い**ため、起こしうる経路をすべて止める（AR-060）。

## 6. 影響

**本文が消え、戻る手段が無い**（ツールバーも含めて画面全体が失われる）。**編集モードの状態も失われる。**
あわせて、**L1 ではドラッグ中の案内がまったく出ない**（UI-070）。**優先度はどちらのケースも「高」である。**

| 何を | どこで |
| --- | --- |
| **ドラッグ中に案内が出る** | **L1 で E2E-223 の確認内容 1**（rc.2 の手動テスト） |
| **どこへ落としても遷移せず、文書が開く** | **L1 で E2E-223 の確認内容 2〜4**。**W1 でも E2E-223 / 224 / 225 を見る**（退行していないこと） |
| 編集モード中にドロップしても遷移しない | **L1 で E2E-381 の確認内容 10** |
