## 1. 症状

編集モードで、**本文のチェックボックスを押すと、脚注の中のタスクが書き換わる**（逆も同じ）。表のセルも同じで、**本文のセルを開くと脚注の表のセルの文字が編集欄に入り、確定すると脚注の表のセルが書き換わる。**

### 1.1 起きる形（本物の変換器と書き換えの組み立てで確かめた）

**MarkView の本物の `internal/renderer` と `internal/document` をそのまま使い**、描画した HTML の目印（`data-ref`）を、フロントエンドが Go へ送るのと同じ値として `ParseRef` → `PlanTask` / `CellSource` / `PlanCell` に渡した（`workspace/tmp/_fnref2`。2026-11-08）。

**形 1: 脚注の定義（タスク入り）が、本文のタスクより前に書いてある**

```markdown
本文[^1]

[^1]: 脚注:

    - [ ] 脚注のタスク

- [ ] 本文のタスク
```

| 画面で押すもの | 目印 | 実際に書き換わる行 |
| --- | --- | --- |
| 本文のタスク | `task:1` | **`    - [ ] 脚注のタスク`** |
| 脚注のタスク | `task:0` | **`- [ ] 本文のタスク`** |

**形 2: 参照されていない脚注の定義（タスク入り）が、本文のタスクより前に書いてある**（その脚注は画面に出ない）

```markdown
[^z]: 使っていない脚注:

    - [ ] 見えないタスク

- [ ] 本文のタスク A
- [ ] 本文のタスク B
```

| 画面で押すもの | 目印 | 実際に起きること |
| --- | --- | --- |
| 本文のタスク A | `task:1` | **`- [ ] 本文のタスク B` が書き換わる** |
| 本文のタスク B | `task:2` | 書き換え位置が見つからない（`ErrRefNotFound`）→ `ErrStale` として**黙って元に戻る**（通知は出ない。FR-143） |

**形 3: 脚注は文書の末尾にあるが、定義の順と参照の順が違う**

```markdown
本文[^a]と[^b]

[^b]: B:

    - [ ] 脚注 b のタスク

[^a]: A:

    - [ ] 脚注 a のタスク
```

| 画面で押すもの | 目印 | 実際に書き換わる行 |
| --- | --- | --- |
| 脚注 a のタスク | `task:1` | **`    - [ ] 脚注 b のタスク`** |
| 脚注 b のタスク | `task:0` | **`    - [ ] 脚注 a のタスク`** |

**表（形 1 と同じ並び）**: 脚注の定義の中の表が本文の表より前にあると、本文の `本文のセル` をダブルクリックしたとき**編集欄に `脚注のセル` が入り**、確定すると `    | 脚注のセル |` の行が書き換わる。

**起きない形**: 脚注を文書の末尾に、参照と同じ順で書き、すべて参照している場合（よくある書き方）。同じ確認で、3 つのタスクとも正しい行が書き換わった。**脚注の中にタスクも表も無ければ、脚注をどう書いても起きない。**

### 1.2 利用者から見えること

- チェックボックスは押した瞬間に切り替わって見える（NFR-012）。**書き込みの後の再描画で、押したものは元に戻り、別のもの（脚注のもの、またはその次のタスク）が切り替わる。** 脚注は文書の末尾に出るため、**押したものが戻ったことにしか気づかない**ことがある。
- **ファイルは、利用者が触っていない箇所が書き換わっている。** `Ctrl+Z`（FR-144）で取り消せる。
- セルでは、**編集欄に入る文字が、ダブルクリックしたセルの文字と違う**ため、気づける場合がある。気づかずに確定すると、脚注の表のセルが上書きされる。

---

## 2. 原因

### 2.1 描画の目印は、脚注が並べ替わる前に番号を付ける

goldmark は AST の変換を**優先度の小さい順**に走らせる（goldmark v1.8.5 の `util.PrioritizedSlice.Sort` は昇順）。

| 変換 | 優先度 | 行うこと |
| --- | --- | --- |
| `refTransformer`（MarkView。目印を付ける） | **80** | タスク・表・セルに、**その時点の木の順で**番号を付ける |
| 脚注の変換（goldmark の `footnoteASTTransformer`） | **999** | 脚注の定義の一覧を、**参照されていない定義を除き、参照の順に並べ替えて、文書の末尾へ移す** |

脚注の定義は、構文解析の時点では**最初の定義が書かれた位置**に一覧としてまとめて置かれ（`footnoteBlockParser.Close`）、優先度 999 の変換で初めて文書の末尾へ移る。**目印は 80 で付くため、定義が書かれた位置・書かれた順・参照されていない定義を含めて番号が振られる。**

### 2.2 書き換え位置の特定は、並べ替わった後の木で数える

`Locate`（IMP-121）は、`Render` と同じ goldmark の構成で構文木を**最後まで**組み立て、**すべての変換が終わった後の木**を `walkRefs` でたどって番号を振る。脚注はすでに末尾にあり、参照の順に並び、参照されていない定義は消えている。

**IMP-120 のとおり、2 か所は同じ関数（`walkRefs`）で数えている。しかし、たどる木が違う**（80 の時点の木と、999 の後の木）。脚注の中にタスクや表があると、番号が食い違う。

| 形 | 目印（80 の時点） | `Locate`（999 の後） |
| --- | --- | --- |
| 1 | 脚注のタスク = 0、本文のタスク = 1 | 本文のタスク = 0、脚注のタスク = 1 |
| 2 | 見えないタスク = 0、A = 1、B = 2 | A = 0、B = 1（見えないタスクは消えている） |
| 3 | b = 0、a = 1（定義の順） | a = 0、b = 1（参照の順） |

---

## 3. 原因の分類 — 仕様か、実装か

**仕様の不足である。** IMP-120 は「番号は 0 起点で、文書の中の出現順とする。数え方は IMP-121 の `Locate` と同じ関数で決める（`walkRefs`）。2 か所に書くと、描画で付けた番号と書き込みで探す番号が食い違い、別のセルを書き換える」と定める。**防ごうとした食い違いは正しく見抜いていたが、「関数を共有すれば足りる」とし、変換の途中で木の形が変わることを考えていなかった。** 「文書の中の出現順」も、脚注のように**書いた位置と描かれる位置が違う要素**について、どちらの順かを定めていない。

実装は IMP-120 の文どおりである（優先度は仕様が定めておらず、他の変換と同じ 80 にした）。

## 4. なぜ見つからなかったのか

| 層 | 見つからなかった理由 |
| --- | --- |
| 単体テスト | **UT-217（目印）と UT-218（位置）は別々に期待値を持ち、どちらも脚注の中のタスクと表のケースが無い。** 両者の番号が一致することを、同じ入力で突き合わせるケースも無い |
| 手動テスト | E2E-383 / E2E-384 の検証用データ（`generated/edit/tasks-lf.md` / `table.md`）に脚注が無い |
| 試作 | v1.2.0 の試作で、選択文字列の修飾のために**全ブロックに目印を付ける変換を優先度 70 で書いたところ、脚注の本文の番号がずれた。** 1000 へ移して直したとき、同じことが v1.1.0 のタスクと表にも起きると気づいた |

## 5. 修正方法

### 5.1 採る案 — 目印を、脚注の並べ替えより後に付ける

**利用者の判断（2026-11-08。v1.2.0 の実現性検討の表の 75）。**

| 対象 | 変えること | 規定 |
| --- | --- | --- |
| 実装仕様 | IMP-120 に「**番号は、すべての AST 変換を終えた後の木（描画される木）の順で付ける。`Locate` も同じ木をたどる**」と書く。「文書の中の出現順」は「描画される順」と言い換える | IMP-120, IMP-121 |
| 実装 | `refTransformer` の優先度を、脚注の変換（999）より大きくする（例: 1000）。**または、描画の直前に番号を付ける** | IMP-120 |
| 単体テスト | **1 章の 3 つの形と表を、目印と `Locate` を同じ入力で突き合わせる形で足す**（描画の `task:n` の直後の文字と、`Locate` の n 番目の行が同じ項目を指すこと） | UT-217, UT-218 |
| 手動テスト | E2E-383 / E2E-384 の検証用データに、脚注の中のタスクと表を足す（`gentestdata -edit`） | E2E-383, E2E-384 |

- **図のブロックの番号（`mermaid:<n>` / `plantuml:<n>`。優先度 85 / 86）も同じ時点で付いている。** v1.1.0 では図は書き換えの対象ではなく、番号は描画どうしでしか照らし合わせないため、食い違いは起きない。**v1.2.0 でコードブロック（図を含む）を書き換えの対象にするときは、同じ規則（すべての変換の後の木で数える）に従う。** 選択文字列の修飾の目印も同じである（試作では 1000 に置いて一致を確かめた）。
- **優先度を上げると、目印を付ける時点で数式の変換（80）と Alerts の変換（90）も済んでいる。** タスク・表・セルの位置には影響しないが、ゴールデンテスト（IMP-041）の差分が目印だけであることを確かめる。

### 5.2 採らなかった案

| 案 | 採らない理由 |
| --- | --- |
| `Locate` の側を、脚注の変換の前の木で数える | `Locate` は書き換え位置を求めるものであり、**数えるべき順は利用者が画面で見ている順**（描画される順）である。目印の側を描画に合わせるほうが筋が通る。また、変換の途中で木を取り出す手段を `Locate` に持ち込むことになる |
| 脚注の中のタスクと表を、編集の対象から外す | 起きる形 2 は、**画面に出ない脚注**が本文のタスクの番号をずらす。外しても直らない |

## 6. 影響範囲

- **ファイルの、利用者が押していない箇所を書き換える。** 編集モードは「書き換える箇所以外のバイト列を 1 バイトも変えない」（FR-143）ことを約束しており、**その約束を破る**（書き換えるのは 1 文字またはセル 1 つであり、ファイルが壊れることはない）。
- `Ctrl+Z` で取り消せる（FR-144）。**取り消しの履歴は編集モードを終えると消え、文書を切り替えると編集モードは自動で終わる**（FR-140）。気づかずに編集モードを終えるか別の文書へ移ると、元に戻すにはテキストエディタで直すしかない。
- 脚注の中にタスクか表がある文書だけで起きる。脚注を文書の末尾に参照の順で書く、よくある書き方では、**参照されていない脚注にタスクや表が無い限り**起きない。

## 7. 修正の前後に確かめること

### 7.1 確かめたこと（2026-11-08）

- 1.1 の 3 つの形と表を、本物の `internal/renderer` と `internal/document` で確かめた（`workspace/tmp/_fnref2`）。**フロントエンドは目印の値をそのまま Go へ送る**（`editmode.js` の `onCheckboxChange` が `ownRef` で鍵を照合してから `setTask(ref, checked)` を呼ぶ）ため、画面からの操作でも同じことが起きると見ている。
- 形 1 は、それより前に、本物の変換器だけで目印と `Locate` の番号の食い違いを確かめていた（`workspace/tmp/_fnref`）。

### 7.2 直す前に、v1.1.0 で症状を確かめる（W1）

1. 1.1 の形 1 を `fn-task.md` として保存し、v1.1.0 の MarkView で開いて編集モードにする
2. **本文のタスク**のチェックボックスを押す
3. テキストエディタで `fn-task.md` を開く → **`- [ ] 脚注のタスク` の行が `- [x] 脚注のタスク` になり、`- [ ] 本文のタスク` が変わっていなければ、症状が出ている**
4. MarkView で `Ctrl+Z` を押し、ファイルが元に戻ることを見る
5. 表（1.1 の「表」）でも、本文のセルをダブルクリックして、編集欄に `脚注のセル` が入るかを見る（確定しない。`Esc` で閉じる）

### 7.3 直した後

- UT-217 / UT-218 に足したケースを、優先度を 80 に戻して一度失敗させてから通す（UT-033）。
- 7.2 の手順で、押したタスクとセルだけが書き換わること（W1 / L1。E2E-383 / E2E-384 に足すケース）。
