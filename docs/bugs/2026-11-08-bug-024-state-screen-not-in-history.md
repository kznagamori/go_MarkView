## 1. 症状（コードから導いたもの）

**状態画面**は、本文ペインに文書の代わりに出す画面のうち `confirm-large`（10 MB 超 50 MB 以下の確認）/ `too-large`（50 MB 超）/ `render-error`（変換の失敗）である（UI-052）。**このうち `confirm-large` だけが履歴に積まれる。**

| # | 操作 | 履歴（`[ ]` が位置） | 画面 | 起きること |
| --- | --- | --- | --- | --- |
| 0 | A → B を開く | A **[B]** | B | |
| 1 | ツリーで 60 MB の Huge を開く | A **[B]** | Huge の上限超過の表示 | **履歴に積まれない**（位置は B のまま） |
| 2 | `Alt+←` | **[A]** B | A | **直前に見ていた B を飛ばして A へ行く** |

- **開いていた文書が 1 つだけ（A → Huge）なら、`Alt+←` を押しても何も起きない。** 位置が A（先頭）のままで、戻る先が無いためである。**A へ戻る手段は、ツリーやリンクから開き直すことしか無い。**
- **確認画面（10〜50 MB）では起きない。** FR-016 が「確認画面を表示した時点で表示履歴に積む。`Alt+←` で直前の文書へ戻れること」と定め、そのとおり積んでいる。**大きさが 50 MB を境に、戻る操作の振る舞いが変わる。**
- `render-error` は変換器の内部の失敗であり、通常の文書では起きない。起きたときの振る舞いは上限超過と同じである。

上の表は、`internal/session` の本物の `History` に、`commitOpen` / `commitPending` が行う呼び出しを同じ順で当てて確かめた（`workspace/tmp/_histstep`。2026-11-08）。

---

## 2. 原因

```go
// desktop/open.go
func (a *App) commitPending(req openRequest, err error) (newRoot string) {
	var sizeErr *document.SizeError

	if !errors.As(err, &sizeErr) || !errors.Is(sizeErr.Err, document.ErrNeedsConfirm) {
		a.pendingConfirm = ""
		return "" // 上限超過・レンダリングエラーはここで帰る（履歴に積まない）
	}
	...
	if pushesHistory(req.src) {
		a.history.Push(session.Entry{Path: sizeErr.Path, Anchor: req.anchor})
	}
	...
}
```

状態画面の 3 種類は、どれも `commit` の `outcomeState` の枝から `commitPending` を通る（画面の対象・監視・タイトルは 3 種類とも同じに扱う。BUG-012 の対策）。**履歴に積むのは、確認画面（`ErrNeedsConfirm`）の枝の中だけである。**

FR-016 が確認画面について「履歴に積む」と書いたため、実装はその場所に積む処理を置いた。**上限超過とレンダリングエラーについては、どの仕様も履歴を定めていない。**

---

## 3. 原因の分類 — 仕様か、実装か

**仕様の不足である。** FR-016 の確認画面の文は、`Alt+←` で直前の文書へ戻れることを目的として書かれており、**同じ目的は上限超過とレンダリングエラーにも当てはまる。** しかし FR-051 も UI-052 も、状態画面と履歴の関係を定めていない。実装は FR-016 の文どおりであり、反する箇所は無い。

---

## 4. なぜ見つからなかったのか

| 層 | 見つからなかった理由 |
| --- | --- |
| 単体テスト | `desktop` は対象外（UT-002） |
| 手動テスト | **E2E-322 は、確認画面から `Alt+←` で戻ることを見る（確認内容 6）が、上限超過の表示（手順 7）からは戻らない。** 上限超過は「表示が出て、実行ボタンが無い」ことだけを見る |
| 利用 | 50 MB を超える Markdown はまれであり、そこから戻る操作はさらにまれである |

## 5. 修正方法

### 5.1 採る案 — 状態画面も、確認画面と同じく履歴に積む

**利用者の判断（2026-11-08。v1.2.0 の実現性検討の 13 章の 4）。**

| 対象 | 変えること | 規定 |
| --- | --- | --- |
| 要求 | FR-051 の積む契機に「**状態画面（UI-052 の 3 種類）を出した場合も、その対象を積む**」を足す。FR-016 の確認画面の文と揃える | FR-051, FR-016 |
| `desktop` | `commitPending` の確認画面の枝の外で積む（`outcomeState` のすべて）。**経路の規則（`pushesHistory`）は変えない**——履歴・再読み込み・確認からは積まない | IMP-192, IMP-314 |
| 手動テスト | E2E-322 の手順 7 の後に `Alt+←` を足し、直前の文書（`large-12mb.md`）へ戻ることを確認内容に書く | E2E-322 |

- 積んだ項目へ履歴で戻ったときは、今と同じく開き直す。上限超過なら上限超過の表示、レンダリングエラーなら変換をやり直す（その間に直っていれば描画される）。
- [BUG-023](2026-11-08-bug-023-history-step-on-open-failure.md)（開けなかった項目を取り除く）とは**区別する。** 状態画面は「開けなかった」ではなく、画面がその文書を対象にしている（UI-013。タイトルもステータス領域もその文書を指す）。

### 5.2 採らなかった案

| 案 | 採らない理由 |
| --- | --- |
| 確認画面も積まないように揃える | **FR-016 の「`Alt+←` で直前の文書へ戻れること」に反する。** 確認画面で `Open anyway` を押さずに戻りたい場面がある |
| 状態画面から `Alt+←` を押したときだけ、位置を動かさずに今の項目を開く | 「状態画面の間は位置が 1 つずれている」という特別な状態を持つことになる。**v1.2.0 の戻る・進むボタンの淡色も、その分だけ特別扱いが要る** |

---

## 6. 影響範囲

- **文書の内容は変わらない。** 戻れる先だけの不具合である。
- 50 MB を超える Markdown か、変換に失敗する文書を開いたときだけ起きる。

---

## 7. 修正の前後に確かめること

### 7.1 直す前に、v1.1.0 で症状を確かめる（W1）

`go run ./scripts/gentestdata` を実行し（`testdata/e2e/generated/large-60mb.md` ができる）、`MarkView testdata/e2e` で起動する（`README.md` が表示される。FR-012）。

1. ツリーで `tables.md` を開く
2. ツリーで `generated/large-60mb.md` を開く（上限超過の表示）
3. `Alt+←` を押す → **`tables.md` ではなく `README.md` が出れば、症状が出ている**
4. （開いていた文書が 1 つの場合）起動し直し、`README.md` が表示されたまま `generated/large-60mb.md` を開き、`Alt+←` を押す → **何も起きなければ、症状が出ている**

### 7.2 直した後

- 7.1 の 3 で `tables.md` に戻り、4 で `README.md` に戻ること。
- 戻った先から `Alt+→` を押すと、`large-60mb.md` の上限超過の表示に戻ること。
- E2E-322 の確認内容 6（確認画面から戻る）が変わらないこと。
