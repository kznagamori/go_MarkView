## 1. 見たもの（ヘッドレスの Edge）

- 本文のリンク（`[a normal link](https://example.com/normal)`）に、`button: 1` の `auxclick` を送る
- **`defaultPrevented` が偽のまま**で、Go も呼ばれない（`FollowLink` なし）

`frontend/js/viewer.js` の本文のリンクの捕捉（IMP-223）は `#markdown` の `click` だけを受け、中ボタンの押下で出る `auxclick` を受けない。v1.0.0 も同じである。

## 2. 懸念

- **Chromium 系のブラウザは、中ボタンでリンクを押すと新しいタブを開く。** WebView2 でも新しいウィンドウの要求（`NewWindowRequested`）になり、アプリケーションの外に別のウィンドウが開くおそれがある。AR-060 は「新しいウィンドウを開く要求（`target="_blank"` 等）も捕捉して既定ブラウザへ委譲する」「アプリケーションは終始 1 つのウィンドウのみを持つ」と定める。
- WebKitGTK の振る舞いは分からない（何も起きない可能性もある）。

## 3. 直す前に確かめること（利用者）

1. **W1**: v1.0.0 の配布物で `testdata/e2e/README.md` を開き、「外部リンク」の節の `https://github.com/kznagamori/go_MarkView` を**中ボタン**でクリックする
2. 同じ文書の `docs/design.md を開く` のリンク（Markdown へのリンク）を中ボタンでクリックする
3. **L1** で 1・2 を繰り返す

**見るもの**: 新しいウィンドウが開くか、MarkView のウィンドウの中身が遷移するか、既定のブラウザが開くか、何も起きないか。

### 3.1 結果（利用者。2026-09-17。v1.0.0）

| 環境 | 外部リンク（手順 1） | Markdown へのリンク（手順 2） |
| --- | --- | --- |
| **W1** | 既定のブラウザで開く（Go の `FollowLink` を通らない） | **既定のブラウザへ回り、表示されない**（MarkView で開くはずのもの。FR-051） |
| **L1** | **MarkView のウィンドウがリンク先のページに置き換わり、戻れない**（BUG-015 と同じ形。AR-060） | **MarkView のウィンドウが置き換わり、何も表示されない** |

- **左クリックはどちらのリンクも期待どおり**だった（W1。外部リンクは既定のブラウザ、`docs/design.md` は MarkView で表示）。初めの報告は左クリックの結果であり、利用者が中ボタンで確かめ直した。
- **L1 では、中ボタンで本文のリンクを押すだけで画面全体が失われる。** 文書は第三者から受け取りうる（NFR-030）。
- W1 で外部リンクがブラウザで開くのは結果として害が無いが、**Go の判定（IMP-312）を通らずに外部へ渡っている**。

## 4. 修正の方向（利用者の判断。2026-09-17）

- **中ボタンでは何もしない。** 本文（`#markdown`）と拡大画面（`#expand-view`）のリンクで、中ボタンの `auxclick` の既定の動作を止め、Go を呼ばない。**リンクを開くのは左クリックだけとする。**
- 候補だった「左クリックと同じく Go へ渡す」は採らなかった。
- 仕様（IMP-223 / AR-060 ほか）への反映と実装は T19-8 で行う（5 章）。

---

## 5. 修正（仕様 4.61.0。T19-8）

### 5.1 エンジンの振る舞い（調べたこと）

| エンジン | 中ボタンで出るイベント | リンクをたどる処理 |
| --- | --- | --- |
| Chromium（WebView2） | `auxclick`（`click` は出ない） | `click` と `auxclick` の既定の動作（右ボタン以外） |
| WebKit 2024 年 7 月以降（WebKitGTK 2.46 以降） | `auxclick`（[WebKit bug 22382](https://bugs.webkit.org/show_bug.cgi?id=22382)。281169@main） | `click` と `auxclick` の既定の動作（`MouseEvent::canTriggerActivationBehavior` が右ボタンだけを除く） |
| WebKit それより前（WebKitGTK 2.44 以前。Ubuntu 24.04 の初版など） | **`click`**（`button` が `1`） | `click` の既定の動作 |

- **L1 の結果（ウィンドウが置き換わる）は、2.46 以降の振る舞いと合う**——`click` が届いていれば v1.0.0 の本文のリスナが止めて Go へ渡し、`docs/design.md` は MarkView で開いたはずである。
- **どちらのエンジン・版でも、既定の動作を止めれば遷移しない。** 止める先は `auxclick` と、古い WebKit の中ボタンの `click` の 2 つである。

### 5.2 実装

| ファイル | 変更 |
| --- | --- |
| `frontend/js/viewer.js` | **`#markdown` と `#expand-view` で `auxclick` を受け、リンクの既定の動作だけを止める**（`preventLinkDefault`。T19-7 の `onExpandLinkClick` を改名し、拡大画面の `click` と共用する）。**本文の `click`（`onLinkClick`）は `preventDefault()` の後、`event.button` が `0` でなければ戻る**（古い WebKit の中ボタンの `click`） |

### 5.3 確かめたこと

- **DOM 検査** `workspace/tmp/_linkcheck`（ヘッドレスの Edge）: 本文のリンク 5 つ（普通のリンク・Markdown へのリンク・見出しのアンカー・図の中のリンク 2 つ）を中ボタンの `auxclick` と `click` で押すと、どれも既定の動作を止めて Go を呼ばない。見出しのアンカーは移らない。拡大画面の図の中のリンク 2 つも同じ。リンクでない所の中ボタンは止めない。左クリックは今までどおり。**修正の前に FAIL することを確かめ、実装を 6 通り壊すとすべて FAIL**。
- **W1 の実物の exe**（ビルドした exe と配布物の中の exe）: UI Automation で `docs/design.md を開く` の位置を求め、WebView2 の描画ウィンドウへ中ボタンのメッセージを送る（カーソルは動かさない）。**タイトルは `README.md - MarkView` のまま、本文も残り、新しいプロセスも起きない。** 同じ位置の左クリックでは `design.md` に切り替わる。
  - **送った中ボタンが `auxclick` として届くこと**は、`auxclick` で Go へ渡すように壊した版で、中ボタンで `design.md` に切り替わることで確かめた。
- **L1 は確かめていない**（手元で Linux のビルドを作れない）。T20-5 で E2E-264 の手順 4 を行う。
