## 1. 見たもの（ヘッドレスの Edge）

Mermaid 図・PlantUML 図・インライン数式を 1 つずつ含む文書を開き、**同梱資産（`mermaid.min.js` / `viz-global.js` / KaTeX）の読み込みを止めた状態で**、それぞれの原文にだけある語（`qzx`）を検索する。その後に読み込みを再開し、描き終えるのを待つ。

| 時点 | 件数の表示 | 本文の中のハイライト | 検索の状態（`state.search.hits`） |
| --- | --- | --- | --- |
| 描く前に検索した直後 | `1 / 3` | 3（Mermaid の原文・PlantUML の原文・数式） | 3 |
| **描き終えた後** | **`1 / 3` のまま** | **0** | **3（すべて DOM から外れている）** |
| **`Enter` を押す** | **`2 / 3` に進む** | 0 | 3。**スクロールもハイライトも起きない** |
| 同じ語を入力し直す | `No results` | 0 | 0 |

- **v1.0.0 のフロントエンド**（`git archive v1.0.0 frontend`）で同じ検査を流しても、**まったく同じ結果**になる（数式を除く 2 つで確かめた。数式は v1.1.0 の作業ツリーで確かめた）。
- **4 章の文書（`slow-plantuml.md`）を、本物の変換（`internal/renderer`）と本物のフロントエンドで通しても同じ**である（資産の読み込みは止めない。実時間で測った）。開いた直後（66 ms）に `zzqpending` を検索すると `1 / 2` でハイライト 2 つ。**16 枚の図を描き終えて最後の図が理由に変わるのは 13.5 秒後**で、そのとき**件数は `1 / 2` のまま、ハイライトは 1 つ**（本文の段落だけ）、戻ったソースには `zzqpending` の文字がある。`Enter` で `2 / 2` に進むが何も起きない。
  - **描き終わるまでの時間**（同じ計測）: 1 枚目が描き始まるのが 0.9 秒後（同梱資産の読み込み）、以降 1 枚あたり 0.7 秒ほど、最後の図の順番は **12.7 秒後**。
- 入力し直すと `No results` になるのは仕様どおりである。描き終えた図と数式の中は検索の対象外（IMP-241）であり、原文は `data-source` と TeX ソースとして別に残っている。

## 2. 原因

- **検索（`search.js` の `find`）は、その時点の DOM のテキストノードを `<mark>` で包み、包んだ要素を `state.search.hits` に持つ。** 描く前の図のブロックには原文の `<pre class="mermaid-source">` / `<pre class="plantuml-source">` があり、数式の要素（`.math-inline` / `.math-block`）の中身は TeX ソースの文字であるため、どれも検索の対象になる。
- **描画は、原文の要素を置き換える。**
  - Mermaid（`lazy.js`）: 描き終えたら `<pre>` を図の器（`.mermaid-rendered`）に置き換える
  - PlantUML（`puml.js`）: **1 枚ずつ、描き始めるときに** `<pre>` を器（`.plantuml-rendered`）に置き換える。描けなかったら、器を**新しく作った** `<pre>` に戻す（`restorePlantUML`）
  - KaTeX（`lazy.js` の `drawMath`）: `katex.render` が要素の中身を描画結果で置き換える
- **置き換えられた要素の中の `<mark>` は DOM から外れるが、`state.search.hits` は持ったまま**であり、件数の表示（`updateCount`）はその長さを数える。移動（`select`）は外れた要素にクラスを付け、`scrollIntoView` を呼ぶが、DOM に無い要素ではスクロールしない。
- **検索の状態を破棄する契機（DSP-361）は、文書の切り替え・再描画・表の並べ替えだけ**であり、図と数式の描画は入っていない。
- **T18-6 で直したのは、テーマの切り替えで「描けなかった図」まで描き直してハイライトが外れる場合だけ**である（描けなかった図は描き直さない。DSP-370）。**文書を開いた直後の最初の描画は、それとは別の経路**であり、今回の症状はそこで起きる。

## 3. 影響

- **起きるのは、文書を開いてから図と数式が出るまでの間に検索したときだけ**である。PlantUML は同梱資産が 5 MB を超え、1 枚に 1 秒近くかかる（IMP-233）ため、図の多い文書ではその間が数秒になる。
- 件数（FR-080 の「現在位置 / 総ヒット数」）が実際のハイライトと食い違い、`Enter` や ∨ ボタンでの移動が**何も起きないように見える**（FR-080 の「移動時は該当箇所までスクロールする」を満たさない）。本文にも同じ語があれば、移動が本文のヒットと見えないヒットを交互にたどり、押しても動かない回が混じる。
- 文書やファイルは壊れない。検索を閉じるか入力し直せば元に戻る。

### 4.1 結果（利用者。2026-09-18。v1.0.0 の W1）

**NG**（症状が出た）。利用者の言葉:

> 描画が終わる前は 2 つヒットして Enter で移動できたけど、描画が終わるとヒットが 2 なのにトップにある文字列にだけになって移動しない

- **描き終える前**: 2 件がヒットし、`Enter` で 2 つの間を移動できる（本文の段落と、最後の図のソース）。

## 5. 修正の方向（利用者の判断。2026-09-18）

- **不具合として記録し、実機で確かめてから直す**（BUG-015 / BUG-016 と同じ進め方）。
- 直し方の案: **図か数式を 1 つ描き終えたとき、検索が開いていれば、DOM から外れたヒットを除き、描けずに原文へ戻ったブロックの中だけを探し直す。今の位置（現在のヒット）は保ち、スクロールしない。** 候補だった「描き終えたら同じ語で検索し直す」は、今の検索が画面に見えている位置からヒットを選び直すため、読んでいる途中で画面が動きうる。
- 候補だった「既知の制限として仕様に書く」は採らなかった。
- 仕様（FR-080 / IMP-241 / DSP-361 / E2E-271 ほか）への反映と実装は、実機での確認の後に行う。

## 6. 修正（仕様 4.69.0。T20-7）

### 6.1 決めたこと（利用者の判断。2026-09-18）

**現在位置のヒットが消えたときは、文書の順でその後ろに残っている最初のヒットへ移す**（末尾なら先頭へ回る）。画面は動かさない。候補だった「先頭のヒットへ戻す」「画面に見えている位置から選び直す」は採らなかった。

### 6.2 実装

| ファイル | 変更 |
| --- | --- |
| `frontend/js/search.js` | **`syncHits(root)` を足した**（FR-080, IMP-241）。DOM から外れた `<mark>` を件数から落とし、`root` の中にヒットが 1 つも残っていなければその中を探し直して包み直す。包み直したものは文書の順に並べ直す。**スクロールしない。** 現在位置が外れていたら、元の並びでその後ろに残っている最初のヒットへ移し、`search-hit-current` を付け替える |
| `frontend/js/lazy.js` | 図を 1 つ描き終えたとき（`settleDiagram`）と、数式を描き終えた要素ごとに `syncHits` を呼ぶ |
| `frontend/js/puml.js` | 図を 1 つ描き終えたとき（`settleDiagram`）と、**描き始めに原文を器へ置き換えた直後**に呼ぶ（描き終えるまで 1 秒近くあるため） |
| `scripts/gentestdata` | **`slow-plantuml.md` を作る**（4 章の文書。E2E-012, E2E-271） |

- **描けなかった Mermaid の原文はそのまま残る**ため、包み直さない（残っているヒットがあれば触らない）。触ると二重に包むことになる。
- **描き終えた図と数式の中は、これまでどおり検索の対象外**である（IMP-241）。入力し直したときと同じ件数になる。

### 6.3 確かめたこと

- **DOM 検査** `workspace/tmp/_searchpending`（ヘッドレスの Edge。同梱資産の読み込みを止めて間を作る）: 15 項目 PASS。
  - `pending`（Mermaid と数式の原文にだけある語）: 描く前は 2 件、描き終えると **0 件・`No results`**、検索バーは開いたまま、画面は動かない。`Enter` を押しても何も起きない。入力し直しても同じ。
  - `keep`（本文 2 件＋描けない Mermaid＋描けない PlantUML）: 描けなかった Mermaid の原文のハイライトは**そのまま**（二重に包まない）、**戻った PlantUML の原文は探し直してハイライトが付く**、件数は 4 件のまま、**現在位置は消えたヒットの次に残っていたもの（本文の最後の段落）へ移り**、画面は動かない。`Enter` で先頭へ回る。
  - **実装を 5 通り壊すと、すべて FAIL**（`lazy.js` の知らせを外す・`puml.js` の知らせを外す・戻った原文を探し直さない・現在位置を先頭へ戻す・現在位置の色を付け替えない）。壊さない写しでは 15 項目 PASS。
- **4 章の文書（本物の変換とフロントエンド、実時間）**: 開いた直後に検索して `1 / 2`、13.8 秒後に最後の図が理由に変わっても **2 件ともハイライトされたまま**、`Enter` で両方へ移動できる（修正の前は件数だけが残っていた。1 章）。
- 描画スモーク 2 部 OK、`domids` OK、DOM 検査 `_redrawcheck` 70 / `_bootcheck` 60 / `_editcheck` 84 / `_menucheck` 105 / `_sortcheck` 50 / `_mediacheck` 56 / `_expandcheck` 63 / `_copycheck` 12 / `_anchorcheck` 24 / `_datacheck` 34 / `_linkcheck` 15 / `_splitcheck` 12 すべて PASS。
- **実機での確認は rc の手動テスト**（E2E-271 の手順 11〜13 と確認内容 15〜18）。
