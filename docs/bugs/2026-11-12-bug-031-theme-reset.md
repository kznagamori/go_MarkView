## 1. 症状

Light を選んで使っていたのに、**新しく開いたウィンドウが OS のテーマ（Dark）で出る。** 開いていたウィンドウの表示は変わらない。いつも起きるわけではなく、利用者の使い方では 10〜20 回に 1 回ほどだった。

利用者の答え（2026-11-12）:

| 問い | 答え |
| --- | --- |
| 何が起きたか | **Light を選んでいたのに Dark で出た**（OS のアプリのモードは Dark） |
| どのウィンドウか | **新しく開いたウィンドウ**が、最初から Dark だった |
| テーマ以外の表示の設定（ペインの開閉・幅・ツリーのフィルター）に触れたか | 覚えていない |
| ウィンドウの使い方 | **同時にいくつも開いていた**（コマンドプロンプトから開き、開いたまま次を開いた） |
| 前の版で見たか | v1.1.0 以前では同じ使い方をしていない（PlantUML のファイルを開けるのは v1.2.0 から） |

利用者は「初期状態のテーマのウィンドウを、手順の間違いで後から閉じたのかもしれない」と推測していた。**その推測は 2.2 として当たっていた。ただし主な原因は、ウィンドウを閉じる順序と関係しない 2.1 である。**

---

## 2. 原因

設定（`config.json`）のテーマは `light` / `dark`（利用者が選んだ）か空文字（まだ選んでいない。OS の設定に追従する。FR-071）を取る。**どちらの戻り方も、保存した `light` が空文字に書き換わり、次に開いたウィンドウが OS のテーマで出る。**

### 2.1 戻り方 1: テーマに触れずに設定を変えると、保存したテーマが消える

フロントエンドは「利用者がこのウィンドウでテーマを切り替えたか」を `state.themeExplicit` に持ち、切り替えるまでは `UpdateConfig` にテーマを空文字で送る（IMP-210, IMP-303）。初回起動の OS 追従を、ペインの開閉などの最初の保存で失わないためである。

**ところが、起動時に保存値のテーマ（`light`）を当てても、この印は立たない。** 往路の `ConfigDTO.Theme` は OS の設定まで解決した値（`light` / `dark`）だけで、保存値が利用者の選んだものか（空文字か）を運ばない。そのため、**保存したテーマのあるウィンドウでテーマ以外の設定を変えると空文字が届き、Go 側（`UpdateConfig`）がそれをそのまま `App.cfg.Theme` へ写していた。** 1 秒後の保存（UI-114）で `config.json` の theme が空文字になる。

- **そのウィンドウは Light のまま**（画面の状態は変わらない）なので、利用者は気づかない。**次に開くウィンドウが OS の Dark で出る。**
- 空文字を送る操作は 7 つある（DOM 検査で確かめた。7.1）: アウトラインの開閉（ボタン・`Ctrl+Shift+O`）、ファイルツリーの開閉（ボタン・`Ctrl+Shift+E`）、**ペインの境界（幅のつまみ）を押して離すだけ**（幅が変わらなくても `pointerup` で保存する。UI-114）、ツリーのフィルター。
- **境界のつまみは、触れたことに気づきにくい。** 利用者の「覚えていない」とも合う。

IMP-303 の表は「復路で解決済みの値を返すと、初回起動の OS 追従が最初の保存で失われる」ことだけを考え、**保存値がある場合を考えていなかった。** v1.2.0 のツリーのフィルターで起きた「起動時に写さないと、最初の保存で保存値を上書きする」（IMP-211。4.76.0）と同じ形である。

### 2.2 戻り方 2: テーマに触れていないウィンドウが、終了時に起動したときのテーマを書き戻す

設定は全インスタンスで共有され、**保存のたびにそのインスタンスの設定を構造体まるごと書いていた**（UI-115 の「後勝ち」）。テーマに触れていないウィンドウも、終了時（UI-114）に**起動したときに読んだテーマ**を書く。

**Dark（空文字）のときに開いたウィンドウ A を残したまま、別のウィンドウ B で Light を選び、その後に A を閉じると、A が空文字を書き戻す。** 次に開くウィンドウは Dark で出る。テーマだけでなく、**ペインの表示・幅・ウィンドウの大きさ・エディタ・ツリーのフィルターも同じように巻き戻る**（7.1 の S7）。

UI-115 は「後から保存したインスタンスの内容が残る」「テーマは後勝ちでも不都合は小さい」としていた。**しかしそれは、変えた本人の値が残るときにしか成り立たない。** 変えていないインスタンスが起動時の古い値を書き戻すのは、後勝ちではなく巻き戻しである。

### 2.3 2 つが重なる

2.1 で一度空文字になると、それ以後に開いたウィンドウはすべて Dark で起動し、テーマの値として空文字を持つ。利用者がどこかのウィンドウで Light を選び直しても、**Dark のときに開いたウィンドウを後から閉じるたびに、2.2 で空文字が書き戻される。** 最後にどのウィンドウを閉じたかで結果が変わるため（7.1 の S5）、「たまに戻る」ように見えた。

**重い PlantUML のファイルを開くこと自体は原因ではない**（7.1 の S2）。ウィンドウを何枚も開いたまま使う使い方が、2.2 の起きる機会を増やした。

## 3. 原因の分類 — 仕様か、実装か

**どちらも仕様の不足である。** 実装は仕様（IMP-303 の表、UI-115 の「構造体全体を置き換える」、IMP-194 の `config.Save`）のとおりだった。

- 2.1: IMP-303 は復路の空文字を「利用者はまだ選んでいない」としたが、**それが「このウィンドウでは」の意味でしかないこと**（保存値の有無を表さないこと）と、Go 側がそれをどう扱うかを定めていなかった。
- 2.2: UI-115 は「後勝ち」を許す項目の性格だけを見て、**変えていないインスタンスが古い値を書き戻すこと**を考えていなかった。

---

## 4. なぜ見つからなかったのか

| 層 | 見つからなかった理由 |
| --- | --- |
| 手動テスト（E2E-311） | **選ぶテーマが Dark に決まっていた。** OS が Dark の機械では、保存したテーマが消えて OS への追従へ戻っても見た目が変わらない（開発機も利用者の PC も OS は Dark）。また、再起動した後にペインを開閉して、もう一度開く手順が無かった |
| 手動テスト（E2E-315） | **「最後に終了したウィンドウの状態になる（後勝ち）」を期待値にしていた。** 2.2 は仕様どおりとして OK になる |
| 単体テスト | 受け取ったテーマを写すのも、構造体まるごとの保存も `desktop` にあり、単体テストの対象外だった（UT-002）。`config` の単体テストは読み書きそのものしか見ていなかった |
| 使い方 | 2.1 は「次に開いたとき」に出るため、原因の操作（ペインの開閉）と時間が離れ、結びつかない。1 つのウィンドウで使っていると、戻っても選び直して終わる |

## 5. 修正

### 5.1 利用者の判断（2026-11-12）

| 問い | 答え |
| --- | --- |
| 起票するか | **BUG-031 として起票する** |
| いつ直すか | **rc.2 に入れる** |
| 2.2（UI-115 の後勝ち）をどうするか | **直す**（保存の直前にファイルを読み直し、そのウィンドウで変えた項目だけを書き換える。UI-115 を改める） |

### 5.2 実装

| 場所 | 変更 |
| --- | --- |
| `internal/config/merge.go`（新設） | `ThemeFromPatch`（`light` / `dark` だけを受け取り、空文字なら保存値を変えない。2.1）、`Read`（`Load` と同じ読み方だが、読めなければエラー）、`Merge`（`base` から変わった項目だけを `cur` から取り、他はファイルの値を残す。項目はリフレクションで並べる）、`SaveChanges`（`Read` → `Merge` → `Save`。読めなければ `cur` をそのまま書く。2.2） |
| `internal/config/config.go` | `Load` を `Read` の上に書き直した（振る舞いは同じ） |
| `desktop/bind.go` | `UpdateConfig` のテーマを `config.ThemeFromPatch` で当てる |
| `desktop/app.go` | `App.savedCfg`（このインスタンスが前回ファイルとそろえた値）を足し、起動時に読んだ値で始める |
| `desktop/lifecycle.go` | `persistConfig` を `config.SaveChanges(savedCfg, cfg)` にし、成功したら `savedCfg` を `cfg` に置き換える（保存の予約と終了時の両方） |
| `frontend/js/state.js` | コメントだけ（`themeExplicit` は「このウィンドウで切り替えたか」であり、Go 側が空文字で保存値を変えないこと） |
| 仕様（4.97.0） | UI-115、IMP-151・IMP-190・IMP-194・IMP-303・IMP-210、UT-507・UT-508 と 31.10、E2E-282・E2E-311・E2E-315 と 40.5、90 章 |

**読み直した値は画面にも `App.cfg` にも反映しない。** 実行中に他のインスタンスの変更へ追従しないこと（UI-115）は変えていない。同じ項目を複数のウィンドウで変えたときは、後から保存したほうが残る（項目ごとの後勝ち）。

### 5.3 採らなかった案

| 案 | 採らなかった理由 |
| --- | --- |
| 往路の `ConfigDTO` に「保存値が利用者の選んだものか」を足し、起動時に `state.themeExplicit` を立てる（2.1） | 直す場所がフロントエンドと Go の境界の両側に分かれる。Go 側で空文字を受け取らないようにすれば 1 か所で済み、フロントエンドが何を送っても保存値は消えない。テーマを OS 追従へ戻す操作は無い（FR-070）ため、空文字で保存値を消す経路は要らない |
| 2.2 は仕様どおりとし、利用者向け文書に「テーマを変えたら、それより前に開いたウィンドウを先に閉じる」と書く | 利用者が直すと判断した（5.1）。何枚も開いて使う使い方（UI-115）で、閉じる順序を気にさせるのは無理がある |
| 読み直しから書き込みまでを錠ファイルで守る | 保存は変更から 1 秒後と終了時にしか起きず、間は数ミリ秒であり、失われても設定は壊れない（一時ファイル＋リネーム。UI-112）。錠ファイルが残ったときの扱いのほうが重い |
| 実行中に他のウィンドウの変更へ追従する（ファイルを監視する） | UI-115 が追従しないと定めている。開いているウィンドウのテーマが、他のウィンドウの操作で突然変わる |

## 6. 影響範囲

- **保存したテーマが、テーマ以外の設定の変更で消えなくなる。** 設定が無い初回起動では、テーマに触れない限り空文字のまま残り、OS への追従を保つ（FR-071。7.2 の S6）。
- **ウィンドウを閉じる順序によらず、各ウィンドウで変えた項目が残る。** テーマ以外（ペインの表示・幅・ウィンドウの大きさ・エディタ・ツリーのフィルター）も同じ。**同じ項目を複数のウィンドウで変えたときは、後から保存したほうが残る。**
- 保存のたびに `config.json` を 1 回読む（数 KB）。
- 既存の設定ファイルはそのまま読める（形式は変えていない）。

## 7. 修正の前後に確かめたこと

### 7.1 直す前（2026-11-12）

**`v1.2.0-rc.1` の配布物**（`MarkView-v1.2.0-rc.1-windows-amd64.zip`。`checksums.txt` と一致）を、`TMP` / `TEMP` を作業用のディレクトリへ向けて起動し（利用者の `%TEMP%\MarkView` には触れない）、UI Automation でボタンを押し、× と同じ `WM_CLOSE` で閉じた（OS のアプリのモードは Dark）。

| # | 操作 | `config.json` の theme | 次に開いたウィンドウ |
| --- | --- | --- | --- |
| S1 | `light` で起動したウィンドウでアウトラインを閉じた（テーマに触れていない） | `"light"` → `""`（1 秒後。ウィンドウは開いたまま Light） | **Dark** |
| S2 | 重い PlantUML のファイルを開き、何も触らずに閉じた（対照） | `"light"` のまま | Light |
| S3 | テーマだけを切り替えた（対照） | `""` → `"light"` | Light |
| S4 | `""` で A と B を開き、B で Light を選んだ後に A を閉じた | `"light"` → `""` | **Dark** |
| S5 | A で Light を選び直した後、B でアウトラインを閉じた | `"light"` → `""`（最後に A を閉じると `"light"`） | **Dark** |
| S6 | `""` で開き、アウトラインを閉じた（対照。FR-071） | `""` のまま | Dark（OS 追従） |
| S7 | `light` で A・B・C を開き、A でテーマを Dark に、B でファイルツリーを開き、A・B・C（何も変えていない）の順に閉じた | テーマは `"light"`、ファイルツリーは非表示 | **A と B の変更がどちらも消えた** |

本物のフロントエンドでの DOM 検査（Go のバインドを差し替え、起動時の設定を保存値 `light` を解決した形にした）: アウトラインのボタン・`Ctrl+Shift+O`・`Ctrl+Shift+E`・ファイルツリーのボタン・アウトラインとファイルツリーの境界を押して離す（幅は 240 px のまま）・ツリーのフィルターの **7 つとも `UpdateConfig` にテーマを空文字で送った**。テーマを一度切り替えた後は `light` を送った。

### 7.2 直した後

- 単体テスト: UT-507（ケース 1〜11）・UT-508（ケース 1〜7）。**実装の写しを 4 通りに壊して落ちることを確かめた**（UT-033）——`Merge` が全項目を写す（rc.1 の書き方）とケース 1〜3・7・8、項目を 1 つ写し忘れるとケース 4、`ThemeFromPatch` が空文字を受け取るとケース 1・2・7、`Read` が読めないときに既定値を返すとケース 9 が落ちる。
- **直したビルド**（`wails build`。`develop/work` の作業ツリー）に 7.1 と同じ操作をした: S1・S4・S5 はどれも `"light"` のままで、次に開いたウィンドウは Light。S2・S3 は 7.1 と同じ。S6 は `""` のまま（OS 追従を保つ）。**S7 はテーマ `"dark"`・ファイルツリー表示**（A と B の変更が両方残る）。
- **rc.2 の手動テスト**: E2E-282 の確認内容 2（テーマに触れずにペインを開閉しても OS 追従が残る）、E2E-311 の確認内容 3（**OS と逆のテーマを選び**、テーマに触れずにペインの開閉と境界のつまみを押してから、もう 1 つ開く）、E2E-315 の確認内容 7（終了の順序を決め、テーマに触れていないウィンドウを最後に閉じる）。W1 / L1。
