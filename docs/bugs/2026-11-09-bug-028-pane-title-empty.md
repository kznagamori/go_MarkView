## 1. 症状

ファイルツリーとアウトラインのペインを開くと、**それぞれの一番上の見出しの行（高さ 28px）に何も出ない。**

| 場所 | 仕様（UI-030, UI-040, DSP-111） | 直す前（v1.0.0 〜 v1.1.0） | 直した後（`1a3434e`） |
| --- | --- | --- | --- |
| ファイルツリーの見出しの行 | `Files`（CSS で大文字にして `FILES` と見える） | **空**（28px の帯だけ） | `FILES` |
| アウトラインの見出しの行 | `Outline`（同じく `OUTLINE`） | **空** | `OUTLINE` |

**利用者向け文書は、直す前から見出しが出ると書いていた**（`docs/usage.md` の「ファイルツリーの見出しは `Files`」「アウトラインの見出しは `Outline`」）。

---

## 2. 原因

```html
<!-- frontend/index.html（v1.1.0）。IMP-202 のとおり、文言は書かない -->
<nav id="pane-filetree" class="pane pane-filetree" hidden>
  <div class="pane-title"></div>
  <div class="pane-subtitle" id="tree-root-name"></div>
  <ul id="tree" class="tree" role="tree"></ul>
</nav>
...
<nav id="pane-outline" class="pane pane-outline">
  <div class="pane-title"></div>
  <ul id="outline" class="outline"></ul>
</nav>
```

```js
// frontend/js/strings.js（v1.1.0）
  paneFiles: "Files",
  paneOutline: "Outline",
```

**`index.html` は文言を持たず（IMP-202, IMP-290）、`strings.js` に文言があるのに、2 つをつなぐ処理がどのモジュールにも無かった。** v1.0.0 と v1.1.0 のタグの木で `paneFiles` / `paneOutline` を探すと、`strings.js` の定義の 1 か所ずつしか出ない（`git grep`）。

ほかの空の要素（ステータス領域・検索の件数・状態画面・ツールチップほか）は、**その要素の機能を受け持つモジュールが、出すときに中身を作る。** ペインの見出しの文字は、**変わらない文字であり、どの機能にも属していなかった。**

---

## 3. 原因の分類 — 仕様か、実装か

**実装の欠落と、仕様の不備（担当の未割り当て）が重なっている。**

- **実装の欠落**: IMP-202 の「上の骨格でテキストが空の要素は、すべて実行時に埋める」は v1.0.0 の仕様にもあった（`v1.0.0` のタグの `12-impl-frontend.md` で確かめた）。実装はこれを満たしていない。
- **仕様の不備**: その「埋める」を**どのモジュールが受け持つかを、どの IMP も書いていなかった。** `panes.js` の IMP-240 は `togglePane` / `setPaneWidth` / `applyResponsive` だけを並べ、12.1 の木の説明も「ペインの開閉とリサイズ」だった。**実装は、IMP-240 に並んだ API をそのとおりに作っていた。**

[BUG-002](2026-09-04-bug-002-filetree-reload-on-show.md)（ツリーの読み直しの契機が未実装。「IMP-240 は `panes.js` の全 API を列挙しているが、ツリーの読み直しを書いていない」）と同じ形である。**要求（UI-030）と表示（DSP-111）は満たすべきことを書いていたが、実装仕様の担当が空いていた。**

## 4. なぜ見つからなかったのか

| 層 | 見つからなかった理由 |
| --- | --- |
| 単体テスト | 対象外（UT-002。フロントエンド） |

| 使い捨ての DOM 検査 | 機能ごとに作っており、ペインの見出しを見るものが無かった |
| **手動テスト** | **E2E-241 の確認内容 5（v1.1.0 まで）は「両方のペインを開いたとき、左から `Files` → `Outline` → 本文の順に並ぶ」だけを書いていた。** `Files` / `Outline` が**ペインの名前**として読まれ、ペインの並びを確かめる項目として **v1.0.0 の rc.2〜rc.4 と v1.1.0 の rc.1・rc.2・rc.4 の 6 回 OK になった**（v1.1.0 の rc.3 は未実施）。**見出しの文字そのものを見る確認内容は無かった** |
| 仕様のレビュー | IMP-202 の「すべて実行時に埋める」を、空の要素ごとに埋める担当と突き合わせていなかった |

**UI-031 が、実装の無いまま rc.2 / rc.3 の E2E-242 で OK になったのと同じ形の通り抜けである**（確認内容が 1 行で、見るべきものを名指ししていなかった）。**空の 28px の帯は、ペインの上の余白と見分けがつかない**——欠けているものは、そこにあるはずだと知らなければ見えない。

## 5. 修正

### 5.1 実装（`1a3434e`）

- `frontend/js/panes.js` の `initPanes` で、2 つの `.pane-title` に `S.paneFiles` / `S.paneOutline` を入れる。**`index.html` には書かない**（IMP-202, IMP-290）。
- `initPanes` は起動時に 1 度だけ呼ばれる（IMP-211）。見出しの文字は変わらないため、それで足りる。

### 5.2 仕様（4.90.0）

| 対象 | 変えたこと | 規定 |
| --- | --- | --- |
| 実装 | IMP-240 の `panes.js` の API に `initPanes` を載せ、「**ペインの見出しの文字は `initPanes` が `strings.js` から入れる**」を足した。12.1 の木の説明を「ペインの見出し・開閉・リサイズ」にした | IMP-240 |
| 実装 | IMP-202 に「**埋めるモジュールは、その要素の機能の IMP に書く**」を足した | IMP-202 |
| 手動テスト | **E2E-241 の確認内容 9 に「2 つの見出しの行に `FILES` と `OUTLINE` の文字が出る」を足し、並びとは別に見る**ようにした。v1.1.0 では NG になる旨を IMPORTANT に書いた。確認内容 7・8（4.73.0）は `FILES` だけを見ており、`OUTLINE` を見る確認内容が無かった | E2E-241 |
| E2E の方針 | 40.3 の不具合の表に BUG-028 の行を足した | E2E-020 系 |

### 5.3 採らなかった案

| 案 | 採らない理由 |
| --- | --- |
| `index.html` に `Files` / `Outline` を直接書く | IMP-202 / IMP-290（UI 文言は `strings.js` に集める）に反する |
| 見出しの行ごと消す | UI-030 / UI-040 / DSP-111 が見出しを MUST で定めている。v1.2.0 ではファイルツリーの見出しの行にフィルターボタンが載る（UI-033） |
| 「`index.html` の空の要素がすべて埋まること」を機械で検査する | **隠れている要素は、出すときに中身を作る**（右クリックメニュー・ツールチップほか）。起動直後に空であることは不具合の印にならず、見えている空の要素も区切り線やリサイザのように文字を持たないものがある。**どれが文字を持つべきかは人が決めることであり、判定にできない**（6 章の調べで、いま見えている空の要素は文字を持たないものだけだった） |

## 6. 影響範囲

- **表示だけである。** 操作・文書・設定に影響しない。ペインの開閉・リサイズ・ツリーとアウトラインの中身は正しく動いていた。
- `docs/usage.md` は直す前から見出しが出ると書いており、利用者向け文書は直さない。
- **同じ形の穴がほかに無いか**: 直した後の木（v1.2.0 の P27 の終わり）を、Go のバインドと Wails のランタイムの代役でヘッドレスの Edge に起動し、ファイルツリーとアウトラインを開いた起動直後の画面で、**子を持たず文字が空の要素をすべて挙げた**（2026-11-09）。**見えているものはツールバーの区切り 3 つと余白 1 つ・リサイザ 2 つ・ツリーの矢印の位置合わせ 2 つで、どれも文字を持たない飾りである。** 隠れているもの（修飾の群の区切り・検索の件数・状態画面・ステータスの通知・ダイアログの暗幕・拡大画面の倍率と中身・右クリックメニュー 2 つ・フィルターの枚・ツールチップ）は、出すときに中身を作る。

## 7. 修正の前後に確かめたこと

### 7.1 直す前（2026-11-09）

- **`v1.0.0` と `v1.1.0` のタグの木**で、`.pane-title` が空であり、`paneFiles` / `paneOutline` が `strings.js` にしか無いことを `git grep` で確かめた。
- **本物の `index.html` と `main.js` を、Go のバインドと Wails のランタイムの代役で起動する使い捨ての DOM 検査**（`workspace/tmp/_panetitle`。ヘッドレスの Edge）を、`v1.0.0`・`v1.1.0`・`a61fd51`（P26 の終わり）の木で走らせた。**どれも起動を終えた後（ステータス領域にパスが出た後）に、2 つの見出しが空で、高さ 28px の行として出ていた。**
- **配布物の実機（WebView2 / WebKitGTK）では確かめていない。** JS が文字を入れていないことはコードで決まり、描画エンジンに依存しない。

### 7.2 直した後

- 同じ DOM 検査で、`1a3434e` の木（`a61fd51` に `panes.js` だけを当てたもの）と P27 の終わり（`74fd1d3`）の木が `Files` / `Outline` になることを確かめた（CSS で大文字に見える）。
- **v1.2.0 の rc の手動テストで、E2E-241 の確認内容 7・9 を W1 で見る。**
