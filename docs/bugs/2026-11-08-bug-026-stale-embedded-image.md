## 1. 症状

画像を埋め込んだ文書（`![](swap.png)`）を MarkView で開いたまま、**画像のファイルを別の画像で上書きし、`F5` を押す。**

| 何を | W1 | L1 |
| --- | --- | --- |
| `F5` の後 | **古い画像のまま**（赤い長方形が、上書きした青に変わらない） | **同じ** |
| MarkView を閉じて文書を開き直した後 | 新しい画像（青） | 同じ |

**ウィンドウを閉じるまで、古い画像が出続ける。** 文書のファイルを書き換えて自動で再描画されたとき（FR-014）も同じである。拡大画面（FR-122）も同じ URL を使うため、古い画像が出る。

利用場面としては、**図を別のツールで描き直して PNG を上書きし、MarkView で確かめる**ときに起きる。利用者からは「`F5` が効かない」に見える。

---

## 2. 原因

### 2.1 同じ URL の画像を、WebView が取り直さない

ローカル画像の URL は、**ファイルの絶対パスだけから**作る（`/__local/<エスケープした絶対パス>`。IMP-118, AR-040）。再描画は `#markdown` の中身を差し替えるだけで、**ページは遷移しない**（AR-060）。

**Chromium（WebView2）と WebKitGTK は、1 つのページの中で一度読んだ画像を、応答のキャッシュの指示に関わらず使い回す。** 再描画で同じ URL の `<img>` が出直しても、サーバへ取りに来ない。

ヘッドレスの Edge 156 で、MarkView の再描画と同じく `#markdown` の `innerHTML` を差し替えて確かめた（`workspace/tmp/_imgcache`。2026-11-08）。サーバは取りに来るたびに幅の違う画像を返し、応答には `/__local/` と同じ `Cache-Control: no-store` と `nosniff` を付けた。

| 出し直し方 | 表示された幅 | サーバへの要求 |
| --- | --- | --- |
| 同じ URL で 4 回（すぐ・1.5 秒後・空にして 0.5 秒後を含む） | 4 回とも最初の幅 | **1 回だけ** |
| クエリを変えて 3 回（`?v=1`〜`?v=3`） | 毎回違う幅 | 3 回 |

### 2.2 IMP-162 の前提が成り立たない

```go
// internal/assetsrv/assetsrv.go
	// 更新した画像が古いまま表示されるのを防ぐ（IMP-162）。文書は編集中に
	// 何度も読み直される。
	head.Set("Cache-Control", "no-store")
```

IMP-162 は、`no-store` を付ければ再描画のたびに画像を取り直すと考えていた。**`no-store` は HTTP のキャッシュに効くが、ページの中の画像の使い回しには効かない。** ページを遷移させない MarkView では、ウィンドウを開いている間ずっと使い回される。

---

## 3. 原因の分類 — 仕様か、実装か

**仕様の誤りである。** IMP-162 の表の「根拠」の列が、成り立たない前提を書いていた。実装は IMP-162 どおりである。

**「描画エンジンの既定の振る舞いに、要求の充足を委ねない」（NFR-061）に当たる。** BUG-008（WebKitGTK が `alt` を描かない）と同じく、エンジンがそう振る舞うと仮定したことが、実機で確かめられていなかった。

---

## 4. なぜ見つからなかったのか

| 層 | 見つからなかった理由 |
| --- | --- |
| 単体テスト | 応答ヘッダが `no-store` であることは見ている（`assetsrv` の単体テスト）。**ヘッダが正しくても、WebView が取り直すかは単体テストでは見えない** |
| 描画スモーク | 文書を 1 回描くだけで、出し直さない |
| 手動テスト | **E2E-236 は画像が出ることを見るが、画像を書き換えてから `F5` を押す手順はどのケースにも無い。** E2E-226（ファイル更新の自動反映）は文書の書き換えだけを見る |

---

## 5. 修正方法

### 5.1 採る案 — ローカル画像の URL に、ファイルの版を付ける

**利用者の判断（2026-11-08。v1.2.0 の実現性検討の表の 77、13 章の 32）。** v1.2.0 で足す画像ファイルの表示（画像ファイルを単体で開く）と同じ仕組みにする。

| 対象 | 変えること | 規定 |
| --- | --- | --- |
| 変換 | ローカル画像の URL に **`?v=<版>`** を付ける。版は**ファイルの更新時刻と大きさ**（`os.Stat` で得る）から作る。読めないファイル・無いファイルには付けない（今と同じく壊れた画像の表示になる） | IMP-118 |
| 配信 | 変えない。`localurl.Decode` は `EscapedPath()` を解くだけであり、クエリを見ない | IMP-161 |
| 応答ヘッダ | `no-store` は残す（HTTP のキャッシュには効く）。**根拠の列を正しく書き直す** | IMP-162 |
| 手動テスト | 画像を書き換えて `F5` を押すと新しい画像になること（W1 / L1）（**4.79.0 で E2E-236 の手順 6〜9 と確認内容 10〜12 にした**。文書と画像は `go run ./scripts/gentestdata -edit` が作る `testdata/e2e/generated/edit/swap.md`・`swap.png`（赤 400 x 100）・`swap-blue.png`（青 500 x 100）） | E2E-236 |

- **ファイルが変わらなければ URL も変わらない**ため、再描画のたびに取り直すことはなく、ちらつかない。変わったときだけ取り直す。
- **変換のたびに、ローカル画像ごとに `Stat` が要る。** 標準的な文書（100 KB）の変換時間の目標（50 ms。NFR-011）に効くかを、直すときに測る。
- 画像のファイルだけを書き換えたときに自動で再描画はしない（今と同じ。FR-014 が監視するのは表示中の文書だけ）。**`F5` か、文書の書き換えで再描画したときに新しい画像になる。**
- 版を作る処理を、変換器（`internal/renderer`）と文書の読み込み（`internal/document`）のどちらに置くかは、v1.2.0 の仕様で決める（変換器は今はファイルを読まない）。

### 5.2 採らなかった案

| 案 | 採らない理由 |
| --- | --- |
| 再描画のたびに、変換ごとに変わる値（鍵など）を URL に付ける | **再描画のたびにすべての画像を取り直す。** 編集モードでは書き込むたびに再描画されるため（FR-143）、画像がちらつき、重い画像では待たされる |
| フロントエンドで、`F5` のときだけ URL に時刻を付ける | 文書の書き換えによる再描画（FR-014）では直らない。URL の組み立てを Go 側（IMP-118）とフロントエンドの 2 か所に持つことになる |
| ページごと読み込み直す | MarkView はページを遷移させない（AR-060）。画面の状態（ペイン・検索・編集モード）がすべて失われる |

---

## 6. 影響範囲

- **表示だけである。** 文書のファイルも画像のファイルも変わらない。
- ローカル画像だけが対象である。**リモートの画像（`http://` / `https://`）は WebView 自身のキャッシュに従う**（NFR-042 で許容している）。
- 古い画像が出ている間も、拡大画面と原寸表示は同じ古い画像を出す。

---

## 7. 修正の前後に確かめること

### 7.1 確かめたこと（2026-11-08。利用者）

v1.1.0 の配布物で、W1 と L1 の両方で確かめた（手順は `workspace/tmp/_manual/README.md` の 1）。

1. 赤い横長の長方形の PNG（`swap.png`）を埋め込んだ文書を開く
2. MarkView を開いたまま、青い長方形の PNG で `swap.png` を上書きする
3. `F5` を押す → **赤いまま**（W1 / L1 とも）
4. MarkView を閉じて文書を開き直す → 青になった

**この手順は E2E-236 の手順 6・7 と同じ形である**（4.79.0）。ケースでは `testdata/e2e/generated/edit/swap.md` を開き、`swap-blue.png` を `swap.png` に上書きしてから `F5` を押す（`go run ./scripts/gentestdata -edit` が作る）。

### 7.2 直した後

- 7.1 の手順の 3 で青に変わること（W1 / L1）。続けて文書の側を書き換えて保存したとき（FR-014）も、新しい画像のままであること。
- 画像を書き換えずに `F5` を押したとき、画像を取り直さないこと（URL が変わらない）。
- **rc の手動テストでは E2E-236 の確認内容 10〜12 で見る**（10 が `F5` で青になる、11 が文書の書き換えの後も青のまま、12 が書き換えずに `F5` を押しても画像が消えない）。
- 単体テスト: 版が更新時刻と大きさで変わること、読めないファイルには付けないこと、クエリが付いても `localurl.Decode` が同じパスを返すこと（UT-808）。
