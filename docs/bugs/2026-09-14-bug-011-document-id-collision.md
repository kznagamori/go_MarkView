## 1. 症状（コードから確定し、一部を headless Chrome で実測したもの）

**文書の中に、次の見出しを 1 つ書くだけで起きる。** 見出しの id は MD-021 の規則で小文字のスラッグになる（`## Tooltip` → `tooltip`）。

| # | 文書に書くもの | 起きること | 経路 |
| --- | --- | --- | --- |
| 1 | `## Tooltip` | **ツールバーのボタンにマウスを乗せると、見出しの文字がツールチップの文言（`Open / 開く (Ctrl+O)`）に置き換わり、見出しの位置がずれる**（`left` / `top` が書かれる）。**マウスを外す・どれかのキーを押す・ウィンドウからフォーカスが外れると、見出しが消える**（`hidden`） | `tooltip.js` の `show` / `place` / `hide` が `$("tooltip")` を引く。`hide` は `keydown` と `blur` でも呼ばれる |
| 2 | `## State screen` | **文書を表示するたびに見出しが消える。** 状態画面を出すと画面に何も出ず、**状態画面の表示中でも `Ctrl+F` で検索バーが開く**（DSP-301 に反する） | 文書を描くたびに `viewer.js` が呼ぶ `overlay.js` の `hideStateScreen` が、見出しを隠して空にする。`showStateScreen` は `#markdown` を空にした後、切り離された見出しへ書く。本物の `#state-screen` は隠れたままなので、`search.js` の `openSearch` の「状態画面なら開かない」が効かない |

- **生 HTML の `id` でも同じことが起きる**（`<div id="tooltip">`）。サニタイズは `h1`〜`h6` / `li` / `sup` / `div` の `id` を形だけ見て通す（許可する要素の一覧は MD-072。サニタイズの実装は IMP-116）。
- **PlantUML の図の器の id（`plantuml-svg-N`）と同じ名前の見出しが図より前にあると、図が見出しへ書かれる**（`lazy.js` が id で出力先を渡すため）。
- **脚注の id**（goldmark が出す `fn:1` / `fnref:1`）は今のアプリの id と重ならないが、**同じ名前空間にある**ことに変わりはない。
- 1〜6・9・10 は **v1.0.0 の画面でも起きる。** 7 は PlantUML を、8・11 は Mermaid を同梱した時点から起きる。**v1.1.0 はさらに `contextmenu` / `expand-view` / `editmode-badge` / `viewer-frame` を足す**（IMP-202）。

> [!IMPORTANT]
> **利用者に「文書が壊れている」ように見える。** 見出しが消える・書き換わるのは表示の側で起きるため、
> ファイルを開き直しても直らず、**エディタで見ると文書は正しい。** 原因を文書の側に探しても見つからない。
>
> **ありふれた見出しで起きる。** UI の設計書やヘルプに `Tooltip` / `Overlay` / `Status` という節があるのは自然である。

## 2. 原因

### 2.1 DOM の id は、ページ全体で 1 つの名前空間である

`document.getElementById(id)` は、**文書の順で最初に現れる**その id の要素を返す。本文（`#markdown`）はページの中ほどにある。そのため、**`index.html` で本文より後ろにある要素**は、本文の中の同じ id の要素に負ける。

```html
<main>
  …
  <article id="markdown">
    <h2 id="tooltip">Tooltip</h2>     <!-- ← こちらが先に見つかる -->
  </article>
  <div id="state-screen" hidden></div>
</main>
<footer id="statusbar">
  <span id="status-path"></span> <span id="status-meta"></span> <span id="status-message"></span>
</footer>
<div id="overlay" hidden></div>
<div id="dropzone" hidden></div>
<div id="tooltip" hidden></div>         <!-- ← アプリの要素は負ける -->
```

`#markdown` より後ろにあり、フロントエンドが `$(id)` で引くのは、`state-screen` / `status-path` / `status-meta` / `status-message` / `overlay` / `dropzone` / `tooltip` と、`#overlay` の中に JavaScript が作る `about-close` / `editor-open` / `editor-x` / `editor-browse` である（`statusbar` は後ろにあるが `$(id)` で引かれていない）。**v1.1.0 で足す `editmode-badge` / `expand-view` / `contextmenu` も後ろにある**（IMP-202）。

**CSS の id セレクタは順番に関係なく効く。** `#app` や `#btn-outline` を指す規則は、同じ id を持つ本文の見出しにも当たる（1 章の 10）。

### 2.2 フロントエンドは、要素をそのつど id で引いている

`frontend/js/util.js` の `$(id)` は `document.getElementById(id)` そのものであり、**要素を起動時に控えずに、使うたびに引いている**（`$("tooltip")` / `$("state-screen")` / `$("status-message")` / `$("overlay")` / `$("dropzone")` ほか）。**本文を挿入した後に引くと、本文の要素が返る。**

### 2.3 同梱資産も id を決め打ちで引く

`plantuml.js` の `status`、`mermaid.min.js` の `cy` である（BUG-006 の 2.7）。**資産は改変できない**（BR-042）。BUG-006 では `index.html` の側を改名して避けたが、**文書の側は書き手が自由に名前を付ける**ため、改名では避けられない。

### 2.4 本文の中の id を引くのは、アンカーの移動とスクロール連動だけである

`viewer.js` の `findAnchor` と `outline.js`（アウトラインの移動とスクロール連動）は、見出しの id で本文の要素を探す。**ここは本文の id を引きたい**が、`document.getElementById` を使うため、**本文に無い id を指すリンクはアプリの要素を返す。** `#overlay` のように隠れている要素ならスクロールしないだけで済むが、`#statusbar` / `#toolbar` / `#viewer` は見えている要素であり、「リンク先が見つからない」の通知も出ない。

## 3. 原因の分類 — 仕様か、実装か

### 3.1 一次原因 — **仕様の不足**

**「文書から生まれる id と、画面・同梱資産の id を分ける」という規則が、どの層にも無かった。**

- MD-021 は GitHub と互換のスラッグを定めるが、**HTML の `id` 属性にそのまま使う**前提で書かれている。**GitHub は `user-content-` を前に付けて出力しており**、そのうえで `#<スラッグ>` のリンクが動くようにしている。**互換にしたのはスラッグだけで、名前空間の分け方は写していなかった。**
- BUG-006 の 3.3 は「同梱資産がページのグローバルな状態を触りうる」ことを仕様へ書いたが、**衝突の相手として見たのは `index.html` だけ**で、文書の id を見ていなかった。
- `scripts/domids`（BR-043）も `index.html` だけを読む。**文書は実行時に来るため、検査の対象になりようがない。**

### 3.2 実装は仕様どおりである

`$(id)` を使うことも、見出しの id にスラッグをそのまま使うことも、仕様（IMP-117, IMP-202）に反していない。

| 層 | 見つからなかった理由 |
| --- | --- |
| 単体テスト | 見出しの id の**規則**（UT-202）は見ているが、**名前空間**は仕様に無かった。フロントエンドは対象外（UT-002） |
| 描画スモーク（BR-054） | **`index.html` を読まない**（BUG-006 の 4.2 と同じ）。`smoke.md` にアプリの id と同じ名前の見出しも無い |

| 仕様レビュー | 4.42.0 の事実確認で `plantuml.js` の決め打ちから疑いが出るまで、文書の id を衝突の相手として見ていなかった |

> [!IMPORTANT]
> **「検証用の文書にたまたま無かった」ことが、不具合を隠した。** BUG-004（折りたたみの中の検索語）と同じ形である。**衝突する名前を、検証用の文書へ意図して置く**（E2E-327, BR-054）。

## 5. 修正方法

### 5.1 採った案 — 文書の id に `user-content-` を付ける（GitHub と同じ）

**文書から生まれる id をすべて `user-content-` で始める。** 画面と同梱資産の id はこの接頭辞で始めない。**名前空間が分かれるため、今後どちらに id を足しても衝突しない。**

| 対象 | 変えること | 規定 |
| --- | --- | --- |
| 要求 | **AR-053 を新設**（名前空間を分ける規則）。MD-021 に「`id` 属性には `user-content-` を付け、`#<スラッグ>` のリンクで移動できる」、MD-050（脚注）と MD-072（生 HTML の `id`）に同じ扱いを足す | AR-053, MD-021, MD-050, MD-072 |
| Go | 見出しの id に接頭辞を付ける（`Heading.ID` も接頭辞付き）。脚注は goldmark の接頭辞の設定を使う。**生 HTML の `id` はサニタイズの後に接頭辞付きへ書き換える**（4.42.0 で足した `input` の後処理と同じ走査） | IMP-117, IMP-111, IMP-116 |
| フロントエンド | **本文の要素を id で探す関数を 1 つにし**（`util.js` の `findInDocument`）、`#<スラッグ>` と `#user-content-<スラッグ>` のどちらでも本文の中だけを探す。**アプリの要素に当たらない。** 見出しのアンカーのアイコンの `href` は接頭辞を付けない（GitHub と同じ） | IMP-223, IMP-224, IMP-227, IMP-302 |
| Mermaid | **`mermaid.initialize` に `dompurifyConfig: { SANITIZE_NAMED_PROPS: true }` を渡し、ラベルの `id` / `name` に `user-content-` を付けさせる**（1 章の 11。Mermaid 11.17.2 で効くことを実測） | IMP-231 |
| 画面の id | `index.html` と JavaScript が作る id は `user-content-` で始めない | IMP-202 |
| 検査 | `scripts/domids` が、`index.html` の id と同梱資産の決め打ち id が接頭辞で始まらないことも確かめる。描画スモークが、本文の id がすべて接頭辞付きで、`Status` の見出しが PlantUML の描画後も書き換わっていないことを確かめる | BR-043, BR-054, UT-810, UT-813 |

- **GitHub の README に書かれた `#見出し` のリンクは、これまでどおり動く。** 変わるのは `id` 属性の値だけであり、スラッグの規則（MD-021 の 1〜5）は変えない。
- **`#user-content-<スラッグ>` と書かれたリンク**（GitHub が出力する見出しの `id` を直接指したもの）も動くようになる。

### 5.2 採らなかった案

| 案 | 採らない理由 |
| --- | --- |
| 衝突する名前だけを避ける（予約語の一覧を持ち、当たる見出しに `-1` を付ける） | **`#tooltip` のリンクが GitHub と食い違う。** アプリに id を足すたびに一覧の更新が要り、**更新を忘れた id がそのまま衝突する** |
| フロントエンドが要素を起動時に控え、そのつど引かない | **同梱資産の `status` / `cy` が残る**（資産は改変できない。BR-042）。資産の側は結局予約語で避けることになり、上の案の欠点が残る |
| `index.html` に「身代わり」の `id="status"` を本文より前に置く | **BUG-006 の再発と見分けがつかない。** `scripts/domids` の規則を例外で崩すことになり、`cy` は Mermaid が器を足してから引くため身代わりでは済まない |

## 6. 影響範囲

- **文書の内容は変わらない。** 表示だけの不具合であり、ファイルは書き換わらない（v1.0.0 は書き込み経路を持たない）。
- **セキュリティ上の影響は限られる。** 書き込まれるのは MarkView 自身の文言と PlantUML のログであり、文書の書き手が任意の文字列を画面の UI へ注入できるわけではない。**ただし、書き手がツールチップ・通知・情報ダイアログの表示を壊せる**（利用者は通知を見落としうる）。
- **v1.1.0 の編集モードの書き込み先には影響しない。** 目印（IMP-120）は `data-ref` 属性であり id を使わないため、文書の id が衝突しても書き込み先を取り違えることは無い。**ただし v1.1.0 で足す画面の要素（`contextmenu` / `expand-view` / `editmode-badge`）も本文より後ろにあり、対策を入れなければ同じ形で乗っ取られる。**

## 7. 修正後の検証方法

### 7.1 機械的な確認

| 確認 | 手段 |
| --- | --- |
| 変換結果のすべての `id` が `user-content-` で始まる。見出し・重複・脚注・生 HTML を含む | UT-219 |
| Mermaid のラベルに書いた `id` が接頭辞付きになる | 描画スモーク（BR-054, E2E-109 の 8。判定は UT-813 のケース 5） |
| `index.html` の id と同梱資産の決め打ち id が接頭辞で始まらない | `scripts/domids`（UT-810 の 10〜12） |
| 本文の id がすべて接頭辞付きで、`Status` の見出しが PlantUML の描画後も書き換わらない | 描画スモーク（BR-054, E2E-109 の 8。判定は UT-813） |

### 7.2 実機での確認（W1）

**E2E-327** の手順で行う。**実装の前に同じ手順で症状が出ることを確かめてから直す。**

### 7.3 回帰

見出しの id を変えるため、**アンカーを使う経路をすべて見る**: 同一文書内のアンカー（E2E-263）、他文書のアンカー付きリンク（E2E-263）、アウトラインからの移動（E2E-252）、開き直したときのアンカーの復元、脚注の相互リンク（E2E-231 の確認内容 7）、見出しのアンカーのアイコン（E2E-231 の確認内容 9・10）、ゴールデンテスト（UT-214。**差分は `id` 属性だけであることを読む**。UT-039）。
