---

## 1. 症状

利用者の報告（E2E-371 の手順 3）:

> L1 では、Copy を選択したら選択が解除され、クリップボードにコピーされない

W1（WebView2）では確認内容 3・4 とも OK である。

## 2. 経路（コードで確かめたこと）

`frontend/js/contextmenu.js` の `open()` は、**メニューを出した直後に最初の項目へフォーカスを移す。**

```js
  menu = current;
  root.hidden = false;
  placeAt(root, ...);

  // 最初の使える項目へ移す。**本文の選択範囲はフォーカスの移動では消えない**（IMP-249）
  const first = root.querySelector(".contextmenu-item:not(:disabled)");
  if (first) first.focus({ preventScroll: true });
```

**コメントに書いてある前提そのものが、WebKitGTK では成り立たない。** WebKit は、要素へフォーカスを移すと文書の選択範囲を解除する。

**`Copy` が淡色にならないのは、判定がフォーカスの前だからである。**

```js
    root.append(
      createItem("copy", S.menuCopy, selectionIn(place) !== null),   // ← focus() の前に評価する
      createItem("selectAll", S.menuSelectAll, true),
    );
```

そのため L1 では次の順に進む。

1. 右クリック → `selectionIn(place)` は真 → **`Copy` は選べる状態で出る**
2. `first.focus()` → **WebKit が選択範囲を解除する**（利用者から見ると「右クリックした時点で選択が消える」）
3. `Copy` を押す → `copySelection()` の `execCommand("copy")` が**偽**を返す
4. 控えの `store(String(getSelection()))` が**空文字**を Go へ渡し、`CopyToClipboard("")` が**クリップボードを空にする**

## 3. 確かめたこと（利用者。L1。2026-09-21）

| 見たもの | 結果 | 分かること |
| --- | --- | --- |
| **右クリックした時点で選択が残っているか** | **消える** | **解除しているのは項目の押下ではなく、メニューを開く処理である**（上の 2） |
| `Ctrl+C` は効くか | **効く** | **WebView 自身のコピーは使える。** `execCommand` に寄せる方針（AR-062）は変えなくてよい |
| `Copy link address` は効くか | **効く** | **Go 経由の経路（`CopyToClipboard`）は生きている** |

**`closeContextMenu()` のフォーカス復帰が原因、という当初の見立ては外れた**——そこへ届く前に、開く処理で消えている。

## 4. 直し方

**選択範囲を控え、当て直す。** 入力欄が `current.start` / `current.end` を控えているのと同じ扱いを、本文の `Range` にも与える。

| 手順 | 何を |
| --- | --- |
| 1 | `open()` で、**`first.focus()` を呼ぶ前**に `getSelection().getRangeAt(0).cloneRange()` を控える |
| 2 | **`first.focus()` の直後に当て直す**（`removeAllRanges()` + `addRange()`）。**これで選択が見えたまま残る**——E2E-371 の確認内容 3（右クリックしても選択範囲が変わらない）を満たす |
| 3 | `copySelection()` の**実行直前にも当て直す**。`closeContextMenu()` が開く前のフォーカス要素へ戻すため、**そこでもう一度消えうる** |
| 4 | **空文字を Go へ渡さない。** 控えの経路は「書式を失ってでも文字列を入れる」ためのものであり、入れる文字列が無いときは何もしない |

**`Select all` は当て直しの対象外である**（自分で選択を作り直す）。**入力欄の経路は既に当て直している**ため変えない。

## 5. 影響

**L1 で右クリックの `Copy` が使えず、さらにクリップボードの元の内容が失われる**（FR-063）。
`Ctrl+C` と `Copy link address` は影響を受けない。

## 6. 直した後に確かめること

| 何を | どこで |
| --- | --- |
| 右クリックしても選択範囲が変わらない | **L1 で E2E-371 の確認内容 3**（rc.2 の手動テスト） |
| `Copy` が書式付きで入り、`Ctrl+C` と同じ内容になる | **L1 と W1 で E2E-371 の確認内容 4** |
| 控えた `Range` を、フォーカスの後と実行の前に当て直している | **DOM 検査**（Chromium。メニューを開いた後に選択を意図的に解除し、`Copy` が空でない内容を渡すことを見る）。**エンジン差は見えないが、当て直しが消えたことは捕まえられる** |
| 入れる文字列が無いときは Go を呼ばない | 同上 |
