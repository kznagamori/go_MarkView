## 1. 症状

`Ctrl+F` で検索し、`Enter` / `Shift+Enter` / `∧` / `∨` で移動していくと、
**折りたたまれた `<details>` の中にあるヒットに来たところで、画面が動かなくなる。**

| 状態 | 挙動 |
| --- | --- |
| ヒット数の表示（`3 / 12`） | **折りたたみの中も数に入っている** |
| 現在位置の強調（`.search-hit-current`） | **付いている**（が、折りたたみの中なので見えない） |
| 該当箇所へのスクロール | **起きない。** 画面はその場に留まる |
| もう一度押す | 次のヒットへ進む（**そのヒットが見えていれば移動する**） |

実施者の記録:

> 折りたたまれているとそこに移動しない

`docs/showcase.md` / `testdata/showcase.md` はどちらも `<details>` を含む（E2E-231 が確認している）ため、**検索語によっては通常の利用でも起きる。**

---

## 2. 原因

> [!IMPORTANT]
> **訂正（2026-09-05。修正時の実測）。** 本節が述べる「レイアウトボックスを持たない」は**正確ではない。**
> 実測（Edge 152。`workspace/tmp/_detailscheck/probe.html`）では、閉じた `<details>` の中の要素は
> **`getBoundingClientRect` が大きさも位置も返す**（723×35、`top=1277`）。
>
> **それでも `scrollIntoView` は何もしない**（`scrollTop` は 0 のまま）。`<details>` が自動で開くこともない。
> **開いてから呼べば動く**（`scrollTop` が 1161 になり、器の中に入る）。
>
> **症状も修正も本報告のとおりだが、理由の言い方が違う。** 「大きさを持っているか」で
> 問題を検知しようとすると**持っているので見落とす。** 判定できるのは
> 「祖先に閉じた `<details>` があるか」だけである。

### 2.1 直接の原因 — 閉じた `<details>` の中は `scrollIntoView()` の対象にならない を呼んでいる

`frontend/js/search.js` の `select()`。

```js
function select(index) {
  ...
  hits[wrapped].classList.add(CURRENT);

  // **スムーススクロールを使わない**（FR-041 と同じ理由）。
  hits[wrapped].scrollIntoView({ block: "center" });   // <- ここ
  syncActive();

  updateCount();
}
```

閉じた `<details>` の中身は、ブラウザの既定スタイルで**レンダリングされない**（`<summary>` を除く子は `content-visibility: hidden` 相当の扱いになり、レイアウトボックスを持たない）。

CSSOM View の `scrollIntoView()` は「要素に関連付けられたボックスが無ければ、何もせずに戻る」と定めている。
**エラーにもならず、静かに何も起きない。**

### 2.2 なぜヒットとして数えられるのか — 走査が「見えているか」を見ていない

```js
// search.js 175
const EXCLUDED = "svg, .katex, script, style";

function textNodes(root) {
  const walker = document.createTreeWalker(root, NodeFilter.SHOW_TEXT, {
    acceptNode(node) {
      if (!node.nodeValue) return NodeFilter.FILTER_REJECT;

      const parent = node.parentElement;
      if (!parent || parent.closest(EXCLUDED)) return NodeFilter.FILTER_REJECT;

      return NodeFilter.FILTER_ACCEPT;
    },
  });
  ...
}
```

除外しているのは **SVG（Mermaid / PlantUML の描画結果）・KaTeX・`script` / `style`** の 4 つだけである。
いずれも「**原文が別に残っている、描画の副産物**」であり、除外の理由が明確に書かれている（IMP-241）。

**閉じた `<details>` の中身は、原文そのものである。** 除外の対象にはならず、`<mark>` が正しく作られ、件数にも入る。
**走査までは正しい。壊れているのは移動だけである。**

### 2.3 同じ構造の問題が、他の移動経路にもある

`scrollIntoView()` を「見えているとは限らない要素」に対して呼ぶ箇所は、他にもある。

| 場所 | 経路 | 折りたたみの中にありうるか |
| --- | --- | --- |
| `search.js` 158 | 検索の移動（FR-080） | **ありうる**（本件） |
| `viewer.js` 61 `scrollToAnchor` | 同一文書内アンカー（FR-050, MD-020） | **ありうる**（`<details>` の中の見出しへのリンク） |
| `viewer.js` 242 `applyScroll` の `anchor` | 履歴復元・リンクからの遷移（IMP-302） | **ありうる**（同上） |
| `outline.js` 132 | アウトラインのクリック（FR-041） | **ありうる**（`<details>` の中の見出しはアウトラインにも出る。IMP-224 は除外していない） |
| `outline.js` 118 / `filetree.js` 84 | ペイン内の項目を見える位置へ | **無い**（ペインに折りたたみは無い） |

**E2E-271 が突いたのは検索だけだが、原因は 4 か所に共通している。**
脚注（MD-050）へのリンクも `<details>` の中に置かれれば同じことが起きる。

## 3. 原因の分類 — 仕様か、実装か

### 3.1 実装の誤り — 移動の前に祖先を開いていない

FR-080 は次を求めている。

> `Enter` / `Shift+Enter` で移動するたびに、**該当箇所までスクロールする**

「該当箇所へ移動する」と定められている以上、**移動できない状態を作ったまま「移動した」ことにするのは実装の誤りである。**
`scrollIntoView()` が黙って何もしないことに気づいていない。

### 3.2 仕様の不備 — 折りたたみの扱いがどこにも書かれていない

| 文書 | 折りたたみへの言及 |
| --- | --- |
| FR-080（検索） | **無い** |
| UI-080（検索バー） | **無い**。件数表示（`3 / 12`）が何を数えるかも定めていない |
| IMP-241（検索の実装） | **無い**。除外対象は SVG / KaTeX / `script` / `style` の 4 つで、理由も書かれているが、折りたたみは想定されていない |
| DSP-161（ヒットの表示） | **無い** |
| MD-026（折りたたみ） | 「GitHub と同様に開閉可能な形で描画する」だけ。**他機能との関係に触れていない** |

**MD-026 で `<details>` を通すと決めた時点で、「本文の一部が非表示になりうる」という状態が生まれた。**
その状態が、検索（FR-080）・アンカー（FR-050）・アウトライン（FR-041）にどう影響するかが、**どの層にも書かれていない。**

これは「仕様が間違っている」のではなく、**「仕様が決めていない」**種類の不備である。決まっていないため、実装が暗黙に「常に見えている」を前提にした。

### 3.3 決めるべきこと（2 つ）

| # | 決めること | 選択肢 |
| --- | --- | --- |
| 1 | 折りたたみの中を**検索対象にするか** | A: する（現状。原文なので当然）／ B: しない |
| 2 | 対象にするなら、**移動時にどうするか** | A: 祖先の `<details>` を開いて移動する／ B: 開かずに件数だけ数える（現状。**破綻している**） |

**現状は「1-A + 2-B」であり、この組み合わせだけが成立しない。** 数えておきながら行けない。

## 4. なぜ単体テストと E2E の自動テストで見つからなかったのか

### 4.1 単体テスト — 対象外（意図的な除外）

31 章 31.10 の対応表はこうなっている。

```
| FR-080 | — (GUI) | |
| UI-080 | — (GUI) | |
| MD-026 | UT-201 系（変換の確認） |
```

- 検索は `frontend/js/search.js` にあり、UT-002 が単体テストの対象を `internal/` に限っている
- `<details>` 側は Go の変換（サニタイズを通ること）だけが検証されており、**描画後の可視性は対象外**

**そもそも `scrollIntoView()` の挙動は DOM とレイアウトが要る。** Go の単体テストでは原理的に検証できない。

### 4.2 自動 E2E — 操作を行わない

40 章の対応表も、FR-080 の検証は手動ケースだけだと記録している。

```
| FR-080 | E2E-271, E2E-272 |  |
| UI-080 | E2E-271 |  |
```

自動 E2E（E2E-101〜109）は配布アーカイブの検査と CLI の確認、および描画スモークテストであり、**検索バーを開く経路が無い。**

### 4.3 描画スモークテスト（E2E-109）でも捕まらない

`scripts/smoke` は Mermaid / PlantUML / KaTeX が描けるかを見るものであり、**`frontend/js/search.js` を読み込まない。**

### 4.4 手動テストの手順にも「折りたたみ」が無い

**E2E-271 の 8 手順のどこにも `<details>` は出てこない。**

```
1. Ctrl+F を押す
2. 複数箇所にある語を入力する
3. Enter と Shift+Enter で移動する
4. 検索バーの ∧ / ∨ ボタンを数回ずつクリックして移動する
5. 本文をホイールで大きくスクロールする
6. コードブロックが検索バーの真下に来る位置までスクロールし、そこで ∨ ボタンを押す
7. ヒットしない語を入力する
8. Esc で閉じる
```

前提条件は「長い文書を開いている。コードブロックを含むものとする（`docs/showcase.md` でよい）」であり、
**`docs/showcase.md` がたまたま `<details>` を含んでいたために露見した。**

実施者が手順どおりに「複数箇所にある語」を入力し、順に移動していった結果、折りたたみの中のヒットに当たったものである。
**別の語を選んでいれば通過していた。**

### 4.5 まとめ

| 層 | 捕まえられたか | 理由 |
| --- | --- | --- |
| 単体テスト | **できない** | 対象が `internal/` のみ（UT-002）。DOM とレイアウトが要る |
| 自動 E2E | **できない** | 検索バーを操作しない |
| 描画スモーク | **できない** | `search.js` を読み込まない |
| 手動テスト | **できた（ただし偶然）** | 手順に折りたたみが無い。検索語の選び方次第で通過していた |
| 仕様レビュー | **できたはず** | MD-026 で「本文の一部が非表示になりうる」と決めた時点で、検索・アンカー・アウトラインへの影響を検討できた |

## 5. 修正方法

### 5.1 案 1（推奨）— 移動の直前に祖先の `<details>` を開く

**「1-A + 2-A」を選ぶ。** ブラウザのページ内検索（Chrome の `hidden=until-found` による自動展開）と同じ挙動になり、利用者の期待に合う。

```js
// frontend/js/search.js

// revealHit は移動先が見えるようにする（FR-080, MD-026）。
//
// **閉じた <details> の中にある要素はレイアウトボックスを持たない。**
// その状態で scrollIntoView を呼んでも、エラーにならず静かに何も起きない
// （CSSOM View: 関連付けられたボックスが無ければ何もせずに戻る）。
// FR-080 は「移動するたびに該当箇所までスクロールする」と定めているため、
// **移動できる状態を作ってから呼ぶ。**
//
// 開いた <details> は閉じ直さない。利用者が「そこにあった」ことを
// 確かめられる状態を残す。
function revealHit(mark) {
  for (let d = mark.parentElement?.closest("details"); d; d = d.parentElement?.closest("details")) {
    d.open = true;
  }
}

function select(index) {
  ...
  hits[wrapped].classList.add(CURRENT);

  revealHit(hits[wrapped]);
  hits[wrapped].scrollIntoView({ block: "center" });
  syncActive();

  updateCount();
}
```

- **入れ子の `<details>` に対応する。** 1 段だけ開くと、二重の折りたたみで同じ症状が残る
- `find()` の末尾で呼ぶ `select(firstFromViewport())` も同じ経路を通るため、**入力した瞬間に折りたたみが開くことがある。** これは受け入れる。開かないと、そのヒットが「現在位置」でありながら見えない状態になる
- **閉じ直さない。** 検索を閉じた（`Esc`）ときに元へ戻すと、利用者が中身を読んでいる最中に閉じてしまう

### 5.2 `firstFromViewport` への影響

```js
function firstFromViewport() {
  const top = $("viewer").getBoundingClientRect().top;
  const index = state.search.hits.findIndex((mark) => mark.getBoundingClientRect().bottom >= top);
  return index < 0 ? 0 : index;
}
```

折りたたみの中の `<mark>` は `getBoundingClientRect()` がすべて 0 を返すため、`0 >= top` は偽になり、**候補から自然に外れる。**
`revealHit` を `select()` の中に置く限り、ここは**変更不要**である（`findIndex` の時点ではまだ開いていない）。

### 5.3 採らない案 — 折りたたみの中を検索対象から外す

`EXCLUDED` に `details:not([open])` を足す案。**採らない。**

- **除外の性格が変わる。** 現在の 4 つはいずれも「原文が別にある描画の副産物」であり、`<details>` の中身は原文そのものである（IMP-241 の除外理由と揃わない）
- **件数が利用者の操作で変わる。** 折りたたみを開閉するたびに `3 / 12` の分母が変わり、`find()` を呼び直さない限り追随もしない
- **「あるのに見つからない」ほうが、利用者にとって害が大きい。** 折りたたみの中は「まだ読んでいない箇所」であり、検索で見つけたい場所そのものである

### 5.4 あわせて直す — 他の 3 経路（3 章の表）

同じ関数を `viewer.js` / `outline.js` からも使えるようにする。

- **`util.js` に置くのが素直である。** `search.js` に置いて他から `import` すると、`outline.js` → `search.js` の依存が増える（`search.js` は既に `outline.js` を `import` しており、**循環参照になる**）
- 対象: `viewer.js` の `scrollToAnchor`（61）と `applyScroll` の `anchor`（242）、`outline.js` の見出しクリック（132）

**ただし、これらは手動テストで NG になっていない。** 直すかどうかは、**同じ修正でまとめて直す**（回帰の芽を残さない）か、**E2E-271 の範囲に絞る**（変更を小さく保つ）かの判断になる。**まとめて直すことを推奨する。** 原因が同一であり、片方だけ直すと「検索では行けるがリンクでは行けない」という説明の付かない差が残る。

### 5.5 あわせて直すべき仕様

**NFR-071 に従い、同じ変更で仕様書も直す。**

| 文書 | 直す内容 |

## 7. 修正後の検証方法

### 7.1 手動

1. **E2E-271**（W1）— `docs/showcase.md` を開き、**折りたたみの中にしかない語**で検索して `∨` を押す → 折りたたみが開き、該当箇所へスクロールすること
2. **入れ子の確認** — `<details>` の中に `<details>` がある文書で同じことを行う（検証用データを追加する必要がある）
3. **既存の回帰** — 折りたたみの外のヒットへの移動、`Enter` / `Shift+Enter` とボタンの一致、`No results`、`Esc` での解除（**`2026-09-03-search-jump-buttons.md` の修正が生きていること**）
4. **開いた折りたたみが閉じ直されないこと** — `Esc` で検索を閉じても開いたままであること
5. 5.4 をまとめて直した場合: **折りたたみの中の見出しへのリンク**（FR-050）と**アウトラインからの移動**（FR-041）

### 7.2 機械的な確認

```bash

grep -rn "scrollIntoView" frontend/js/
```

go vet ./...
