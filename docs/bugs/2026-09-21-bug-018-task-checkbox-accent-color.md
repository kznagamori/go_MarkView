# BUG-018: タスクリストのチェックボックスの色を、描画エンジンの既定に委ねている

| 項目 | 内容 |
| --- | --- |
| 不具合番号 | **BUG-018** |
| 報告日 | 2026-09-21 |
| 対象 | **`v1.0.0` から**（`frontend/css/` に `accent-color` の指定が無いのは v1.0.0 も同じ）。`v1.1.0-rc.1` で現れた |
| 検出 | **`v1.1.0-rc.1` の手動テスト E2E-231 の確認内容 4**（利用者。2026-09-21） |
| 環境 | **L1 で NG / W1 は OK**。L1 は **実機の Ubuntu 24.04 / GNOME（Wayland）**（rc.4 までの L1 は WSL 上の Ubuntu であり、環境が変わっている） |
| 関連要求 | FR-020, MD-022, DSP-121, NFR-061, E2E-231 |
| 分類 | **仕様の不足**（DSP-121 はチェックボックスの寸法と位置を定めるが、**色を定めていない**） |
| 状態 | **調査済み。修正はこれから**（**利用者の判断: 不具合として直す**。2026-09-21） |

---

## 1. 症状

**L1 で、チェック済みのタスクリストのチェックボックスがオレンジで描かれる**（利用者の報告）。W1 では青である。

```markdown
- [x] 済んだ項目      <- L1 ではオレンジ、W1 では青
- [ ] まだの項目
```

## 2. 原因

**`frontend/css/` のどこにも `accent-color` の指定が無い。**

```bash
$ grep -rn "accent-color" frontend/css/
（何も出ない）
```

`.markdown-body input[type="checkbox"]`（`markdown.css`）が与えているのは**左マージンと縦の位置合わせだけ**であり、**塗りの色はエンジンの既定に委ねている。**
WebKitGTK は GTK テーマのアクセント色で描くため、**Ubuntu の既定のテーマ（Yaru）ではオレンジ**になる。Chromium（WebView2）は OS のテーマを見ず、自前の青で描く。

**これは NFR-061 が名指しで禁じている形である**——「描画エンジンの既定の振る舞いに、要求の充足を委ねない」。
[BUG-008](2026-09-06-bug-008-broken-image-alt-webkitgtk.md)（壊れた画像の `alt`）と同じ構図であり、**そのとき委ねてよいと決めたのは「差が出ても要求が壊れないもの」だけ**である（[BUG-009](2026-09-06-bug-009-task-checkbox-size-webkitgtk.md) の 2px の寸法差）。

## 3. なぜ v1.0.0 で出ていなかったか

**色は報告されていないが、コードは v1.0.0 と同じである**（`accent-color` は v1.0.0 の `markdown.css` にも無い）。

| rc | E2E-231 の L1 | 備考にあるもの |
| --- | --- | --- |
| `v1.0.0-rc.3` | **NG** | チェックボックスの**寸法**（13px / 12px）と、リモート画像の代替テキスト。**色の記述は無い** |
| `v1.0.0-rc.4` | OK | 備考なし |
| `v1.1.0-rc.1` | **NG** | **チェック済みがオレンジ** |

**L1 の環境が WSL 上の Ubuntu から実機の Ubuntu（GNOME）へ変わっている**（rc.4 の E2E-223 の備考と、2026-09-21 の確認）。
GTK のテーマとアクセント色は環境で変わるため、**「前の rc で出なかったから無かった」とは言えない。** 色を決めていない以上、**どの環境でどう出るかはこちらで決められない**——それがこの不具合の本質である。

## 4. 直し方（案）

**`accent-color` をテーマのトークンで明示する。** 1 行で足りる。

```css
.markdown-body input[type="checkbox"] {
  /* **塗りの色をエンジンの既定に委ねない**（NFR-061）。WebKitGTK は GTK テーマの
     アクセント色（Ubuntu の既定はオレンジ）で描く。DSP-121 の色を明示する。 */
  accent-color: var(--accent-emphasis);
  ...
}
```

- **`--accent-emphasis`** はライトで `#0969da`、ダークで `#1f6feb`（`tokens.css`）。**テーマの切り替えに追随する**
- **生 HTML のチェックボックスにも同じ色が付く。** DSP-121 / DSP-122 の見分け（編集できるかどうか）は**カーソルとホバーの帯**が受け持っており、色では区別していない
- **W1 の見た目は変わらない**（既定の青とほぼ同じ値）。**変わるのは L1 だけ**である

## 5. 影響

**表示だけである。** データにも操作にも影響しない。ただし FR-020（GitHub と同じ体裁）と DSP-121 が満たせておらず、**利用者が OS のテーマを変えるたびに本文の見た目が変わる。**

## 6. 直した後に確かめること

| 何を | どこで |
| --- | --- |
| チェック済みの色が W1 と L1 で同じ | **L1 で E2E-231 の確認内容 4**（rc.2 の手動テスト） |
| ライトとダークで色が切り替わる | 同上（E2E-281 のテーマ切り替えと合わせて見る） |
| 計算値が `accent-color` を持つ | **DOM 検査**（Chromium。`getComputedStyle` で見える。エンジン差は見えないが、**指定が消えたことは捕まえられる**） |
